React/Vue 深度原理：虚拟 DOM

🏷️ 前端框架

React 和 Vue 为什么快？不是直接操作 DOM 快，是因为虚拟 DOM + Diff 算法，只更新真正变的部分。这篇讲透前端框架底层原理。

核心原理1：虚拟 DOM 原理

直接操作真实 DOM 很慢，浏览器要重排重绘。虚拟 DOM 是 JS 对象，在内存里对比，只把变化的部分更新到真实 DOM。

flowchart TD A[状态变化] --> B[生成新虚拟 DOM] B --> C[和旧虚拟 DOM Diff] C --> D[找到变化的节点] D --> E[批量更新真实 DOM]

虚拟DOM vs 直接DOM

操作 直接 DOM 虚拟 DOM
更新方式 改一个节点就操作 DOM 内存对比后批量更新
重排重绘 频繁触发 最小化触发
跨平台 只能浏览器 可以 Native/SSR/小程序
开发效率 手动操作容易出错 声明式，自动更新

核心原理2：Diff 算法原理

两棵完整树 Diff 是 O(n^3)，React/Vue 用三个假设把复杂度降到 O(n)：同层对比、不同类型直接换、key 标记列表。

flowchart TD A[Diff 优化] --> B[同层对比] A --> C[不同类型 直接替换] A --> D[key 标记列表项] B --> B1[不跨层找子节点] C --> C1[div → p 不看子树] D --> D1[key 相同才复用]

Diff 三个假设

假设 原理 复杂度
同层对比 只比较同一层级节点 O(n) 基础
类型不同 节点类型变了直接删旧建新 不递归子树
key 复用 列表用 key 标记，相同 key 复用 列表更新快
结论 三个假设 O(n^3) → O(n)

核心原理3：响应式原理：Vue vs React

Vue3 用 Proxy 拦截属性访问，自动收集依赖；React 靠 setState 通知重新渲染，手动控制。

flowchart LR A[Vue3 响应式] --> B[Proxy 代理对象] B --> C[读取属性 收集依赖] C --> D[修改属性 触发更新] E[React] --> F[setState] F --> G[重新渲染函数] G --> H[Diff 找变化]

Vue3 vs React 响应式对比

对比 Vue3 React
响应式 Proxy 自动追踪 setState 手动触发
更新粒度 组件级，精准到属性 组件级，整树 Diff
心智负担 低，写就行 高，useMemo/useCallback 优化
编译优化 Vue 编译器静态提升 React Compiler 自动优化

新手最容易踩的坑

❌
避坑指南
  • 列表一定要加 key，用唯一 id，不要用 index，不然排序更新会出 bug
  • React 里不要在渲染函数里改状态，会无限循环
  • Vue 里不要用 this.$set，Vue3 Proxy 已经自动响应式了
  • 大列表不要一次性渲染全部，用虚拟滚动，不然页面卡
