Vue 3 Composition API

🏷️ Vue 3

一、Vue 的设计哲学：渐进式与响应式

我从 Vue 2 用到 Vue 3，最喜欢它的"渐进式"——你拿它写个指令增强的静态页可以，搭大型 SPA 也行。但 Vue 真正区别于其他框架的是响应式系统：你改一个普通变量，界面自动更新，不用手动 setState。Vue 3 用 Proxy 重写响应式核心，配上 Composition API，我写出来的代码比 Vue 2 短一半，类型推断还更好。

二、Composition API：逻辑组织的新范式

Vue 2 的 Options API（data/methods/computed/watch）按"选项类型"组织代码，同一个功能的逻辑被拆散在不同选项里。Composition API 反过来：按功能组织代码，一个功能的状态、计算、监听器写在一起，还能抽成可复用的 composable 函数。

2.1 ref 与 reactive：两种响应式入口

import { ref, reactive, computed, watch } from "vue";

// ref：包装任意类型，模板里自动解包，脚本里用 .value
const count = ref(0);
const doubled = computed(() => count.value * 2);

// reactive：包装对象/数组，直接修改属性
const state = reactive({
  user: { name: "junjunyi" },
  list: [1, 2, 3],
});

// 侦听：source 可以是 ref/getter/多个源
watch(count, (newVal, oldVal) => {
  console.log(`count: ${oldVal} -> ${newVal}`);
});

// 直接修改，界面自动更新
function increment() {
  count.value++;
  state.user.name = "updated";
}

选择原则：基础类型用 ref，对象用 reactive（或 ref）。我们团队规范是"统一用 ref"，避免 reactive 解构丢失响应式的坑。

我踩过的 reactive 解构坑

我早年写 const { name } = state 然后改 name，界面纹丝不动，调试了半小时才想起来：解构 reactive 对象会丢失响应式。要么用 toRefs(state) 转成 ref 再解构，要么直接 state.name = 'x'。这个坑我在 code review 里至少拦过同事五次。

2.2 Composable：逻辑复用的终极形态

Composition API 的杀手锏是 composable 函数——把一段有状态的逻辑抽出来，像自定义 Hook 一样在多个组件间复用：

// composables/useMouse.ts
import { ref, onMounted, onUnmounted } from "vue";

export function useMouse() {
  const x = ref(0);
  const y = ref(0);

  function update(e: MouseEvent) {
    x.value = e.pageX;
    y.value = e.pageY;
  }

  onMounted(() => window.addEventListener("mousemove", update));
  onUnmounted(() => window.removeEventListener("mousemove", update));

  return { x, y };
}

// 组件中使用
// const { x, y } = useMouse();
// <p>鼠标位置: {{ x }}, {{ y }}</p>

三、响应式原理：依赖收集与派发更新

Vue 3 的响应式系统建立在 ES2015 Proxy 之上。当组件 render 函数执行时，访问了哪些响应式属性，就会被"收集"为依赖；当这些属性变化时，通知所有依赖它们的 effect（通常是组件 render）重新执行。

flowchart LR A[访问响应式属性
读取 obj.name] --> B[Proxy get 拦截] B --> C[track: 收集 activeEffect
到 deps Map] D[修改响应式属性
obj.name = 'new'] --> E[Proxy set 拦截] E --> F[trigger: 遍历 deps
通知所有 effect] F --> G[组件重新 render
更新 DOM] C -.记录依赖.-> F style B fill:#3b82f6,color:#fff style E fill:#10b981,color:#fff

这套机制的精妙之处在于依赖追踪是自动的、精确的：你只改了 obj.name，只有用了 name 的组件会重渲染，用了 obj.age 的组件不受影响。对比 Vue 2 的 Object.defineProperty（必须预定义属性、数组需要重写方法），Proxy 方案天然支持 Map/Set、动态新增属性，性能也更好。

五、实战：一个带类型的 Todo 组件

下面是一个完整的 Vue 3 SFC（单文件组件），展示 Composition API + TypeScript + 模板语法的协同：

<script setup lang="ts">
import { ref, computed } from "vue";

interface Todo {
  id: number;
  text: string;
  done: boolean;
}

const todos = ref<Todo[]>([
  { id: 1, text: "学习 Vue 3", done: true },
  { id: 2, text: "写一篇博客", done: false },
]);
const newText = ref("");

const remaining = computed(() => todos.value.filter(t => !t.done).length);

function addTodo() {
  const text = newText.value.trim();
  if (!text) return;
  todos.value.push({ id: Date.now(), text, done: false });
  newText.value = "";
}
</script>

<template>
  <h2>Todo 列表（{ remaining } 项未完成）</h2>
  <input v-model="newText" @keyup.enter="addTodo" placeholder="输入新任务" />
  <ul>
    <li v-for="todo in todos" :key="todo.id">
      <label>
        <input type="checkbox" v-model="todo.done" />
        <span :style="{ textDecoration: todo.done ? 'line-through' : 'none' }">
          {{ todo.text }}
        </span>
      </label>
    </li>
  </ul>
</template>

六、最佳实践

  • script setup 是官方推荐写法：编译期语法糖，比 options API 更简洁、类型推导更好、性能更优。新项目一律用 <script setup lang="ts">。
  • props 必须用 TS 接口定义：defineProps<{ title: string; count?: number }>() 能获得完整的类型检查和模板提示。
  • 避免解构 reactive 对象：解构会丢失响应式。如果需要解构，用 toRefs 把每个属性转成 ref。
  • 用 Pinia 替代 Vuex：Pinia 是 Vue 官方推荐的状态管理库，去掉了 mutations，完整 TypeScript 支持，API 更简洁。
  • 组件设计要"单向下行"：props 向下，事件向上（emit），不要在子组件里直接修改 prop。

七、常见问题 FAQ

Q1：ref 和 reactive 到底用哪个？

社区主流共识是"统一用 ref"。原因：reactive 有几个坑——解构丢失响应式、不能直接整体替换（state = newState 会断开引用）、TypeScript 推导不如 ref 直接。ref 虽然多一个 .value，但行为一致、心智模型简单。模板里 ref 自动解包，写起来也不繁琐。

Q2：Vue 的响应式和 React 的状态有什么本质区别？

一句话：Vue 是"主动追踪"，React 是"被动重渲染"。我做了个对比：

Vue 3React 18
追踪方式访问属性时记录依赖setState 触发整个函数重跑
重渲染粒度精确到用到的属性组件级，靠 diff 算 DOM
心智模型电子表格公式自动重算函数重新执行
并发渲染模板编译优化强Fiber 可中断，RSC 更灵活

各有取舍：Vue 上手快、模板编译优化强；React 生态大、并发和服务端组件更灵活。两个我都写过，选哪个主要看团队现有技术栈，别纠结"哪个更先进"。

Q3：Vue 3 迁移成本高吗？

Vue 2.7 已经 backport 了 Composition API，大部分代码可以渐进迁移。几个要注意的破坏性变更：

  • 全局 API 改造成 app.use()；
  • 过滤器 filter 移除；
  • $listeners 合并到 $attrs；
  • v-model 参数变化。

官方迁移构建工具能自动处理 80% 改动。另外 Vue 3 不兼容 IE11，要支持 IE 就留在 Vue 2。

八、总结

Vue 3 的核心价值是"响应式 + Composition API"的组合：Proxy 让追踪精确高效，Composition API 让逻辑组织和复用变得自然。它对初学者友好（模板 + 指令上手快），对大型项目也不妥协（TypeScript、Pinia、Volar 工具链完整）。下一篇我们跳出框架本身，看看支撑现代前端开发的工程化体系——构建工具、包管理、Monorepo。
