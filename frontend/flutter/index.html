Flutter

🏷️ 前端

Flutter：一套代码，两端运行

我做过一个要同时上 iOS 和 Android 的工具 App，团队就三个前端。用 Flutter 一个月出了双端版本，按原生写根本做不到。这就是 Flutter 的杀手锏：Dart + 自绘引擎，一套代码同时跑在 iOS 和 Android，UI 完全一致。但它也不是万能药，我先讲清楚它的取舍。

核心差异

别的跨端框架（React Native）借原生组件，UI 在两端会有细微差异；Flutter 自己用 Skia 画像素，不借原生控件，所以 iOS 和 Android 长得一模一样。代价是包体积大、原生能力要自己接。

自绘引擎：为什么 UI 能一致

关键认知：Flutter 的控件（Widget）不是原生控件的封装，是 Flutter 自己画的。这就是为什么它能做到 iOS/Android 像素级一致。但反过来说，要调系统级能力（蓝牙、通知、相机），得通过 Platform Channel 桥接原生，这就是 Flutter 的复杂度来源。

2024-2026：Flutter 的新变化

方向进展
渲染引擎Impeller 替代 Skia，iOS 卡顿大幅改善
WebCanvasKit 渲染稳定，PWA 体验提升
桌面Windows/macOS/Linux 稳定可用

我最在意的是 Impeller。以前 Flutter 在 iOS 上有著名的「首帧掉帧」，新引擎 Impeller 就是为了根治这个。2024 年 Impeller 成了 iOS 默认，动画卡顿明显好转。这是 Flutter 从「能用」到「好用」的关键一跃。

Widget：一切都是 Widget

Flutter 的设计哲学：UI 树上全是 Widget。按钮是 Widget，padding 是 Widget，甚至对齐也是 Widget。这种「万物皆组件」的思路，和 React 的组件化很像：

Scaffold(
  appBar: AppBar(title: Text('Hello')),
  body: Center(
    child: Column(children: [
      Text('Hi'),
      ElevatedButton(onPressed: () {}, child: Text('点击')),
    ]),
  ),
)

新手会觉得「加个 padding 都要套一层 Container」很烦，但理解后你会发现：声明式 UI，组合大于继承，改 UI 就是改 Widget 树。

状态管理：Flutter 最绕的部分

新手必坑

Flutter 的状态管理是新手最大的坎。官方方案有 Provider、Riverpod、Bloc、GetX……选哪个吵了好几年。我的建议：小项目用 Riverpod（简洁、类型安全），大团队复杂业务用 Bloc（强制分层、可测试）。别上来就学 Bloc，会被它的样板代码劝退。

方案定位适合
setState局部状态简单小部件
Provider官方基础中小项目
Riverpod类型安全中大型推荐
Bloc严格分层大型复杂业务
GetX全家桶快速原型

语言DartJS/TSSwift / Kotlin

性能接近原生接近原生原生
包体积大（~15MB 起）中小
原生能力需桥接需桥接原生支持
适合UI 一致、要快JS 团队极致体验

我的实战清单

  • 包体积：用 --tree-shake-icons 和移除未用字体，能压掉几 MB；
  • 性能：列表用 ListView.builder 懒加载，别一次性 build 全部 item；
  • 原生能力：Platform Channel 写得薄，别把业务逻辑塞进原生；
  • 热重载：开发时用 hot reload，改 UI 秒见，比原生快多了；
  • 别用太多 GetX 全家桶，隐式依赖难维护。

FAQ

Q：Flutter 学 Dart 值吗？
Dart 不难，有 JS/Java 基础一两周上手。真正的成本是 Flutter 的 Widget 体系和状态管理。如果你只写一次跨端 App，投资回报没问题。

Q：Flutter Web 能用吗？
2026 年 CanvasKit 渲染稳定了，做内部工具、简单展示站可以。但 SEO 和首屏体积还是弱项，营销站别用 Flutter Web。

Q：Flutter 性能真能追原生吗？
UI 渲染层面几乎没差别。但重计算、平台级 API（如游戏物理引擎）还是原生强。普通 App 体感不出差距。

Q：2026 了，Tauri 和 Flutter 怎么选？
Tauri 是桌面端 Rust + Web，Flutter 是移动端为主。如果你要做移动 App，选 Flutter；做桌面轻量应用，Tauri 更轻。两者定位不同。

小结

Flutter 的价值是「一套代码双端一致」，代价是包大、原生能力要桥接。小团队要快速出双端 App，它是最优解；要极致原生体验，还是得原生写。下一篇 App 上架，看怎么把做好的 App 发到应用商店。
