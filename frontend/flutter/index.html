Flutter 入门：从你遇到的问题出发

🏷️ Flutter 入门

你要做个 App，既要安卓又要 iOS，用原生开发要写两套代码，成本翻倍。或者你想做个跨平台应用，一套代码到处跑。

这篇不讲理论，就讲你真的会遇到的问题，以及 Flutter 怎么帮你解决。

场景一：要做安卓和 iOS 两个 App，写两套代码太麻烦

你遇到的问题

你做个电商 App，要支持安卓和 iPhone。用原生开发，安卓用 Kotlin 写一套，iOS 用 Swift 写一套，两个团队开发，成本翻倍，还要保持功能一致，改个按钮都要改两次，太麻烦了。

Flutter 怎么解决？你用 Dart 写一套代码，同时编译成安卓 App 和 iOS App，代码共用 90% 以上。改一次，两个平台都更新了，不用写两套。

// Flutter 写一个按钮，安卓和 iOS 都能跑
ElevatedButton(
  onPressed: () { print("点击了"); },
  child: Text("点我"),
)

场景二：App 页面滑动卡顿，掉帧

你遇到的问题

你用跨平台框架做的 App，列表滑动的时候一卡一卡的，动画不流畅，用户体验很差。

Flutter 怎么解决？Flutter 自己渲染 UI，不依赖原生控件，性能很接近原生，60fps/120fps 流畅滑动，不会卡顿。

场景三：除了手机，还要做网页和桌面端

你遇到的问题

你做了个手机 App，领导说还要做网页版、Windows 桌面版、Mac 桌面版。每个端都要单独开发，工作量太大了。

Flutter 怎么解决？同一份 Flutter 代码，还能编译成网页、Windows 桌面、Mac 桌面、Linux 桌面，一套代码跑所有平台。

对比原生开发Flutter
代码量安卓一套、iOS 一套，两套一套代码
性能最好接近原生
多端支持每个端单独开发手机、网页、桌面都支持
开发成本高低很多
新手最容易踩的坑
  • 状态管理要选对：小项目用 setState 就行，大项目用 Riverpod 或者 Bloc，不要上来就用复杂的状态管理。
  • 不要乱用大小：用 MediaQuery 获取屏幕尺寸，不要写死像素，适配不同手机屏幕。
  • 原生功能要写通道：Flutter 没有的原生功能（比如蓝牙、传感器），要写平台通道调用原生代码。
  • App 体积会大：Flutter 打包出来的 App 比原生稍大，这个是正常的。
