浏览器渲染原理：从输入 URL 到页面像素

🏷️ 浏览器原理

在地址栏输入一个网址，敲回车，到页面完整显示在屏幕上，中间发生了什么？这篇从 DNS 解析、TCP 连接、HTTP 请求、JS 执行、浏览器解析渲染，一步一步讲透整个过程。

flowchart TD A[输入 URL 敲回车] --> B[DNS 解析域名] B --> C[TCP/TLS 连接] C --> D[发送 HTTP 请求] D --> E[服务器返回 HTML] E --> F[浏览器解析 HTML] F --> G[构建 DOM 树] F --> H[解析 CSS 构建 CSSOM] F --> I[解析并执行 JS] G --> J[合成渲染树 Render Tree] H --> J I --> J J --> K[Layout 布局计算位置大小] K --> L[Paint 绘制像素] L --> M[Composite 合成图层] M --> N[屏幕显示页面]

第一步：DNS 解析，把域名变成 IP

你输入的是 www.yijunjun.asia，但网络通信要靠 IP 地址，所以第一步要把域名翻译成 IP，这就是 DNS 解析。

flowchart TD A[DNS 解析流程] --> B[浏览器缓存] B --> C[操作系统缓存] C --> D[本地 hosts 文件] D --> E[递归查询 DNS 服务器] E --> F[根域名服务器] F --> G[顶级域名服务器 .asia] G --> H[权威域名服务器] H --> I[拿到服务器 IP]

DNS 解析步骤

步骤查哪里说明
1浏览器缓存浏览器自己存 DNS 结果，有效期几分钟
2操作系统缓存操作系统也存
3hosts 文件本地配置的域名映射
4递归 DNS 服务器运营商/公共 DNS（8.8.8.8）
5根→顶级→权威逐级查询，最终拿到 IP

第二步：建立 TCP/TLS 连接

拿到 IP 后，要和服务器建立连接。HTTP 是明文，HTTPS 还要做 TLS 握手加密。

flowchart LR A[三次握手] --> B[SYN] B --> C[SYN+ACK] C --> D[ACK] D --> E[TLS 握手 HTTPS] E --> F[协商密钥] F --> G[加密传输]

为什么要三次握手？

确认双方都有收发能力：我发一个你能收到，你回一个我能收到，再确认一下，连接就建好了。

第三步：发送 HTTP 请求，服务器返回 HTML

连接建好了，浏览器发 HTTP 请求，带请求头（Cookie、User-Agent 等），服务器处理完，返回 HTML 文本。

第四步：JS 引擎执行 JS 代码

浏览器有个专门的 JS 引擎（Chrome 是 V8），负责解析执行 JS。JS 是单线程的，这是浏览器渲染里最关键的部分。

flowchart TD A[V8 引擎] --> B[解析 Parser] B --> C[AST 抽象语法树] C --> D[Ignition 解释器] D --> E[字节码] E --> F[TurboFan 优化编译器] F --> G[机器码]

JS 执行为什么是单线程？

JS 设计出来就是操作 DOM 的，如果多线程同时改同一个 DOM，浏览器就乱了，所以设计成单线程，同一时刻只能做一件事。

JS 执行会阻塞渲染

⚠️
为什么 JS 放底部？

解析 HTML 遇到 <script> 标签，会暂停 DOM 构建，先下载并执行 JS，因为 JS 可能直接改 DOM（比如 document.write）。所以 JS 放 body 最后，或者加 defer/async，不然会白屏。

属性下载执行时机阻塞 DOM
普通 script同步阻塞下载完立即执行是
async异步下载下载完立即执行不阻塞 DOM 解析，执行时阻塞
defer异步下载DOM 解析完执行不阻塞，按顺序执行

第五步：事件循环 Event Loop

JS 单线程，但要处理异步任务（定时器、网络请求、事件回调），靠的就是事件循环：执行完同步代码，再从队列里拿异步任务执行。

flowchart TD A[执行栈] --> B[同步代码执行] B --> C[执行栈空了] C --> D[清空微任务队列] D --> E[取一个宏任务执行] E --> F[清空所有微任务] F --> G[渲染更新] G --> E

宏任务 vs 微任务

类型常见任务执行时机
微任务Promise.then、queueMicrotask、MutationObserver同步代码后立即清空
宏任务setTimeout、setInterval、I/O、UI 事件、script每次循环取一个
💡
记住规则

同步代码 → 所有微任务 → 一个宏任务 → 渲染 → 下一个宏任务。微任务优先级比宏任务高很多。

第六步：解析 HTML，构建 DOM 树

浏览器从上到下解析 HTML，构建成 DOM 树（Document Object Model），每个标签是一个节点。JS 可以通过 API 操作这棵树。

flowchart TD A[HTML 源码] --> B[字符流] B --> C[令牌 Token] C --> D[节点 Node] D --> E[DOM 树] E --> F[html] F --> G[head] F --> H[body] H --> I[div p span]

第七步：解析 CSS，构建 CSSOM 树

浏览器解析 CSS，计算出每个节点的样式，构建成 CSSOM（CSS Object Model）树。

flowchart TD A[CSS 源码] --> B[解析选择器] B --> C[计算样式规则] C --> D[层叠优先级] D --> E[继承计算] E --> F[CSSOM 树]

CSS 选择器优先级

优先级选择器例子
1!important最高
2内联样式style="color:red"
3ID 选择器#app
4类/伪类/属性.btn
5标签选择器div p

第八步：合成渲染树 Render Tree

DOM 树和 CSSOM 树都建好了，把它们合并成渲染树：只包含可见节点（display:none 的不进渲染树），每个节点有计算好的样式。

flowchart LR A[DOM 树] --> C[Render Tree] B[CSSOM 树] --> C C --> D[可见节点 + 样式] style C fill:#4ade80,color:#fff
💡
注意

display: none 的元素不进渲染树，visibility: hidden 的元素进渲染树但不可见，占位置。

第九步：Layout 布局（回流）

渲染树有了，但每个节点的位置和大小还不知道，这一步就是布局：算出每个节点在屏幕上的确切坐标和尺寸。JS 改样式、改 DOM 结构，都会触发重新布局。

flowchart TD A[Layout 布局] --> B[从根节点开始遍历] B --> C[计算每个节点的大小] C --> D[计算每个节点的位置] D --> E[生成布局树]

JS 操作 DOM 什么时候触发回流？

  • JS 增删 DOM 节点
  • JS 改元素位置、大小、宽高、字体大小
  • JS 读取 offsetWidth、offsetTop、getComputedStyle
  • 窗口大小变了

第十步：Paint 绘制（重绘）

布局好了，知道每个节点在哪、多大，接下来就是把像素画出来：颜色、边框、文字、图片，画到内存的位图里。改颜色这种不影响布局的，只触发重绘。

第十一步：Composite 合成图层

页面不是一张整图，是分层的：滚动条、固定定位、z-index 高的元素，各自在独立的图层。合成阶段把这些图层按正确顺序拼成一张最终的图，交给 GPU 显示到屏幕。

flowchart TD A[多个图层] --> B[图层1 背景] A --> C[图层2 内容] A --> D[图层3 弹窗] B --> E[Composite 合成] C --> E D --> E E --> F[GPU 绘制到屏幕] style F fill:#f59e0b,color:#fff

哪些属性只触发合成，不触发回流重绘？

属性触发阶段性能
transform只合成最好，GPU 加速
opacity只合成最好
visibility/color重绘中等
width/height/left/top回流+重绘+合成最差

JS 和渲染的关键时机：requestAnimationFrame

JS 改样式，不是立即渲染，浏览器会等这一帧的 JS 都执行完，再统一更新。requestAnimationFrame 就是在渲染前执行回调，保证动画流畅。

flowchart LR A[JS 执行] --> B[微任务清空] B --> C[requestAnimationFrame 回调] C --> D[Layout] D --> E[Paint] E --> F[Composite]

实际例子：一个简单页面的渲染全过程

我们拿一个最简单的页面举例，看每一步发生了什么：

<!DOCTYPE html>
<html>
  <head>
    <style>
      .box { width: 100px; height: 100px; background: red; }
    </style>
  </head>
  <body>
    <div class="box">Hello</div>
    <script src="app.js"></script>
  </body>
</html>

新手最容易踩的坑

❌
避坑指南
  • JS 放 body 最后，或者加 defer，不要阻塞 DOM 解析白屏
  • 微任务优先级比宏任务高，Promise.then 比 setTimeout 先执行
  • 动画用 transform/opacity，不要改 left/top，避免频繁回流
  • 批量改 DOM，不要循环里一个一个改，不然每次都回流
  • 读 offsetWidth 后要改样式，先读再改，不要读写交替，不然强制同步布局
  • 动画用 requestAnimationFrame，不要用 setTimeout，保证和屏幕刷新同步
