位置作用约定放错的后果
pages 目录每个文件对应一个路由文件名决定路径，方括号表示动态参数组件误放进来会生成一个多余的空页面
layouts 目录页面公共外壳，通过插槽接收内容只是约定，本质就是组件无强制约束，但混放会让结构难找
content 目录内容集合与模式声明集合名对应子目录，需要一份模式配置目录名与配置里的集合名不一致时查询结果为空
public 目录原样拷贝的静态资源引用时用根路径，不经过构建处理放图片进这里会失去尺寸优化与哈希文件名
src 内的资源目录需要构建处理的图片等资源通过导入引用，产物带哈希用根路径引用会 404，因为文件名被改写了
配置文件输出模式、适配器、集成位于项目根改动后需要重启开发服务器才生效

组件结构：两条横线划出的边界

.astro 组件由两部分组成：顶部两条横线之间的 frontmatter，以及下面的模板。frontmatter 只在服务端执行——构建期或请求期跑一次，然后被丢弃，它的代码不会出现在客户端产物里。这是整个模型最需要先建立的直觉。

需求写在哪理由
取数据、读文件、访问数据库frontmatter服务端执行，凭据不会泄露到客户端
读取请求头或 Cookiefrontmatter，且页面须按请求渲染预渲染时没有请求上下文
操作 DOM、监听滚动模板里的脚本标签frontmatter 没有浏览器环境
有状态的交互界面框架组件加客户端指令需要组件运行时来维护状态
读取环境变量里的密钥frontmatter只有服务端代码能安全读取，前缀暴露的变量会进产物
条件渲染与循环模板模板语法直接支持表达式

内容集合：给 Markdown 的元数据加上类型

内容集合是 Astro 最实用的能力之一。它做的事是：把某个目录下的 Markdown 声明成一个集合，给这个集合定义一份字段模式，构建时逐个文件校验元数据，校验不过就让构建失败。这把「某篇文章忘写日期导致列表页排序错乱」这类问题从线上提前到了构建阶段。

// src/content.config.ts —— 集合定义与模式校验
import { defineCollection, reference, z } from 'astro:content'
import { glob } from 'astro/loaders'

const posts = defineCollection({
  // 加载器决定从哪里读：本地文件、也可以换成远程 CMS
  loader: glob({ pattern: '**/*.md', base: './src/content/posts' }),
  schema: z.object({
    title: z.string().min(1).max(80),
    // 日期用日期类型而不是字符串，这样排序不会因为格式不统一而出错
    pubDate: z.coerce.date(),
    updatedDate: z.coerce.date().optional(),
    // 默认值让存量文件不必全部补字段，迁移时非常有用
    draft: z.boolean().default(false),
    tags: z.array(z.string()).default([]),
    // 枚举把「拼错分类名」变成构建期错误
    category: z.enum(['frontend', 'backend', 'ops']),
    // 引用另一个集合，作者不存在时构建失败
    author: reference('authors'),
    cover: z.string().url().optional(),
  }),
})

const authors = defineCollection({
  loader: glob({ pattern: '**/*.json', base: './src/content/authors' }),
  schema: z.object({ name: z.string(), avatar: z.string().optional() }),
})

export const collections = { posts, authors }

做法元数据校验类型提示查询与排序适合
内容集合构建期强校验，失败即中断完整推导内置过滤与排序文章、文档、产品页等结构化内容
直接读取并解析文件无，全靠自己写检查需要手写类型且容易与实际脱节自己实现一次性脚本或极简场景
远程 CMS 在页面里取数取决于接口，通常无需要生成或手写类型依赖接口能力内容由非技术人员维护
CMS 配合内容集合加载器可在加载后统一校验完整推导内置既要 CMS 又要类型安全

路由与动态参数

---
// src/pages/posts/[...slug].astro
import { getCollection, render } from 'astro:content'
import Base from '../../layouts/Base.astro'

// 预渲染动态路由必须提供参数列表，否则构建期不知道要生成哪些页面
export async function getStaticPaths() {
  const posts = await getCollection('posts', ({ data }) => !data.draft)
  return posts
    // 日期是真正的日期类型，所以可以直接相减排序
    .sort((a, b) => b.data.pubDate.valueOf() - a.data.pubDate.valueOf())
    .map((post) => ({
      // 这里的键名必须与文件名里的占位符一致，否则页面会被生成成空白
      params: { slug: post.id },
      props: { post },
    }))
}

const { post } = Astro.props
const { Content, headings } = await render(post)
---

<Base title={post.data.title} description={post.data.title}>
  <nav aria-label="目录">
    {headings.map((h) => <a href={`#${h.slug}`}>{h.text}</a>)}
  </nav>
  <article><Content /></article>
</Base>
路由写法匹配预渲染时按请求渲染时易错点
普通文件名固定路径直接生成每次请求渲染文件名大小写在部分平台敏感
方括号单参数一段路径需要参数列表从请求参数取参数名与返回的键名不一致时静默生成空页
方括号加三点零到多段路径需要参数列表，可包含斜杠从请求参数取用它匹配根路径时要显式返回空值项
接口路由返回非 HTML 响应可生成静态文件可读请求忘记设置内容类型头
索引文件目录根路径直接生成同上与同名上级文件冲突时行为不直观

按页面选择渲染时机

输出模式是项目级默认值，但每个页面都可以单独覆盖：导出一个预渲染开关即可。这让「整站静态 + 少数动态页」和「整站动态 + 多数静态页」两种组织方式都能实现。

// 项目默认是静态时，这一行把当前页面切成按请求渲染；需要已配置适配器
export const prerender = false

// 现在可以安全地读取请求级信息
const token = Astro.cookies.get('session')?.value
if (!token) return Astro.redirect('/login')

常见报错与成因对照

上手阶段的报错高度集中在三类边界上：服务端与客户端的边界、预渲染与按请求渲染的边界、以及集合名与路由参数这类字符串一致性。下面这张表按报错现象反查原因，比逐条读文档快得多。

现象真实原因怎么确认修法
提示某个对象未定义，构建直接失败在 frontmatter 里访问了浏览器专属对象看报错栈指向的是页面文件顶部把这段逻辑移到脚本标签或带客户端指令的组件里
提示动态路由缺少参数列表页面处于预渲染模式但没有导出参数生成函数检查页面是否导出了预渲染开关补上参数生成函数，或关闭该页预渲染
页面生成了但内容空白，无任何报错路由参数名与返回的键名不一致比对文件名占位符与返回对象的键统一命名
集合查询返回空数组目录名与配置里的集合名不一致，或加载器匹配模式写错打印查询结果长度，检查匹配模式对齐集合名与文件匹配范围
构建时报某篇内容字段校验失败模式与实际元数据不符，这是设计如此的行为报错会指出文件路径与字段名补字段或给模式加可选与默认值
关闭预渲染后构建提示缺少运行时目标没有配置适配器检查配置文件里的适配器项按部署平台配置适配器
岛屿在浏览器里报属性为空传入的 props 含不可序列化的值，被丢弃了在页面源码里查看岛屿占位上的序列化数据只传纯数据，复杂对象改成传标识符
资源在开发时正常，构建后 404用根路径引用了参与构建的资源，产物名带哈希对比产物目录里的实际文件名改成导入引用，或把资源移进原样拷贝目录

props、插槽与布局

能力写法要点常见误用
propsfrontmatter 里从组件属性对象解构，可配合类型声明给岛屿传函数或类实例，序列化失败
默认插槽子内容通过插槽元素落位忘记写插槽，子内容被静默丢弃
具名插槽父组件用属性指定名字，子组件按名接收名字拼错时内容消失且无警告
插槽默认内容插槽元素内部写兜底内容误以为传了空字符串会显示兜底
布局组件本质就是带插槽的组件，负责文档骨架在布局里放需要交互的东西导致全页变岛屿
作用域样式组件内样式默认只作用于本组件元素期望它影响插槽传入的内容或子组件

  :global(.prose a) { text-decoration: underline; }
</style>
⚠️
作用域样式的边界

作用域化是靠给本组件模板里的元素加唯一标记实现的，因此通过插槽传进来的元素不属于本组件作用域。这就是「样式明明写了却对子内容无效」的最常见原因。处理办法是用全局标记限定在一个明确的容器类下，而不是整段样式都改成全局。

❌
最容易踩的坑
  • 在 frontmatter 里访问浏览器对象：那段代码在服务端执行，访问窗口或文档一定报错，需要浏览器 API 的逻辑要放到脚本标签或岛屿里。
  • 动态路由的参数名不一致：文件名占位符与返回的参数键名不同，页面会生成成空白而不报错，先比对这两处命名。
  • 预渲染页面里读 Cookie：构建期没有请求上下文，读取结果恒为空，必须先关闭该页面的预渲染。
  • 为了一小块动态内容关掉整页预渲染：整页失去 CDN 缓存能力，应该只把那一块做成延迟渲染或客户端取数。
  • 集合目录名与配置里的集合名不一致：查询返回空数组，页面渲染出空列表且没有任何提示。
  • 日期字段用字符串：排序按字典序进行，格式稍有不同就乱序，应该在模式里声明为日期类型。
  • 给岛屿传不可序列化的 props：函数与类实例跨不过服务端到客户端的边界，需要传纯数据或只传标识符。
  • 把密钥通过 props 传给岛屿：props 会明文出现在页面源码里，等于公开泄露，敏感操作必须留在服务端。
  • 把图片放进原样拷贝的目录：失去尺寸优化与哈希文件名，既慢又不利于长期缓存。
  • 用根路径引用参与构建的资源：产物文件名带哈希，硬编码路径会 404，必须通过导入引用。
  • 期待作用域样式影响插槽内容：插槽内容属于父组件作用域，需要显式的全局限定。
  • 在布局里放交互组件：布局被所有页面使用，一个客户端指令会让全站都带上运行时。
  • 改了配置不重启开发服务器：输出模式、适配器、集成的改动需要重启才生效，否则表现与预期不符。
