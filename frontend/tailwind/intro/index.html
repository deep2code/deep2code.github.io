Tailwind 上手：配置、按需生成与编辑器支持

🏷️ Tailwind CSS

Tailwind 的上手难点不在工具类语法，而在「明明写了类却没有样式」这类问题——它们几乎全部来自对按需生成机制的误解，以及配置里扫描范围没写对。这篇按真实接入顺序讲：怎么装、v3 与 v4 的配置怎么对应、生成器到底看到了什么、样式丢失怎么排查、编辑器要装什么。

为什么选择原子类、以及它和 CSS Modules 之类方案的取舍，见《Tailwind 的设计取舍》；构建工具本身的代际差异见站内《前端工程化》。

三种接入方式怎么选

接入方式适用场景开发期速度需要额外配置常见问题
框架插件（Vite 等）绝大多数现代项目，首选最快，直接走构建管线一条插件注册插件版本与框架版本不匹配时静默不生成
PostCSS 插件已有 PostCSS 链路的项目，或非 Vite 构建快，受其他 PostCSS 插件顺序影响PostCSS 配置文件插件顺序放错会导致嵌套或变量处理异常
独立 CLI纯静态站点、服务端模板项目、无前端构建中，需要单独起一个 watch 进程输入输出路径与 watch 参数忘记开 watch，或部署脚本漏掉构建这一步
CDN 运行时脚本只用于快速试验无构建，但运行时扫描 DOM无有运行时开销且无法定制令牌，不要用于生产
// vite.config.ts —— v4 的接入只有一行插件，不再需要 PostCSS 配置
import { defineConfig } from 'vite'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [tailwindcss()],
  build: {
    // CSS 产物单独拆出来便于核查体积，也便于长期缓存
    cssCodeSplit: true,
  },
})

v3 与 v4 的配置对应关系

配置项v3 写在哪v4 写在哪迁移时的坑
引入框架CSS 里三条 tailwind 指令CSS 里一条 import 引入自定义样式的插入位置改由 CSS 层级控制，顺序假设会变
颜色令牌JS 配置 theme.extend.colors@theme 里的 color 前缀自定义属性嵌套对象要拍平成扁平命名，深层结构不再支持
间距令牌theme.extend.spacing@theme 里的 spacing 前缀属性数字键要改成合法的自定义属性名
字号与行高fontSize 用数组表达成对值text 前缀属性配合 line-height 后缀漏写行高后缀会退回默认行高，视觉差异很小容易忽略
扫描范围content 数组，必填默认自动发现，@source 追加依赖包里的模板不会被自动发现，必须显式追加
暗色模式darkMode 配置项自定义 variant 声明用属性选择器做主题切换的项目需要重新声明变体
插件plugins 数组CSS 里 plugin 指令引入未适配 v4 的插件会直接报错或静默失效
/* v4：src/styles/app.css 就是全部配置 */
@import "tailwindcss";

/* 项目自己的模板都会被自动发现；依赖包里的组件必须显式声明 */
@source "../../node_modules/@acme/ui/dist/**/*.{js,ts,jsx,tsx}";

@theme {
  --color-brand-500: oklch(0.62 0.17 250);
  --color-brand-600: oklch(0.55 0.16 250);
  --spacing-gutter: 1.25rem;
  --text-body: 0.9375rem;
  --text-body--line-height: 1.7;   /* 成对定义，避免各处单独写行高 */
  --radius-card: 0.625rem;
}

/* 用 data 属性切主题：类名不变，只换变量的值 */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

@layer base {
  html { font-size: 16px; }
  body { font-size: var(--text-body); line-height: var(--text-body--line-height); }
}

按需生成的真实机制

这是必须准确理解的一点：生成器不执行你的代码，它只是把源文件当纯文本扫一遍，把看起来像类名的片段收集成候选集，再对候选集里能匹配上工具类规则的部分生成 CSS。它不知道 JavaScript 的语义，不做类型推导，也不会跟踪变量。

图里右下角那条虚线就是新手第一大坑的全部成因：碎片进不了候选集，于是没有规则，于是线上少样式，而整个过程没有任何错误提示。

动态类名的四种处理方式

// 坏例子：这三种写法生成器都看不到完整类名
const bad1 = `text-${color}-500`            // 碎片：text- 和 -500
const bad2 = 'bg-' + tone + '-100'          // 同上
const bad3 = `p-${size}`                    // 同上

// 正确做法一：完整类名映射表（首选，类型安全且可被扫描）
const TONE: Record<'info' | 'warn' | 'danger', string> = {
  info:   'bg-sky-50 text-sky-700 ring-sky-200',
  warn:   'bg-amber-50 text-amber-700 ring-amber-200',
  danger: 'bg-rose-50 text-rose-700 ring-rose-200',
}
// 每个完整类名都以字面量形式出现在源码里，扫描器能看到
export function Badge({ tone = 'info' }: { tone?: keyof typeof TONE }) {
  return `inline-flex items-center rounded-full px-2 py-0.5 ring-1 ${TONE[tone]}`
}

// 正确做法二：值来自运行时数据（无法穷举）时走 CSS 变量，不要拼类名
// <div class="w-[var(--bar-w)] bg-brand-500" style={{ '--bar-w': `${pct}%` }} />

// 正确做法三：类名来自后端或 CMS，必须穷举不了时用 safelist（最后手段）
// v4 在 CSS 里声明：@source inline("bg-red-500 bg-green-500 bg-blue-500");
做法适用情形产物影响代价
完整类名映射表取值可穷举（状态、尺寸、语义色）只生成用到的组合，最优新增取值要改映射表
CSS 变量 + 任意值连续数值：进度、位置、动态宽高一条规则即可，最优需要写行内 style 传变量
safelist / inline 声明类名由外部数据决定，无法穷举无论用不用都生成，体积上升易被滥用，写通配会生成整组色板
把类名字面量写进注释不推荐，但确实能被扫描到同 safelist注释与代码脱节后无人敢删，成为死配置

# 第一步：确认产物里到底有没有这条规则（最快定位）
npx tailwindcss -i src/styles/app.css -o /tmp/out.css --minify
grep -c 'bg-brand-500' /tmp/out.css     # 输出 0 说明根本没生成

# 第二步：确认源码里有没有完整字面量（注意用固定字符串匹配）
grep -rn --fixed-strings 'bg-brand-500' src/ | head

# 第三步：确认文件是否在扫描范围内。把可疑文件临时改名后重新构建，
# 若产物规则数量没有任何变化，说明这个文件从来没被扫到
grep -o '^\.[^ {,]*' /tmp/out.css | sort -u | wc -l

# 第四步：排除缓存干扰。构建缓存复用是本地正常线上异常的常见原因
rm -rf node_modules/.vite node_modules/.cache && npm run build
症状最可能的原因确认方式修法
某个目录下所有页面完全没样式扫描范围漏了这个目录产物里搜该目录独有的类名，结果为空补扫描声明，检查路径通配是否覆盖子目录
只有某些颜色或尺寸失效动态拼接类名源码固定字符串搜完整类名，搜不到改映射表
本地正常，构建产物异常缓存复用或环境变量差异清缓存后重建对比CI 上禁用跨版本缓存复用
类有规则但被覆盖同属性冲突类叠加，源码顺序决定胜负浏览器里看计算样式与生效规则用类名合并工具做冲突消解
自定义令牌不生效令牌类别前缀写错，生成器静默忽略产物里搜该 CSS 变量名，结果为空按类别前缀规范重写令牌名
构建突然变慢数倍扫描范围包含依赖目录或大体积产物目录统计扫描文件数，或临时缩小范围对比耗时显式排除依赖与构建输出目录

编辑器与协作工具

工具解决什么不装的后果
官方编辑器插件类名补全、悬浮显示对应 CSS、令牌颜色预览写错类名零提示，只能靠页面表现发现
类名排序插件（配合格式化工具）把类串顺序规范化，与产物顺序一致顺序人各不同，diff 不可读、合并冲突高发
类名合并工具条件覆盖时消解同属性冲突条件样式行为看似随机，排查耗时
变体管理工具把组件的尺寸与语义变体集中声明类串在多处复制，改一处漏三处
lint 规则集禁止任意值、禁止冲突类、要求简写约定只存在于文档里，没有执行力
{
  "plugins": ["prettier-plugin-tailwindcss"],
  "tailwindStylesheet": "./src/styles/app.css",
  "tailwindFunctions": ["clsx", "cn", "cva"]
}

最后一项容易漏：如果类名写在 clsx 或自定义的 cn 函数参数里，不声明这些函数名，排序插件就不会处理它们，于是「有的地方排了序有的地方没排」，比完全不排更难看。

开发期的生成时序：为什么有时必须重启

理解这条时序能省掉大量「玄学不生效」的时间。开发模式下类名是增量生成的：你保存文件，插件拿到变更文件列表，只对这些文件重新扫描，把新出现的候选类追加进产物，然后通过热更新把 CSS 推给浏览器。关键在于已经生成过的规则不会因为你删掉那行代码而立即消失，这就是为什么删掉动态拼接的代码后页面样式看起来还在，而生产构建一跑就少一半。

sequenceDiagram participant Dev as 开发者 participant Watcher as 文件监听 participant Scan as 扫描与生成 participant Cache as 增量缓存 participant Browser as 浏览器 Dev->>Watcher: 保存组件文件 Watcher->>Scan: 只传变更文件列表 Scan->>Cache: 查已有候选集 Cache-->>Scan: 返回历史候选 含已删除的类 Scan->>Browser: 推送合并后的 CSS Note over Cache,Browser: 历史类名仍在产物里
删代码后页面依旧正常 Dev->>Scan: 修改配置文件里的令牌 Scan->>Cache: 配置变更需整体失效 Cache-->>Scan: 若配置文件不在监听范围则不失效 Note over Dev,Scan: 此时必须重启开发服务器
否则新令牌永远不生效 Dev->>Scan: 执行生产构建 Scan->>Scan: 从零全量扫描 Note over Scan: 只有这一步的产物
才是线上真实样式

由此得到两条可操作的规矩：验证样式是否真实存在，必须跑一次生产构建；改动配置文件后先重启服务器再怀疑其他原因。前者能提前发现动态拼接与扫描遗漏，后者能省掉一轮无效排查。

与预处理器的关系

Sass 能力在 Tailwind 项目里的替代是否还需要 Sass
变量@theme 令牌自动生成 CSS 变量，且支持运行时换值不需要，CSS 变量能力更强
嵌套原生 CSS 已支持嵌套，框架也内置处理不需要
mixin工具类组合，或组件层封装不需要
文件拆分与导入构建工具处理 import不需要
循环生成大量规则工具类本身就是生成出来的不需要，用循环生成类名反而破坏可扫描性
复杂数学计算CSS 的 calc 与相对颜色语法极少数场景可能还想用
⚠️
共存时的注意点

存量项目里 Sass 与 Tailwind 可以共存，但要明确边界：Sass 只处理老代码，新代码一律用工具类。危险点在于用 Sass 的插值生成类名——那些类名同样不会被扫描到，会复现「动态拼接」那一类问题。

❌
最容易踩的坑
  • 用模板字符串拼类名：生成器只做文本扫描，拼接后的类名从未以完整形式出现，规则不会生成且构建不报错。
  • 扫描路径通配写错层级：只写了一层通配导致子目录被漏掉，症状是某些页面整片没样式，本地因缓存往往看不出来。
  • 把依赖目录纳入扫描：扫描耗时暴涨、产物混入无用规则，开发期热更新也会明显变慢。
  • 用 CDN 脚本上生产：运行时扫描 DOM 带来额外开销，无法定制令牌，也拿不到按需生成的体积收益。
  • safelist 写通配：一条宽松规则可能把整组颜色的所有阶梯与变体都生成出来，产物体积翻倍。
  • v4 令牌名类别前缀写错：生成器不认识该类别就静默忽略，产物里既没有变量也没有工具类，排查时先去产物里搜变量名。
  • 迁移时漏掉字号的行高后缀：字号生效但行高回落到默认值，视觉差异细微，容易在多个页面上留下不一致。
  • 不声明自定义类名函数：排序插件不处理 clsx 或 cn 里的类名，导致项目里一半排序一半没排。
  • 只在开发模式验证：开发模式常常按需增量生成并保留历史结果，必须跑一次生产构建再看产物。
  • CI 复用旧构建缓存：升级依赖或改配置后仍命中旧缓存，出现本地正常线上异常的经典现象。
  • 用 Sass 插值生成类名：与拼接类名同类问题，且更隐蔽，因为生成发生在样式层而不是模板层。
  • 改了配置不重启开发服务器：部分配置改动不在监听范围内，先重启再清缓存再查产物，按这个顺序省时间。
