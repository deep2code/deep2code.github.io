前端知识体系

🏷️ 前端与客户端

前端三大支柱，一句话讲清

带新人时我总让他先记住一句话：HTML 管结构，CSS 管长相，JavaScript 管行为。就这么简单。但「现代前端」早就不是切页面了，框架、构建、状态管理、性能、可访问性，每一样都是坑。这篇是我这几年踩坑踩出来的地图。

我的入门建议：别上来就学框架。先把 HTML/CSS/JS 这老三样底层吃透——事件循环、原型链、盒模型。框架三个月就换代，底层原理十年不变。

HTML：不止是标签堆砌

浏览器渲染流水线：性能优化的根

理解浏览器怎么把 HTML 变成像素，你才知道性能优化该往哪使力。我给新人讲这条流水线讲过无数次：

  1. 网络加载：HTML 流式解析，边下载边构建 DOM；
  2. DOM + CSSOM：解析成两棵树，合并成渲染树；
  3. 布局 Layout：算每个元素的位置大小；
  4. 绘制 Paint：填色、画字、光栅化；
  5. 合成 Composite：GPU 把图层拼成最终画面。
动画为什么只用 transform/opacity

因为改这两个属性只触发「合成」这一步，不重新布局也不重新绘制。改 top/width 要从布局重跑一遍，60fps 动画直接变 30。这是渲染流水线给你的最实用结论。

HTML 新特性：2024-2026

  • <dialog>：原生模态框，自动焦点管理、ESC 关闭，不用再引第三方弹窗库；
  • Popover API：原生 tooltip/下拉，零 JS；
  • View Transitions：原生页面过渡动画，document.startViewTransition()；
  • 原生懒加载：<img loading="lazy">，不用 IntersectionObserver 了。

CSS：盒模型和现代特性

盒模型：被问烂的问题

所有项目我第一行 CSS 就是 * { box-sizing: border-box; }。标准盒模型 width 只是内容，padding 还要额外加，新手算尺寸算到崩溃。border-box 才是正常人脑的模型。

布局方式维度适合
Flexbox一维导航栏、居中、卡片行
Grid二维页面整体布局、图片墙
定位层叠上下文弹层、固定头

z-index 不生效是新手最常见的困惑。答案不是「z-index 不够大」，是你不在同一个层叠上下文里。搞懂 opacity<1、transform、filter 都会创建层叠上下文，比背 z-index 数值有用。

CSS 现代特性

  • 容器查询：@container，组件根据自己容器大小响应式，不再只看视口；
  • :has() 父选择器：CSS 终于能「向上选」了，div:has(> img)；
  • CSS 原生嵌套：不用 Sass 了，.parent { .child {} }；
  • OKLCH 颜色：感知均匀的颜色空间，比 HSL 靠谱。

JavaScript：事件循环是灵魂

事件循环：面试必考，生产必用

JS 单线程靠事件循环实现异步。规则就一句：同步代码跑完 → 清空所有微任务 → 执行一个宏任务 → 再清空微任务。微任务（Promise.then、await）永远比宏任务（setTimeout）先执行。

经典面试题答案

console.log(1); setTimeout(()=>console.log(2),0); Promise.resolve().then(()=>console.log(3)); console.log(4); 输出 1,4,3,2。同步先打 1、4；微任务打 3；最后宏任务打 2。

为什么生产要用这个知识？因为「界面卡」往往是长任务堵住了主线程。把 >50ms 的计算拆成块、放 Web Worker，就是这个原理。一个可运行的例子：

// 证明微任务插队：先打 1、4，再打 3，最后才打 2
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// 输出顺序：1 → 4 → 3 → 2

// 生产用法：长计算拆成 chunk，让出主线程不卡 UI
function processInChunks(items, chunkSize = 50) {
  let i = 0;
  function next() {
    const slice = items.slice(i, i + chunkSize);
    slice.forEach(item => heavyWork(item));
    i += chunkSize;
    if (i < items.length) setTimeout(next, 0); // 宏任务让出主线程
  }
  next();
}

2024-2026：框架和渲染模式

前端这两年最大的变化是渲染模式的选择变多了。别再无脑 SPA：

模式HTML 生成时机适合
SPA客户端运行时纯后台管理
SSR服务端请求时要 SEO 交互又多
SSG构建时博客文档
ISR构建时 + 后台再生成内容型最优解
Astro 群岛零 JS + 局部水合内容站
我的选型

内容站、文档、博客用 SSG/SSG（这个站就是）；电商、营销页用 SSR/ISR；纯后台管理系统 SPA 没问题。别用 SPA 做内容站——首屏白屏 + SEO 差，用户等不及就走了。

状态管理：分清楚服务端和客户端状态

这是我踩过最大的认知坑。大多数应用 80% 的状态是服务端数据（用户列表、商品信息），不该塞全局 store。用 TanStack Query 管服务端状态（自带缓存、去重、后台刷新），剩下 20% 的 UI 状态（弹窗开关、当前 tab）用 Zustand 就够了。Redux 这套，新项目我基本不用了。

Core Web Vitals：Google 的三个硬指标

指标含义良好值
LCP最大内容绘制<2.5s
INP交互到下一次绘制<200ms
CLS累积布局偏移<0.1

INP 是 2024 年 3 月替掉 FID 的。CLS 那个「页面元素突然跳动」的烦人体验，给图片加上 width/height 就治好了。

我踩过的大坑（精简版）

  1. 内存泄漏：组件卸载没 removeEventListener、没 clearInterval。React 用 useEffect 的清理函数，一次性管掉；
  2. CSS 优先级战争：别用 !important，扁平化类名，用 @layer 分层；
  3. 未处理的 Promise rejection：所有 await 包 try/catch，别空 catch 吞错误；
  4. XSS：别用 innerHTML 插不可信数据，富文本用 DOMPurify，开 CSP；
  5. 移动端 100vh：用 100dvh，别用 100vh——地址栏显示时会跳；
  6. 产物体积：路由级代码分割，第三方库走 Tree-shaking（用 lodash-es 不是 lodash）；
  7. 可访问性：语义化 HTML 优先，图片写 alt，别只靠颜色传达信息；
  8. Safari 兼容性：iOS 上所有浏览器都是 WebKit，新特性先测 Safari。

FAQ

Q：2026 了，前端框架选哪个？
React 生态最大、岗位最多；Vue 中文社区友好、上手快；Svelte/Astro 适合内容站。别纠结「最好的」，选团队最熟的。框架三个月一换代，底层原理不变。

Q：AI 会取代前端吗？
初级切页面的活确实被 AI 大量接管了。但「定义问题、审查 AI 生成的代码、做架构和性能调优」这些更值钱。我的做法：让 AI 出初稿，我来审和优化。

Q：要不要学 TypeScript？
必须。新项目没 TS 我都不敢接。它不是语法糖，是大型项目可维护性的保障。JSDoc 注释能渐进迁移。

Q：前端性能优化从哪下手？
先量。Chrome Performance 面板看时间花在哪——网络、JS 执行、还是渲染。别上来就「代码分割」，先找到真瓶颈。

小结

前端这摊水很深，但骨架就那三样：HTML、CSS、JS。框架换得再勤，事件循环、渲染流水线、盒模型这些底层是不变的。把地基打牢，上层的 React/Vue 随便换。下一篇 Mermaid，看怎么用文字画图。
