Firefox 入门：从你遇到的问题出发

🏷️ Firefox 入门

你是前端开发，要做浏览器扩展，或者调试网页兼容性，想知道除了 Chrome 之外的浏览器怎么开发。

这篇不讲理论，就讲你真的会遇到的问题，以及 Firefox 开发相关的知识。

场景一：你要做个浏览器扩展，Chrome 做了还要兼容 Firefox

你遇到的问题

你做了个广告拦截的 Chrome 扩展，用户说想要 Firefox 版本。你以为要重新写一遍，其实大部分代码都能共用。

怎么解决？Firefox 扩展基本兼容 Chrome 扩展的 API，改几个配置就能打包成 Firefox 扩展，不用重新写。

// manifest.json，加个 browser_specific_settings 就能兼容 Firefox
{
  "manifest_version": 3,
  "name": "我的扩展",
  "version": "1.0",
  "browser_specific_settings": {
    "gecko": {
      "id": "myext@example.com"
    }
  }
}

场景二：网页在 Chrome 上正常，在 Firefox 上样式乱了

你遇到的问题

你做的网页在 Chrome 上好好的，用 Firefox 打开，样式全乱了，按钮位置不对，颜色不对。你不知道哪里出问题了。

怎么解决？Firefox 自带的开发者工具和 Chrome 差不多，按 F12 打开，找到对应的元素，看是哪个 CSS 属性不兼容，加个 -moz- 前缀或者换个写法就行。

对比ChromeFirefox
内核BlinkGecko
扩展兼容性基本兼容大部分兼容
开发者工具很强大也很强大，有些功能更贴心
隐私保护一般更好，默认屏蔽更多追踪

场景三：要做自动化测试，要支持 Firefox 浏览器

你遇到的问题

你用 Playwright 或者 Selenium 做自动化测试，现在只测了 Chrome，还要测 Firefox 上是不是正常。

怎么解决？Playwright 和 Selenium 都支持 Firefox，改一行配置就行，不用重新写测试代码。

新手最容易踩的坑
  • CSS 属性要测兼容性：有些新的 CSS 属性 Firefox 支持的和 Chrome 不一样，上线前一定要用 Firefox 打开看一下。
  • 扩展 API 有差异：大部分 API 兼容，少数特殊 API 要单独适配，不要直接拿来就打包。
  • 不要忽略 Firefox 用户：虽然 Chrome 占比高，但还有 10% 左右的用户用 Firefox，不能让他们打开网站全乱。
  • 调试用 Firefox Developer Edition：Mozilla 出的开发者版 Firefox，自带更多开发工具，调试更方便。
