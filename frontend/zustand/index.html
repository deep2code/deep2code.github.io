Zustand 入门：从你遇到的问题出发

🏷️ Zustand 入门

你用 React 做应用，组件之间要传数据，一层层 props 传下去，太麻烦了。或者用 Redux，配置一大堆，写个简单功能要写好多代码。

这篇不讲理论，就讲你真的会遇到的问题，以及 Zustand 怎么帮你解决。

场景一：组件之间传数据，一层一层传 props 太麻烦

你遇到的问题

你有个用户登录状态，存在最顶层的 App 组件里，要传给导航栏、传给页面、传给按钮组件，一层一层传 props。中间根本不需要这个数据的组件也要接收再往下传，改个数据结构，所有中间组件都要改，麻烦死了。

Zustand 怎么解决？你把全局存在一个 store 里，哪个组件需要用，直接从 store 里拿，不用一层层传 props。

// store/useUserStore.js，创建一个全局store
import { create } from 'zustand'

const useUserStore = create((set) => ({
  user: null,
  login: (user) => set({ user }),
  logout: () => set({ user: null }),
}))

// 任何组件里直接用，不用传props
function Navbar() {
  const user = useUserStore(state => state.user)
  return <div>当前用户：{user?.name}</div>
}

现在不用一层层传 props 了，哪个组件需要用户数据，直接从 store 里拿就行。

场景二：用 Redux 写个简单功能，配置一大堆太麻烦

你遇到的问题

你用 Redux 存个用户状态，要写 action、reducer、dispatch、配置 store，写了一堆文件，就为了存个用户名，开发效率太低了。

Zustand 怎么解决？就像刚才那样，几行代码就写完了，不用写 action、reducer，简单直接。

场景三：两个组件用同一个数据，改了一个另一个不更新

你遇到的问题

导航栏显示用户名，个人中心也显示用户名。你在个人中心改了用户名，导航栏的用户名没变，因为两个组件各自存了一份，不同步。

Zustand 怎么解决？所有组件都从同一个 store 拿数据，store 里的数据变了，所有用这个数据的组件自动更新，永远同步。

对比ReduxZustand
代码量多，要写 action/reducer少，几行就搞定
学习成本高很低
中间件很丰富够用
适合场景大型复杂应用中小型应用，简单直接
新手最容易踩的坑
  • 不要把所有数据都放 store：只有跨组件共用的全局状态才放 store，组件内部自己用的状态还是用 useState。
  • 选择器要精准：useUserStore(state => state.user) 只取需要的字段，不要整个 store 都取，不然会不必要的重渲染。
  • 异步操作要写清楚：异步请求完了再 set store，不要在 render 里直接 set。
  • 不要把 store 当数据库：刷新页面 store 就清空了，要持久化的数据还是要存 localStorage 或者后端。
