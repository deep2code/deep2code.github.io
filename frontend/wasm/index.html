Wasm 入门：从你遇到的问题出发

🏷️ Wasm 入门

你想在网页里跑个很复杂的计算，比如图片处理、视频剪辑、3D 渲染，用 JavaScript 跑太慢了，卡得要死。

这篇不讲理论，就讲你真的会遇到的问题，以及 Wasm 怎么帮你解决。

场景一：网页里跑复杂计算，JavaScript 太慢了

你遇到的问题

你做个网页版的图片处理工具，要把一张 10M 的图片压缩、调色、加滤镜。用 JavaScript 写，一张图片处理要 5 秒，用户点了按钮等半天，体验很差。你想：有没有更快的办法？

Wasm 怎么解决？Wasm 是 WebAssembly，就是把 C/C++/Rust 写的代码，编译成可以在浏览器里跑的二进制格式。性能比 JavaScript 快 10 倍以上。刚才那个图片处理，用 Wasm 写，几百毫秒就搞定了。

// Rust 写的图片处理代码，编译成 Wasm
#[wasm_bindgen]
pub fn process_image(image_data: &[u8]) -> Vec {
    // 压缩、调色、加滤镜，性能比 JS 快 10 倍
}

场景二：你有个现成的 C++ 库，想搬到网页里用

你遇到的问题

你有个 C++ 写的 PDF 解析库，已经很成熟了。你想把它搬到网页里，让用户直接在浏览器里上传 PDF 解析。用 JavaScript 重写一遍？工作量太大了，根本不现实。

Wasm 怎么解决？你不用重写，直接把 C++ 代码编译成 Wasm，就能在浏览器里跑了。比如现在浏览器里的在线 PS、在线视频剪辑、PDF 解析，很多都是用 Wasm 跑的原生代码。

场景三：网页里跑 3D 游戏，JavaScript 跑不动

你遇到的问题

你想在网页里跑个 3D 游戏，用 JavaScript 写，帧率很低，卡得要死，玩不了。

Wasm 怎么解决？很多网页 3D 游戏、网页版的 Autocad、Photoshop，都是用 Wasm 跑的，性能接近原生应用。

对比JavaScriptWasm
性能慢快 10 倍以上
代码体积文本，小二进制，稍大
开发语言只能用 JS/TSC/C++/Rust/Go 都可以
DOM 操作很方便不方便，要和 JS 交互
适合场景普通网页交互复杂计算、3D、音视频处理
新手最容易踩的坑
  • 不要用 Wasm 做普通网页：普通的表单、列表、按钮交互，用 JS 就够了，Wasm 是用来做复杂计算的，不要为了用而用。
  • Wasm 操作 DOM 很麻烦：Wasm 不能直接操作 DOM，要和 JavaScript 交互，界面部分还是用 JS 写比较方便。
  • Wasm 文件要压缩：编译完的 Wasm 文件比较大，上线前要 gzip 压缩，不然加载很慢。
  • 不要把 Wasm 当银弹：大部分网页应用用 JS 就够了，Wasm 是解决 JS 性能不够的场景，不是所有场景都要用。
