PostgreSQL MVCC：从你遇到的问题出发

🏷️ MVCC

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及MVCC怎么帮你解决。

flowchart TB A[读] --> B[读旧版本快照] C[写] --> D[生成新版本] B & D --> E[读写不阻塞]

1. 读的时候写会锁吗

你遇到的问题

你查数据的时候，另一个人在写数据，会不会卡住？

怎么解决？PostgreSQL 用 MVCC，读的是快照，不会被写阻塞。

2. 为什么叫多版本

你遇到的问题

一个数据有多个版本？

怎么解决？每次更新都生成新版本，读的时候读旧版本，不锁表。

3. 和 MySQL InnoDB 一样吗

你遇到的问题

都是 MVCC，有什么区别？

怎么解决？原理类似，PG 更彻底，用元组指针，Undo Log 机制不一样。

MVCC 优点

优点说明
读写不阻塞读的是快照
并发好适合高并发读
实现事务隔离事务隔离级别好实现
新手最容易踩的坑
  • 要清理死元组长时间运行会有很多死元组，要 VACUUM 清理。
  • 长事务影响性能长事务会导致死元组不能清理，占空间。
