PostgreSQL 安装配置

🏷️ PostgreSQL,关系数据库

安装方式的选择：包管理器 vs 源码 vs Docker

我自己在生产上装过十几套 PostgreSQL，结论很简单：生产一律用 PGDG 官方仓库，别用操作系统自带的老版本。Debian/Ubuntu 自带的 PG 版本往往滞后一两个大版本，安全补丁也慢。PGDG 维护了各发行版的官方仓库，版本新很多，这是大多数生产环境的首选。

源码编译我只在需要定制编译选项或跟内核调试时才碰；Docker 适合本地开发测试，但我不建议直接把数据卷跑在生产裸容器里——容器一删一升级，数据文件的归属和生命周期很容易出岔子。下面以 Debian/Ubuntu 的 apt 与 RHEL/Rocky 的 dnf 为主线，覆盖生产最常见的部署路径。

flowchart LR A[选择大版本
PG 17] --> B[添加 PGDG 官方仓库] B --> C[安装 postgresql-17 服务端] C --> D[initdb 初始化数据目录
或 apt 自动 initdb] D --> E[配置 postgresql.conf
监听 内存 WAL] E --> F[配置 pg_hba.conf
认证策略] F --> G[启动并验证
pg_isready + psql] G --> H[创建业务库 角色 扩展]

Debian/Ubuntu 安装实操

使用 PGDG 官方仓库可以拿到最新大版本，而不是系统自带的陈旧版本：

# 1. 安装官方仓库源（以 PG17 为例，Ubuntu 22.04/24.04）
sudo apt-get install -y curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc
sudo sh -c 'echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'

# 2. 安装服务端与常用扩展包
sudo apt-get update
sudo apt-get install -y postgresql-17 postgresql-contrib-17

# 3. 服务状态（apt 包会自动 initdb 并启动）
sudo systemctl enable --now postgresql@17-main
sudo systemctl status postgresql@17-main
sudo pg_isready -h 127.0.0.1 -p 5432

RHEL/Rocky/AlmaLinux 系使用 dnf 仓库：

# RHEL/Rocky 9 安装 PG17
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf install -y postgresql17-server postgresql17-contrib
# 手动初始化（dnf 包默认不自动 initdb）
sudo /usr/pgsql-17/bin/postgresql-17-setup initdb
sudo systemctl enable --now postgresql-17

数据目录初始化与目录结构

无论哪个平台，initdb 都会创建一个独立的数据目录（PGDATA）。生产环境应把它放在独立磁盘/卷上。手工初始化时用 postgres 系统用户执行，禁止用 root 跑 initdb：

# 手工初始化（非 apt 自动场景）
export PGDATA=/mnt/pgdata/17/main
sudo mkdir -p $PGDATA && sudo chown postgres:postgres $PGDATA
sudo -u postgres /usr/lib/postgresql/17/bin/initdb -D $PGDATA \
     --encoding=UTF8 --locale=C.UTF-8 --data-checksums --wal-segsize=64
# --data-checksums 开启数据页校验，能在 silent corruption 时及时发现，强烈推荐
# --wal-segsize=64 把 WAL 段从默认 16MB 调到 64MB，减少段数量

# 目录结构速览
ls $PGDATA
# base/         表数据（每个数据库一个子目录）
# global/       集群共享系统表
# pg_wal/       WAL 日志（10+ 版本从 pg_xlog 改名）
# pg_hba.conf   客户端认证配置
# postgresql.conf 主配置
# pg_stat / pg_replslot 等

两个核心配置文件

postgresql.conf 控制实例行为，pg_hba.conf 控制谁能从哪里连进来。生产最小化的关键改动如下（17 版本可用 ALTER SYSTEM 写入 postgresql.auto.conf，避免直接改主文件）：

-- 用 SQL 改配置，更易版本管理；改完 reload 或 restart
ALTER SYSTEM SET listen_addresses = '*';          -- 监听所有网卡
ALTER SYSTEM SET port = 5432;
ALTER SYSTEM SET max_connections = 200;
ALTER SYSTEM SET shared_buffers = '4GB';          -- 约为内存的 25%
ALTER SYSTEM SET effective_cache_size = '12GB';  -- 约为内存的 60-75%
ALTER SYSTEM SET work_mem = '32MB';
ALTER SYSTEM SET maintenance_work_mem = '512MB';
ALTER SYSTEM SET wal_level = 'replica';          -- 流复制必需
ALTER SYSTEM SET max_wal_size = '16GB';
ALTER SYSTEM SET checkpoint_completion_target = 0.9;
ALTER SYSTEM SET password_encryption = 'scram-sha-256';

SELECT pg_reload_conf();  -- 多数参数 reload 即可，不需要重启
参数我的推荐（16GB 内存示例）干啥用
shared_buffers4GB（内存 25%）内核缓存，最关键的一个
effective_cache_size12GB（内存 75%）告诉优化器 OS 还能给多少缓存
work_mem32MB单条排序/哈希的内存，别给太大
maintenance_work_mem512MB建索引、VACUUM 用
max_connections200连接多了别硬调，上 PgBouncer
wal_levelreplica要做主从复制必须改

pg_hba.conf 的每一行是一条规则，从上往下匹配，命中即停。生产典型写法：

# TYPE  DATABASE  USER   ADDRESS        METHOD
local   all       all                    peer        # 本地 unix socket 用系统用户映射
host    all       all    127.0.0.1/32   scram-sha-256
host    all       appuser 10.0.0.0/8     scram-sha-256
# 复制专用账号，仅允许复制连接
host    replication replicator 10.0.0.0/8 scram-sha-256

初始化业务库与扩展

实例起来后，第一件事是用最小权限原则创建业务角色与数据库，而不是直接用 superuser postgres 跑应用：

-- 创建业务角色（密码用强随机串）
CREATE ROLE appuser WITH LOGIN PASSWORD 'REPLACE_STRONG_PASSWORD' CONNECTION LIMIT 200;
CREATE DATABASE appdb OWNER appuser ENCODING 'UTF8' LC_COLLATE 'C.UTF8' LC_CTYPE 'C.UTF8' TEMPLATE template0;
\c appdb
-- 常用扩展（需要 postgresql-contrib 包）
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;   -- 慢查询统计，必装
CREATE EXTENSION IF NOT EXISTS pgcrypto;             -- 加密函数
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";          -- UUID 生成
-- 给业务用户授权
GRANT CONNECT ON DATABASE appdb TO appuser;
GRANT USAGE ON SCHEMA public TO appuser;
ALTER DEFAULT PRIVILEGES FOR ROLE appuser IN SCHEMA public
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO appuser;

性能优化与最佳实践

我踩过的坑：远程连接死活连不上

刚装好用应用连，报 no pg_hba.conf entry for host。我改了 listen_addresses 也没用，绕了半天才想明白 pg_hba.conf 是从上往下匹配、命中即停——我新加的规则排在一条 host all all 127.0.0.1/32 后面，根本轮不到。把业务网段的规则挪到前面，reload 就通了。这个坑我见新人踩过不下五次。

  • 数据目录与 WAL 分盘：把 pg_wal 单独挂一块 SSD，顺序写与数据文件随机读写互不干扰。
  • 先调 shared_buffers 与 effective_cache_size：这两个是查询规划与缓存的根基，其他参数都是围绕它们微调。
  • 用 ALTER SYSTEM 而不是手编 postgresql.conf：变更可追溯、可回滚（删除 postgresql.auto.conf 中对应行即可）。
  • 生产开 data_checksums：initdb 时加上，或在线用 pg_checksums -e 后开启，能提前发现磁盘静默坏块。
  • 防火墙/安全组收紧：PostgreSQL 不直接暴露公网，永远走内网 + 安全组 + VPN。

常见问题 FAQ

Q1：装完了连不上，报 "Connection refused" 或 "no pg_hba.conf entry"？

前者是 listen_addresses 默认只绑 localhost，或防火墙挡了 5432；后者是 pg_hba.conf 没有匹配你来源 IP 的规则。先 ss -lntp | grep 5432 确认监听，再看 pg_hba.conf 最后一条匹配规则，改完 SELECT pg_reload_conf();。

Q2：initdb 报 "could not create directory /var/lib/pgsql/data" 权限错误？

你用 root 跑了 initdb。必须 sudo -u postgres 切换到 postgres 系统用户再执行，且数据目录属主要是 postgres。PostgreSQL 出于安全设计拒绝以 root 运行任何服务进程。

Q3：apt 装完后怎么连？密码是什么？

Debian/Ubuntu 包默认给 postgres 用户设置了 peer 认证，本地 sudo -u postgres psql 不需要密码。远程应用连接需要先 ALTER USER postgres PASSWORD 'xxx'; 并在 pg_hba.conf 里把对应行改成 scram-sha-256。

总结

安装 PostgreSQL 的难点从来不是跑那几行 apt/dnf，而是初始化参数与认证策略的一次性选择：数据目录放哪、WAL 分不分盘、shared_buffers 给多少、pg_hba 怎么收紧、扩展装哪些。这些决策一旦上线，后期改起来都要停机或重启，所以第一次配置时就要按生产标准来。下一篇进入 PostgreSQL 最有特色的部分——它的数据类型系统。
