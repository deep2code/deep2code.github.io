PostgreSQL 主从复制：读写分离

🏷️ PostgreSQL

数据库读压力太大，一台主库扛不住，加从库做读写分离。主库写，从库读，性能翻倍。这篇讲 PostgreSQL 主从复制怎么配。

flowchart LR A[应用] --> B{读写分离} B -->|写| C[主库 Master] B -->|读| D[从库 Slave 1] B -->|读| E[从库 Slave 2] C -->|同步| D C -->|同步| E

主库读压力太大

⚠️
你遇到的问题

所有请求都打到主库，QPS 上万，CPU 跑满。

怎么解决？加从库做读写分离，写走主库，读走从库，读性能翻倍。

# 主从复制原理
主库把 WAL 日志发给从库
从库重放 WAL，和主库保持一致
延迟通常是毫秒级

主库挂了，服务停了

⚠️
你遇到的问题

主库服务器坏了，数据库直接不可用，业务停了。

怎么解决？加自动故障转移，主库挂了自动把从库提升为主库，几秒恢复。

# 高可用方案
Patroni + etcd：自动故障转移
 repmgr：简单点的方案
 Keepalived + VIP：最简单

主从复制方式

方式 原理 优点 缺点
流复制 实时传 WAL 延迟低 主库压力大
逻辑复制 逻辑解码 更灵活 配置复杂
快照复制 定时全量 简单 延迟高

新手最容易踩的坑

❌
避坑指南
  • 主从延迟是正常的，别指望完全一致，读一致性要求高的还是走主库
  • 从库不要太多，3-5 个足够了，太多主库同步压力大
  • 大事务会导致主从延迟突然变大，要注意拆分大事务
  • 故障转移一定要测，别等真挂了才发现切换有问题
