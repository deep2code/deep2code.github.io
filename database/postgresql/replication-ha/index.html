PostgreSQL 主从复制：从你遇到的问题出发

🏷️ PG 主从

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及PG 主从怎么帮你解决。

flowchart LR A[主库] -->|同步 WAL| B[从库1] A -->|同步 WAL| C[从库2] B --> D[读请求] C --> D[读请求]

1. 数据库单点风险高

你遇到的问题

生产数据库只有一个，挂了整个网站就没了。

怎么解决？搭主从复制，主库写，从库读，主库挂了切从库。

2. 读请求太多扛不住

你遇到的问题

主库读压力太大，CPU 跑满了。

怎么解决？读请求分发到从库，主库只处理写。

3. 怎么配置主从

你遇到的问题

知道要主从，不知道怎么配。

怎么解决？主库开 wal_level，从库配连接，基础配置就搞定。

复制模式

模式特点
同步复制主库等从库确认才提交，安全但慢
异步复制主库不等从库，快但可能丢数据
新手最容易踩的坑
  • 生产用异步复制大部分场景异步复制够用，性能好。
  • 定期切主库演练不要等真挂了才发现切不过去，定期演练。
