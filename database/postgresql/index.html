PostgreSQL 深度原理：MVCC 与 WAL

🏷️ PostgreSQL

PostgreSQL 比 MySQL 还强大，是因为它的 MVCC 实现更彻底，支持复杂查询和事务。这篇讲透 PG 底层原理。

核心原理1：MVCC 多版本并发控制

PostgreSQL 读写不阻塞，是因为 MVCC：每一行有多个版本，读老版本，写新版本，不用加锁。

flowchart TD A[一行数据] --> B[版本1 旧的] A --> C[版本2 中间的] A --> D[版本3 最新] B -->|可见| E[读事务A] D -->|可见| F[读事务B]

PG vs MySQL MVCC 对比

对比 PostgreSQL MySQL InnoDB
MVCC 实现 每行存多个版本 undo log 回滚段
清理 VACUUM 后台清理 Purge 线程自动清理
写放大 较大，更新产生新行 较小
长事务影响 大，老版本不清理 相对小

核心原理2：WAL 预写日志原理

PostgreSQL 写数据不是直接改磁盘，是先写 WAL 日志，再改内存，崩溃了用 WAL 恢复。

flowchart LR A[写请求] --> B[写 WAL 日志 磁盘] B --> C[改内存页] C --> D[后台异步刷盘] D --> E[崩溃恢复 重放 WAL]

PostgreSQL 核心组件

组件 作用 说明
WAL 预写日志 保证事务持久化，崩溃恢复
shared_buffers 内存缓冲池 热数据放内存，加速读写
VACUUM 清理死元组 MVCC 旧版本垃圾回收
checkpoint 检查点 把脏页刷到磁盘，缩短恢复时间

核心原理3：索引原理：B+树 vs GIN/GiST

PostgreSQL 不止 B+ 树索引，还有 GIN、GiST 等多种索引，适合 JSON、数组、全文搜索、空间数据。

flowchart LR A[索引类型] --> B[B+树 默认] A --> C[Hash] A --> D[GIN 倒排] A --> E[GiST 广义搜索] B --> B1[等值 范围] D --> D1[JSON 数组 全文] E --> E1[空间 几何]

PostgreSQL 索引类型

索引类型 适用场景 例子
B+树 等值、范围查询 WHERE id = 1
Hash 纯等值查询 WHERE phone = "xxx"
GIN JSONB、数组、全文 WHERE tags @> ['java']
GiST 空间数据、几何 PostGIS 地理查询

新手最容易踩的坑

❌
避坑指南
  • VACUUM 一定要开自动清理，长事务会导致垃圾不回收，表膨胀
  • 不要随便 SELECT *，PostgreSQL 存储是堆表，宽表查询慢
  • JSONB 比 JSON 快，建 GIN 索引后查询性能高很多
  • 大表加索引不要直接 CREATE INDEX，用 CONCURRENTLY 不锁表
