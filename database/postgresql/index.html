PostgreSQL 入门：从你遇到的问题出发

🏷️ PostgreSQL 入门

你觉得 MySQL 不够用了：要存 JSON、要做复杂查询、要处理地理空间数据。或者你听说 PostgreSQL 比 MySQL 功能更强，想试试。

这篇不讲理论，就讲你真的会遇到的问题，以及 PostgreSQL 怎么帮你解决。

场景一：MySQL 不够用了，要存 JSON 还要做复杂查询

你遇到的问题

你用 MySQL 存用户数据，要存用户的偏好设置，是个 JSON 结构。MySQL 虽然支持 JSON，但查询、更新都很麻烦。你还要做一些复杂的统计分析，MySQL 写 SQL 写得很痛苦。

PostgreSQL 怎么解决？PostgreSQL 对 JSON 支持特别好，可以直接在 JSON 字段里查、更新，就像查普通字段一样。而且对复杂查询、统计分析的支持比 MySQL 强很多。

-- 建个表，存 JSON 字段
CREATE TABLE users (
  id INT PRIMARY KEY,
  name TEXT,
  preferences JSONB
);

-- 直接查 JSON 里的字段
SELECT * FROM users WHERE preferences -> 'theme' ->> 'mode' = 'dark';

现在你不用把 JSON 拆成好几个表，直接存 JSONB，查询更新都很方便。

场景二：金融系统，对数据一致性要求特别高

你遇到的问题

你做了个金融系统，对数据一致性要求特别高，一分钱都不能错。听说 MySQL 在高并发下会有幻读、不可重复读的问题，你想找个更可靠的数据库。

PostgreSQL 怎么解决？PostgreSQL 的事务隔离级别比 MySQL 严格，默认就是可串行化，数据一致性更有保障。金融、医疗这种对数据要求高的系统，很多都用 PostgreSQL。

场景三：要做附近的人、附近的店，地理空间查询

你遇到的问题

你做了个外卖 App，要根据用户的位置，搜附近 3 公里内的餐厅。用 MySQL 算经纬度距离，性能很差，数据量大了根本跑不动。

PostgreSQL 怎么解决？装个 PostGIS 扩展，PostgreSQL 就变成了专业的地理空间数据库，做"附近的 XX"查询特别快。

-- 搜附近 3 公里内的餐厅
SELECT name, location
FROM restaurants
WHERE ST_DWithin(location, user_location, 3000);
对比MySQLPostgreSQL
JSON 支持一般很好（JSONB）
复杂查询一般很强
事务隔离默认可重复读默认可串行化
扩展能力弱很强（PostGIS 等）
简单业务性能更好差不多
新手最容易踩的坑
  • 字段名默认小写：PostgreSQL 会把你写的大写字段名自动转成小写，要保留大小写得加双引号。
  • 自增主键用法不一样：MySQL 用 AUTO_INCREMENT，PostgreSQL 用 SERIAL 或者 GENERATED AS IDENTITY。
  • 不要把 MySQL 的 SQL 直接搬过来：有些函数、语法不一样，要改一下。
  • JSON 要用 JSONB 不要用 JSON：JSONB 是二进制存的，查询更快，还能建索引。
