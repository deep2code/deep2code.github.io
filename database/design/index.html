数据库设计：从需求到建表

🏷️ 数据库设计

做项目上来就建表，建到一半发现要改，数据全乱了。好的表设计能省后面无数麻烦。这篇讲从需求分析到建表的完整流程。

flowchart LR A[需求分析] --> B[ER图设计] B --> C[表结构设计] C --> D[范式校验] D --> E[索引设计] E --> F[反范式优化]

上来就建表，建到一半要改

⚠️
你遇到的问题

需求还没理清楚就开始建表，建完发现少了字段，又要改，数据迁移麻烦死。

怎么解决？先画 ER 图，把实体和关系理清楚，再建表，后面改的就少了。

# ER 图步骤
1. 找实体：用户、订单、商品
2. 找属性：每个实体有哪些字段
3. 找关系：一对多、多对多

表建好了，查询很慢

⚠️
你遇到的问题

表建完就上线，结果查询慢得要死，全表扫描。

怎么解决？提前想好查询场景，给常用查询字段加索引。

-- 加索引
CREATE INDEX idx_user_id ON orders(user_id);
CREATE INDEX idx_order_time ON orders(create_time);

设计步骤

步骤 做什么 产出
需求分析 搞清楚要存什么数据 需求文档
ER图设计 画实体关系图 ER图
表结构设计 设计字段和类型 建表SQL
索引设计 加常用查询索引 索引SQL
性能优化 必要时反范式 优化后的表

新手最容易踩的坑

❌
避坑指南
  • 字段类型尽量小，能用 int 就别用 bigint，能用 varchar(50) 就别用 varchar(255)
  • 所有表都要有 id、create_time、update_time、is_deleted 这几个基础字段
  • 字段名用小写加下划线，别用驼峰，MySQL 大小写敏感的坑很多
  • 状态字段用 tinyint，别用 varchar，后面加索引快
