分库分表策略：从你遇到的问题出发

🏷️ 分库分表

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及分库分表怎么帮你解决。

flowchart TB A[单表数据太大] --> B{按什么分?} B --> C[按时间分] B --> D[按ID哈希分] B --> E[按业务分库]

1. 单表数据几亿行

你遇到的问题

你的订单表几亿行，查询越来越慢。

怎么解决？分库分表，把数据拆到多个库多个表。

2. 怎么选分片键

你遇到的问题

知道要分，不知道按什么分。

怎么解决？按查询最多的字段分，常用用户 ID 或时间。

3. 分了之后怎么查

你遇到的问题

分表了，跨表查询怎么办？

怎么解决？尽量不要跨分片查询，业务设计时就要考虑。

分片策略

策略适合场景
按时间分日志、订单类数据
按ID哈希分用户数据
按业务分库不同业务拆到不同库
新手最容易踩的坑
  • 能不分就不分分库分表很复杂，单表几百万行加索引完全够用。
  • 全局ID要处理分表了主键不能自增了，要用雪花算法。
