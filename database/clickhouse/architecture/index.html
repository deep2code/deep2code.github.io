CK 架构：从你遇到的问题出发

🏷️ CK 架构

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及CK 架构怎么帮你解决。

flowchart TB A[CK 架构] --> B[列式存储] B --> C[向量化执行] C --> D[分布式集群]

1. 为什么 ClickHouse 这么快

你遇到的问题

为什么 CK 查询比 MySQL 快几百倍？

怎么解决？列式存储 + 向量化执行，分析查询扫的数据少，处理快。

2. 列式存储是什么

你遇到的问题

听说 CK 是列式存储，和行式有什么区别？

怎么解决？MySQL 是行式存，一条数据存一起；CK 是列式存，一列数据存一起，分析查询快。

3. CK 集群怎么搭

你遇到的问题

数据量大了怎么搭 CK 集群？

怎么解决？分片 + 副本，数据分片存多台，每分片有副本。

行式 vs 列式

对比行式 MySQL列式 ClickHouse
存储一行存一起一列存一起
分析查询慢（扫全表）快（只扫需要的列）
写入快批量写快
新手最容易踩的坑
  • CK 不适合 OLTP不要拿 CK 当 MySQL 用，它是分析型的。
  • 批量写入CK 适合批量导入，不要一条一条插。
