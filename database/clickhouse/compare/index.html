ClickHouse vs Elasticsearch vs Doris

🏷️ ClickHouse,选型对比

选型前先把误解打掉

这三个引擎经常被放在一张图上比，但我发现很多人比错了方向——拿 ClickHouse 的聚合能力去比 ES 的全文检索，拿 Doris 的 Join 能力去踩 CH 的写入，结论当然歪。这篇我把三个引擎放回各自的定位，用一张大表 + 一张决策树，帮你 10 分钟做决定。先说我的核心判断：它仨不是"谁取代谁"，而是"各有主场"。

ClickHouse：单表聚合的偏执狂

ClickHouse 的优势非常尖锐：单表大批量聚合，它就是开源第一梯队。列式存储 + 向量化 + 高压缩，同样的硬件，聚合查询经常比 ES 快一个数量级，磁盘还省一大半。日志分析、埋点统计、实时报表，它是我的首选。

但它的短板同样明显：

  • 不擅长多表大 Join：ClickHouse 的 Join 是把右表整个加载进内存做哈希，大表 Join 直接 OOM。
  • 不擅长单行更新/删除：mutation 是重写数据，大表上跑一次几小时。
  • 全文检索弱：虽然有 ngram 跳数索引，但和 ES 的分词 + 相关性打分不是一个时代的产品。
  • 并发低：它为"少并发大批量"设计，同时来几百个大查询就互相打架。
CH 适合谁

你的核心查询是"一张大明细表 + 按时间/维度 GROUP BY"，几乎没有多表 Join，不需要全文检索——选 ClickHouse，它会让你忘记数据库还能这么快。

Elasticsearch：搜索王者，聚合是附赠

ES 的看家本领是全文检索。倒排索引 + 分词器 + BM25 打分，"搜含某个关键词的文档并按相关性排序"这件事，它做了二十年，没人比它更成熟。中文有 IK 分词器，商品搜索、日志检索、站内搜索都是它的主场。

但把 ES 当 OLAP 引擎用是常见误区。它的聚合是"附赠功能"——数据量一大，terms 聚合要分桶、要排序，堆内存直接告警。我之前用 ES 做日志聚合，十亿条数据按状态码 group by 一次，堆就撑爆了。

ES 的强项ES 的弱项

Doris：能分析的"数仓"，MySQL 党的甜点

Doris（起源于百度 Palo，现在 Apache 顶级项目）是 MPP 架构，定位介于 CH 和传统数仓之间。最大卖点是MySQL 协议全兼容——你用 MySQL 客户端、Navicat、BI 工具直连就能查，SQL 方言几乎不用学。它的 Join 能力远强于 CH，因为 FE 做优化器、BE 做分布式执行，多表 Join 能并行下推。

另外 Doris 的实时 upsert 能力是 CH 比不了的：Unique 数据模型支持按主键实时更新，这意味着你可以把业务库的近实时数据同步过来做分析，不用像 CH 那样忍受 mutation。

别被"全兼容"冲昏头

Doris 的单表聚合极限其实不如 ClickHouse——CH 为单表扫描做的向量化和压缩优化更极致。如果你 90% 查询都是单表大聚合，CH 还是更快。Doris 的价值在"既要 Join 又要实时又要 MySQL 生态"的折中场景。

真实组合架构：我的推荐

我团队线上跑的其实是"ES + CH"双引擎：

  • ES 负责：日志全文检索（搜 error、按关键词查上下文）、商品搜索。
  • CH 负责：日志聚合报表（按天 PV/UV、状态码分布、P95 延迟）、用户行为分析。

数据通过 Kafka 双写两边，各司其职。别指望一个引擎解决所有问题——ES 做聚合贵，CH 做搜索弱，组合才是正解。

FAQ

Q：我们团队小，只能选一个，选哪个？
看你要解决的核心问题。要做"数据报表/大屏"，选 ClickHouse；要做"站内搜索/日志关键词检索"，选 Elasticsearch；要"把业务库直接做分析、多表 Join"，选 Doris。别选一个"全能"的，没有全能引擎。

Q：ClickHouse 能装全文检索插件替代 ES 吗？
能做简单的关键词匹配（ngram 跳数索引），但分词、相关性打分、高亮、同义词这些 ES 的成熟能力，CH 都没有。严肃的全文搜索场景别省 ES。

Q：Doris 会取代 ClickHouse 吗？
短期不会。两者优化目标不同：CH 把单表聚合做到极致，Doris 把多表 Join 和实时 upsert 做顺手。2026 年两者在大厂并行使用，不存在谁取代谁。

我的结论

选型这件事没有"最强"，只有"最匹配你的查询模型"。记住三句话：单表聚合报表选 ClickHouse，全文搜索选 Elasticsearch，多表 Join 实时数仓选 Doris。数据量大了，大概率最后是 ES + CH 双引擎组合，而不是二选一。这一系列到这里就结束了，从架构到建表、优化、实战、选型，你手里应该有一套能落地的 ClickHouse 知识了。
