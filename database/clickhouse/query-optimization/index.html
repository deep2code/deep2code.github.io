ClickHouse 查询优化：从你遇到的问题出发

🏷️ CK 查询优化

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及CK 查询优化怎么帮你解决。

flowchart TB A[慢查询] --> B[explain] B --> C[排序键设计] C --> D[分区裁剪] D --> E[减少扫描]

1. CK 查询慢

你遇到的问题

ClickHouse 查询聚合要好几秒，太慢。

怎么解决？CK 是 OLAP，优化思路和 MySQL 不一样，靠排序键和分区裁剪。

2. 排序键很重要

你遇到的问题

CK 的排序键是什么？

怎么解决？CK 数据按排序键物理存储，查询带排序键条件就快很多。

3. 怎么优化

你遇到的问题

常用优化手段有哪些？

怎么解决？设计好排序键、用分区裁剪、避免 SELECT *、用物化视图。

优化要点

要点说明
排序键设计把常用过滤/排序字段放排序键前面
分区裁剪查询带分区字段条件，不扫全表
避免 SELECT *只查需要的列，CK 列存优势
物化视图预计算常用聚合查询
新手最容易踩的坑
  • 不要当 MySQL 用CK 是 OLAP，不要频繁 UPDATE/DELETE。
  • 排序键想好再建表CK 改排序键很麻烦，建表前想清楚。
