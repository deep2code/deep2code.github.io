Redis 入门：从你遇到的问题出发

🏷️ Redis

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及 Redis 怎么帮你解决。2026 年主流版本是 Redis 8.x。

flowchart TB A[Redis 8.x] --> B[缓存] A --> C[分布式锁] A --> D[排行榜] A --> E[消息队列] A --> F[地理位置]

1. 数据库查询太慢

你遇到的问题

一个详情页接口查数据库要 300ms，QPS 高了数据库直接扛不住。

怎么解决？前面架一层 Redis 缓存，热点数据放内存，快 10~100 倍。

# 写入缓存
SET user:1001 '{"name":"张三","age":28}' EX 3600

# 读缓存
GET user:1001

2. Redis 8.x 新特性（2026）

你遇到的问题

还在用 Redis 5.x/6.x，不知道新版本有什么好处。

怎么解决？Redis 8.x 比 6.x 性能提升 30%+，自带向量搜索和 JSON 原生支持。

版本关键特性建议
Redis 5.x基础功能太老，建议升级
Redis 6.x多线程 IO、ACL可用，但推荐升 8
Redis 7.xFunctions、Sharded Pub/Sub稳定
Redis 8.x向量搜索、JSON 原生、性能 +30%2026 主流推荐

4. 缓存三大经典问题

flowchart LR A[缓存问题] --> B[穿透] A --> C[击穿] A --> D[雪崩] B --> B1[查不存在的数据] C --> C1[热点 key 过期] D --> D1[大量 key 同时过期]

缓存穿透

问题：查数据库不存在的数据，每次都打数据库。

解决：空值也缓存（短时间），或用布隆过滤器。

缓存击穿

问题：某个热点 key 突然过期，瞬间大量请求打数据库。

解决：热点 key 不过期，或用互斥锁重建缓存。

缓存雪崩

问题：大量 key 同一时间过期，数据库瞬间压力陡增。

解决：过期时间加随机值，不要同一批过期。

# 过期时间加随机值，防雪崩
EXPIRE key 3600 + random(0, 600)

5. 持久化：RDB vs AOF

对比RDBAOF
原理快照（二进制）追加写命令日志
恢复速度快慢
数据安全可能丢最后一次快照后的数据更安全（最多丢 1 秒）
文件体积小大
适合备份、容灾生产环境

生产建议：Redis 8 默认 RDB + AOF 混合持久化，直接用默认配置就行。

7. 常用场景实战

分布式锁

# 加锁（原子操作）
SET lock:order:1001 random_value NX EX 10

# 解锁（Lua 脚本保证原子）
EVAL "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end" 1 lock:order:1001 random_value

排行榜

# 添加分数
ZADD rank:weekly 95 "user1001"
ZADD rank:weekly 88 "user1002"

# 取 Top 10
ZRANGE rank:weekly 0 9 WITHSCORES REV

计数器

# 阅读量 +1
INCR article:123:views

# 限频（每分钟最多 100 次）
INCR rate:user:1001
EXPIRE rate:user:1001 60
新手最容易踩的坑
  • 缓存一定要设过期：不要把数据一直放内存，迟早撑爆。
  • 防三大问题：穿透、击穿、雪崩，上线前一定想清楚怎么防。
  • key 要有前缀：user:1001、order:2024，不要乱命名。
  • 大 key 要拆：一个 key 不要存几 MB 数据，拆成多个小 key。
  • 不要当数据库用：Redis 是缓存，不是持久化数据库，重要数据还是要落库。
