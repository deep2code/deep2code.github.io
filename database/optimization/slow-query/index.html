慢查询排查：从你遇到的问题出发

🏷️ 慢查询

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及慢查询怎么帮你解决。

flowchart TB A[慢查询] --> B[开启慢查询日志] B --> C[explain 看执行计划] C --> D{全表扫描?} D -->|是| E[加索引] D -->|否| F[优化SQL]

1. 不知道哪条 SQL 慢

你遇到的问题

系统慢，但不知道是哪条 SQL 慢。

怎么解决？开启慢查询日志，记录执行时间超过阈值的 SQL。

2. 知道 SQL 慢不知道为什么

你遇到的问题

找到那条慢 SQL 了，不知道为什么慢。

怎么解决？用 explain 看执行计划，看有没有走全表扫描。

3. 加了索引还是慢

你遇到的问题

加了索引但还是慢。

怎么解决？看是不是索引失效了，或者是不是要查的数据太多了。

explain 关键字段

字段说明
typeALL 是全表扫描，要优化
key用了哪个索引
rows扫描了多少行
新手最容易踩的坑
  • 先开慢查询日志不要靠猜，先开日志找慢 SQL。
  • EXPLAIN 一定要看看执行计划比瞎猜有用。
