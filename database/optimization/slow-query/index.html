慢查询优化

EXPLAIN 分析

EXPLAIN SELECT * FROM users WHERE name = '张三';
字段说明关注
type访问类型至少 range，最好 ref/const
key用了哪个索引NULL 说明没走索引
rows扫描行数越小越好
Extra额外信息Using filesort/temporary 要优化

常见优化手段

问题优化
SELECT *只查需要的字段
大表 JOIN小表驱动大表
深分页用游标/延迟关联
COUNT(*)用近似值或单独计数表

深分页优化

-- ❌ 慢：OFFSET 10000 要扫描 10000 行
SELECT * FROM orders ORDER BY id LIMIT 20 OFFSET 10000;

-- ✅ 快：用游标
SELECT * FROM orders WHERE id > 100000 ORDER BY id LIMIT 20;
