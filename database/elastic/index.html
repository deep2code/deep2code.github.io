Elasticsearch 入门：从你遇到的问题出发

🏷️ ES 入门

你想做个搜索功能，用户输入关键词就能搜到相关内容。用 MySQL 的 like 查询？慢不说，还搜不准。

这篇不讲理论，就讲你真的会遇到的问题，以及 ES 怎么帮你解决。

场景一：用 MySQL 做搜索，又慢又不准

你遇到的问题

你做了个博客网站，有 10 万篇文章。用户输入"怎么学 Python"，你用 MySQL 的 WHERE title LIKE '%Python%' 查询。结果查一次要 3 秒，还搜不准，把标题里带 Python 的都搜出来了，不相关的一大堆。

ES 怎么解决？ES 是专门做全文搜索的，比 MySQL 的 like 快 100 倍以上，还能分词、相关度排序，搜出来的结果更准。

# 搜索"怎么学 Python"，按相关度排序
GET /articles/_search
{
  "query": {
    "match": {
      "title": "怎么学 Python"
    }
  }
}

现在搜一次只要几十毫秒，结果按相关度排序，最相关的排在最前面。

场景二：要查日志，翻半天找不到

你遇到的问题

你的应用每天产生 10G 日志，存在服务器上。出了问题要查日志，你要 grep、awk、sed，翻半天才能找到相关的那几行。

ES 怎么解决？把所有日志都存到 ES 里，你在网页上输入关键词，几毫秒就能搜到相关的日志，还能按时间、级别过滤。

# 搜所有 ERROR 级别的日志
GET /logs/_search
{
  "query": {
    "term": {
      "level": "ERROR"
    }
  }
}

现在查日志不用 SSH 到服务器上 grep 了，在 Kibana 上输入关键词就行。

场景三：电商网站商品搜索，要按价格、分类筛选

你遇到的问题

你做了个电商网站，用户要搜"手机"，还要按价格区间、品牌、分类筛选，还要按价格、销量排序。用 MySQL 写 SQL 越来越复杂，数据量大了还慢。

ES 怎么解决？ES 做这种多条件筛选、排序特别方便，一条查询就能搞定。

GET /products/_search
{
  "query": {
    "bool": {
      "must": { "match": { "name": "手机" } },
      "filter": [
        { "range": { "price": { "gte": 1000, "lte": 5000 } } },
        { "term": { "brand": "苹果" } }
      ]
    }
  },
  "sort": [{ "sales": "desc" }]
}

现在多条件筛选、排序一条查询就搞定了，性能还好。

概念通俗理解
Index（索引）数据库：一类数据的集合，比如 articles、products
Document（文档）行：一条数据，比如一篇文章、一个商品
Mapping（映射）表结构：每个字段是什么类型，怎么分词
Shard（分片）分库分表：数据太多了，分成多个片存在不同机器上
新手最容易踩的坑
  • 不要把 ES 当数据库用：ES 是搜索引擎，不是事务型数据库，重要数据还是要存 MySQL。
  • 内存要给够：ES 很吃内存，默认给的太少，性能会很差。
  • 不要随便改 Mapping：字段类型改了，旧数据就不兼容了，要重建索引。
  • 分页不要太深：深分页（比如第 1000 页）性能很差，要用 search_after。
