向量数据库：AI 时代的新数据库

🏷️ 向量数据库

大模型、RAG 火了，向量数据库突然就热门了。它不是存传统数据的，是存向量、做相似度搜索的。这篇讲向量数据库是干嘛的，怎么选。

flowchart LR A[文本/图片] --> B[Embedding 模型] B --> C[生成向量] C --> D[向量数据库] D --> E[相似度搜索] E --> F[最相似结果]

为什么需要向量数据库

⚠️
你遇到的问题

传统数据库搜文本，只能精确匹配，搜个"差不多意思"的根本搜不到。

怎么解决？向量数据库把文本转成向量，算向量距离，找语义最相似的，就是 RAG 的基础。

# 向量搜索原理
1. 把文本转成 1536 维向量
2. 存到向量数据库
3. 查询时也算成向量
4. 找距离最近的 N 个结果

向量数据库怎么选

⚠️
你遇到的问题

PgVector、Milvus、Chroma、Qdrant，一大堆，选哪个？

怎么解决？小项目先用 PgVector（基于 PostgreSQL，不用额外装），大项目再换 Milvus 或 Qdrant。

# 选型建议
个人项目 / 小数据：PgVector
中等规模：Chroma / Qdrant
大规模 / 生产：Milvus

常见向量数据库对比

数据库 优点 缺点 适用场景
PgVector 基于PG，不用新栈 性能一般 小项目、已有PG
Chroma 轻量，上手快 功能少 Demo、原型
Qdrant 性能好，功能全 要单独部署 生产小中型
Milvus 性能最强，分布式 重，运维复杂 大规模生产

新手最容易踩的坑

❌
避坑指南
  • 向量数据库不是替代传统数据库，是补充，存向量用它，业务数据还是用 MySQL
  • Embedding 模型选对很重要，不同模型生成的向量不能混用
  • 维度不是越高越好，1536 维基本够用，太高了存储和计算都贵
  • 小数据量别上 Milvus，杀鸡用牛刀，PgVector 足够了
