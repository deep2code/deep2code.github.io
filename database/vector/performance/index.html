向量数据库性能：从你遇到的问题出发

🏷️ 向量性能

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及向量性能怎么帮你解决。

flowchart TB A[向量搜索慢] --> B{数据量多大?} B -->|小| C[pgvector 就够] B -->|大| D[上专门向量库] D --> E[HNSW/IVF 索引]

1. 向量搜索太慢

你遇到的问题

你的向量库数据量大了，搜索要几秒。

怎么解决？加向量索引，HNSW 或者 IVF，快很多。

2. pgvector 能撑多大

你遇到的问题

pgvector 最多能存多少向量？

怎么解决？百万级完全够用，千万级要看情况。

3. 什么时候要换专门向量库

你遇到的问题

什么时候 pgvector 不够用？

怎么解决？亿级向量、高并发、要求毫秒级响应，再上专门向量库。

索引类型

索引特点适合
Flat精确搜索小数据量
IVFFlat聚类索引中等数据量
HNSW图索引大数据量、高要求
新手最容易踩的坑
  • 先从 pgvector 开始小项目用 pgvector，简单够用，不要一开始就上复杂的。
  • 维度不要太高维度越高搜索越慢，一般几百维合适。
