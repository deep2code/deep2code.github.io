pgvector：从你遇到的问题出发

🏷️ pgvector

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及pgvector怎么帮你解决。

flowchart LR A[PostgreSQL] --> B[加 pgvector 扩展] B --> C[存向量] C --> D[相似度搜索]

1. 想做 RAG 不想装新数据库

你遇到的问题

你想用向量做搜索，但不想再装个向量数据库。

怎么解决？PostgreSQL 加 pgvector 扩展，直接在 PG 里存向量做搜索。

2. 项目已经用了 PG

你遇到的问题

你项目已经在用 PostgreSQL，不想再加新组件。

怎么解决？pgvector 就是 PG 的扩展，不用改技术栈。

3. 什么时候要用专门的向量库

你遇到的问题

pgvector 够用吗？什么时候要换专门的？

怎么解决？数据量小、并发低，pgvector 完全够用；量大了再上专门的向量库。

pgvector 特点

特点说明
扩展PG 的扩展，不用装新数据库
简单和普通 SQL 一样用
够用中小规模完全够用
新手最容易踩的坑
  • 要建向量索引数据量大了要建 ivfflat 索引，不然全表扫描很慢。
  • 维度不要太高维度太高性能会下降，一般几百维合适。
