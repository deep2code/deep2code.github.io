我为什么从 UE 转回 Unity

2019 年我做一个独立手游项目，团队三个人，选了 Unity。原因很现实：招人快、手机平台支持最好、Asset Store 资源多。

MonoBehaviour 生命周期：背下来就能少踩一半坑

Unity 按固定顺序调用生命周期方法。这个顺序搞不清，出 bug 都不知道从哪查。

方法调用时机我用来干嘛
Awake()实例化就调，即使脚本没启用缓存 GetComponent 引用
OnEnable()每次激活注册事件
Start()第一帧前，脚本启用时依赖其他对象的初始化
Update()每帧输入、移动
FixedUpdate()固定间隔（0.02s）物理操作
LateUpdate()所有 Update 之后相机跟随
OnDisable()每次禁用取消事件订阅
OnDestroy()销毁清理资源
 
public class PlayerController : MonoBehaviour
{
    [SerializeField] private float speed = 5f;
    private Rigidbody rb;

    void Awake() { rb = GetComponent<Rigidbody>(); }

    void Update()
    {
        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");
        transform.Translate(new Vector3(h, 0, v) * speed * Time.deltaTime);
    }

    void FixedUpdate() { rb.AddForce(Vector3.up * 9.8f); }
}
Awake 和 Start 的区别

Awake 实例化就调，哪怕脚本是 disabled 的。Start 要等到脚本启用且第一帧前才调。初始化自己用 Awake，依赖其他 GameObject 的用 Start。我见过太多人把 GetComponent 写在 Start 里，结果 Awake 阶段就被别的脚本访问，拿到 null。

物理系统：别在 Update 里做物理

这是新手最容易犯的错。物理操作必须放在 FixedUpdate 里——物理引擎按固定时间步长模拟（默认 0.02 秒），放在 Update 里帧率变了物理行为就不对。

// 三种施加运动的方式
rb.AddForce(Vector3.forward * 10f, ForceMode.Impulse);  // 冲量
rb.velocity = Vector3.forward * 5f;                       // 直接设速度
rb.MovePosition(transform.position + Vector3.forward * Time.fixedDeltaTime); // 运动学

OnCollisionEnter/Stay/Exit碰撞（需 Rigidbody+Collider）
OnTriggerEnter/Stay/Exit触发器（Collider 勾 IsTrigger）
Raycast射线检测
高速物体穿透

子弹这种高速物体，一帧位移比碰撞体还厚，直接穿过去。Collsion Detection 设为 Continuous Dynamic。但别全开——开销大，只给高速物体开。

资源管理：新项目直接 Addressables

Resources 文件夹是新手坑——所有东西全打进包里，包体巨大。Addressables 是现代方案：按 key 异步加载、引用计数自动释放、支持 CDN。

ResourcesAssetBundleAddressables
增量更新❌ 全量重打包✅✅
远程下载❌✅✅ CDN
内存管理手动 Unload手动处理依赖引用计数自动
新项目推荐❌老项目维护✅ 首选
 
var handle = Addressables.LoadAssetAsync<GameObject>("PlayerPrefab");
await handle.Task;
if (handle.Status == AsyncOperationStatus.Succeeded)
    Instantiate(handle.Result);
Addressables.Release(handle);  // 用完释放

DOTS/ECS：什么时候该用

Entities 1.0 以后 ECS 终于成熟了。但别上来就用——ECS 适合海量同构实体（几千个敌人、几万粒子），普通游戏用 OOP 就够了。

渲染管线：立项就定死

管线定位平台
Built-in传统固定管线仅遗留项目
URP通用可编程新项目默认推荐
HDRP高清光追PC/主机高端项目

URP 和 HDRP 的 Shader 不通用。项目中途切管线成本极高，等于重写所有材质。立项时就定好。

性能优化：先 Profiler 再动手

别凭感觉优化。Unity Profiler 一开，哪个函数耗时一目了然。

方向手段什么时候用
GC 卡顿对象池、减少 Update new子弹/特效/敌人必用
Draw Call 多SRP Batcher、GPU Instancing大量同材质物体
顶点太多LOD 多级细节远处模型降精度

8 个坑

  1. Update 里 GetComponent：每帧查找组件，GC 爆炸。Awake 里缓存引用
  2. Update 里 new 对象：字符串拼接、装箱，GC 每帧涨。缓存复用
  3. 协程不停：SetActive(false) 不会停协程。OnDisable 里手动 Stop
  4. Resources 文件夹塞一堆：全打进安装包。新项目用 Addressables
  5. 高速物体穿透：Collision Detection 开 Continuous Dynamic
  6. 事件订阅不取消：对象销毁了事件还在调用，NullReferenceException。OnDisable 里 Unsubscribe
  7. ECS 乱用：几百个敌人没必要 ECS。OOP 够简单就别硬上 DOTS
  8. 中途换渲染管线：URP 和 HDRP 不兼容。立项就定

FAQ

Unity 6 跟 Unity 2021 有什么区别？

Unity 6 是 2024 年的大版本改名（之前叫 Unity 2023）。主要变化：性能提升、WebGPU 支持、Entities 1.0 正式版、AI 工具集成。API 基本兼容，老项目升级没大问题。

IL2CPP 和 Mono 选哪个？

手机发布用 IL2CPP（性能好、防反编译），开发用 Mono（编译快）。IL2CPP 编译慢但运行快。

Unity 2026 年 AI 工具有哪些？

Unity Muse（创作辅助，对话生成代码）、Unity Sentis（本地模型推理，不用传服务器）。我试过 Muse 写简单的 UI 脚本，确实能省点时间，但复杂逻辑还是得自己写。

WebGL 导出性能怎么样？

比原生差 30-50%，内存限制大。简单 2D 游戏还行，3D 别想了。WebGPU 支持后好一些，但浏览器兼容性还是问题。
