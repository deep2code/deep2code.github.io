游戏热更方案

🏷️ 游戏开发

为什么手游需要热更

苹果 App Store 审核一个版本要 1-3 天，紧急 bug 根本等不起。所以手游行业搞出了"热更新"——不重新过商店审核，直接下载新代码替换。我 2021 年做手游的时候踩过这个坑：线上闪退，苹果审核排了两天，玩家跑了一半。从那以后热更就是刚需。

三条技术路线

国内 Unity 热更方案主要三代演进：

方案原理性能2026 现状
Lua 系（xlua/tolua）嵌 Lua 虚拟机解释执行中，C#/Lua 互调开销大老项目维护，新项目少用
ILRuntime解释执行 C# DLL低，慢 3-10 倍渐被替代
HybridCLRIL2CPP 解释器直接跑热更 DLL高，接近原生国内主流

HybridCLR 原名 huatuo（花驼），2021 年开源后迅速取代了 ILRuntime。原理是在 IL2CPP 的 AOT 编译之外加一个解释器——

  • AOT 部分：原生编译，性能不变
  • 热更 DLL：用解释器跑，比 Lua 高 3-5 倍，C# 语法全兼容
我为什么选 HybridCLR

2023 年我们项目从 xlua 迁到 HybridCLR。原因：Lua 调 C# 的互调开销太大，一个技能系统每帧调几十次 Lua，GC 卡顿明显。迁完之后同屏 200 个单位从 30 帧跑到 55 帧。C# 全语法兼容，迁移成本也不高。

ET 框架：C# 双端游戏框架

ET（Entity Threading）是开源的 C# 双端游戏框架。客户端和服务端同一套代码，省了一套语言的维护成本。ET 7 以后从 ILRuntime 切到了 HybridCLR。

ECS 架构：Entity + Component + System

ET 的核心是 ECS。Entity 就是个空 ID 容器，数据全挂 Component，逻辑全在 System 里跑。

    }

网络：KCP 为什么比 TCP 快

ET 默认用 KCP。KCP 是基于 UDP 的可靠传输，没有 TCP 的拥塞控制，所以延迟低 30-40%。

TCPKCP
传输层操作系统内核用户态实现
重传策略RTO 退避（慢）快速重传
拥塞控制有可配（默认无）
延迟高（200ms+）低（100ms 以内）
带宽浪费少多（冗余 10-20%）
适合普通业务MOBA/FPS 实时对战

代价是 KCP 会浪费带宽——为了低延迟，丢包了就立刻重传，不等 RTO。实时对战这点带宽换延迟值。

HybridCLR 热更完整流程

flowchart LR A[开发阶段
AOT 编译核心代码] --> B[热更 DLL
用解释器跑] B --> C[打包到 CDN] C --> D[玩家客户端启动
检查版本] D --> E[下载差量 DLL] E --> F[LoadAssembly 加载] F --> G[进入游戏] style B fill:#fff3e0 
// 加载热更 DLL
var assembly = HybridCLR.RuntimeApi.LoadAssemblyForHotUpdate("HotUpdate.dll");
var type = assembly.GetType("HotUpdate.TestClass");
type.GetMethod("HotUpdateMethod").Invoke(null, null);

关键设计：AOT 代码定义接口，热更代码实现接口。这样替换实现不影响调用方。项目一开始就要规划好哪些接口放 AOT、哪些逻辑放热更。

5 个热更的坑

  1. AOT 泛型缺失：热更 DLL 里用到 List<int> 这种泛型类，IL2CPP 没预编译，运行时报错。要在 AOT 侧补充泛型元数据
  2. 热更 DLL 被篡改：热更包从 CDN 下载，MD5/SHA 校验必须做。不然有人改 DLL 注入作弊代码
  3. 事件订阅不取消：热更代码加载了新 DLL，旧 DLL 的事件还在监听，内存泄漏。切热更版本时清空事件系统
  4. 异步异常被吞：ETTask 的 fire-and-forget 异常静默失败。顶层 try-catch 记日志
  5. 过早分布式：几千人在线单进程够了。上来就拆多进程，状态同步复杂度翻十倍

FAQ

HybridCLR 有性能损失吗？

热更代码走解释器，比 AOT 原生慢 10-20%。但比 Lua 快 3-5 倍。把性能敏感的逻辑（战斗循环、寻路）放 AOT，UI 和业务逻辑放热更，综合性能损失很小。

热更包多大合适？

差量包控制在 5MB 以内。资源和代码分开——代码热更 DLL 几 MB，资源走 Addressables 按需下载。全量包超过 20MB 玩家就不愿意下了。

ET 框架学习成本高吗？

会 C# 和 Unity 的话上手挺快。ECS 概念需要适应——一开始会觉得"为什么不能直接 new 个 Player"。写两个 Demo 就习惯了。文档中文社区维护，国内资料多。

热更被苹果拒审怎么办？

苹果不反对热更代码，但反对热更下载新功能（比如热更一个赌博模块上去）。规则是：热更只能修 bug 和调数值，不能加新的玩法。审核时别在审核版本里展示热更能力，过了审再开。
