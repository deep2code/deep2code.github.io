<h3 id="memcached-cluster">集群与扩展方案</h3>
<ul>
<li>官方没有内置集群：水平扩展靠<strong>客户端一致性哈希</strong>（如 ketama）与虚拟节点，故障时只影响少数缓存键</li>
<li>典型拓扑：多台实例 + Twemproxy / 自研代理层或直连客户端分片</li>
<li>相比 Redis Cluster：Memcached 集群更"裸"，没有元数据与 Gossip 开销，适合纯粹的缓存层</li>
</ul>
<blockquote>
<p>实践要点：缓存层设计成"可整体清空重建"，应用侧对缓存缺失做降级，Memcached 节点增减就无痛了。</p>
</blockquote>

<h3 id="memcached-alternatives">替代与竞品：Dragonfly / Valkey（2026）</h3>
<p>如果嫌 Memcached 太朴素，2026 年有两大主流替代：</p>
<ul>
<li><strong>Dragonfly</strong>：多线程共享内存架构，协议同时兼容 Redis 与 Memcached，Memcached 存量应用几乎零改动迁移，单机吞吐在官方基准中数倍于 Redis 单线程</li>
<li><strong>Valkey</strong>（Linux 基金会）：Redis 7.2 的社区分支，命令集兼容，若组织要求"纯开源治理"且想兼顾数据结构能力可评估替换</li>
</ul>
