<h3 id="redis-7-features">Redis 7.x 关键特性回顾</h3>
<ul>
<li><strong>ACL v2</strong>：细粒度权限控制，支持用户、命令、Key 维度授权</li>
<li><strong>Function</strong>：持久化 Lua 脚本，替代易失的 EVAL/EVALSHA</li>
<li><strong>Multi-part AOF</strong>：AOF 分片存储，避免重写阻塞主线程</li>
<li><strong>Sharded Pub/Sub</strong>：分片发布订阅，消息只在持有对应 slot 的节点传播</li>
<li><strong>LISTPACK</strong>：更紧凑的内存编码，替代 ziplist</li>
</ul>

<h3 id="redis-stack">Redis Stack 退场</h3>
<p>Stack 发行版已被 8.0 完全吸收进主线，<strong>不再作为独立产品维护</strong>；需要搜索/JSON/时序/概率结构的用户直接升级到 8.x 即可。</p>

<h3 id="valkey-eco">生态：Valkey 与 Dragonfly</h3>
<p>2024 年许可风波催生了社区分支，2026 年选型绕不开它们：</p>
<ul>
<li><strong>Valkey</strong>：Linux 基金会托管（Google、AWS、Oracle、腾讯等共建），基于 7.2.4 fork；Valkey 9 加入集群多逻辑库、原子 slot 迁移、官方 JSON/Bloom/向量模块，命令集与 Redis 7.2 兼容</li>
<li><strong>Dragonfly</strong>：多线程共享内存架构，单节点吞吐号称数倍于 Redis 单线程，协议同时兼容 Redis 与 Memcached，可用作无缝替换</li>
</ul>
<blockquote>
<p>选择建议：认官方血统就用 Redis 8.x；对开源许可与治理有硬约束用 Valkey；单机极致吞吐可评估 Dragonfly。</p>
</blockquote>
