Nginx 安装更新：官方仓库与版本线

版本线选型：mainline vs stable

2026 年 Nginx.org 官方仓库的版本线（单数 = 主线、双数 = 稳定，和官方约定一致）：

通道版本说明
mainline（主线）1.31.x约 1-2 个月一版，含最新特性；官方默认推荐用于生产
stable（稳定）1.30.x约一年一版或按需回溯关键修复；严格稳定性要求的选它
维护线1.28.x旧稳定线，仅关键安全修复

官方明确建议：没有特殊稳定性约束时，生产环境直接用 mainline；已上 stable 的按「偶数版本相邻升级」滚动就行。

官方 apt 仓库

官方仓库已覆盖 Ubuntu 22.04 / 24.04 / 26.04（resolute）、Debian 11 / 12 / 13（trixie）、RHEL 8 / 9 / 10、Alpine 3.21-3.24 等，全部支持 x86_64 和 aarch64 / arm64。推荐做法（仓库地址已统一为 HTTPS）：

# Ubuntu/Debian - 官方仓库（https）
sudo apt install -y curl gnupg2 ca-certificates lsb-release ubuntu-keyring
curl -fsSL https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] https://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" | sudo tee /etc/apt/sources.list.d/nginx.list
# 让官方源优先于系统源
echo -e "Package: *\nPin: origin nginx.org\nPin-Priority: 900\n" | sudo tee /etc/apt/preferences.d/99nginx
sudo apt update && sudo apt install nginx

# 改用 mainline 通道（默认装的是 stable）
# 把上面 sources.list 里的 " nginx " 换成 " nginx/mainline "
  • 密钥指纹：2024 年起官方签名密钥更新，校验时匹配 573B FD6B 3D8F BC64 1079 A6AB ABF5 BD82 7BD9 BF62。
  • 为何不用系统源：Ubuntu / Debian 自带的 Nginx 通常落后多个大版本且模块受限（比如 Ubuntu 24.04 默认还是 1.18 系）。
  • 版本固定：需要锁版本时 apt list -a Nginx 查看可用版本，apt install Nginx=<版本> 后 apt-mark hold Nginx。

macOS 与 Docker

# macOS
brew install nginx

# Docker（官方镜像：1.31 mainline 标签）
docker run -d --name nginx -p 80:80 -p 443:443 -v ./nginx.conf:/etc/nginx/nginx.conf nginx:mainline

Docker 官方镜像的 Nginx 标签默认指向 mainline；Nginx:stable 是稳定线，按需选用。

模块系统：静态 vs 动态

Nginx 模块系统：

  静态模块（默认）：
  - 编译时链接到 nginx 二进制文件
  - 优点：运行时无加载开销，性能略好
  - 缺点：增删模块必须重新编译
  - 用法：./configure --with-http_ssl_module

  动态模块（Nginx 1.9.11+）：
  - 编译为独立的 .so 文件
  - 运行时通过 load_module 指令加载
  - 优点：增删模块无需重新编译主程序
  - 缺点：少量加载开销（可忽略）
  - 用法：
    ./configure --with-http_geoip_module=dynamic
    配置文件：load_module modules/ngx_http_geoip_module.so;

  第三方模块：
  - 编译时通过 --add-module 加入
  - 静态：--add-module=/path/to/module
  - 动态：--add-dynamic-module=/path/to/module
  
  常用第三方模块：
  - ngx_devel_kit（NDK）：开发工具包，很多模块依赖
  - lua-nginx-module：Lua 脚本支持（OpenResty 核心）
  - echo-nginx-module：echo/sleep 等调试指令
  - headers-more-nginx-module：更灵活的响应头控制
  - ngx_cache_purge：缓存清除
  - nginx-rtmp-module：RTMP 流媒体
  - nginx-upsync-module：动态 upstream（consul/etcd）

从源码编译完整流程

#!/bin/bash
# Nginx 从源码编译完整脚本

set -e

# 1. 安装编译依赖
apt-get update
apt-get install -y build-essential libpcre3 libpcre3-dev     zlib1g zlib1g-dev libssl-dev libgd-dev libxml2-dev     libxslt1-dev libgeoip-dev libmaxminddb-dev

# 2. 下载源码
NGINX_VERSION=1.26.2
PCRE_VERSION=8.45
ZLIB_VERSION=1.3.1
OPENSSL_VERSION=3.0.13

cd /usr/local/src
wget https://nginx.org/download/nginx-${NGINX_VERSION}.tar.gz
wget https://ftp.pcre.org/pub/pcre/pcre-${PCRE_VERSION}.tar.gz
wget https://zlib.net/zlib-${ZLIB_VERSION}.tar.gz
wget https://www.openssl.org/source/openssl-${OPENSSL_VERSION}.tar.gz

tar xzf nginx-${NGINX_VERSION}.tar.gz
tar xzf pcre-${PCRE_VERSION}.tar.gz
tar xzf zlib-${ZLIB_VERSION}.tar.gz
tar xzf openssl-${OPENSSL_VERSION}.tar.gz

# 3. 下载第三方模块
git clone https://github.com/vision5/ngx_devel_kit.git
git clone https://github.com/openresty/lua-nginx-module.git
git clone https://github.com/openresty/headers-more-nginx-module.git

# 4. 配置编译选项
cd nginx-${NGINX_VERSION}
./configure     --prefix=/usr/local/nginx     --user=nginx --group=nginx     --with-pcre=../pcre-${PCRE_VERSION}     --with-pcre-jit     --with-zlib=../zlib-${ZLIB_VERSION}     --with-openssl=../openssl-${OPENSSL_VERSION}     --with-http_ssl_module     --with-http_v2_module     --with-http_realip_module     --with-http_gzip_static_module     --with-http_stub_status_module     --with-http_auth_request_module     --with-http_secure_link_module     --with-http_slice_module     --with-stream     --with-stream_ssl_module     --with-mail     --with-mail_ssl_module     --add-module=../ngx_devel_kit     --add-module=../lua-nginx-module     --add-module=../headers-more-nginx-module     --with-cc-opt="-O2 -march=native"

# 5. 编译安装
make -j$(nproc)   # 并行编译，利用所有 CPU 核心
make install

# 6. 创建用户和服务
useradd -r -s /sbin/nologin nginx
cat > /etc/systemd/system/nginx.service << 'EOF'
[Unit]
Description=Nginx Web Server
After=network.target

[Service]
Type=forking
PIDFile=/usr/local/nginx/logs/nginx.pid
ExecStart=/usr/local/nginx/sbin/nginx
ExecReload=/usr/local/nginx/sbin/nginx -s reload
ExecStop=/usr/local/nginx/sbin/nginx -s quit
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable nginx
systemctl start nginx

# 7. 验证
/usr/local/nginx/sbin/nginx -V  # 查看编译版本和模块
curl -I http://localhost/

版本选择策略

Nginx 版本分支：

  Mainline（主线版）：
  - 奇数版本号：1.25.x, 1.27.x
  - 最新功能，活跃开发
  - 可能有新 bug
  - 适合：需要最新功能（如 HTTP/3）、测试环境
  
  Stable（稳定版）：
  - 偶数版本号：1.24.x, 1.26.x
  - 只修复关键 bug 和安全漏洞
  - 生产环境推荐
  - 适合：生产环境、稳定性优先
  
  旧版本维护：
  - 1.22.x, 1.20.x 等旧稳定版
  - 只修复安全漏洞
  - 建议尽快升级到最新稳定版

  版本号规则：
  - 主版本号.次版本号.补丁号
  - 次版本号奇数 = mainline，偶数 = stable
  - 例如：1.26.2 = 主版本1，次版本26（稳定），补丁2

  升级建议：
  - 生产环境：跟随 stable 分支，定期升级补丁版本
  - 大版本升级：先在测试环境验证，再灰度升级
  - 回滚方案：保留旧版本二进制，配置文件备份
  - 平滑升级：make upgrade（不中断服务的热升级）

官方 v3 模块（ngx_http_v3_module）是 OpenSSL 3.x + QUIC 的推荐路径；多数发行版包不含这个模块，要启用 HTTP/3 得自行从源码构建：

# 启用 HTTP/3 需要从源码编译（mainline 源码）
./configure --with-http_v3_module --with-http_ssl_module --with-debug
make && make install

注意：--with-http_v3_module 依赖 OpenSSL 3.x（含 QUIC），构建前确认系统的 OpenSSL 版本满足要求。
