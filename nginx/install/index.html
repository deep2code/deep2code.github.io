AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • 以 1.21.6（2022 年）演示源码安装全流程，2026 现值机 1.31.x mainline / 1.30.x stable
  • --prefix 规划默认路径，--with-debug 增加调试日志（正式环境别开）
  • 第三方模块装载与 HTTP/3 源码编译姿势清晰

关键结论与取舍

  • 线上用 stable 1.30.x，想提前拿特性用 mainline 1.31.x
  • 官方 apt 仓库 2026 已是入门首选，源码编译留给定制需求

Nginx 安装更新（2026）：官方仓库与版本线

版本线选型：mainline vs stable

2026 年 nginx.org 官方仓库的版本线（单数 = 主线、双数 = 稳定，和官方约定一致）：

通道版本说明
mainline（主线）1.31.x约 1-2 个月一版，含最新特性；官方默认推荐用于生产
stable（稳定）1.30.x约一年一版或按需回溯关键修复；严格稳定性要求的选它
维护线1.28.x旧稳定线，仅关键安全修复

官方明确建议：没有特殊稳定性约束时，生产环境直接用 mainline；已上 stable 的按「偶数版本相邻升级」滚动就行。

官方 apt 仓库（2026）

官方仓库已覆盖 Ubuntu 22.04 / 24.04 / 26.04（resolute）、Debian 11 / 12 / 13（trixie）、RHEL 8 / 9 / 10、Alpine 3.21-3.24 等，全部支持 x86_64 和 aarch64 / arm64。推荐做法（仓库地址已统一为 https）：

# Ubuntu/Debian - 官方仓库（https）
sudo apt install -y curl gnupg2 ca-certificates lsb-release ubuntu-keyring
curl -fsSL https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] https://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" | sudo tee /etc/apt/sources.list.d/nginx.list
# 让官方源优先于系统源
echo -e "Package: *\nPin: origin nginx.org\nPin-Priority: 900\n" | sudo tee /etc/apt/preferences.d/99nginx
sudo apt update && sudo apt install nginx

# 改用 mainline 通道（默认装的是 stable）
# 把上面 sources.list 里的 " nginx " 换成 " nginx/mainline "
  • 密钥指纹：2024 年起官方签名密钥更新，校验时匹配 573B FD6B 3D8F BC64 1079 A6AB ABF5 BD82 7BD9 BF62 。
  • 为何不用系统源：Ubuntu / Debian 自带的 nginx 通常落后多个大版本且模块受限（比如 Ubuntu 24.04 默认还是 1.18 系）。
  • 版本固定：需要锁版本时 apt list -a nginx 查看可用版本，apt install nginx=<版本> 后 apt-mark hold nginx 。

macOS 与 Docker

# macOS
brew install nginx

# Docker（官方镜像：1.31 mainline 标签）
docker run -d --name nginx -p 80:80 -p 443:443 -v ./nginx.conf:/etc/nginx/nginx.conf nginx:mainline

Docker 官方镜像的 nginx 标签默认指向 mainline；nginx:stable 是稳定线，按需选用。

HTTP/3：源码编译的官方姿势

官方 v3 模块（ngx_http_v3_module）是 OpenSSL 3.x + QUIC 的推荐路径；多数发行版包不含这个模块，要启用 HTTP/3 得自行从源码构建：

# 启用 HTTP/3 需要从源码编译（mainline 源码）
./configure --with-http_v3_module --with-http_ssl_module --with-debug
make && make install

注意：--with-http_v3_module 依赖 OpenSSL 3.x（含 QUIC），构建前确认系统的 OpenSSL 版本满足要求。
