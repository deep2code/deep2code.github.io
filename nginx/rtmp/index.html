RTMP

下载安装rtmp模块

编译

# 在 nginx 源码根目录执行;模块停更现状与 2026 替代方案见文末「RTMP 模块更新」
./configure --prefix=/Users/Shared/nginx \
             --add-module=../nginx-party-module/nginx-rtmp-module \
             --with-http_ssl_module \
             --with-openssl=/opt/homebrew/opt/openssl@3\   # openssl@1.1 已于 2023-09 EOL
             --with-debug
make
make install

修改配置

rtmp {
    server {
        listen 1935;
        application vod {
            play /Users/xxx/iCloud-archive/video;
        }
    }
}

附录

  • RTMP、RTSP、HTTP协议理论上都可以用来做视频直播或点播,直播一般用RTMP,RTSP,点播用 HTTP

  • RTMP协议

    • 是流媒体协议。
    • RTMP 规范 Adobe 早在 2009 年公开,但 Flash/RTMP 生态已随 2020-12-31 Flash 停更整体退场,如今只在推流入口(Push)存活
    • RTMP协议一般传输的是 flv，f4v 格式流。
    • RTMP一般在 TCP 1个通道上传输命令和数据。

  • RTSP协议

    • 是流媒体协议。
    • RTSP协议是共有协议，并有专门机构做维护
    • RTSP协议一般传输的是 ts、mp4 格式的流。
    • RTSP传输一般需要 2-3 个通道，命令和数据通道分离。

  • HTTP协议

    • HTTP 本身不是流媒体协议(无状态流语义),HLS/DASH 只是把媒体切片装进普通 HTTP 文件请求
    • HTTP协议是共有协议，并有专门机构做维护
    • HTTP协议没有特定的传输流
    • HTTP 是请求-响应模型:每个媒体分段一个 GET 请求,没有独立命令通道;分片文件天然适合 CDN 缓存与多级分发

RTMP 模块更新

原版 nginx-rtmp-module（arut）官方 tag 仍停留在 v1.2.x，多年未发新正式版，仅有零星编译修复提交——基本处于「停更维护」状态，社区靠 fork（如 nginx-http-flv-module 等）延续。新 nginx 主线（1.29+/1.31）若需使用该模块，务必在目标 nginx 版本上重新编译并做推拉流回归测试，不建议直接沿用旧版本二进制。2026 年自建直播服务的选型如下：

2026 替代方案对照

方案语言定位与要点
SRSC++老牌开源流媒体服务器（Go 编写是常见误传），RTMP/HTTP-FLV/HLS/WebRTC/SRT 全协议，生态与文档完善，适合自建单点直播
MediaMTXGo轻量统一接入层，RTSP/RTMP/HLS/WebRTC/SRT 互转，单二进制易部署，适合把现有 RTSP/RTMP 源转成 WebRTC/HLS 分发
OvenMediaEngineC++韩系商业化开源，主打 LL-HLS 与低延迟 WebRTC 分发，集群与 Edge 架构成熟
ZLMediaKitC++国内社区活跃，RTSP/RTMP/HTTP-FLV/HLS 全覆盖，C API 二次开发友好

何时继续用 nginx-rtmp

若只是「OBS 推流 → 服务器录制/转 HLS 点播」的轻量内部场景，nginx-rtmp 加 hls on 分片仍然够用，配置熟悉、无迁移成本，注意录制用 record 指令落 FLV、HLS 分片 2-4s 可兼顾兼容与延迟。一旦需要 WebRTC 低延迟分发、多协议互转、集群扩容，就应迁移到上表方案——2026 年直播协议格局是「RTMP 仍是推流主流入口（OBS/手机推流兼容性最好），分发端已全面转向 HLS/LL-HLS/WebRTC」，nginx-rtmp 无法原生终结 WebRTC 是其最大短板。
