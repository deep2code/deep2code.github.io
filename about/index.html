关于本站

这个站写什么，不写什么

这里是一个后端工程师的技术笔记站，写作对象是已经在生产环境里维护过服务的人。判断一篇内容要不要写，标准只有一条：它能不能改变读者的一个决策。能改变决策的是机制、代价与边界条件；不能改变决策的是安装步骤、API 罗列和把官方文档换句话说。

内容类型是否收录原因
机制层面的解释（为什么这样设计、内部怎么跑）核心理解机制才能预测没见过的故障，记住结论只够应付见过的场景
方案对比与决策矩阵（各维度差异、失效场景）核心工程里没有「更好」，只有「代价挪到哪里」，矩阵比结论耐用
常见错误认知的纠正核心流传最广的说法往往漏掉了前提条件，这类内容密度最高
参数默认值、量级数字、版本差异收录不带默认值和数量级的调参讨论无法验证，只会变成口味之争
可直接敲的排查命令与输出判读收录排障的难点不是敲命令，而是看懂哪个字段在说谎
安装步骤、快速开始、API 清单不写官方文档更快更准，复述一遍会在版本变化后变成错误信息
新闻式版本速报不写没有落地取舍的版本号罗列，三个月后即失效
无法复现的跑分不写脱离硬件、数据集与并发模型的数字会误导选型

每篇文章的深度标准

站内的文章按同一套规格写，目标不是字数，而是信息密度：能用表承载的不写成段落，能用图表达结构的不写成流程叙述。下面这张表就是实际的验收口径，也说明了什么样的写法会被判定为不合格。

要素本站的要求被判为不合格的写法
表格可决策的对比矩阵：默认值与调错后果、各维度差异、失效场景与修法、输出字段判读只有「优点 / 缺点」两列，或第二列是第一列的同义复述
图按信息类型选图：分层归属用带子图的流程图，协议往返用时序图，生命周期用状态图，选型用判定图把三个名词连成一条直线的流程图，本质是给标题加了个框
代码能直接抄走用，带关键参数和「为什么这么写」的注释伪代码、省略号占位、留着待办注释
视角先说边界条件与失效场景，再说正常路径；主动纠正流传很广的说法只覆盖 happy path，出问题时读者一无所依
结尾一个「最容易踩的坑」清单，每条都能复现、能对号入座「要注意安全」「建议做好监控」这类无法执行的空话
去重与已有文章重叠的主题只做要点概述并指明详见哪篇同一段原理在多篇里各写一遍，且细节互相矛盾

技术实现：一个没有构建步骤的静态站

整站就是一堆手写的 index.html，没有构建步骤、没有 node_modules、没有模板引擎。仓库里的文件与线上产物一一对应，diff 出来的就是最终产物。所有第三方资源自托管在 vendor/ 下，页面不依赖任何 CDN 上的脚本。

能力实现方式代价与边界

为什么不用静态站点生成器

这不是「更好」的选择，而是把成本挪到了别的地方。站内《静态站点生成的构建模型与内容架构》那篇专门算过这笔账：真正把你锁定在生成器里的不是 Markdown 正文，而是模板语言、专有的正文内嵌语法，以及目录结构与永久链接共同形成的 URL 契约。手写 HTML 放弃了模板复用，换来的是零依赖与产物即源码。

维度手写 HTML 且无构建（本站）生成器加主题带后台的内容系统
新增一页的成本最高，复制一份现有页面再改最低，写一个 Markdown 文件后台点几下
全站改版成本要写脚本批量改写每个文件，脚本本身还得先测改模板，一次生效换主题，受后台能力限制
一致性保障靠纪律与自检脚本，页面间容易出现细微不一致模板天然保证系统保证
工具链风险零依赖，十年后浏览器照样打开受版本升级影响，主题可能失去维护需要持续运维与升级
产物可审查性diff 就是最终产物，改了什么一目了然diff 是源码，要构建后才知道效果基本无 diff 可言
非工程师参与基本不可能会写 Markdown 就行最友好

页面规模是分界线：几十页且改版不频繁时，零依赖换来长期省心；上百页或多人协作时，模板化的一致性收益会迅速超过它引入的构建复杂度。本站已经越过这条线，所以补的不是生成器，而是只做校验不做生成的脚本——检查标签配平、代码块转义、图表标签引号、路径变量缺失、结构化数据能否被解析。这条路可以随时回退，引入生成器则不能。

搜索是纯前端子串匹配，不分词也不纠错：搜「一致」有结果，搜错别字就没有；结果只显示标题，不做摘要高亮。这是纯静态站的固有取舍——索引是提交时的产物，不是查询时计算的服务。相应地，本站没有评论、没有表单、不做个性化，也不收集访客数据，浏览器里只留一个记住明暗主题的本地存储键。

从 2004 到 2026，一个理工男的编程之路

AI 对软件开发的影响

架构变革

从单体→微服务→AI-native：系统设计不再只考虑人读 API，更要为 Agent 设计可发现、可调用的接口。MCP 成为新的"API 网关"。

编码方式

从手写每一行代码到自然语言描述意图→AI 生成→人工审查。Copilot/Codeium 已是标配，Claude Code/Cursor 让"对话式编程"成为日常。

测试与质量

AI 自动生成测试用例、发现边界条件、审计代码安全。从"写完再测"到"边写边测边修复"，CI/CD 管线深度嵌入 AI。

运维与部署

Agent 自主排查线上故障、生成修复方案、执行回滚。从人盯监控大盘到 AI 预警→自动止损→人工确认。

团队与协作

一人+多 Agent 成为新型"全栈团队"。PRD 由 AI 起草、代码由 AI 生成、文档由 AI 编写——人的角色从"执行者"变为"决策者"。

未来趋势

模型即基础设施，Skill 即应用，Agent 即用户。软件开发的终局不是"写代码"，而是"定义意图、约束边界、验证结果"。
