RAG 实战

RAG 是什么

Retrieval-Augmented Generation，检索增强生成。先从知识库检索相关文档，再把文档内容放到 Prompt 里让 LLM 回答。解决 LLM 不知道私有知识、知识截止的问题。

graph LR A[用户问题] --> B[检索知识库] B --> C[相关文档片段] C --> D[拼接 Prompt] D --> E[LLM 生成答案] E --> F[最终回答]

完整 RAG 流程

from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import Chroma
from langchain.chains import RetrievalQA

# 1. 加载文档
loader = PyPDFLoader("company-handbook.pdf")
documents = loader.load()

# 2. 分块
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)
chunks = text_splitter.split_documents(documents)

# 3. 存入向量数据库
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(chunks, embeddings)

# 4. 创建 RAG Chain
qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-4o"),
    chain_type="stuff",
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3})
)

# 5. 提问
result = qa.invoke("公司年假有多少天？")
print(result["result"])

分块策略很重要

参数推荐值说明
chunk_size500-1000太小丢失上下文，太大检索不准
chunk_overlap50-100块之间重叠，避免截断
分隔符先按段落，再按句子RecursiveCharacterTextSplitter
优化技巧：检索质量比生成质量更重要。检索不到相关文档，再强的 LLM 也答不对。多花时间调分块和检索参数。
