Fine-tuning 微调

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • 传统 Fine-tuning 是改 output 层、微调前层参数、加大末层学习率的迁移学习
  • LLM 时代参数动辄数十亿，全量微调代价过高，主流转向 LoRA/QLoRA 等 PEFT
  • 文末更新节覆盖 2024-2026 微调技术演进

关键结论与取舍

  • 小模型或专业任务仍可用全量微调；LLM 场景默认 LoRA 起步
  • 先评估数据量级与任务偏移度，再决定微调还是走 RAG 或 Prompt 工程
适合谁读想微调大模型但被算力与成本困扰的工程师 读完可获得迁移学习→PEFT 的演进逻辑，以及 LoRA 族方法的选型依据

深度学习 Fine-tuning 微调技术

Fine-tuning（微调）是深度学习中迁移学习的核心技术。其原理是利用已知的网络结构和预训练参数，修改 output 层为自定义层，微调最后一层前的所有层参数，同时加大最后一层的学习率（因为需要重新学习），这样既有效利用了深度神经网络强大的泛化能力，又免去了设计复杂模型和耗时良久的训练。

上述是传统迁移学习（替换 CNN 分类头）的视角；LLM 时代参数动辄数十亿、全量微调代价过高，主流已转向 LoRA / QLoRA 等参数高效微调（PEFT），见下文。

微调的主要方式

1. Full Fine-tuning（全量微调）

更新模型所有参数，效果最好但计算成本高，需要大量 GPU 显存。

from transformers import AutoModelForSequenceClassification, Trainer, TrainingArguments

model = AutoModelForSequenceClassification.from_pretrained("bert-base-chinese", num_labels=10)

training_args = TrainingArguments(
    output_dir="./results",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    learning_rate=5e-5,
    weight_decay=0.01,
)

trainer = Trainer(model=model, args=training_args, train_dataset=train_ds)
trainer.train()
2. LoRA（Low-Rank Adaptation）

LoRA 通过在权重矩阵旁增加低秩分解矩阵来实现高效微调，只训练少量参数（通常 <1%），极大降低显存需求。

from peft import LoraConfig, get_peft_model, TaskType

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,                    # 低秩矩阵的秩
    lora_alpha=32,          # 缩放因子
    lora_dropout=0.1,
    target_modules=["q_proj", "v_proj"],  # 应用 LoRA 的层
)

model = get_peft_model(base_model, lora_config)
model.print_trainable_parameters()
# 输出示例: trainable params: 1,474,560 || all params: 7,000,000,000 || trainable%: 0.02%
3. QLoRA（Quantized LoRA）

QLoRA 在 LoRA 基础上对基础模型做 4-bit 量化（NF4 + 双重量化），单张 48GB 显存显卡即可微调 65B/70B 级模型；24GB 消费级显卡可微调 7B–13B 级模型。

from transformers import BitsAndBytesConfig
import torch

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b",  # gated 仓库：需先在 HF 同意许可协议并配置访问 token
    quantization_config=bnb_config,
    device_map="auto",
)

微调方式对比

方式训练参数量显存需求效果适用场景
Full Fine-tuning100%高最好有充足 GPU 资源
LoRA0.1%-1%中接近全量资源受限场景
QLoRA0.1%-1%低略低于 LoRA单卡微调大模型
P-Tuning v20.1%低中等自然语言理解任务

实践建议

  1. 数据质量 > 数据量：1,000 条高质量样本比 10,000 条低质量样本效果好。
  2. 学习率选择：LoRA 通常用 1e-4 到 5e-4，全量微调用 1e-5 到 5e-5。
  3. 评估指标：除了 loss，还要关注 BLEU、ROUGE 等任务相关指标。
  4. 防止过拟合：使用 early stopping、dropout 和 weight decay。
  5. 数据格式：使用 ChatML 或 Alpaca 格式，保持与推理时一致的 prompt 模板。

微调更新（2024-2026）

  • LoRA / QLoRA 成为默认：配合 PEFT / Unsloth，7B–14B 模型微调已是单卡日常（24GB 消费卡即可跑通）；
  • 对齐微调：推理模型常用 RLHF / GRPO 对齐（DeepSeek-R1 风格）来强化代码与数学能力，但数据与算力门槛高，多数场景仍以 SFT + 提示词工程为主；
  • 蒸馏数据：高质量训练集多来自强模型蒸馏输出，纯人工标注比例下降；
  • 替代路径：RAG、超长上下文与工具调用常能覆盖「为回答某类问题而微调」的场景，动手前先评估是否真的需要微调；
  • 中文工具链：Qwen3、GLM-5 等开源基座 + LLaMA-Factory / ms-swift 微调工具，是中文微调的主流组合。
