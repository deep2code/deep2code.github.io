模型微调

深度学习 Fine-tuning 微调技术

Fine-tuning（微调）是深度学习里迁移学习的看家本领。思路是：复用已知的网络结构和预训练参数，把 output 层换成自定义层，微调最后一层之前的所有层，同时把最后一层的学习率调大（毕竟要重新学），这样既吃到了深度网络强大的泛化红利，又省去从零设计模型和漫长训练的功夫。

上面这套是传统迁移学习（换 CNN 分类头）的视角；到了 LLM 时代，参数动辄几十亿，全量微调太烧钱，主流已经转向 LoRA / QLoRA 这类参数高效微调（PEFT），往下看。

微调的主要方式

1. Full Fine-tuning（全量微调）

更新模型全部参数，效果最顶但算力代价高，得堆大量 GPU 显存。

from transformers import AutoModelForSequenceClassification, Trainer, TrainingArguments

model = AutoModelForSequenceClassification.from_pretrained("bert-base-chinese", num_labels=10)

training_args = TrainingArguments(
    output_dir="./results",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    learning_rate=5e-5,
    weight_decay=0.01,
)

trainer = Trainer(model=model, args=training_args, train_dataset=train_ds)
trainer.train()
2. LoRA（Low-Rank Adaptation）

LoRA 在权重矩阵旁边挂一组低秩分解矩阵来做高效微调，只训少量参数（通常不到 1%），显存需求大幅降下来。

from peft import LoraConfig, get_peft_model, TaskType

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,                    # 低秩矩阵的秩
    lora_alpha=32,          # 缩放因子
    lora_dropout=0.1,
    target_modules=["q_proj", "v_proj"],  # 应用 LoRA 的层
)

model = get_peft_model(base_model, lora_config)
model.print_trainable_parameters()
# 输出示例: trainable params: 1,474,560 || all params: 7,000,000,000 || trainable%: 0.02%
3. QLoRA（Quantized LoRA）

QLoRA 在 LoRA 之上再给基础模型套 4-bit 量化（NF4 + 双重量化），单张 48GB 显卡就能微调 65B / 70B 级模型；24GB 消费级显卡能微调 7B–13B 级。

from transformers import BitsAndBytesConfig
import torch

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b",  # gated 仓库：需先在 HF 同意许可协议并配置访问 token
    quantization_config=bnb_config,
    device_map="auto",
)

实践建议

  1. 数据质量压过数据量：1000 条高质量样本，效果胜过 10000 条低质量的。
  2. 学习率怎么挑：LoRA 一般用 1e-4 到 5e-4，全量微调用 1e-5 到 5e-5。
  3. 评估指标：别只盯 loss，BLEU、ROUGE 这类任务相关指标也得看。
  4. 防过拟合：上 early stopping、dropout 和 weight decay。
  5. 数据格式：用 ChatML 或 Alpaca 格式，prompt 模板要跟推理时对齐。

微调工具链

LoRA 原理与数学推导

LoRA（Low-Rank Adaptation）是目前最主流的参数高效微调方法，通过低秩矩阵分解大幅减少可训练参数。

LoRA 的核心直觉：微调时权重矩阵的变化量 ΔW 其实是"低秩"的——它可以用两个小矩阵的乘积来近似。这样只需训练 <1% 的参数，效果却接近全量微调，推理时还能把 A、B 合并回 W，零额外延迟。

LoRA 核心思想

传统微调：更新整个权重矩阵 W (d × k)
  W' = W + ΔW，ΔW 是完整的 d×k 矩阵
  可训练参数量：d × k（例如 4096×4096 = 16.7M）

LoRA：用两个低秩矩阵近似 ΔW
  ΔW = B × A，其中 B (d × r)，A (r × k)
  r << min(d, k)，通常 r=8~64
  
  W' = W + B × A
  
  可训练参数量：d × r + r × k = r × (d + k)
  例如 r=8, d=k=4096：8 × 8192 = 65,536（减少 99.6%！）

前向传播：
  h = W' × x = (W + B × A) × x = W × x + B × (A × x)
  推理时可以合并：W_merged = W + B × A，无额外延迟

LoRA 应用哪些层

Transformer 中的线性层：
  - Q, K, V, O 投影矩阵（注意力）
  - FFN 的上投影和下投影
  - LM Head（词表投影，通常不微调）

常见配置：
  - LLaMA 系列：只微调 Q, V（r=8~16）
  - 更全面：Q, K, V, O, FFN 上/下投影（r=16~64）
  - 全层 LoRA：所有线性层（r=8，参数量仍远小于全参数微调）

经验：
  - 注意力层的 Q, V 最重要（影响模型理解和生成）
  - FFN 层影响知识存储，需要时再加
  - r 不是越大越好，r=8 通常足够，r>64 收益递减

QLoRA：量化 + LoRA

QLoRA = 4bit 量化基础模型 + LoRA 微调

  显存对比（LLaMA-2 70B，batch size=1，序列长度=2048）：
  ┌──────────────┬──────────┬──────────────────┐
  │ 方法         │ 显存     │ 可训练参数       │
  ├──────────────┼──────────┼──────────────────┤
  │ 全参数 FP16  │ ~1.8TB   │ 70B              │
  │ 全参数 INT8  │ ~900GB   │ 70B              │
  │ LoRA FP16    │ ~160GB   │ 0.4M (r=8)      │
  │ QLoRA 4bit   │ ~48GB    │ 0.4M (r=8)      │
  └──────────────┴──────────┴──────────────────┘

  QLoRA 关键技术：
  1. 4bit NormalFloat (NF4) 量化
     - 基于正态分布的最优量化，比标准 4bit 精度更高
     - 分块量化（block size=64），减少量化误差
     
  2. 双重量化（Double Quantization）
     - 量化常数本身也被量化，进一步节省显存
     - 平均每个参数节省 0.37 bits
     
  3. 分页优化器（Paged Optimizers）
     - 用 NVIDIA 统一内存，显存不足时自动 offload 到 CPU
     - 防止 OOM，支持更大 batch size

  结论：QLoRA 可以在单张 48GB 显卡上微调 70B 模型，
  且效果接近全参数微调（MMLU 差距 < 1%）

微调超参调优指南

超参数推荐值说明
学习率1e-5 ~ 3e-4LoRA 可用较大学习率（2e-4），全参数微调用较小（1e-5）

梯度裁剪1.0防止梯度爆炸

LoRA alpha16~32通常 alpha = 2 × rank，控制缩放比例
LoRA dropout0.05~0.1防止过拟合

微调常见陷阱

  • 陷阱1：灾难性遗忘（Catastrophic Forgetting）
    • 微调后模型在通用任务上能力下降
    • 原因：学习率过大、训练轮数过多、数据分布太窄
    • 解决：用较小学习率、限制 epochs、混合通用数据、用 LoRA 而非全参数
  • 陷阱2：数据污染（Data Contamination）
    • 微调数据包含了评估集的答案，导致评估分数虚高
    • 解决：微调前用 n-gram 去重，确保训练集和测试集无重叠
  • 陷阱3：过拟合（Overfitting）
    • 训练 loss 持续下降，但验证 loss 上升，模型记住训练数据而非学习规律
    • 解决：早停（Early Stopping）、增加数据多样性、dropout、权重衰减
  • 陷阱4：指令模板不匹配
    • 微调时用的模板和推理时不一致，导致模型输出格式混乱
    • 解决：固定模板，微调和推理用完全相同的 prompt 格式
  • 陷阱5：只微调不评估
    • 没有建立评估流水线，无法判断微调效果
    • 解决：准备验证集，每个 epoch 后评估，监控关键指标
from peft import PromptEncoderConfig, get_peft_model

我微调过的一个真实项目

2025 年我在公司微调过一个客服意图分类模型。原始方案是用 GPT-4 直接分类，一个月 API 费三千多，而且延迟还不稳定。后来我们拿了 5000 条标注数据，在 Qwen3 7B 上用 LoRA 微调，效果差不多，成本直接砍到一个月两百块（推理走自己的 vLLM）。

说这个不是为了吹微调多厉害，而是想说：微调不是银弹，但当你的场景足够垂直、数据足够多、调用量足够大的时候，微调的 ROI 是算得过来的。我们当时算过账，日调用量超过 5 万次，微调就比调 API 划算。

什么时候值得微调

三个条件同时满足再考虑：场景足够垂直（比如客服意图、法律文书分类）、有几百到几千条标注数据、调用量大到 API 成本扛不住。缺一个就先别折腾，RAG 或者 Prompt 工程更划算。

LoRA 到底省了什么

很多人知道 LoRA 省显存，但不知道它到底在干嘛。说白了，全量微调是把模型每一层的权重都更新；LoRA 偷懒了，它在原权重旁边挂两个小矩阵 A 和 B，只训练这两个小矩阵，原权重冻着不动。

数学上就是 W' = W + BA，其中 W 是原始大矩阵，B 和 A 是小矩阵。原始 W 是 4096×4096，LoRA 的 B 和 A 可能是 4096×8 和 8×4096。训练参数量从 1600 万降到了 6.5 万，差了 250 倍。这就是为什么 LoRA 能在一张消费级显卡上跑。

微调方式训练参数量显存需求（7B模型）效果适合谁
全量微调100%~80GB（多张 A100）最好大厂、有充足算力
LoRA~0.5%~24GB（一张 4090）接近全量大多数场景
QLoRA~0.3%~12GB（消费级显卡）略低于 LoRA显存紧张、个人开发者
P-Tuning v2~0.1%~16GB中等参数极省，但效果一般

我的建议：有 4090 就用 LoRA，没条件就 QLoRA。2026 年了，P-Tuning 基本可以不用看了，LoRA 生态成熟得多。

数据比算法重要

微调这件事，我踩过最大的坑就是以为"算法调好了效果就好"。实际上数据质量才是决定性的。

有次我们拿了 2000 条数据微调，效果很差。后来花了一周清洗数据——去重、去噪、修正标注错误、补充边界 case——数据量没变，还是 2000 条，效果直接翻倍。这个教训我记到现在：微调 80% 的精力应该花在数据上，不是调参上。

数据问题表现怎么解决
标注错误模型学了错误的模式人工抽检 10%，发现错误批量修
数据重复过拟合，泛化差用 MinHash 去重
分布不均高频类学得好，低频类学不好低频类补数据，或做加权采样
缺边界 case训练集好看，线上翻车专门构造边界 case 加进去
别犯我犯过的错

微调完一定要在"没见过的数据"上测，别用训练集的 loss 汇报效果。训练集 loss 再低，线上翻车等于白干。留出 10% 做验证集，跟训练集严格隔离。

常见问题 FAQ

Q1：微调跟 RAG 怎么选？

看你要什么。要"知识"（比如企业内部文档），用 RAG，知识更新方便；要"风格"或"格式"（比如固定的输出模板、特定领域的术语习惯），用微调。最常见的错误是拿微调去灌知识——知识会过期，微调成本又高，RAG 才是对的工具。

Q2：微调一个 7B 模型要多少钱？

自己有显卡的话，一张 4090 跑 LoRA，几小时就完事，成本就是电费。用云 GPU 的话，租一张 A100 跑一天大概几十到一百块。2026 年微调一个 7B 模型的成本，已经降到大多数团队能承受的范围了。

Q3：微调会让模型变笨吗？

会，这叫"灾难性遗忘"。全量微调尤其明显，LoRA 好很多但也不是完全免疫。解决办法：一是学习率别太大，二是混入一部分通用数据，三是优先用 LoRA 而不是全量。如果你发现微调后模型的通用能力下降了，大概率是学习率太大或者训过头了。

Q4：微调后的模型怎么部署？

LoRA 有两种部署方式：一是把 LoRA 权重合并进原模型，直接用 vLLM 加载；二是用支持 LoRA 热加载的推理框架（比如 vLLM 的 LoRA serving）。我推荐合并后部署，简单稳定，性能也好。

Q5：多少条数据才够微调？

看任务复杂度。简单分类任务 500 条就能起步；复杂生成任务可能要几千条。但数据量不是唯一因素，质量比数量重要。我见过 1000 条高质量数据微调效果吊打 10000 条脏数据。别盲目堆数据，先把数据洗干净。
