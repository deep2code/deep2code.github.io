RAG

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • RAG 将信息检索与 LLM 结合：从外部知识库检索相关文档增强回答
  • 核心价值：缓解幻觉 + 提供可溯源知识
  • 文末更新节覆盖 2024-2026 RAG 工程实践演进

关键结论与取舍

  • 知识库质量决定 RAG 上限，检索链路要先于生成调优
  • 简单场景先做朴素 RAG，再按需补 rerank 与长上下文优化
适合谁读做知识库问答、想让 LLM 落地业务数据的工程师 读完可获得RAG 全链路原理与 2026 工程实践要点

检索增强生成（RAG）

RAG（Retrieval-Augmented Generation）把信息检索和大语言模型拼到一起：先从外部知识库捞相关文档，再喂给 LLM 来增强回答，既压幻觉又能给出可溯源的知识。

RAG 架构

flowchart TD A[用户提问] --> B[Query Embedding] B --> C[向量检索 Vector Search] C --> D[Top-K 相关文档] D --> E[构建 Prompt: 问题 + 检索到的上下文] E --> F[LLM 生成回答] F --> G[输出： 答案 + 来源引用] subgraph 离线建库 H[文档库] --> I[分块 Chunking] I --> J[Embedding 向量化] J --> K[向量数据库] end C -.-> K

核心组件

1. 文档处理
# langchain 0.3+：text_splitter 移入独立包 langchain-text-splitters，DirectoryLoader 移入 langchain-community
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import DirectoryLoader

# 加载文档
loader = DirectoryLoader("./docs", glob="**/*.md")
docs = loader.load()

# 文档分块
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每块最大 500 字符
    chunk_overlap=50,      # 块之间重叠 50 字符
    separators=["\n\n", "\n", "。", "！", "？", " "],
)
chunks = splitter.split_documents(docs)
print(f"共 {len(chunks)} 个文档块")
2. 向量化与存储
# langchain 0.3+：embeddings/vectorstores 位于 langchain-community 与 langchain-chroma 包
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import Chroma

# 使用中文 embedding 模型
embeddings = HuggingFaceEmbeddings(
    model_name="BAAI/bge-small-zh-v1.5",
    encode_kwargs={"normalize_embeddings": True},
)

# 存入向量数据库
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",  # Chroma 0.4+ 自动持久化，persist() 已移除
)
3. 检索与生成
# langchain 1.x 已移除 RetrievalQA 链式接口；此处为 0.2 老写法，新写法见文末更新段
from langchain.chains import RetrievalQA
from langchain.llms import Ollama

# 初始化 LLM
llm = Ollama(model="llama3", temperature=0.3)

# 构建 RAG 链
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vectorstore.as_retriever(search_kwargs={"k": 5}),
    return_source_documents=True,
)

# 提问
result = qa_chain({"query": "Go 语言中 context 的作用是什么？"})
print(result["result"])
for doc in result["source_documents"]:
    print(f"来源: {doc.metadata['source']}")

向量数据库选型

数据库类型特点适用场景
Milvus专用向量库分布式、高性能大规模生产环境
Chroma轻量向量库嵌入式、易用原型开发、小规模
Qdrant专用向量库Rust 实现、过滤强需要复杂过滤
PgvectorPostgreSQL 扩展SQL 生态已有 PG 基础设施
Elasticsearch搜索引擎全文+向量混合检索已有 ES 基础设施

进阶技巧

  • 混合检索：BM25 全文检索 + 向量检索一起上，取并集再做重排。
  • Query 重写：用 LLM 把用户查询改写成更适合检索的表达。
  • 重排序（Reranking）：用 Cross-Encoder 对检索结果再排一遍，把精度顶上去。
  • 多路召回：同时从多个知识源捞，结果合并。
  • 动态 chunk：按文档结构（段落、标题）动态切块，而不是死磕固定长度。

RAG 更新（2024-2026）

  • langchain 1.x / LCEL：RetrievalQA 这类老链式接口已经移除，改用 create_retrieval_chain + create_stuff_documents_chain （或用 LangGraph 做图编排）；按需装 langchain-community、langchain-chroma、langchain-ollama 这些独立包。
  • GraphRAG：知识图谱 + 向量检索混着用（微软 GraphRAG、LightRAG 等）成了企业级 RAG 的新宠，专治多跳关系。
  • 混合检索 + 重排成标配：BM25 / 稀疏向量 + 稠密向量一起召回（比如 Qdrant 稀疏向量、bm25s），再上 Cohere / BGE 系 Reranker 精排。
  • 中文 embedding：BGE-M3（多语言、多粒度）和 Qwen3-Embedding 成了中文场景的默认选项，顶替早期 bge-small-zh 这种单粒度模型。
  • Agentic RAG：多轮「检索 → 反思 → 再检索」的链路，召回不够就自动改写查询或调工具，缓解一次性检索的召回瓶颈。
  • 评测先行：RAGAS、TruLens 这类框架把检索质量和生成质量拆开评，上线前先备好评测集已经成了工程纪律。
  • 本地推理：Ollama + vLLM / llama.cpp 撑起轻量私有化 RAG，llama 4 系和 Qwen3 系是常见基座。
