Continue.dev 简介

Continue.dev 是由 Continue 团队开发的开源 AI 编程助手，2023 年推出，GitHub Stars 15K+。

flowchart LR A[Continue.dev] --> B[编辑器插件] A --> C[模型支持] A --> D[自定义能力] B --> B1[VS Code] B --> B2[JetBrains] C --> C1[OpenAI GPT] C --> C2[Anthropic Claude] C --> C3[Google Gemini] C --> C4[本地 Ollama] C --> C5[自托管 vLLM] C --> C6[任意 OpenAI 兼容 API] D --> D1[Slash Commands] D --> D2[自定义 Prompt] D --> D3[上下文提供器] D --> D4[代码库索引] D --> D5[自定义 Agent]

差异化定位：Continue.dev 的两大护城河是"任意 LLM"和"完全开源可自托管"——代码不出内网、行为完全可定制，这是闭源 AI IDE 给不了的。

核心特性

  • 完全开源：Apache 2.0 协议，代码完全透明，可审计和定制
  • 跨编辑器：支持 VS Code 和 JetBrains 全家桶（IDEA、PyCharm、WebStorm 等）
  • 任意 LLM：支持 OpenAI、Anthropic、Google、本地模型、自托管模型、任意 OpenAI 兼容 API
  • 可自托管：可以完全在本地或私有服务器运行，数据不离开内网
  • 高度可定制：自定义 Slash Commands、Prompt 模板、上下文提供器、Agent 行为
  • 代码库索引：本地索引代码库，支持语义搜索和代码库问答
  • 行内补全：支持 Tab 补全（FIM 模型）
  • 侧边栏 Chat：对话式编程，代码解释、生成、修复、重构
  • 编辑模式：选中代码后用自然语言编辑
  • 隐私优先：默认不收集数据，可配置代理和遥测

自托管部署

Continue.dev 可以完全自托管，适合企业和对隐私敏感的用户。

flowchart TD A[选择部署方式] --> B{隐私/算力要求?} B -- 单机/笔记本 --> C[Ollama 本地模型] B -- 服务器/GPU --> D[vLLM 自托管 OpenAI 兼容 API] B -- 无隐私顾虑 --> E[直接用云厂商 API] C --> F[Continue 插件配 provider=ollama] D --> F E --> F F --> G[日常 Chat/编辑用强模型] F --> H[Tab 补全用本地小 FIM 模型]
部署方式算力需求数据流向适合场景
Ollama 本地普通笔记本可跑 7B完全不出本机个人开发、隐私敏感、离线
vLLM 自托管需 GPU（≥1 张）不出内网企业团队、批量、内网部署
云厂商 API无需本地算力代码上云追求最强模型、无合规约束
混合（推荐）本地小模型 + 云端大模型敏感片段本地补全本地、复杂任务上云

混合部署建议：Tab 补全走本地 FIM 小模型（快、免费、隐私），Chat/复杂任务走云端强模型——既省 token 费又兼顾隐私。

使用 vLLM 自托管模型

# 1. 安装 vLLM
pip install vllm

# 2. 启动模型服务（OpenAI 兼容 API）
python -m vllm.entrypoints.openai.api_server   --model deepseek-ai/deepseek-coder-6.7b-instruct   --host 0.0.0.0   --port 8000   --dtype auto   --gpu-memory-utilization 0.9

# 3. 在 Continue 配置中使用
# config.json
{
  "models": [{
    "title": "Self-hosted DeepSeek",
    "provider": "openai",
    "model": "deepseek-coder-6.7b-instruct",
    "apiBase": "http://my-server:8000/v1",
    "apiKey": "EMPTY"
  }]
}

最佳实践

  1. 配置多个模型：日常用快速模型，复杂任务切换强模型
  2. 使用本地模型做补全：Tab 补全用本地小模型，快速免费隐私好
  3. 自定义 Slash Commands：把常用操作定义为命令，提高效率
  4. 启用代码库索引：大项目中代码库搜索非常有用
  5. 项目级配置：每个项目配置不同的模型和规则
  6. 利用上下文提供器：@codebase、@diff、@terminal 等提供丰富上下文
  7. 自托管模型：企业和隐私敏感场景用 vLLM/Ollama 自托管
  8. 关闭遥测："allowAnonymousTelemetry": false 保护隐私
  9. 审查所有修改：AI 生成的代码必须人工审查
  10. 持续优化配置：根据使用体验不断优化 config.json

config.json 怎么调才好用

Continue 最强大的地方是它高度可定制，但默认配置很朴素，得自己调。我给你看个我实际在用的配置片段：

{
  "models": [
    {
      "title": "Qwen3-Coder 内网",
      "provider": "openai",
      "model": "qwen3-coder-32b",
      "apiBase": "http://内网vllm:8000/v1",
      "apiKey": "xxx",
      "contextLength": 128000
    }
  ],
  "tabAutocompleteModel": {
    "title": "Qwen3-Coder FIM",
    "provider": "openai",
    "model": "qwen3-coder-7b",
    "apiBase": "http://内网vllm:8000/v1"
  }
}

注意我把 Chat 模型和 Tab 补全模型分开了：Chat 用 32B 的强模型，Tab 补全用 7B 的小模型。因为 Tab 补全要求低延迟，小模型又快又够准；Chat 推理才需要大模型。这个分层是省钱的关键。

配置项我踩过的坑建议
contextLength填错了会截断上下文按模型实际上下文填，Qwen3 是 128K
Tab 模型用大模型做补全，延迟高到不能用补全用 7B 小模型，Chat 才用大模型
apiBase忘了加 /v1 后缀vLLM 的 OpenAI 兼容端点必须带 /v1
自定义命令写得太复杂，AI 不按套路来命令写简单点，一个命令干一件事

常见问题 FAQ

Q1：Continue.dev 的 Tab 补全为什么不如 Copilot 准？

因为 Tab 补全质量很大程度上取决于你用的模型。Copilot 用的是微软调教好的专用补全模型，你自己接的开源模型在 FIM 上还有差距。2026 年 Qwen3-Coder 这种专用模型补全已经不错了，但跟 Copilot 还是有点距离。

Q2：Continue 自托管要什么硬件？

跑 7B 补全模型，一张 RTX 4090（24G）够了。跑 32B Chat 模型，得两张 4090 或者一张 A100。如果公司开发者多，得上 GPU 服务器集群，用 vLLM 做多卡多实例。这块成本得算清楚。

Q3：Continue 支持 JetBrains 吗？

支持，2025 年后就有 JetBrains 插件了。这也是很多人选它的原因——Copilot 对 JetBrains 的支持一直不如 VS Code，Continue 在两边体验一致。

Q4：Continue 能接多个模型吗？

能，config.json 里可以配多个 model，聊天的时候随便切。我自己配了内网 Qwen3、DeepSeek API、Claude API 三个，日常用内网，遇到硬骨头切 Claude。

Q5：Continue 和 Aider 冲突吗？

不冲突。Continue 是 IDE 插件，管补全和聊天；Aider 是命令行工具，管批量改代码。我两个一起用：写代码开 Continue，跑重构开 Aider。各干各的活。
