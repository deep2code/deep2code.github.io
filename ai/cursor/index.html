Cursor 简介

Cursor 是由 Anysphere 公司开发的 AI 原生代码编辑器，基于 VS Code fork，2023 年推出。它将 AI 深度集成到编辑器中，提供业界最佳的行内 Tab 补全、侧边栏 Chat、Composer Agent 模式等功能。Cursor 是目前最流行的 AI IDE，被全球数百万开发者使用。

flowchart LR A[Cursor IDE] --> B[Tab 补全] A --> C[Cursor Chat] A --> D[Composer Agent] A --> E[多模型支持] B --> B1[行内补全] B --> B2[多行生成] B --> B3[注释驱动] C --> C1[侧边栏对话] C --> C2[代码解释] C --> C3[代码生成] C --> C4[Bug 修复] D --> D1[自主规划] D --> D2[多文件编辑] D --> D3[终端执行] D --> D4[测试运行] E --> E1[Claude] E --> E2[GPT] E --> E3[Gemini] E --> E4[本地模型]

一句话定位：Cursor = VS Code 兼容底座 + 三件套能力（Tab 行内补全、侧边 Chat、Composer 多文件 Agent），再加可插拔的多模型与 MCP 外部工具。

核心特性

  • Tab 补全最佳：业界最快最准的行内补全，亚秒级延迟，高准确率
  • AI 原生：AI 深度集成到编辑器核心，不是插件
  • Composer Agent：自主 Agent 模式，规划任务、多文件编辑、运行命令
  • 多模型支持：Claude Opus/Sonnet、GPT-5/4o、Gemini 2.5 Pro，自由切换
  • VS Code 兼容：基于 VS Code，所有扩展、快捷键、设置直接可用
  • 代码库索引：自动索引整个代码库，支持语义搜索和上下文理解
  • MCP 支持：Model Context Protocol，连接外部工具和数据源
  • 规则系统：.cursorrules 项目规则，自定义 AI 行为
  • 团队协作：团队规则、共享上下文、管理后台

Tab 补全（核心功能）

Cursor 的 Tab 补全是业界标杆，亚秒级延迟，高准确率。它理解当前文件、打开的文件、整个代码库的上下文。

功能特点

  • 单行补全：输入时实时提示下一行代码
  • 多行补全：一次生成整个函数、类、代码块
  • 注释驱动：写注释描述功能，自动生成代码
  • 上下文感知：理解项目结构、编码风格、依赖关系
  • 全语言支持：100+ 编程语言
  • 幽灵文本：灰色显示建议，Tab 接受，Esc 拒绝
  • 循环建议：Option+] / Option+[ 切换多个建议

使用技巧

  1. 写好注释：清晰的注释能引导生成更准确的代码
  2. 打开相关文件：Cursor 会参考打开的文件的代码风格
  3. 先写函数签名：写好函数名和参数，Cursor 自动补全实现
  4. 小步生成：一次生成一个函数，不要一次生成整个文件
  5. 审查代码：所有建议必须人工审查，不要盲目 Tab
  6. 使用多行补全：生成函数时等待多行建议出现，比单行更高效
  7. 配置模型：日常用快速模型（Sonnet/GPT-mini），复杂任务切换强模型

示例

// 写注释，Cursor 自动生成代码
// 防抖函数，延迟执行
function debounce(fn: Function, delay: number): Function {
  // Cursor 自动补全：
  let timer: NodeJS.Timeout | null = null;
  return function(this: any, ...args: any[]) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 写函数签名，自动补全实现
export function formatDate(date: Date, format: string = 'YYYY-MM-DD'): string {
  // Cursor 自动补全完整的日期格式化函数
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const day = String(date.getDate()).padStart(2, '0');
  // ...
}

Cursor Chat

Cursor Chat 是侧边栏对话功能，可以用自然语言与 AI 对话，解释代码、生成代码、修复 Bug、重构代码。

核心功能

  • 代码库感知：自动索引整个代码库，回答基于项目上下文
  • @引用：@文件、@文件夹、@函数、@错误，精准引用上下文
  • 代码生成：生成新代码、新文件、新功能
  • 代码解释：解释选中代码、整个文件、复杂逻辑
  • Bug 修复：分析错误、定位问题、修复代码
  • 代码重构：重构选中代码、提取函数、优化性能
  • 测试生成：为选中代码生成单元测试
  • 文档生成：生成注释、README、API 文档
  • 代码审查：审查代码质量、安全性、性能
  • 终端集成：可以运行命令、查看输出、根据错误修复

使用方式

# 打开 Chat
Cmd+L（macOS）/ Ctrl+L（Windows）

# 基本对话
直接输入问题："解释用户认证流程"

# @引用文件
@src/auth/login.ts 解释这个登录函数的逻辑
@src/models/ 分析这些模型的设计

# @引用错误
@error 修复这个 TypeScript 编译错误
@terminal 修复终端中的运行时错误

# 选中代码后 Chat
选中代码 → Cmd+L → 自动引用选中代码
"优化这个函数的性能"
"为这个函数生成单元测试"
"解释这段代码的作用"

# 代码操作按钮
Chat 回答后可以点击：
- Apply：应用代码修改
- Diff：查看差异
- Copy：复制代码
- Insert：插入到光标位置
- Retry：重新生成

Chat 使用技巧

  1. 精准引用：用 @引用具体文件和代码，不要让 AI 猜
  2. 提供上下文：描述需求时包含背景、目标、约束
  3. 分步执行：大任务拆成小步骤，逐步验证
  4. 使用 Apply：AI 生成代码后用 Apply 应用，不要手动复制
  5. 查看 Diff：应用前查看差异，确认修改正确
  6. 迭代优化：第一次结果不满意，继续追问"优化"、"加测试"、"重构"
  7. 切换模型：复杂任务切换到 Claude Opus 或 GPT-5

Composer Agent 模式

Composer 是 Cursor 的自主 Agent 模式，可以规划任务、多文件编辑、运行终端命令、执行测试，类似 Claude Code 的能力。

flowchart TD A[输入任务描述] --> B[分析现有代码结构] B --> C[规划实现步骤] C --> D[创建/修改多个文件] D --> E[运行终端命令/测试] E --> F{测试通过?} F -- 否 --> G[自动分析错误并修复] G --> E F -- 是 --> H[展示变更摘要] H --> I[人工审查 Diff] I --> J[Approve 合并到分支]

核心功能

  • 自主规划：将复杂需求拆解为可执行的子任务
  • 多文件编辑：同时创建和修改多个文件
  • 终端执行：运行命令、安装依赖、执行测试、构建项目
  • 错误恢复：遇到错误自动分析和修复
  • Git 操作：创建分支、提交代码、生成 PR 描述
  • 实时预览：实时查看文件变更和执行进度
  • 人工干预：可以随时暂停、修改、批准操作

使用方式

# 打开 Composer
Cmd+I（macOS）/ Ctrl+I（Windows）

# 输入任务描述
"实现用户密码重置功能：
1. 创建密码重置请求 API
2. 发送重置邮件（JWT 令牌，1小时有效）
3. 创建密码重置确认 API
4. 添加数据库迁移
5. 编写单元测试
6. 更新 API 文档"

# Composer 会：
1. 分析现有代码结构
2. 规划实现步骤
3. 创建/修改多个文件
4. 运行测试验证
5. 展示变更摘要

# 交互控制
- Approve：批准当前步骤继续
- Reject：拒绝当前修改
- Edit：修改 AI 的计划
- Pause：暂停执行
- Resume：继续执行
- Stop：停止执行

# 查看变更
- 文件树：查看所有修改的文件
- Diff：查看每个文件的具体变更
- Terminal：查看命令执行输出
- Timeline：查看执行历史

Composer 使用技巧

  1. 任务描述清晰：包含需求、约束、验收标准
  2. 大任务拆小：不要一次让 Composer 做太多，分步执行
  3. 随时审查：每一步都查看 Diff，确认修改正确
  4. 使用 Git：在独立分支上运行 Composer，方便回滚
  5. 配置规则：.cursorrules 定义项目规范，让 Composer 遵循
  6. 选择强模型：复杂任务用 Claude Opus，日常用 Sonnet
  7. 人工干预：遇到不确定的操作，暂停并手动指导

.cursorrules 项目规则

.cursorrules 是 Cursor 的项目级配置文件，放在项目根目录。Cursor 启动时自动读取，让 AI 理解项目的编码规范、架构约定、命令脚本等。

完整示例

# 项目规范

## 技术栈
- 前端：React 18 + TypeScript + Vite + TailwindCSS + shadcn/ui
- 后端：Node.js + Express + Prisma + PostgreSQL
- 测试：Vitest + Testing Library
- 部署：Docker + Nginx + AWS

## 编码规范
- TypeScript strict 模式，禁止 any 类型
- React 使用函数组件 + Hooks，禁止 class 组件
- 样式使用 TailwindCSS，禁止写 CSS 文件
- 组件命名：PascalCase，文件命名：kebab-case
- 所有函数必须有 JSDoc 注释
- 错误处理：使用 try-catch，不使用 throw new Error('error')
- 异步代码：使用 async/await，不使用 .then() 链

## 架构约定
- 前端分层：pages → components → hooks → services → types
- 后端分层：routes → controllers → services → repositories → models
- API 设计：RESTful，版本前缀 /api/v1/
- 状态管理：Zustand，禁止使用 Redux
- 数据获取：React Query，禁止直接在组件中 fetch
- 数据库：软删除用 deleted_at，时间戳用 created_at/updated_at

## 常用命令
- 开发：npm run dev
- 构建：npm run build
- 测试：npm test
- 代码检查：npm run lint
- 数据库迁移：npx prisma migrate dev
- 数据库生成：npx prisma generate
- 启动 Docker：docker-compose up -d

## 注意事项
- 不要修改 prisma/schema.prisma 不创建迁移
- 不要提交 .env 和 secrets/ 目录
- 不要使用 console.log，使用 logger
- 所有 API 路由必须有错误处理和输入验证
- 所有外部 API 调用必须有超时和重试
- 敏感数据必须加密存储
- 前端组件必须支持 SSR

## 测试要求
- 单元测试覆盖率 ≥ 70%
- 关键组件必须有测试
- 新功能必须包含测试
- CI 中测试必须全部通过

## Git 工作流
- 分支命名：feature/xxx, fix/xxx, hotfix/xxx
- 提交信息：Conventional Commits（feat:, fix:, docs:, refactor:）
- PR 必须通过 CI 和 Code Review
- main 分支受保护，只能通过 PR 合并

编写技巧

  1. 简洁明了：重点突出，不要写太长
  2. 命令准确：常用命令必须准确，Cursor 会直接执行
  3. 禁止事项：明确列出不能做的事情
  4. 持续更新：随着项目演进更新规则
  5. 分层放置：根目录放全局规范，子目录可以放局部规范

MCP 集成

Cursor 支持 MCP（Model Context Protocol），可以连接外部工具和数据源，让 AI 访问数据库、API、文件系统、第三方服务等。

flowchart LR User[用户在 Cursor 中提问] --> Cursor[Cursor Chat/Composer] Cursor --> MCP[MCP Client] MCP --> FS[filesystem Server] MCP --> GH[github Server] MCP --> PG[postgres Server] MCP --> PW[playwright Server] FS --> R1[读写项目文件] GH --> R2[读 PR/Issue/代码] PG --> R3[查询业务数据] PW --> R4[浏览器自动化验证]
MCP Server能力典型用途
filesystem受限读写指定目录让 Agent 操作项目文件
github读 PR/Issue、评论、代码结合 Issue 修 Bug、生成 PR 描述
postgres只读查询数据库基于真实表结构/数据写 SQL 与模型
fetch抓取网页内容查文档、读 API 说明
playwright浏览器自动化改完前端自动打开页面验证

安全提醒：MCP 把"真实工具"交给了 AI，务必最小授权——数据库用只读账号、文件系统限定项目目录、敏感 token 走环境变量，并对写操作保持人工 Approve。

配置 MCP Server

在 Cursor 设置中配置：Settings → Cursor → MCP → Add Server

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/project"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxx"
      }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@localhost:5432/db"]
    },
    "fetch": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-fetch"]
    },
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}

总结

Cursor 是目前最流行、体验最好的 AI IDE，Tab 补全业界最佳，Composer Agent 模式强大，多模型支持灵活。适合：

  • 追求最佳开发体验的个人开发者
  • 习惯 VS Code但想要更深度 AI 集成的团队
  • 需要多模型灵活切换的用户
  • 日常编码 + 复杂任务混合的工作流

建议组合：Cursor 做日常编码（Tab 补全 + Chat），复杂任务用 Composer 或 Claude Code CLI。

Cursor 是我日常用得最多的工具，没有之一。从 2024 年它还叫 VSCode 魔改版的时候我就在用。说点真实的，不是官网那种营销话术。

Tab 补全确实是目前最好的，没有之一。它比 Copilot 更懂你当前文件的上下文，有时候我刚写了半行，它直接把我脑子里接下来要写的三行给补出来了。这种"心有灵犀"的感觉，用了就回不去。

但 Cursor 也有让我崩溃的时候。有次 Composer 改一个功能，它自作主张改了 15 个文件，其中 3 个是我根本不想让它碰的。还好它给的是 diff，我一个一个 review 才敢合。这就是我为什么一直强调：AI 给的修改建议，一定要看 diff，别直接接受。

Composer 到底怎么用才高效

很多人开了 Composer 就一句话"帮我加个 XX 功能"，结果出来的东西一团糟。Composer 好用的关键是：你得给它足够明确的上下文。

我自己的用法是这样的：先 @引用相关文件，把需求说清楚，明确告诉它要改哪几个文件、不要碰哪些文件、输出格式是什么。这样它出来的 diff 我 review 起来也快。

常见问题 FAQ

Q1：Cursor 和 Copilot 到底选哪个？

日常写代码的流畅度，Cursor 的 Tab 补全比 Copilot 强一截，这是很多人的共识。但 Copilot 便宜（$10 vs $20），而且企业版管理方便。预算有限用 Copilot，追求体验用 Cursor。我自己两个都装了，看场景切。

Q2：Cursor 会把我的代码上传吗？

会，它本质是调云端模型。企业版有代码不留存的承诺，但个人版的政策你得自己看。敏感项目别用 Cursor，换本地模型方案。这个没什么好说的，隐私红线。

Q3：为什么 Cursor 有时候补全突然变差了？

几个原因：一是你到了额度上限，它自动切到便宜模型了；二是项目太大，上下文没跟上；三是模型本身抽风。解决办法：检查额度、新开个窗口、或者手动切个模型。Cursor 偶尔抽风很正常，别慌。

Q4：Composer 改完代码一团乱怎么办？

它改之前你就该控制好范围。已经改乱了也别怕，它给的是 diff，你可以一个一个文件 review，不要的就 reject。实在乱了就 git checkout 把改动撤了，重新来。别硬着头皮接受一堆你不懂的改动。

Q5：Cursor 支持自定义模型吗？

2026 年的版本支持接自定义 endpoint，理论上可以接本地模型（Ollama、vLLM）。但体验比官方模型差一截，尤其是 Tab 补全。日常写代码还是建议用官方模型，敏感项目再考虑本地。
