Transformer 架构深度解析

现代 LLM 都基于 Transformer 架构，理解其内部机制是掌握大模型技术的基础。

自注意力机制数学推导

Scaled Dot-Product Attention:

  Q = X · W_Q    (查询矩阵，维度 [seq_len, d_k])
  K = X · W_K    (键矩阵，维度 [seq_len, d_k])
  V = X · W_V    (值矩阵，维度 [seq_len, d_v])

  Attention(Q, K, V) = softmax(Q · K^T / √d_k) · V

  其中：
  - Q · K^T：计算每个 token 与所有 token 的相关性分数
  - / √d_k：缩放因子，防止点积过大导致 softmax 梯度消失
  - softmax：归一化为概率分布
  - · V：加权求和得到输出

  计算复杂度：O(n² · d)，n = 序列长度，d = 模型维度
  这也是长序列处理的瓶颈所在

多头注意力（Multi-Head Attention）

MultiHead(Q, K, V) = Concat(head_1, ..., head_h) · W_O

  head_i = Attention(Q · W_Q^i, K · W_K^i, V · W_V^i)

  8 头注意力示例（d_model=512, d_k=d_v=64）：
  ┌─────────────────────────────────────────┐
  │  Head 1: 关注语法关系（主谓宾）          │
  │  Head 2: 关注指代关系（it → 前文名词）   │
  │  Head 3: 关注位置关系（前后顺序）         │
  │  Head 4: 关注语义相似性                   │
  │  ...                                      │
  │  Head 8: 关注其他模式                     │
  └─────────────────────────────────────────┘
  每个头学习不同的注意力模式，最后拼接融合

  参数量：4 · d_model²（Q,K,V,O 四个投影矩阵）
  GPT-3 (175B, d_model=12288): 单注意力层约 600M 参数

Transformer Block 结构

Decoder-only 架构（GPT 系列）：

  ┌─────────────────────────────────────┐
  │  输入 Embedding + 位置编码           │
  └──────────────┬──────────────────────┘
                 │
  ┌──────────────▼──────────────────────┐
  │  LayerNorm（预归一化，Pre-LN）       │
  ├──────────────────────────────────────┤
  │  因果自注意力（Causal Self-Attention）│
  │  - 掩码：只能看到左侧 token           │
  │  - KV Cache：推理优化                │
  ├──────────────────────────────────────┤
  │  残差连接（Residual Connection）      │
  ├──────────────────────────────────────┤
  │  LayerNorm                            │
  ├──────────────────────────────────────┤
  │  前馈网络（FFN）                      │
  │  - 两层线性变换 + GELU 激活           │
  │  - 中间维度通常是 d_model 的 4 倍     │
  ├──────────────────────────────────────┤
  │  残差连接                              │
  └──────────────┬──────────────────────┘
                 │  重复 N 层（GPT-3: 96层）
  ┌──────────────▼──────────────────────┐
  │  最终 LayerNorm                       │
  ├──────────────────────────────────────┤
  │  线性投影到词表（LM Head）            │
  ├──────────────────────────────────────┤
  │  Softmax → 下一个 token 的概率分布    │
  └──────────────────────────────────────┘

  关键设计：
  - Pre-LN（GPT）vs Post-LN（原始 Transformer）：Pre-LN 训练更稳定
  - 因果掩码：确保生成时只能看到已生成的 token
  - 残差连接：缓解梯度消失，支持深层网络训练

训练流程深度解析

预训练（Pre-training）细节

预训练数据流程：

  原始文本（TB~PB 级）
    │
    ▼
  数据清洗
    - 去重（MinHash + LSH）
    - 质量过滤（语言识别、毒性检测）
    - 个人信息脱敏（PII 移除）
    │
    ▼
  分词（Tokenization）
    - BPE（Byte-Pair Encoding）
    - 词表大小：32K~128K
    - 中文模型通常有更多中文字符
    │
    ▼
  构建训练样本
    - 序列长度：2K~128K tokens
    - 下一句预测（已被抛弃，GPT 只用因果 LM）
    - 文档边界处理（EOD 标记）
    │
    ▼
  训练目标：Next Token Prediction
    - 输入：x_1, x_2, ..., x_n
    - 目标：预测 x_2, x_3, ..., x_{n+1}
    - Loss = -Σ log P(x_{i+1} | x_1, ..., x_i)
    - 即交叉熵损失，对所有位置求平均

  训练配置（GPT-3 175B 参考）：
    - 训练 tokens：300B
    - Batch size：3.2M tokens（梯度累积）
    - 优化器：AdamW (β1=0.9, β2=0.95, ε=1e-8)
    - 学习率：6e-5，余弦退火，warmup 375M tokens
    - 权重衰减：0.1
    - 梯度裁剪：1.0
    - 训练时间：300 天（1024 张 A100）

SFT 与 RLHF 对齐

三阶段对齐流程：

  阶段1：监督微调（SFT, Supervised Fine-Tuning）
  ┌─────────────────────────────────────────┐
  │  收集高质量指令-回答对（10K~100K 条）    │
  │  - 人工编写（高质量，成本高）             │
  │  - 模型生成 + 人工筛选（效率高）          │
  │  - Evol-Instruct（指令进化，WizardLM）   │
  │                                          │
  │  训练：在预训练模型基础上微调             │
  │  - Loss = 只计算回答部分的交叉熵          │
  │  - 学习率：1e-5 ~ 5e-6（比预训练小）     │
  │  - Epochs：2~3（避免过拟合）             │
  └─────────────────────────────────────────┘
                    │
                    ▼
  阶段2：奖励模型训练（RM, Reward Model）
  ┌─────────────────────────────────────────┐
  │  收集人类偏好数据（对同一个问题的多个回答）│
  │  - 标注员对回答进行排序（A > B > C）     │
  │  - 数据量：100K 偏好对                   │
  │                                          │
  │  训练奖励模型：                           │
  │  - 基于 SFT 模型，替换 LM Head 为标量输出 │
  │  - Loss = -log(σ(r(x, y_w) - r(x, y_l)))│
  │    即 Bradley-Terry 模型，最大化偏好概率  │
  │  - 输出：给定 prompt+response 的奖励分数  │
  └─────────────────────────────────────────┘
                    │
                    ▼
  阶段3：强化学习（RLHF / PPO / DPO）
  ┌─────────────────────────────────────────┐
  │  PPO（Proximal Policy Optimization）：   │
  │  - 策略模型生成回答                       │
  │  - 奖励模型打分                           │
  │  - KL 惩罚（防止偏离 SFT 模型太远）       │
  │  - PPO 算法更新策略                       │
  │  - 不稳定，需要精细调参                   │
  │                                          │
  │  DPO（Direct Preference Optimization）：  │
  │  - 2023 年提出，简化 RLHF                │
  │  - 不需要奖励模型，直接用偏好数据训练     │
  │  - Loss = -log(σ(β · log π(y_w|x)/π_ref(y_w|x) │
  │                - β · log π(y_l|x)/π_ref(y_l|x)))│
  │  - 更稳定，更高效，已成为主流             │
  │                                          │
  │  后续发展：                               │
  │  - IPO、KTO、ORPO（简化对齐流程）        │
  │  - RLHF-V（视觉语言模型对齐）            │
  │  - 过程奖励（PRM）替代结果奖励（ORM）     │
  └─────────────────────────────────────────┘

推理优化技术深度解析

KV Cache 原理

自回归生成的计算瓶颈：

  生成第 n 个 token 时，需要计算：
  Q_n · (K_1, K_2, ..., K_n)^T → 注意力分数

  如果每次都重新计算所有 K、V：
  - 计算量：O(n² · d) 每步
  - 总计算量：O(n³ · d) 生成 n 个 token

  KV Cache 优化：
  - 缓存每一层的 K、V 矩阵
  - 生成第 n 个 token 时，只计算 Q_n 和新的 K_n、V_n
  - 注意力计算：Q_n · (K_cache + K_n)^T
  - 计算量：O(n · d) 每步
  - 总计算量：O(n² · d) 生成 n 个 token

  显存开销：
  - KV Cache 大小 = 2 · n_layers · n_heads · d_head · seq_len · 2(bytes)
  - LLaMA-2 70B，4K 上下文：约 1.4GB（FP16）
  - LLaMA-2 70B，128K 上下文：约 45GB（FP16）
  - 这就是长上下文需要大量显存的原因

  优化方案：
  - MQA（Multi-Query Attention）：多个头共享 KV，Gemma、PaLM
  - GQA（Grouped-Query Attention）：分组共享 KV，LLaMA-2、Qwen
  - PagedAttention：分页管理 KV Cache，vLLM
  - KV Cache 量化：FP8/INT8 存储，减少显存

投机解码（Speculative Decoding）

原理：用小模型快速生成候选 token，大模型一次验证多个

  传统解码：每生成 1 个 token 需要 1 次大模型前向传播
  投机解码：小模型生成 K 个候选，大模型一次验证

  流程：
  1. 小模型（Draft Model）自回归生成 K 个候选 token
  2. 大模型（Target Model）一次前向传播，计算 K 个位置的概率
  3. 从左到右验证：
     - 如果大模型同意小模型的 token，接受
     - 如果不同意，用大模型的分布采样，停止
  4. 所有 K 个都接受，则额外采样 1 个 token

  加速比：
  - 接受率 γ（通常 0.7~0.9）
  - 理论加速比：(1 - γ^(K+1)) / (1 - γ) ≈ 1/(1-γ)
  - γ=0.8, K=5：加速比约 3.5x
  - 实际加速比：2x~3x（考虑小模型开销）

  变种：
  - Medusa：在大模型上添加多个解码头，预测未来 token
  - EAGLE：自回归草稿头，更准确的候选生成
  - Lookahead：推理时的并行解码
  - 无需小模型，直接在大模型上实现

大语言模型（LLM）技术概览

大语言模型（Large Language Model）以 Transformer 为骨架、拿海量文本喂出来的深度学习模型，能写文本、写代码、做推理、跨语言理解。2022 年 ChatGPT 让 LLM 出圈；到 2025–2026 年，开源模型在推理、代码、数学这些核心能力上跟闭源旗舰的差距已经压到 5% 以内，而且只用差不多 1/30

核心架构

现代 LLM 基本都走 Transformer 的 Decoder-only 架构（2024 年起就是绝对主流），核心机制是自注意力（Self-Attention），再叠一层 Causal mask，保证每个位置只能看到自己及之前的 token：

# Self-Attention 简化示意
import torch
import torch.nn.functional as F

def attention(Q, K, V):
    # Scaled Dot-Product Attention
    # Q: query  (batch, seq_len, d_k)
    # K: key    (batch, seq_len, d_k)
    # V: value  (batch, seq_len, d_v)
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    # Causal mask: 只看当前及之前的 token
    mask = torch.tril(torch.ones(scores.size(-2), scores.size(-1)))
    scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = F.softmax(scores, dim=-1)
    return torch.matmul(weights, V)

推理优化技术

  • KV Cache：把算过的 Key/Value 矩阵缓存下来，省得重复算，是长上下文的地基。
  • 量化（Quantization）：把 FP16 权重压到 INT8 / INT4 / FP8，显存占用砍下来，本地部署必备。
  • PagedAttention：vLLM 的招牌创新，用分页方式管 KV Cache 显存，把吞吐顶上去。
  • 推测解码（Speculative Decoding）：小模型出草稿、大模型来验收，解码能快 2–3 倍。
  • Flash Attention：重排 GPU 显存的访问模式，既加速注意力计算又省显存。

2026 年的落地标配基本是：vLLM + 连续批处理 + Prefix Caching + INT4 量化，端侧走蒸馏小模型。

调用 LLM API

2026 年 OpenAI 兼容端点已是事实标准——OpenAI、DeepSeek、通义、智谱都给兼容接口。Go 侧用 go-openai 一把通吃，模型名和密钥都从环境变量取，别让代码被某家厂商绑死：

// Go 调用任意 OpenAI 兼容 API
package main

import (
    "context"
    "fmt"
    "os"
    "github.com/sashabaranov/go-openai"
)

func main() {
    client := openai.NewClientWithConfig(openai.ClientConfig{
        BaseURL: os.Getenv("LLM_BASE_URL"), // 如 https://api.openai.com/v1 或厂商兼容端点
        APIKey:  os.Getenv("LLM_API_KEY"),
    })
    resp, err := client.CreateChatCompletion(context.Background(),
        openai.ChatCompletionRequest{
            Model: os.Getenv("LLM_MODEL"), // 如 "gpt-5.6"、"deepseek-v4-flash"、"qwen3.8-max"
            Messages: []openai.ChatCompletionMessage{
                {Role: openai.ChatMessageRoleUser, Content: "用一句话解释 Go 的 goroutine"},
            },
            MaxTokens: 100,
        },
    )
    if err != nil {
        panic(err)
    }
    fmt.Println(resp.Choices[0].Message.Content)
}
