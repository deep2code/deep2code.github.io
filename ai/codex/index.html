OpenAI Codex 与 GitHub Copilot 简介

OpenAI Codex 和 GitHub Copilot 是 AI 编程领域的先驱和主流产品。Codex 最初于 2021 年作为 GitHub Copilot 的底层模型推出，2025 年 OpenAI 重新打造 C...

GitHub Copilot 则是 GitHub 与 OpenAI 合作推出的 AI 编程助手，是企业采用率最高的 AI 编程工具。

flowchart LR A[OpenAI Codex 产品线] --> B[Codex CLI] A --> C[Codex Cloud] A --> D[Codex SDK] A --> E[Codex in ChatGPT] B --> B1[终端交互] B --> B2[本地执行] B --> B3[开源免费] C --> C1[云端沙箱] C --> C2[长时间任务] C --> C3[PR 自动提交] D --> D1[集成到 IDE] D --> D2[自定义工作流] F[GitHub Copilot] --> G[行内补全] F --> H[Copilot Chat] F --> I[Agent 模式] F --> J[企业管理]

产品格局：Codex 是"模型出身、2025 年重启为 Agent 产品线"（CLI + Cloud + SDK）；Copilot 是"企业默认、行内补全标杆"。两者一个偏 CLI/云端自治，一个偏 IDE 内联补全，常组合使用。

Codex CLI

Codex CLI 是 OpenAI 推出的开源命令行 AI 编程工具，基于 GPT-5.6 / GPT-6 模型，支持在终端中通过自然语言操作代码库。

flowchart TD A[终端输入自然语言任务] --> B[Codex 解析并规划] B --> C[沙箱中执行命令/编辑文件] C --> D{需要批准?} D -- on-request --> E[人工审批危险命令] E --> C D -- 自动 --> F[继续执行] F --> G[运行测试/校验] G --> H[上下文接近上限?] H -- 是 --> I[Compaction 智能压缩] I --> B H -- 否 --> J[生成 commit / PR]

核心功能

  • 多模型支持：GPT-5.6 Sonnet、GPT-6 Astra、o3 等
  • Compaction 机制：上下文接近限制时智能压缩，保留关键信息，支持数百万 token 连续工作
  • 沙箱执行：命令在沙箱中执行，安全隔离
  • Git 集成：自动创建分支、提交代码、生成 PR
  • MCP 支持：连接外部工具和数据源
  • 开源：MIT 协议，可自定义和扩展
  • SDK 集成：可集成到自己的工具和工作流中

Codex Cloud

Codex Cloud 是 OpenAI 推出的云端 Agent 执行环境，可以在云端沙箱中长时间运行复杂任务，不占用本地资源。

形态运行位置擅长何时选它
Codex CLI本地终端即时交互、本地文件操作日常改代码、调试、快速迭代
Codex Cloud云端沙箱长时间/通宵任务、自动 PR大型重构、批量迁移、不占本机
Codex SDK嵌入自有工具可编程、接入 CI/CD把 Agent 能力嵌进自研工作流
Codex in ChatGPTChatGPT 网页对话式委派任务不想装 CLI、快速试一个任务

选型提示：本地反复调试用 CLI；跑一个"通宵大活"用 Cloud；要嵌进自己的流水线用 SDK。三者共享同一套模型和上下文能力。

核心特性

  • 云端沙箱：任务在云端 Docker 容器中执行，安全隔离
  • 长时间运行：支持"通宵"处理任务，适合大型重构和复杂功能开发
  • 自动 PR：任务完成后自动提交代码并发起 Pull Request
  • 实时监控：Web 界面实时查看任务进度、日志、文件变更
  • Slack 集成：在 Slack 中 @Codex 委派任务，自动获取上下文
  • 多任务并行：同时运行多个 Codex 任务

GitHub Copilot

GitHub Copilot 是 GitHub 与 OpenAI 合作推出的 AI 编程助手，2021 年推出，是 AI 编程的先驱。它以 VS Code 插件形式提供行内代码补全，后续增加了 Copilot Chat、Agent 模式、代码审查等功能。凭借 GitHub 的生态优势，Copilot 是企业采用率最高的 AI 编程工具。

行内补全（核心功能）

Copilot 的行内补全是业界标杆，支持：

  • 单行补全：输入代码时实时提示下一行
  • 多行补全：一次生成整个函数或代码块
  • 注释驱动：写注释描述功能，Copilot 生成对应代码
  • 上下文感知：理解当前文件、项目结构、编码风格
  • 多语言：支持 100+ 编程语言
  • Tab 接受：按 Tab 接受建议，Esc 拒绝
  • 循环建议：Alt+] / Alt+[ 切换多个建议
// 写注释，Copilot 自动生成代码
// 计算两个日期之间的天数
function daysBetween(date1, date2) {
  // Copilot 会自动补全以下代码
  const oneDay = 24 * 60 * 60 * 1000;
  const firstDate = new Date(date1);
  const secondDate = new Date(date2);
  return Math.round(Math.abs((firstDate - secondDate) / oneDay));
}

// 输入函数名，自动补全实现
function debounce(fn, delay) {
  // Copilot 自动补全防抖函数实现
  let timer = null;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

Agent 模式

Copilot Agent 模式是 2025 年推出的自主编程功能，可以规划任务、多文件编辑、运行命令、执行测试，类似 Claude Code 的能力。

# 在 VS Code 中使用 Agent 模式
1. 打开 Copilot Chat
2. 点击 "Agent" 标签或输入 /agent
3. 描述任务："实现用户密码重置功能，包含邮件发送"
4. Agent 会：
   - 分析现有代码
   - 规划实现步骤
   - 创建/修改多个文件
   - 运行测试验证
   - 展示变更摘要

# 三级自主操作
Level 1 - 问答：解释代码、回答问题
Level 2 - 建议：识别问题、推荐方案
Level 3 - 执行：授权后运行测试、修 Bug、提 PR

# 支持的功能
- 多文件编辑
- 终端命令执行
- 测试运行
- 联网搜索文档
- Git 操作（分支/提交/PR）
- 代码审查

企业管理

  • 管理后台：统一管理席位、权限、策略
  • SSO 集成：支持 SAML SSO、SCIM 用户同步
  • 审计日志：记录所有 Copilot 使用情况
  • 内容排除：指定文件/目录不被 Copilot 索引（如 secrets、.env）
  • 数据不用于训练：Business/Enterprise 计划数据不用于模型训练
  • 自定义模型：Enterprise 可选择不同模型（GPT、Claude、Gemini）
  • 内容过滤：过滤不安全或不适当的建议
  • Copilot 代理：企业内部知识问答，连接内部文档和代码库

Codex CLI 我的真实用法

Codex CLI 是 OpenAI 出的命令行编程工具，2025 年开源之后我一直在用。说几个真实场景你就知道它啥时候好用。

最舒服的是跑"一次性脚本任务"。比如我要写个 Python 脚本，把一堆 CSV 文件清洗一下、合并成一个 Excel，这种没什么技术含量但琐碎的活，我直接扔给 Codex CLI，一句话说清楚，它自己读文件、写脚本、跑起来、报错了自己修。我泡杯咖啡回来就搞定了。

但它写生产代码就差点意思。有次我让它实现一个带鉴权的 HTTP 中间件，它写得很"能跑"，但错误处理粗糙、日志缺失、边界情况没考虑。这种活还是 Claude Code 靠谱。Codex CLI 的强项是"快速出个能用的原型"，不是"写生产级代码"。

我的分工

原型脚本、数据处理、小工具——Codex CLI 快速出活；生产代码、复杂架构、需要严谨错误处理的——Claude Code 或 Cursor。别拿工具短板碰硬活。

Compaction 机制是啥

Codex CLI 有个特点叫 Compaction，很多人不明白。说白了就是：对话太长了，上下文快满了，它自动把之前的对话摘要压缩一下，腾出空间继续聊。这跟 Claude Code 的 /compact 类似，只不过 Codex 是自动做的。

这个机制的好处是你不用手动管上下文，坏处是摘要可能丢信息。有次我跟它讨论了一个复杂的设计，它自动 compact 之后，把我们之前定的一个关键约束给丢了，结果后面写的代码不符合要求。

情况表现我的应对
自动 compact 触发突然感觉它"忘了"之前的讨论重要约束重复强调一遍，或者新开会话
任务跨多次会话新会话没有之前的上下文把关键决策写进 AGENTS.md 或项目文档
超长任务（1小时+）上下文接近上限，响应变慢拆成多个小任务，别硬扛

Codex Cloud 适合团队吗

Codex Cloud 是 OpenAI 的云端 Agent，你在 Slack 里 @它，它在云端跑任务，跑完给你 PR。这个模式对团队挺香的——产品经理在 Slack 里说一句"帮我加个导出 Excel 的功能"，Codex 就去改代码、跑测试、提 PR，开发者 review 一下就合并。

但有个现实问题：它跑出来的代码质量参差。简单功能没问题，复杂业务逻辑经常漏需求。所以团队落地的时候，我建议把它定位成"PR 生成器"，不是"代码提交者"。它提 PR，人来 review，别让它直接 merge。

成本提醒

Codex Cloud 跑长任务烧 token 很猛。一个复杂任务可能跑半小时，烧掉几十万 token。团队用的话一定设好用量上限和告警，不然月底账单会吓你一跳。

Copilot 和 Codex CLI 怎么选

很多人把这俩搞混。其实它们定位完全不同：

维度GitHub CopilotCodex CLI

我的做法是两个都用：写代码的时候开着 Copilot 补全；有个独立的任务要跑（比如"把这 20 个文件的日志格式统一一下"），就开 Codex CLI 让它自己跑。这俩不冲突。

常见问题 FAQ

Q1：Codex CLI 要钱吗？

工具本身开源免费，但你得有 OpenAI API key 或者 ChatGPT 订阅。用 API 的话按 token 计费；用 ChatGPT Plus/Pro 订阅的话可以直接用，额度跟订阅走。我自己是 API key，用量大的时候比订阅便宜。

Q2：Codex CLI 支持本地模型吗？

2026 年的版本支持配置自定义 endpoint，理论上能接本地模型（Ollama、vLLM）。但体验比官方模型差一截，尤其是工具调用和长任务规划。我试过接 Qwen3，写简单脚本可以，复杂任务容易跑偏。

Q3：Codex 写的代码能直接上生产吗？

我的答案是：不能。它适合出原型、写工具、做批量改动。生产代码一定要人工 review，尤其是涉及鉴权、数据处理、错误恢复的部分。AI 写的代码"看起来对"，但边界情况经常漏。

Q4：Codex Cloud 提的 PR 质量怎么样？

简单功能（加个字段、改个文案、写个小接口）质量不错，review 一下就能合。复杂业务逻辑经常漏需求、漏测试。把它当"初级实习生"用——能干杂活，但你得盯着。

Q5：Codex CLI 和 Claude Code 谁更强？

写代码质量我投 Claude Code，尤其是复杂任务。Codex CLI 的优势是便宜、开源、跟 OpenAI 生态绑定。如果你已经在用 GitHub 全家桶，Copilot + Codex CLI 的组合很顺；如果你追求代码质量，Claude Code 还是首选。
