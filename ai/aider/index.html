Aider AI 编程助手

🏷️ Coding Agent

Aider 简介

Aider 是由 Paul Gauthier 开发的开源 AI 编程助手，2023 年推出，GitHub Stars 20K+。它在终端中运行，通过自然语言与 AI 协作编写代码，以 Git 原生集成和 pair programming 模式为核心特色。Aider 支持 100+ 模型，包括 GPT、Claude、Gemini、DeepSeek 以及本地模型（Ollama），是开源 AI 编程工具的首选。

flowchart LR A[Aider CLI] --> B[Git 集成] A --> C[多模型支持] A --> D[Pair Programming] B --> B1[自动提交] B --> B2[分支管理] B --> B3[Diff 审查] B --> B4[回滚] C --> C1[GPT-5/4o] C --> C2[Claude] C --> C3[Gemini] C --> C4[DeepSeek] C --> C5[Ollama 本地] D --> D1[添加文件] D --> D2[对话编程] D --> D3[代码审查] D --> D4[测试运行]

差异化定位：Aider 的两大杀手锏是"Git 原生集成"（每次改动自动成 commit，可随时 /undo）和"100+ 模型可插拔"——终端里的结对程序员，而非绑定单一厂商的 IDE。

核心特性

  • 开源免费：Apache 2.0 协议，完全开源，可自托管和定制
  • Git 原生集成：每次 AI 修改自动提交到 Git，方便审查、对比、回滚
  • Pair Programming 模式：像和结对程序员一起工作，添加文件、对话、修改、测试
  • 100+ 模型支持：GPT、Claude、Gemini、DeepSeek、Qwen、本地模型等
  • 本地模型友好：支持 Ollama、LM Studio、llama.cpp 等本地模型，数据不离开本地
  • 终端运行：在终端中运行，轻量快速，不依赖特定编辑器
  • 多文件编辑：同时添加多个文件，AI 理解跨文件依赖
  • 仓库地图：自动生成代码库地图，帮助 AI 理解项目结构
  • 测试集成：自动运行测试，根据失败信息修复代码
  • Voice Mode：支持语音输入，解放双手

安装与配置

安装

# pip 安装（推荐）
pip install aider-chat

# 或 pipx 安装（隔离环境）
pipx install aider-chat

# macOS Homebrew
brew install aider

# 验证安装
aider --version

配置 API Key

# OpenAI API Key
export OPENAI_API_KEY="sk-xxx"

# Anthropic API Key
export ANTHROPIC_API_KEY="sk-ant-xxx"

# Google Gemini API Key
export GEMINI_API_KEY="xxx"

# DeepSeek API Key
export DEEPSEEK_API_KEY="sk-xxx"

# 或写入 ~/.aider.conf.yml
cat > ~/.aider.conf.yml << 'EOF'
openai-api-key: sk-xxx
model: gpt-5
editor: nvim
auto-commits: true
EOF

配置文件

# ~/.aider.conf.yml 或 .aider.conf.yml（项目级）

# 模型配置
model: gpt-5                    # 主模型
editor-model: gpt-5-mini       # 编辑器模型（快速任务）
weak-model: gpt-5-mini          # 弱模型（简单任务）

# API Keys
openai-api-key: sk-xxx
anthropic-api-key: sk-ant-xxx
gemini-api-key: xxx

# Git 配置
auto-commits: true              # 自动提交 AI 修改
commit-prompt: true             # 提交前确认
dirty-commits: false            # 允许在脏工作区提交

# 编辑器
editor: nvim                    # 用于编辑文件的编辑器
auto-test: true                 # 自动运行测试
test-cmd: "npm test"            # 测试命令

# 界面
pretty: true                    # 美化输出
show-diffs: true                # 显示差异
stream: true                    # 流式输出

# 高级
map-tokens: 4096                # 仓库地图 token 数
context-window: 128000          # 上下文窗口大小
input-format: markdown           # 输入格式

基础使用

启动 Aider

# 在项目目录中启动
cd my-project
aider

# 启动时添加文件
aider src/auth/login.py src/auth/register.py

# 启动时添加目录（递归添加所有文件）
aider src/auth/

# 指定模型启动
aider --model claude-sonnet-4-20250514

# 只读模式（不修改文件）
aider --read-only

# 快速命令模式（不进入交互）
aider --message "修复 login.py 中的导入错误" src/auth/login.py

Git 原生集成

Aider 的 Git 集成是其核心特色，每次 AI 修改都会自动提交到 Git，方便审查、对比和回滚。

flowchart LR Edit[AI 修改代码] --> Detect[检测变更] Detect --> AutoCommit[自动 git add 加 commit] AutoCommit --> Log[进入提交历史] User1[diff 命令] --> Show[查看工作区差异] User2[undo 命令] --> Revert[git revert 最近一次提交] User3[独立分支 feature] --> Review[git diff main 审查] Review --> Merge[满意则 merge] Review --> Drop[不满意则删分支]
任务类型推荐模型理由
简单补全/小修小补gpt-5-mini / qwen2.5-coder:7b快、便宜，本地可跑
日常功能开发Claude Sonnet 4性价比与编码能力平衡
复杂架构/调试Claude Opus 4 / GPT-5推理最强
敏感/内网代码Ollama 本地 qwen2.5-coder数据不出本机
中文为主DeepSeek / Qwen中文表达好、成本低

Git 工作流纪律：永远在独立分支上跑 Aider，让它把每次改动都变成 commit——满意就 merge，不满意就 /undo 或直接删分支，主分支永远干净。

核心功能

  • 自动提交：每次 AI 修改自动创建 Git 提交，提交信息描述修改内容
  • 分支管理：可以在独立分支上工作，不影响主分支
  • Diff 审查：/diff 查看当前修改的具体差异
  • 一键回滚：/undo 撤销最后一次 AI 修改（Git revert）
  • 提交历史：完整的修改历史，每次 AI 操作都有记录
  • 代码审查：可以用 Git 工具审查 AI 的所有修改
  • 脏工作区保护：默认不在脏工作区提交，避免混淆人工和 AI 修改

Git 工作流

# 推荐：在独立分支上使用 Aider
git checkout -b feature/aider-login

# 启动 Aider
aider src/auth/

# AI 会自动提交，查看提交历史
git log --oneline

# 审查所有 AI 修改
git diff main...feature/aider-login

# 满意后合并
git checkout main
git merge feature/aider-login

# 不满意则删除分支
git branch -D feature/aider-login

本地模型支持

Aider 对本地模型支持友好，可以使用 Ollama、LM Studio、llama.cpp 等运行本地模型，数据不离开本地，保护隐私，免费使用。

Ollama 集成

# 1. 安装 Ollama
# macOS: brew install ollama
# Linux: curl -fsSL https://ollama.com/install.sh | sh

# 2. 下载模型
ollama pull codellama:7b
ollama pull deepseek-coder:6.7b
ollama pull qwen2.5-coder:7b

# 3. 启动 Aider 使用本地模型
aider --model ollama/codellama:7b

# 或配置为默认
cat >> ~/.aider.conf.yml << 'EOF'
model: ollama/qwen2.5-coder:7b
editor-model: ollama/qwen2.5-coder:7b
weak-model: ollama/qwen2.5-coder:1.5b
EOF

# 推荐的本地编码模型
# - qwen2.5-coder:7b（阿里，中文好，编码能力强）
# - deepseek-coder:6.7b（DeepSeek，编码能力强）
# - codellama:7b（Meta，基础编码）
# - starcoder2:7b（HuggingFace，开源）

本地模型使用技巧

  1. 选择编码专用模型：qwen2.5-coder、deepseek-coder 等比通用模型编码能力强
  2. 足够的显存：7B 模型需要约 8GB 显存，13B 需要 16GB
  3. 量化模型：使用 Q4_K_M 量化，在质量和速度间平衡
  4. 增加上下文：ollama run qwen2.5-coder:7b --ctx-size 8192
  5. 小文件优先：本地模型上下文有限，添加少量相关文件
  6. 简单任务：本地模型适合简单任务，复杂任务用云端强模型

我用 Aider 干过的几件实事

我是 Aider 的老用户了，从 2024 年它还没什么名气的时候就在用。说几个真实场景，你就知道它适合干啥、不适合干啥。

最爽的一次是重构一个老 Go 项目。那项目有 40 多个文件，我让 Aider 把所有 http.Handler 改成带中间件的版本，它自己读了仓库地图、加了相关文件、改完还自动跑了测试。整个过程我就敲了一句话，它改了 12 个文件，commit 历史清清楚楚。这种"批量机械改造"的活，Aider 比我手敲快 10 倍。

但它也有翻车的时候。有次我让它加个业务逻辑，它自作主张改了一个我没 /add 的公共函数，导致另外两个模块挂了。还好它每次改动都自动 commit，我 git diff 一看就发现了，git revert 一秒回滚。这就是我为什么死磕它的 Git 集成——没有这个，我真不敢让它碰生产代码。

别犯我犯过的错

Aider 默认改完就 commit，但它改的文件范围可能比你想的大。养成习惯：每次让它干活前，/add 精确控制文件范围；干完活先 /diff 看一眼再让它提交。别盲信。

仓库地图到底是个啥

Aider 有个独门武器叫 repo map，很多人没搞懂它在干嘛。说白了就是：你的项目可能有几百个文件，全塞给 LLM 上下文放不下，也浪费钱。Aider 用一个简单的 PageRank 变种，分析你的代码符号关系，挑出"最相关的那一小块"塞进上下文。

比如你让它改登录逻辑，它会自动把 auth.go、session.go、user.go 的关键函数签名拎出来，而不是把整个仓库读一遍。这个机制让它在大项目里也能跑，而且省 token。

配置地图大小效果适用场景
默认 auto自动按 token 预算切平衡日常开发
--map-tokens 10241K token快但可能漏上下文小项目、简单改动
--map-tokens 40964K token上下文足，准大型重构、跨模块改动
关闭地图0纯靠 /add 文件你自己很清楚要改哪几个文件

我的习惯是大项目直接给 --map-tokens 2048，够它看清结构，又不会把上下文塞爆。这个值调到多少合适，你拿自己的项目试两次就有数了。

常见问题 FAQ

Q1：Aider 和 Cursor 到底选哪个？

这俩我都重度用。Cursor 是 GUI，在编辑器里改代码直观，适合边看边改；Aider 是命令行，Git 集成是它的灵魂，每次改动自动 commit、一键回滚。我个人的分工是：写新功能、看代码用 Cursor；批量重构、跑自动化、CI 里集成用 Aider。没有谁更好，看你工作流。

Q2：Aider 改坏了代码怎么办？

别慌。它每改一次都会自动 git commit，你 git log 一看就知道哪次改坏了，git revert 跟上那次提交号就回去了。这也是为什么我强烈建议你在独立分支上用它，别直接在 main 上跑。真出事了，分支一删就完事。

Q3：为什么 Aider 老是改我没让它改的文件？

两个原因：一是仓库地图把相关文件拉进来了，它觉得要一起改；二是它"自作主张"补全了它认为该改的地方。解决办法：用 /add 精确指定文件，别靠 auto-add；系统提示词里写清楚"只改我指定的文件"。

Q4：本地模型跑 Aider 体验差多少？

2026 年差距已经很小了。Qwen3 14B 量化之后跑在本地，写常规业务代码没什么问题，复杂算法设计还是差点意思。最大的好处是隐私——公司代码不敢往云端 API 送的，本地模型是唯一选择。我自己开发的时候，敏感项目全走本地。

Q5：Aider 支持 MCP 吗？

2025 年后的版本已经支持 MCP 了，可以接外部工具。但说实话，Aider 的核心场景是"改代码+Git"，MCP 工具链不是它的强项。如果你需要复杂的工具调用编排，那应该看 Claude Code 或 LangGraph，别指望 Aider 干那个。
