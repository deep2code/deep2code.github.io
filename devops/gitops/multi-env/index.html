GitOps 多环境管理：开发、测试、生产

🏷️ GitOps

开发环境改了东西，测试环境说没效果，生产环境又出问题。多环境管理就是个头疼事。GitOps 用 Git 来管理所有环境配置，改了什么一目了然。

flowchart LR A[开发环境] --> B[测试环境] B --> C[预发环境] C --> D[生产环境] A -->|Git PR| B B -->|审批| C C -->|灰度| D

环境太多，配置乱了

⚠️
你遇到的问题

开发、测试、预发、生产四个环境，每个环境配置都不一样，改了生产忘了改测试。

怎么解决？用 Git 管理所有环境配置，每个环境一个分支，改了什么都有记录，可追溯。

# GitOps 流程
1. 代码合并到 dev 分支 → 自动部署开发环境
2. 提 PR 到 test 分支 → 自动部署测试环境
3. 审批合并到 main → 自动部署生产环境

生产环境改了东西，没人知道

⚠️
你遇到的问题

运维直接登服务器改配置，出问题了谁也不知道改了啥。

怎么解决？所有配置改动都必须通过 Git PR，禁止直接改服务器，改了什么一目了然。

# 禁止直接改服务器
所有配置改动 → 提 PR → 代码评审 → 自动部署
谁改的、什么时候改的、改了啥，Git 里全有记录

环境对应分支

环境 Git 分支 部署触发 用途
开发环境 dev 提交自动部署 开发自测
测试环境 test 提 PR 自动部署 测试人员测试
预发环境 staging 合并自动部署 上线前验证
生产环境 main 合并自动部署 正式环境

新手最容易踩的坑

❌
避坑指南
  • 生产环境一定要加审批，不能自动部署，至少要两个人确认
  • 所有环境配置尽量一致，除了地址、密码这些环境相关的，其他都一样
  • 配置和代码分开管理，别把配置硬编码到代码里
  • GitOps 不是万能的，小项目直接手动部署就行，别过度设计
