GitOps 入门：从你遇到的问题出发

🏷️ GitOps 入门

你在服务器上手动改了个配置，过了几天，没人记得改了什么，也不知道现在线上是什么状态，出了问题要翻半天。

这篇不讲理论，就讲你真的会遇到的问题，以及 GitOps 怎么帮你解决。

场景一：线上配置手动改了，没人记得改了什么

你遇到的问题

半夜出问题，你在服务器上手动改了个 Nginx 配置，重启服务就好了。过了一个月，配置又出问题了，你根本不记得当时改了什么，也不知道现在线上的配置和 Git 仓库里的差了多少。

GitOps 怎么解决？线上所有配置都存在 Git 仓库里，线上的状态永远和 Git 里的一样。你改配置只要改 Git 仓库里的文件，提交了，自动就同步到线上了。谁改了什么，Git 里都有记录，一清二楚。

# 改配置，只需要改 Git 仓库里的文件
git add nginx.conf
git commit -m "修改超时时间为 30s"
git push

# GitOps 工具自动把这个配置同步到线上服务器

现在线上的所有配置都在 Git 里，谁改了什么，什么时候改的，都有记录，再也不会出现"没人记得改了什么"的情况。

场景二：10 台服务器，配置不一样，有的改了有的没改

你遇到的问题

你有 10 台服务器跑 Nginx，你在第一台改了配置，第二台也改了，但是忘了改第八台。过了半个月，第八台出问题了，因为配置不对，排查了半天才发现。

GitOps 怎么解决？GitOps 工具会自动把 Git 里的配置同步到所有服务器，只要你改了 Git 里的文件，所有服务器自动就更新成一样的，不会有的改了有的没改。

场景三：改配置改坏了，回不到原来的状态

你遇到的问题

你改了个配置，结果服务挂了，你想回到改之前的样子，但是你不记得原来的配置是什么了，只能凭记忆改回去，越改越乱。

GitOps 怎么解决？Git 里每次改配置都有提交记录，你只要 git revert 一下，就能回到上一个版本，自动就把线上的配置恢复成原来的样子了，一键回滚。

概念通俗理解
Git 仓库唯一的配置来源：线上所有配置都从这里来
同步Git 里的配置变了，自动同步到线上
回滚改坏了，Git revert 一下，一键恢复
新手最容易踩的坑
  • 不要手动在线上改配置：所有配置都要改 Git 仓库里的文件，手动改了下次同步就被覆盖了，白改了。
  • 改完要提交 PR：不要直接 push 到 main 分支，走 PR 流程，有人审核了再合并，减少错误。
  • 敏感信息不要提交到 Git：密码、密钥这些不要提交到 Git 仓库，泄密了就出大事了。
  • 同步失败要有告警：Git 里的配置和线上不一致了，要马上告警，不然时间长了又乱了。
