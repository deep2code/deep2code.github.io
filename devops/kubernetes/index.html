K8s 深度原理：容器编排到底编什么？

🏷️ K8s

K8s 听起来很复杂，其实核心就几个概念：Pod、Deployment、Service。它解决的是容器管理问题：挂了自动拉起、扩容缩容、滚动更新。这篇从原理讲透 K8s。

核心原理1：Pod 是什么？为什么不直接用容器？

K8s 不直接管理容器，而是管理 Pod。Pod 是最小调度单位，里面可以跑一个或多个容器，共享网络和存储。

flowchart TD A[Pod] --> B[容器1 主应用] A --> C[容器2 Sidecar 边车] B --> D[共享网络 IP] C --> D B --> E[共享 Volume 存储] C --> E

Pod 核心概念

概念 含义 为什么需要
Pod 最小调度单位 多个紧密耦合的容器一起调度
Sidecar 边车容器 日志采集、代理、监控等辅助功能
共享网络 同一个 Pod 共享 IP 容器之间 localhost 通信
共享存储 同一个 Pod 共享 Volume 容器之间共享文件

核心原理2：Deployment 原理：怎么保证服务不挂？

Deployment 管理 Pod 副本数，挂了自动拉起，扩容缩容，滚动更新不停机。

flowchart LR A[Deployment] --> B[期望副本数 3] B --> C[ReplicaSet] C --> D[Pod 1] C --> E[Pod 2] C --> F[Pod 3] D -->|挂了| G[自动创建新 Pod]

K8s 核心资源

资源对象 作用 解决什么问题
Deployment 管理无状态应用 副本管理、滚动更新、回滚
ReplicaSet 保证副本数 挂了自动拉起新 Pod
Service 服务发现负载均衡 Pod IP 会变，Service 固定 IP
StatefulSet 有状态应用 固定网络标识、持久化

核心原理3：Service 原理：Pod IP 老变怎么访问？

Pod 重启 IP 就变了，不能直接用 Pod IP 访问。Service 有固定 IP，自动关联后端 Pod，负载均衡。

flowchart LR A[客户端] --> B[Service 固定IP] B --> C[负载均衡] C --> D[Pod 1 IP] C --> E[Pod 2 IP] C --> F[Pod 3 IP] D -->|挂了换新IP| G[自动更新 endpoints]

Service 类型

Service 类型 原理 适用场景
ClusterIP 集群内部虚拟 IP 集群内部服务访问
NodePort 每个节点开端口 外部测试访问
LoadBalancer 云厂商负载均衡 生产对外服务
Ingress 七层路由 域名转发到不同 Service

新手最容易踩的坑

❌
避坑指南
  • 不是所有项目都要上 K8s，小项目 Docker Compose 就够了
  • K8s 学习曲线陡，先搞懂核心概念再深入，别上来就搞 Operator
  • 资源请求和限制一定要设，不然一个 Pod 把节点资源吃光了
  • 配置和镜像不要硬编码，用 ConfigMap 和 Secret 管理
