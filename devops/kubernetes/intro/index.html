Kubernetes 入门：从你遇到的问题出发

🏷️ K8s 入门

你用 Docker 跑了 10 个服务，现在要更新一个版本，得一个个 docker stop、docker run，稍不注意就挂了一个。或者其中一台服务器挂了，上面的服务全都没了。

这些问题，K8s 就是为解决这个而生的。这篇不讲理论，就讲你真的会遇到的问题，以及 K8s 怎么帮你解决。

场景一：跑了 10 个服务，更新一个要手动操作半天

你遇到的问题

你用 Docker 跑了 10 个微服务，现在要更新一个版本，得先停旧的，再跑新的，一个一个来。10 个服务还好，等你跑到 100 个服务，你就疯了。而且哪个服务跑在哪台服务器上，你都记不清了。

K8s 怎么解决？你只要告诉 K8s："我要跑 3 个我的应用，版本是 v2"，K8s 自动帮你安排在哪台服务器上跑，自动更新，自动重启挂掉的。你不用管具体哪台机器跑了什么。

# deployment.yaml：你只要描述你想要什么
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3  # 我要跑3个实例
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: myapp:v2  # 版本是v2
# 一条命令应用，K8s自动帮你搞定
kubectl apply -f deployment.yaml

现在你要更新版本？改一下 image 标签，再 apply 一下，K8s 自动帮你滚动更新，不会停服。

场景二：一台服务器挂了，上面的服务全没了

你遇到的问题

你有 3 台服务器，上面跑了各种服务。突然其中一台服务器硬件坏了，上面跑的 5 个服务全挂了，用户投诉爆了。你才发现，你没有做高可用。

K8s 怎么解决？K8s 会自动把挂掉服务器上的服务，重新调度到其他正常的服务器上。你只要告诉它"我要 3 个实例一直跑着"，不管哪台服务器挂了，它都会自动补上。

# 看看现在有几个实例
kubectl get pods

# 手动删掉一个，K8s会自动再起一个新的
kubectl delete pod myapp-xxx

现在服务器挂了？K8s 自动把服务搬到其他服务器上，用户根本感觉不到。

场景三：流量突然暴涨，服务器扛不住了

你遇到的问题

你的网站突然上热搜了，流量一下子涨了 10 倍，服务器 CPU 直接 100%，用户开始打不开。你要手动去新的服务器上启动更多实例，等你弄完，流量都已经退了。

K8s 怎么解决？自动伸缩。流量大的时候自动多起几个实例，流量小的时候自动缩回去。

# HorizontalPodAutoscaler：自动伸缩
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  minReplicas: 2  # 最少2个
  maxReplicas: 10  # 最多10个
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70  # CPU超过70%就扩容

现在流量涨了，K8s 自动帮你多起几个实例，流量降了，自动缩回去。你什么都不用管。

概念通俗理解
Pod最小的运行单元：跑起来的一个容器
Deployment管理 Pod：保证一直有 N 个实例跑着
Service服务发现：给一组 Pod 一个固定的访问地址
Node工作机器：你的物理机或者虚拟机
Cluster集群：所有 Node 加起来就是一个集群
新手最容易踩的坑
  • 不要一开始就用 K8s：就一两个小网站，用 Docker Compose 就够了，K8s 是给大规模用的。
  • 配置文件不要写死：用 ConfigMap 和 Secret 管理配置和密码。
  • 一定要设资源限制：不设的话一个服务就能把整台机器吃满。
  • 日志不要写在容器里：容器删了日志就没了，要输出到 stdout，让 K8s 收集。
