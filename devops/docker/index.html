Docker：从开发到生产的标配

Docker 我用了快十年了。最早 2015 年左右接触的时候，大家都觉得这是个"虚拟机替代品"，性能比虚拟机好。后来发现不对——它不是虚拟机，是用 Linux namespace 和 cgroups 搞出来的轻量级隔离。2026 年了，Docker Engine 已经到 29.x，容器化基本是新项目的默认选项。

装一个

macOS 直接下 Docker Desktop，省心。Linux 上用 yum/apt：

# CentOS
yum install -y docker
systemctl start docker
systemctl enable docker

# 国内拉镜像慢，配个加速器
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io"],
  "live-restore": true
}
EOF
systemctl restart docker
国内拉镜像超时怎么办

这个问题我被问了无数次。Docker Hub 国内直连经常 TLS 握手超时，配个加速器就好。注意 2024 年官方的 docker-cn.com 镜像站关了，现在用 daocloud 或者阿里云的加速器，地址填到 registry-mirrors 数组里。

版本选哪个

版本线状态我的建议
29.x当前稳定（29.7.2 @ 2026-08）生产推荐
28.x2026-05 已停止支持赶紧升 29.x
25.0.x维护到 2026-12老系统，规划升级

Docker 到底是什么：底层原理

很多人天天用 Docker，但说不清容器和虚拟机的区别。我画个图你就明白了：

graph TB subgraph 容器 C1[容器1
应用+依赖] C2[容器2
应用+依赖] end subgraph 共享内核 KR[Linux 内核
namespace + cgroups] end subgraph 虚拟机 V1[Guest OS] V2[Guest OS] HV[Hypervisor] end KR --> C1 KR --> C2 HV --> V1 HV --> V2 style KR fill:#c8e6c9 style HV fill:#fff9c4

虚拟机要把整个操作系统装进去，每个 VM 有自己的内核，重得很。容器共享宿主机的内核，只是用 namespace 把进程隔离开，用 cgroups 限制资源。所以容器启动是秒级的，镜像比 VM 小一两个数量级。

Namespace：隔离的核心

Docker 用了 6 种 namespace，把容器跟宿主机隔开：

Namespace隔离什么不隔离会怎样
PID进程 ID容器能看到宿主机所有进程
Network网络栈容器跟宿主机共享 IP 和端口
Mount文件系统挂载点容器能看到宿主机整个文件系统
UTS主机名容器和宿主机 hostname 一样
IPC进程间通信容器间共享内存
User用户和组 ID容器内 root = 宿主机 root

Cgroups：资源限制

Namespace 负责"隔离开"，Cgroups 负责"限制住"。不给内存限制的话，一个容器把内存吃满，整个宿主机就 OOM 了。

# 限制 CPU 和内存
docker run -d --cpus="1.5" --memory="512m" nginx

# --cpus：最多用 1.5 个核
# --memory：最多用 512MB，超了 OOM Killer 直接杀进程
不给内存限制的教训

我早期踩过一个坑：一个 Java 容器没设内存限制，JVM 以为自己有宿主机全部内存，堆设得很大，结果把宿主机内存吃满，OOM Killer 把 Docker daemon 杀了，所有容器全挂。从那以后我所有容器都设 --memory 限制，JVM 启动参数也跟着调 -Xmx。

镜像层：Copy-on-Write

Docker 镜像是分层的，每层只读，多个容器共享相同的层。这就是为什么拉镜像快、占空间少——公共层只存一份。

graph TB subgraph 镜像层 L1[基础层
alpine rootfs] L2[依赖层
apt install ...] L3[应用层
COPY app] end subgraph 容器 C[可写层
容器运行时修改] end L1 --> L2 --> L3 --> C style C fill:#fedd00,stroke:#333

容器启动的时候，在镜像层上面加一个可写层。修改文件的时候，先把文件从只读层复制到可写层（Copy-on-Write），然后改副本。所以容器删除了，镜像层不受影响，多个容器共享。

常用命令速查

容器管理

docker ps              # 看运行中的
docker ps -a           # 看所有（包括停了的）
docker stop $(docker ps -q)   # 停所有运行中的
docker rm $(docker ps -a -q) # 删所有停了的

# 进入正在运行的容器
docker exec -it  /bin/bash

# 看日志
docker logs -f 
docker logs --tail 100 

# 进入容器 vs 在容器里执行
# docker run -it：容器前台跑，命令结束容器就停了
# docker exec -it：容器已经在跑了，进去开个新终端

镜像管理

docker images                    # 列镜像
docker rmi              # 删镜像
docker image prune               # 删所有没在用的镜像

# 清理悬空镜像（ 标签的）
docker images | grep none | awk '{print $3}' | xargs docker rmi

# 看镜像怎么构建出来的
docker history --no-trunc nginx

卷管理

docker volume ls                 # 列卷
docker volume create mydata       # 建卷
docker volume prune               # 清没用的卷

Dockerfile 怎么写

Dockerfile 写得好不好，直接决定镜像大小和构建速度。我踩过很多坑，总结几条经验。

多阶段构建：从 1.2GB 到 20MB

这是最重要的优化。编译需要编译工具，但运行时不需要。把编译和运行分开：

# 第一阶段：编译
FROM golang:1.26 AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN go build -o /app/server .

# 第二阶段：只复制二进制到极简镜像
FROM gcr.io/distroless/static
COPY --from=builder /app/server /server
EXPOSE 8080
ENTRYPOINT ["/server"]
效果有多明显

上面这个 Dockerfile，最终镜像大概 20MB。如果不用多阶段，直接在 golang 镜像里跑，镜像 1.2GB。差距 60 倍。我现在所有 Go 项目都用这个模式，CI 构建快、推送快、拉取快。

Dockerfile 写法规避

  1. 基础镜像选小的：alpine > slim > debian。alpine 用 musl libc，5MB 左右。但有些 C 扩展编译不了，那就用 slim
  2. COPY 顺序要注意缓存：先 COPY 依赖文件（go.mod / requirements.txt），下载依赖，再 COPY 代码。这样代码变了不用重新下依赖
  3. 合并 RUN：每多一行 RUN 就多一层，apt-get update && apt-get install -y xxx && rm -rf /var/lib/apt/lists/* 写一行
  4. 用 .dockerignore：把 .git、node_modules、.env 排除掉，不然构建上下文传一大堆没用的文件
  5. 别用 latest 标签：写死版本号 nginx:1.25，不然今天和明天拉的镜像不一样，出了问题没法复现

Docker Compose：多容器编排

一个项目有 Web、API、数据库、缓存，手动 docker run 太麻烦。Compose 用一个 yaml 文件管理所有服务。注意 v2 已经没有 version 字段了，直接写 services：

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    depends_on:
      - api

  api:
    build: ./api
    environment:
      - DB_HOST=db
    deploy:
      replicas: 3
      resources:
        limits:
          memory: 512M

  db:
    image: postgres:16
    volumes:
      - db_data:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: secret

volumes:
  db_data:

启动就一行：docker compose up -d。停掉：docker compose down。开发环境用这个比手动管方便太多。

私有镜像仓库

公司内部镜像总不能推到 Docker Hub 吧。搭个私有 Registry 很简单：

docker run -d -p 5000:5000 --restart=always \
  -v /opt/registry:/var/lib/registry \
  registry:2

# 打标签推上去
docker tag myapp:latest myregistry:5000/myapp:v1
docker push myregistry:5000/myapp:v1

# 默认 Registry 走 HTTP，Docker daemon 要配 insecure
# /etc/docker/daemon.json:
# { "insecure-registries": ["myregistry:5000"] }

生产环境我推荐用 Harbor 而不是裸 Registry——Harbor 有 UI、有 RBAC、有镜像扫描、有复制。裸 Registry 就是个存储桶，啥功能都没有。

网络模式

模式原理性能什么时候用
bridge（默认）独立网络栈，通过 docker0 通信中等大多数场景
host共享宿主机网络最高高性能网络，端口不冲突时
none只有 loopback—完全隔离的离线任务
自定义 bridge类似默认 bridge 但有 DNS中等多容器编排，用容器名互访

我在生产环境一般用自定义 bridge，服务之间直接用容器名通信，不用管 IP 变没变。默认 bridge 没有 DNS，只能用 IP，容器重启 IP 变了就找不到了。

2026 年的安全提醒

Docker 这几年出了几个比较严重的 CVE，特别是容器逃逸类的。几个我知道的：

  • CVE-2026-41567：docker cp 解压恶意归档可以逃逸到宿主机 root。29.5.1 修了
  • CVE-2026-41568：docker cp 挂载竞态，可以在宿主机任意路径创建文件。也是 29.5.1 修的
安全建议
  • 别用 --privileged，除非真的需要。特权容器等于把宿主机 root 交出去了
  • Dockerfile 里加 USER appuser，别用 root 跑应用
  • 基础镜像用官方的、签名验证过的，别随便用不知名的第三方镜像
  • 及时升级 Docker Engine，29.5.1 以下的版本有逃逸漏洞

Docker 不是唯一选择

工具特点什么时候选
Docker全家桶，最流行大多数场景，开发和 CI/CD
Podman无 daemon，Rootless安全敏感环境，K8s 生态
containerd轻量运行时K8s 节点用的就是这个
KanikoK8s 里构建镜像CI/CD 不需要装 Docker daemon

K8s 底层用的就是 containerd，不是 Docker。所以很多人以为 K8s = Docker，其实不是。K8s 只是用 OCI 标准，Docker 和 containerd 都是实现。

我踩过的坑

  1. 数据存容器里：容器删了数据就没了。所有有状态的数据一定要挂 volume，容器本身是临时的
  2. 没设内存限制：前面说了，OOM 把整个宿主机搞挂
  3. 用 latest 标签：今天构建的和明天构建的 latest 不是同一个镜像，出了问题回滚都不知道回哪个版本
  4. 日志写文件：应用把日志写到容器内文件，容器删了日志没了。正确做法是输出到 stdout/stderr，Docker 的 json-file driver 自动收集
  5. 构建上下文太大：忘了写 .dockerignore，把 node_modules（几个 G）全传上去，构建慢得要死
  6. 特权容器：图省事加了 --privileged，等于把宿主机内核暴露给容器了。能不用就不用，用 --cap-add 加特定能力

FAQ

容器和虚拟机到底有啥区别？

虚拟机每个有自己的内核，重，启动分钟级。容器共享宿主机内核，轻，启动秒级。容器不是虚拟化硬件，是虚拟化操作系统。你可以理解成"沙盒化的进程"，比 VM 快但隔离性弱一些。

Docker Desktop 和 Engine 有什么区别？

Docker Engine 是服务端，跑在 Linux 上。Docker Desktop 是给 Mac/Windows 用的桌面应用，里面跑了个 Linux VM，VM 里装了 Engine。Mac 上跑 Docker 其实就是跑虚拟机里的 Linux，这就是为什么 Mac 上 Docker 比 Linux 上慢——多了一层虚拟化。

怎么减小镜像体积？

多阶段构建是第一招。然后选小基础镜像（alpine 或 distroless），合并 RUN 清理缓存，用 .dockerignore。我一般把一个 Go 服务从 1.2GB 压到 20MB 左右。

Docker 和 K8s 是什么关系？

Docker 是容器运行时，K8s 是容器编排系统。K8s 管一堆机器上的容器怎么调度、怎么扩容、怎么自愈。K8s 底层可以用 containerd、CRI-O，不一定非要 Docker。但 Docker Desktop 是开发本机用的，K8s 生产环境跑在服务器上。
