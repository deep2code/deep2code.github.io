Docker 深度原理：容器为什么轻量？

🏷️ Docker

很多人用 Docker 只会 docker run，但不知道容器为什么比虚拟机轻这么多，不知道镜像分层怎么回事，也不知道网络和存储怎么实现的。这篇从底层原理讲透 Docker。

核心原理1：容器 vs 虚拟机：为什么轻 100 倍？

虚拟机要装完整的 Guest OS，每个几 GB，启动几分钟。容器共享宿主机内核，只有几百 MB，启动毫秒级。

flowchart TD A[架构对比] --> B[虚拟机] A --> C[容器] B --> B1[App] B --> B2[Guest OS 几GB] B --> B3[Hypervisor] B --> B4[宿主机 OS] C --> C1[App] C --> C2[依赖库] C --> C3[容器引擎 Docker] C --> C4[宿主机内核 共享]

对比表格

对比项 虚拟机 容器
启动时间 分钟级 毫秒级
资源占用 几 GB 几百 MB
隔离级别 硬件级隔离 进程级隔离
安全性 高 中
性能损耗 多一层 Hypervisor 几乎无损耗
部署密度 一台机几个 一台机几百个

核心原理2：镜像分层：为什么镜像那么小？

Docker 镜像不是一个完整的文件，是一层层叠起来的，每层只读，改了只加新层，相同层共享。

flowchart LR A[Base 层] --> B[系统层] B --> C[依赖层] C --> D[代码层] D --> E[配置层] A1[ubuntu:22.04] --> B1[apt install] B1 --> C1[node_modules] C1 --> D1[app code] D1 --> E1[config]

分层优势

优势 原理 好处
复用 相同层只存一份 多个镜像共享，省磁盘
传输快 只传变化的层 push/pull 快，省带宽
构建快 改了代码只加一层 不用从头构建
缓存 层没变就用缓存 CI/CD 构建快很多

核心原理3：网络原理：容器之间怎么通信？

Docker 默认用 bridge 网络，每个容器分配一个虚拟 IP，通过宿主机的网桥转发。

flowchart LR A[容器1 172.17.0.2] --> B[docker0 网桥] C[容器2 172.17.0.3] --> B B --> D[宿主机 网卡] D --> E[外网]

网络模式

模式 原理 适用场景
bridge 默认，网桥 NAT 单机容器通信
host 直接用宿主机网络 性能要求高
none 没有网络 安全隔离
overlay 跨主机网络 Swarm 集群
