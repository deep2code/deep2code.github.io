Docker 实战：从你遇到的问题出发

🏷️ Docker 入门

你在自己电脑上写的代码，跑到同事电脑上就跑不起来了。"我这明明是好的啊！"——每个程序员都喊过这句话。

或者：你要部署个新服务，光装依赖就装了一下午，还遇到各种版本冲突。部署到服务器上又出问题，来回折腾了一整天。

这些问题，Docker 就是为解决这个而生的。这篇不讲理论，就讲你真的会遇到的问题，以及怎么用 Docker 解决。

场景一：我这明明是好的啊！

你遇到的问题

你在自己电脑上写了个 Python 服务，跑的好好的。你把代码发给同事，他一跑就报错："依赖找不到！"你们俩 Python 版本不一样，你是 3.10，他是 3.8。折腾了一下午才弄好环境。

Docker 怎么解决？把你的代码和环境一起打包成一个镜像，这个镜像在任何地方跑都是一样的。你电脑上跑的好好的，同事电脑上、服务器上，跑出来一模一样。

# Dockerfile：把你的项目和环境打包
FROM python:3.10-slim

WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .

CMD ["python", "main.py"]
# 打包成镜像
docker build -t myapp .

# 跑起来，不管在哪都是一样的环境
docker run -p 8080:8080 myapp

现在你把镜像发给同事，他直接跑就行，不用装 Python，不用装依赖，什么都不用管。再也不用说"我这明明是好的啊"了。

场景二：部署个新服务，光装环境就装了一下午

你遇到的问题

你要在服务器上部署一个 MySQL、一个 Redis、一个你的应用。你要先装 MySQL，配配置，启动；再装 Redis，配密码，启动；再装你的应用，配环境变量。一台服务器装一下午，换台服务器又要再来一遍。

Docker 怎么解决？所有服务都跑在容器里，一条命令就能起一个服务。

# 启动 MySQL，一条命令
docker run -d --name mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0

# 启动 Redis，一条命令
docker run -d --name redis -p 6379:6379 redis:7

# 启动你的应用，一条命令
docker run -d --name myapp -p 8080:8080 myapp

现在部署一个服务只要一条命令，换台服务器？把这三条命令复制过去就行，5 分钟搞定。

场景三：测试环境好好的，上线就挂了

你遇到的问题

测试环境你装的 MySQL 8.0，线上服务器是 MySQL 5.7。测试的时候好好的，上线就报语法错误。你还得在本地重新装个 5.7 来调试，折腾死了。

Docker 怎么解决？测试环境和线上环境用同一个 Docker 镜像，版本完全一样。测试的时候跑的就是 8.0，线上跑的也是 8.0，不会有版本不一致的问题。

概念通俗理解
镜像（Image）安装包：把程序和环境打包好的文件
容器（Container）运行起来的程序：用安装包装完跑起来的进程
Dockerfile安装脚本：告诉你怎么打包成镜像
仓库（Registry）应用商店：存镜像的地方，比如 Docker Hub

场景四：服务挂了，要手动重启

你遇到的问题

你的应用半夜崩溃了，第二天用户投诉了你才发现。你想：能不能服务挂了自动重启？

Docker 怎么解决？加个 --restart=always 参数，容器挂了自动重启。

# 服务挂了自动重启，开机也自动启动
docker run -d --restart=always --name myapp -p 8080:8080 myapp

现在服务崩了，Docker 自动帮你重启，不用你半夜爬起来手动操作了。

新手最容易踩的坑
  • 不要把数据存在容器里：容器删了数据就没了，要用 volume 挂载出来。
  • 镜像不要太大：用 alpine 或者 slim 版本，能小一半。多阶段构建也能减体积。
  • 不要把密码写在 Dockerfile 里：用环境变量或者 secrets。
  • 不要用 latest 标签：版本不固定，下次拉镜像可能就变了，要指定具体版本号。
