结构化日志入门：从你遇到的问题出发

🏷️ 结构化日志

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及结构化日志怎么帮你解决。

flowchart TB A[传统日志] --> B[非结构化] B --> C[难搜索] C --> D[结构化日志] D --> E[JSON 格式] E --> F[易搜索分析]

1. 日志不好搜

你遇到的问题

日志都是一行行文本，想按用户 ID 搜要写正则，太麻烦。

怎么解决？用结构化日志，JSON 格式，字段固定，方便搜索分析。

2. 结构化日志是什么

你遇到的问题

结构化日志是什么？

怎么解决？日志用 JSON 格式，字段固定（time/level/user_id/msg），方便机器解析。

3. 怎么打

你遇到的问题

怎么打结构化日志？

怎么解决？日志库选支持结构化的（zap/serilog），输出 JSON 格式。

对比传统日志结构化日志

新手最容易踩的坑
  • 一定要带 Trace ID所有结构化日志都要带 Trace ID，能串起来。
  • 字段要统一不同服务日志字段要统一，不要各写各的。
