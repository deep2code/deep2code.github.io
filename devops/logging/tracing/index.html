链路追踪

什么是链路追踪

一个请求经过多个服务：网关 → 订单服务 → 库存服务 → 支付服务。出问题了不知道哪一步慢了。链路追踪就是把整个请求路径串起来，每一步耗时都能看到。

graph LR A[用户请求] --> B[网关 10ms] B --> C[订单服务 50ms] C --> D[库存服务 30ms] D --> E[支付服务 200ms] E --> F[响应 290ms]

核心概念

概念说明
Trace一次完整请求链路
Span一个操作（一次 RPC、一次 DB 查询）
TraceId链路唯一 ID，全链路透传

OpenTelemetry

2026 年链路追踪的标准。统一了指标、日志、追踪三个信号。

  • 自动埋点：主流框架自动埋，不用自己写
  • 导出标准：OTLP 协议，兼容 Jaeger/Zipkin
  • 语言无关：Java/Go/Python/Node 都支持

怎么用

  • 每个请求生成 TraceId，通过 HTTP Header 透传
  • 每一步操作生成 Span，记录开始结束时间
  • 上报到 Jaeger/Tempo 等后端存储
  • 看火焰图找性能瓶颈
