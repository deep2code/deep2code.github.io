Harbor

🏷️ Harbor

为什么需要 Harbor

Docker Hub 是公共镜像仓库，国内拉取速度慢还容易被封。公司内网环境更不能直接连外网。这时候就得搭私有镜像仓库——我从 2018 年开始用 Harbor，一开始是用官方 Registry + 自己写鉴权脚本，后来 Harbor 成熟了就直接用它。

Harbor 最早是 VMware 开源的，2022 年捐给了 CNCF，现在已经毕业了。它比官方 Docker Registry 多了 Web UI、RBAC 权限管理、LDAP 集成、镜像漏洞扫描、镜像签名——这些都是生产环境必须的。

安装部署

官方最低要求 2 核 4G，我生产环境至少给 4 核 8G。不然 Trivy 扫描的时候内存吃紧，整个仓库响应就变慢了。

在线安装

# 下载离线安装包（推荐用 offline 版本，包含所有镜像）
wget https://github.com/goharbor/harbor/releases/download/v2.10.0/harbor-offline-installer-v2.10.0.tgz
tar -xzf harbor-offline-installer-v2.10.0.tgz
cd harbor

# 配置
cp harbor.yml.tmpl harbor.yml
# 编辑 harbor.yml：改 hostname、https 证书路径、admin 密码

# 安装（带 Trivy 扫描和 Chart 仓库）
sudo ./install.sh --with-trivy --with-chartmuseum

harbor.yml 关键配置

hostname: harbor.yourdomain.com
https:
  port: 443
  certificate: /data/cert/harbor.crt
  private_key: /data/cert/harbor.key

harbor_admin_password: 自己改一个强密码！

# 数据库（生产建议用外部 PG）
database:
  password: 自己改！
  max_idle_conns: 50
  max_open_conns: 100

# 镜像存储
storage_service:
  filesystem:
    rootdirectory: /data/registry

# 启用组件
with_trivy: true
with_chartmuseum: true
with_notary: true
默认密码的坑

Harbor 默认 admin 密码是 Harbor12345。我见过太多团队忘了改就上线，被人爬了镜像仓库。首次登录第一件事：改密码！

推送和拉取镜像

# 登录
docker login harbor.yourdomain.com

# 标记镜像（命名格式：域名/项目名/镜像名:标签）
docker tag myapp:latest harbor.yourdomain.com/prod/myapp:v1.0

# 推送
docker push harbor.yourdomain.com/prod/myapp:v1.0

# 拉取
docker pull harbor.yourdomain.com/prod/myapp:v1.0

镜像复制与多仓库架构

我们公司有两个机房（深圳 + 上海），各跑一个 Harbor 实例。镜像推到深圳后自动复制到上海，K8s 节点就近拉取，延迟从 200ms 降到 10ms。

复制策略触发方式适合场景
Push-based源推到目标主中心 + 分中心
Pull-based目标从源拉边缘节点主动拉
事件触发镜像推送时自动复制多机房实时同步
定时触发cron 定时非实时，省带宽

复制是增量的——基于内容寻址（digest 相同则内容相同），相同的层只传一次。第一次全量同步可能慢，但后续增量很快。

垃圾回收：磁盘杀手的克星

这是 Harbor 运维中最容易踩坑的地方。删了镜像标签，但磁盘空间没释放——因为 Harbor 的垃圾回收不是实时的。

# 先把 Registry 设为只读（避免 GC 期间新上传导致问题）
docker-compose stop harbor-core
docker start registry # 或者直接改 registry 配置

# 执行 GC（dry-run 先看会删什么）
docker exec -it harbor-registry registry garbage-collect --dry-run /etc/registry/config.yml

# 正式执行
docker exec -it harbor-registry registry garbage-collect /etc/registry/config.yml

# 恢复服务
docker-compose start harbor-core
GC 必须在低峰期做

GC 期间 Registry 是只读的，不能 push。我之前周三下午跑 GC，正好赶上发版，CI 流水线全挂了。现在固定周日凌晨 3 点跑，没人用。

安全：漏洞扫描和镜像签名

2024 年以后安全要求越来越严。我们公司所有镜像推送到 Harbor 后自动用 Trivy 扫描，有 Critical 漏洞的镜像禁止部署到生产 K8s。

安全层级技术手段作用
RBAC 权限项目级角色（管理员/开发者/访客）谁能推、谁能拉
漏洞扫描Trivy 自动扫描发现已知 CVE
镜像签名Notary / Cosign防止镜像被篡改
部署策略只有扫描通过的镜像才能拉安全门禁
审计日志记录所有 push/pull/delete事后追溯

备份和恢复

# 备份数据库
docker exec harbor-db pg_dump -U postgres harbor > harbor_backup.sql

# 备份镜像存储（大，增量用 rsync）
rsync -av /data/registry/ /backup/registry/

# 备份配置
cp harbor.yml harbor.yml.bak

# 恢复
docker exec -i harbor-db psql -U postgres harbor < harbor_backup.sql
rsync -av /backup/registry/ /data/registry/
docker-compose restart

8 个踩过的坑

  1. 不配置 HTTPS：Docker 默认拒绝 HTTP 仓库，客户端要加 insecure-registries，生产千万别这么干
  2. 磁盘满了没人知道：Harbor 没有磁盘使用率告警，我装了个 Node Exporter + Grafana 监控，超过 80% 告警
  3. 镜像标签不清理：CI/CD 每次构建都打新 tag，三个月磁盘从 100G 涨到 2T。现在配了保留策略，每个镜像保留最近 10 个 tag
  4. 单节点部署：生产必须高可用！单节点挂了，CI/CD 全停。多节点 + 共享 S3 存储 + 外部 PG
  5. GC 期间推送：GC 期间 Registry 只读，CI 推送会失败。固定低峰期跑 GC
  6. Trivy 数据库不更新：漏洞数据库每周更新一次，忘了配自动更新，扫了一堆旧 CVE
  7. 项目公开：新建项目默认设为公开，内部镜像谁都能拉。全部改成私有
  8. 没配额限制：一个项目传了 500G 镜像，把整个仓库撑爆。项目级配额限 50G

FAQ

Harbor 能用 S3 做后端存储吗？

可以。harbor.yml 里把 storage_service 从 filesystem 改成 s3，配 bucket 和密钥就行。用 S3 的好处是存储弹性扩展，不用自己管磁盘。但注意 S3 的访问延迟比本地文件系统高，大量小文件会慢。

Harbor 支持 Helm Chart 吗？

支持。安装时加 --with-chartmuseum 参数就启用了 Helm Chart 仓库。helm push 直接推到 Harbor，跟 Docker 镜像一个 UI 管理。

怎么清理不用的镜像标签？

Harbor 有 Tag Retention 策略：在项目设置里配"保留最近 N 个标签"，自动清理旧标签。但注意：清理标签不释放磁盘空间，还要跑垃圾回收才真正释放。

Harbor 升级要注意什么？

先备份数据库和镜像存储！然后停服务，下载新版本，用新配置启动。跨大版本升级（比如 2.5 → 2.10）要按官方文档一步步来，别跳版本。

K8s 怎么用 Harbor 私有仓库？

在节点上配置 docker login 保存凭证。然后在 K8s Secret 里创建 dockerconfigjson 类型的 secret，Pod 里 imagePullSecrets 引用它。我一般把 secret 放到每个 namespace 里。
