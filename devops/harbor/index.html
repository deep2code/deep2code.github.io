Harbor 入门：从你遇到的问题出发

🏷️ Harbor 入门

你用 Docker 打包了镜像，存在 Docker Hub 上，但是拉镜像太慢了，而且公司的内部镜像不能传到公网。你想：有没有自己的镜像仓库？

这篇不讲理论，就讲你真的会遇到的问题，以及 Harbor 怎么帮你解决。

场景一：从 Docker Hub 拉镜像太慢了

你遇到的问题

你在服务器上拉个 nginx 镜像，等了 10 分钟还没拉完。国内访问 Docker Hub 太慢了，经常超时，部署个应用半天都跑不起来。

Harbor 怎么解决？你自己搭一个 Harbor 镜像仓库，把常用的镜像都同步到自己的仓库里，拉镜像直接从你自己的仓库拉，速度快 10 倍以上。

# 之前：从 Docker Hub 拉，慢死
docker pull nginx:latest

# 现在：从自己的 Harbor 拉，秒拉
docker pull harbor.yourcompany.com/library/nginx:latest

场景二：公司内部镜像不能传到公网 Docker Hub

你遇到的问题

你打包了公司业务的镜像，里面有公司的代码，不能传到公网的 Docker Hub 上，泄密了就出大事了。但是你要把镜像传到生产服务器上跑，怎么传？

Harbor 怎么解决？Harbor 是你自己搭的私有镜像仓库，只有公司内网能访问。你把镜像传到自己的 Harbor，生产服务器从 Harbor 拉镜像，既快又安全，不会泄密。

场景三：镜像版本乱了，不知道哪个是生产在用的

你遇到的问题

大家随便打镜像标签，有的叫 v1，有的叫 test，有的叫 latest，过了几个月，根本不知道哪个版本是生产在用的，哪个是测试的，乱成一锅粥。

Harbor 怎么解决？Harbor 可以按项目分：生产镜像放一个项目，测试镜像放另一个项目。还能给镜像打标签、做漏洞扫描、保留策略，旧的镜像自动清理，不会乱。

概念通俗理解
Project（项目）镜像分组：生产镜像一个项目，测试镜像另一个
Repository（仓库）一个应用的镜像：比如 nginx 仓库、redis 仓库
Tag（标签）镜像版本：v1.0、v2.0、latest
新手最容易踩的坑
  • 不要用 latest 标签部署生产：latest 指向哪个版本都不知道，出问题根本回滚不了，生产一定要用明确的版本号。
  • Harbor 要定期备份：镜像仓库挂了，所有镜像都没了，业务就跑不起来了。
  • 不要给公共项目写权限：公共项目只能读，不能随便写，不然有人乱传镜像。
  • 定期清理旧镜像：镜像太多占满磁盘，设置保留策略，只留最近几个版本。
