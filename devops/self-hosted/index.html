为什么我要自己搭代码托管

2020 年我开始折腾自托管。起因很简单：公司代码不能放 GitHub，GitHub Enterprise 太贵，GitLab CE 又太重。后来发现 Gogs 这个轻量级方案，一个二进制文件就能跑，512MB 内存就够了。从那以后我就入坑了自托管。

硬件怎么选

自托管第一步是选硬件。我从树莓派 4 开始，后来换了 N100 小主机，现在跑了 6 个服务，功耗才 15W。

个人自托管首选 N100 小主机。500 块钱，16GB 内存，能跑 10 个容器服务。功耗低到忽略不计。比树莓派强在 x86 架构，不用折腾 ARM 编译。

公网访问：没公网 IP 怎么办

这是自托管最头疼的问题。国内家庭宽带默认没有公网 IPv4，IPv6 倒是有但运营商不一定给你分配稳定的。我试过几种方案：

方案原理优点缺点我用了吗
Cloudflare Tunnel反向隧道，不用公网 IP免费，自动 HTTPS流量过 Cloudflare主力方案
TailscaleWireGuard 虚拟内网零配置，P2P只能内网访问管理用
frp 自建有公网 VPS 做中转完全可控要维护 VPS早期方案
DDNS + 端口转发有公网 IP 直接映射最快运营商不给公网 IP问过客服，不给

现在我的方案是：Cloudflare Tunnel 暴露 Gitea 和 Nextcloud 到公网，Tailscale 用来 SSH 管理服务器。两全其美。

Gitea：轻量代码托管

原文用的是 Gogs，我后来迁移到了 Gitea。Gogs 近年维护慢了，Gitea 活跃得多。迁移很简单——Gitea 兼容 Gogs 的数据格式，直接导入就行。

# 安装 Gitea（单二进制）
wget -O gitea https://dl.gitea.com/gitea/1.22.0/gitea-1.22.0-linux-amd64
chmod +x gitea
sudo mv gitea /usr/local/bin/

# 创建用户
sudo useradd --system --shell /bin/bash --create-home git

# 初始化配置
sudo -u git gitea web -c /etc/gitea/app.ini

或者用 Docker 部署，更省心：

# docker-compose.yml
version: '3.8'
services:
  gitea:
    image: gitea/gitea:1.22
    container_name: gitea
    restart: always
    ports:
      - "3000:3000"   # Web
      - "222:22"      # SSH
    volumes:
      - ./data:/data
      - /etc/timezone:/etc/timezone:ro

反向代理：Caddy 还是 Nginx

原文用的 Nginx，我现在换成 Caddy 了。原因很简单：Caddy 自动申请和续期 Let's Encrypt 证书，一行配置搞定。Nginx 要配 certbot，还要写 cron 续期，烦。

CaddyNginxTraefik
自动 HTTPS✅ 全自动❌ 要 certbot✅ 全自动
配置复杂度极简（Caddyfile 一行）复杂中等
性能够用最高够用
调试日志清晰最成熟一般
我推荐个人项目首选生产环境Docker/K8s 环境

Caddy 配置示例：

git.mydomain.com {
    reverse_proxy localhost:3000
}

cloud.mydomain.com {
    reverse_proxy localhost:8080
}

就这两行。Caddy 自动申请证书、自动续期、自动 HTTP/2。比 Nginx 少写 90% 的配置。

备份：3-2-1 原则

自托管最痛的就是数据安全。我见过好几个朋友，硬盘挂了，几年的照片和代码全没了。

3-2-1 原则：3 份数据（原始 + 2 份备份）、2 种介质、1 份异地。

flowchart TD A[原始数据
NAS 主存储] --> B[本地备份
USB 硬盘] A --> C[云备份
Backblaze B2] B --> D[每周同步] C --> E[每天增量上传] F[3-2-1 原则] --> A F --> B F --> C style F fill:#fff3e0

我用的备份工具是 restic：

# 初始化备份仓库（在 Backblaze B2 上）
restic -r b2:mybucket:/homebackup init

# 备份主目录
restic -r b2:mybucket:/homebackup backup /home

# 查看快照
restic -r b2:mybucket:/homebackup snapshots

# 恢复文件
restic -r b2:mybucket:/homebackup restore latest --target /tmp/restore
备份没验证等于没备份

2023 年我的 NAS 硬盘坏了，才发现之前配的 restic 备份脚本有 bug，实际没成功跑。从那以后我每季度做一次恢复演练——从备份恢复到测试环境，确认数据完整。现在脚本跑了之后会发 Telegram 通知我成功还是失败。

自托管的 8 个坑

  1. 把 RAID 当备份：RAID 只能防硬盘坏，防不了误删、防不了勒索病毒。RAID 1 里一个文件被删了，两块盘同时删。必须有独立的备份
  2. 数据库暴露到公网：MySQL 3306、Redis 6379 绝对不能对公网开。我用 SSH 隧道访问管理端口
  3. 不更新：自托管服务要持续维护。我配了 unattended-upgrades 自动安全更新，但重大版本手动升
  4. 单点故障：一台服务器跑所有服务，挂了全挂。我至少保证有快速恢复能力——部署脚本 30 分钟内新机器恢复
  5. 没监控：服务挂了不知道。Uptime Kuma 监控所有 HTTP 服务，磁盘用 Node Exporter
  6. 密码全明文：配置文件里写数据库密码，谁拿到服务器就能看。我用 Docker secrets 或者环境变量
  7. 证书过期：Let's Encrypt 证书 90 天过期。Caddy 和 Traefik 自动续期，Nginx 要配 cron
  8. 过度工程：个人项目别上 K8s，别搞微服务。Docker Compose 就够了。我见过有人用 K8s 跑一个博客，纯属折腾

FAQ

自托管到底省不省钱？

说实话，小团队自托管不省钱。Gitea + Nextcloud + 服务器 + 电费，一个月成本跟用 SaaS 差不多。省的是数据主权和定制化能力。我自托管主要是不想把数据放在别人那里。

没有公网 IP 怎么外网访问？

三个方案：Cloudflare Tunnel（免费最推荐）、Tailscale（内网穿透）、frp（自己搭）。我用 Cloudflare Tunnel，域名解析到 Cloudflare，本地跑 cloudflared 客户端，不用开任何端口。

家用宽带上行带宽够吗？

这是个硬伤。家用宽带上行一般只有 30-50Mbps，多人同时访问会卡。我自己用没问题，但如果对外提供服务（比如博客），还是放云 VPS 上更好。

断电了怎么办？

买个 UPS（不间断电源），几百块钱。停电了能撑 30 分钟，够你优雅关机。不然突然断电容易损坏文件系统。我之前的 NAS 突然断电，ZFS 文件系统修复了半天才好。

Gitea 和 Gogs 选哪个？

新项目选 Gitea。Gogs 已经半停滞了，Gitea 活跃得多，功能也全（Actions、包管理、组织）。从 Gogs 迁移到 Gitea 很简单，Gitea 直接导入 Gogs 的数据库。
