安全入门：从你遇到的问题出发

🏷️ 安全入门

你的网站被人扫漏洞了，或者数据库密码泄露了，被人拖库了。你想：怎么才能防止别人搞破坏？

这篇不讲理论，就讲你真的会遇到的问题，以及怎么做安全防护。

场景一：服务器天天被人扫端口，SSH 爆破

你遇到的问题

你看服务器日志，发现每天有几千次 SSH 登录尝试，都是不同的 IP 在爆破密码。你的 root 密码设的很简单，说不定哪天就被爆破开了，服务器就成别人的肉鸡了。

怎么解决？第一，SSH 不要用密码登录，用密钥登录。第二，改 SSH 默认端口（22 改成别的）。第三，用 fail2ban 自动封掉爆破的 IP。

# 1. SSH 禁用密码登录，只允许密钥
# /etc/ssh/sshd_config
PasswordAuthentication no
PubkeyAuthentication yes

# 2. 改 SSH 端口
Port 2222

# 3. 装 fail2ban，自动封爆破 IP

现在爆破密码的人根本登不上来，扫端口的也扫不到你的 SSH 端口。

场景二：数据库密码写在代码里，被人拖库了

你遇到的问题

你把数据库密码写在配置文件里，然后把代码传到 GitHub 了。没过几天，就有人扫到了你的 GitHub 仓库，试了一下你的数据库 IP + 密码，直接登进来了，把用户表全拖走了。

怎么解决？第一，密码绝对不要传到 GitHub。第二，数据库不要对公网开放，只允许内网 IP 访问。第三，用配置中心存密码，不要硬编码在代码里。

# 数据库只允许内网访问
# 用防火墙把 3306 端口只对内网开放，外网根本访问不到

现在就算密码泄露了，别人在外网也连不上你的数据库。

场景三：网站被人 SQL 注入，数据全被删了

你遇到的问题

你写的查询是直接把用户输入拼到 SQL 里的：sql = "SELECT * FROM users WHERE name = '" + input + "'"。有人输入 ' OR 1=1 --，直接把所有用户数据都查出来了，还能执行 DROP TABLE 把表删了。

怎么解决？永远不要把用户输入直接拼到 SQL 里，用预编译语句（参数化查询）。

# 错误写法：直接拼接，会被注入
sql = "SELECT * FROM users WHERE name = '" + input + "'"

# 正确写法：参数化查询，自动防注入
cursor.execute("SELECT * FROM users WHERE name = %s", (input,))

现在不管用户输入什么，都不会被当成 SQL 执行，注入攻击就失效了。

常见安全问题怎么防
SQL 注入用参数化查询，不要拼接 SQL
XSS 攻击用户输入要转义，不要直接渲染到页面上
密码泄露密码不要传到 GitHub，不要硬编码在代码里
SSH 爆破用密钥登录，改默认端口，用 fail2ban
数据被拖库数据库不对公网开放，只允许内网访问
新手最容易踩的坑
  • 不要用 root 跑应用：应用用普通用户跑，就算被攻破了，权限也有限，不会把整个服务器搞坏。
  • 定期更新系统：系统有安全补丁要及时打，不要一直用旧版本。
  • 备份很重要：就算被攻击了，有备份就能恢复，没有备份就真的完了。
  • 不要开没必要的端口：什么端口都开着，就是给黑客送机会，只开必须的端口。
