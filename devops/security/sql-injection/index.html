SQL 注入防御：从你遇到的问题出发

🏷️ SQL 注入

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及SQL 注入怎么帮你解决。

flowchart TB A[用户输入] --> B[拼接 SQL] B --> C[输入 OR 1=1] C --> D[SQL 全表查/删]

1. 数据库被拖库了

你遇到的问题

登录框输入 OR 1=1，直接登录成功，甚至拖了整个库。

怎么解决？防 SQL 注入，用参数化查询，不要拼接 SQL。

2. SQL 注入是什么

你遇到的问题

SQL 注入是什么？

怎么解决？用户输入恶意 SQL，拼接到 SQL 语句里，执行非法操作。

3. 怎么防

你遇到的问题

怎么防 SQL 注入？

怎么解决？参数化查询（预编译）、用 ORM、输入校验。

错误 vs 正确

做法安全？
字符串拼接 SQL不安全
参数化查询安全
ORM安全
新手最容易踩的坑
  • 永远不要拼接 SQL永远不要把用户输入直接拼到 SQL 里。
  • 用 ORM用 MyBatis/JPA 这类 ORM，默认安全。
