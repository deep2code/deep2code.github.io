OWASP Top 10 入门：从你遇到的问题出发

🏷️ OWASP Top 10

OWASP Top 10 不是漏洞列表，而是风险类别的统计排序。2021 版相比 2017 版最大的变化是把「注入」从第一位挤到第三位，权限控制失效升到 A01，并新增了 A04 不安全设计与 A08 软件和数据完整性失效。这个排序变化本身就说明了一件事：随着 ORM 和模板引擎普及，纯语法层面的注入已经被框架大面积消灭，剩下的高频风险都是「框架帮不了你」的业务逻辑和工程配置问题。

这篇按后端工程师的实际工作面组织：先给一张十项全景对照表，再挑工程上最高频、最容易在 code review 里漏过的五项深入展开，最后收在一张上线前自查清单和一组能直接跑的扫描命令上。

十类风险的责任分层

把十项按「谁应该在哪个环节堵住它」分层，比按编号背诵有用得多。代码逻辑层的问题只能靠 review 和测试发现，配置与依赖层的问题可以靠自动化工具持续扫描，而观测层是所有防线失效之后唯一还能让你知道「出事了」的东西。

A03 注入与 XSS 有专篇

注入类的细节（预编译原理、ORM 的哪些 API 仍会拼接、二次注入、输出编码的上下文差异）在 SQL 注入防护 和 XSS 防御 两篇里展开，这里只保留上面表格中的要点概述。本文剩余篇幅集中在 A01、A02、A05、A06、A09 这五项上，它们是框架默认不帮你解决、必须靠工程纪律兜住的部分。

A01 权限控制失效：IDOR 是最高频的线上漏洞

先纠正一个流传很广的说法：「我们在网关统一做了鉴权，所以不存在越权问题」。这句话混淆了两件事。网关能回答的是「你是谁」（authentication），回答不了「这条数据是不是你的」（authorization 中的资源归属），因为归属关系只存在于业务数据库里。JWT 校验通过、角色也是普通用户，接口照样能把别人的订单返回给你，这就是 IDOR（不安全的直接对象引用），也是渗透测试里成本最低、成功率最高的一类攻击。
