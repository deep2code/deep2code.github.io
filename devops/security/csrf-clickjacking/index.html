CSRF 和点击劫持：从你遇到的问题出发

🏷️ CSRF

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及CSRF怎么帮你解决。

flowchart LR A[用户登录你的站] --> B[访问恶意网站] B --> C[恶意网站偷偷发请求] C --> D[用你的登录态操作]

1. 怎么会被盗号发操作

你遇到的问题

你登录了你的网站，然后访问了一个恶意网站，那个网站偷偷用你的登录态发了个转账请求。

怎么解决？CSRF 跨站请求伪造，利用你的登录态做你不想做的事。

2. 怎么防止 CSRF

你遇到的问题

知道有风险，不知道怎么防。

怎么解决？加 CSRF Token，请求带 Token 才是合法的。

3. 什么是点击劫持

你遇到的问题

你在 A 网站点按钮，其实点的是被透明覆盖的 B 网站的按钮。

怎么解决？用 X-Frame-Options 防止被 iframe 嵌套。

防护手段

攻击防护
CSRFCSRF Token、SameSite Cookie
点击劫持X-Frame-Options、CSP frame-ancestors
新手最容易踩的坑
  • Cookie 加 SameSite设成 Lax 或 Strict，防止跨站带 Cookie。
  • 不要信任 GET 请求改数据改数据的操作用 POST，不要用 GET。
