阿里云：国内最大的云平台，也是我用得最多的

阿里云我从 2016 年开始用，那时候还是 CDN + 轻量应用服务器的组合。现在成了全套云服务商——从 ECS 到函数计算，从 RDS 到灵骏智算，基本你能想到的它都有。这篇文章聊聊 2024-2026 年阿里云的一些关键变化，以及我实际用下来的体会。

弹性计算：ECS 和抢占式实例

ECS 是阿里云的 IaaS 基础。我自己用下来，普通业务跑 2C4G 就够了，一个月一百多块。但 AI 训练和高并发场景，实例规格选择就有讲究了。

实例规格族特点我用来干啥
通用型 g7/g8均衡 CPU 内存，性价比高Web 后端、API 服务
计算型 c7/c8高主频，CPU 密集编译、日志处理
内存型 r7/r8大内存Elasticsearch、缓存
GPU 型 gn10/20NVIDIA A10/A100AI 训练推理
倚天 e1 (ARM)阿里云自研芯片，性价比极高云原生容器、Go 服务

2024 年以后我开始大规模用倚天 ARM 实例。它是阿里自研的 CPU，性能对标 Intel 但价格便宜 20-30%。前提是你的应用能编译 ARM 版本——Go 交叉编译一行命令的事，Java 用 GraalVM 也没问题。

抢占式实例的省钱技巧

非关键任务（CI/CD、批处理、离线分析）我全用抢占式实例。价格是按量付费的 10-20%，但随时可能被回收。我的做法是把任务设计成可中断的——checkpoint 定期保存，被回收了自动重启新实例接着跑。跑一个月能省 80% 的计算费用。

容器服务 ACK：K8s 的托管版

自己维护 K8s 集群的痛苦我不想再回忆了——升级、证书过期、etcd 备份，全是坑。ACK 托管版把控制面全托管了，你只管 Worker 节点。生产环境我强烈推荐托管版，别自己搭 K8s。

版本特性什么时候用
ACK 托管版 Pro控制面 SLA 99.95%，自动升级生产环境
ACK 边缘版边缘计算，IoT 场景设备端推理
ACK Serverless不用管节点，直接跑 Pod流量波动大的场景

数据库：RDS 和 PolarDB

MySQL 我基本都用 RDS 了，自己搭的只有测试环境。RDS 自动备份、自动主备切换、慢查询分析全配齐了，比自己运维省心太多。

PolarDB 是阿里云自研的云原生数据库，跟 RDS MySQL 协议兼容，但存储和计算分离，性能比自建 MySQL 快好几倍。特别是读多写少的场景，PolarDB 只读节点能横向扩到 15 个。

扩展能力垂直升级只读节点线性扩展分库分表
备份恢复自动自动 + 闪回自己做
成本中较高低但人力贵
适合场景大多数业务高并发 + 云原生学习/特殊定制

OSS 对象存储：存什么都合适

OSS 是我用得最久的云产品。图片、日志、备份、模型文件，全放 OSS。它有几个实用功能：

  • 生命周期规则：热数据存标准存储，30 天后自动转低频访问，90 天后转归档。成本降 80% 以上
  • 图片处理：URL 加参数自动生成缩略图、加水印、格式转换。不用自己搭图片服务
  • CDN 回源：OSS 前面挂 CDN，静态资源全球加速，命中率 90% 以上

AI 产品线：灵骏和 PAI

这是 2024-2026 年阿里云变化最大的地方。以前云厂商就是卖计算资源，现在开始卖 AI 全栈。

PAI（平台人工智能）：从数据标注、模型训练、推理部署一条龙。我做过一个文本分类项目，从标注数据到上线 API，全在 PAI 上搞定，没买一台 GPU 服务器。

灵骏智算：专门跑大模型的万卡集群。2024 年阿里云开放了灵骏的对外服务，企业可以租用 A100/H800 集群跑训练任务。做 LLM 微调的团队不用自己买卡了，按需租用就行。

Serverless：函数计算 FC

函数计算是我最意外的产品。以前觉得 Serverless 是个玩具，2025 年做了个微信公众号自动回复的项目，用函数计算跑，一个月成本不到 5 块钱。

# 函数计算 Python 示例
import json

def handler(event, context):
    evt = json.loads(event['body'])
    name = evt.get('name', 'world')
    return {
        'statusCode': 200,
        'body': json.dumps({'message': f'Hello, {name}!'}),
        'headers': {'Content-Type': 'application/json'}
    }

Serverless 的好处是不用管服务器，按调用次数计费，缩容到零的时候不花钱。坏处是冷启动——第一次请求要初始化运行时，可能慢几百毫秒。对延迟敏感的场景不适合。

我在阿里云踩过的坑

  1. 公网流量费：一开始没注意，OSS 出公网流量一个月收了 800 多块。后来加了 CDN，流量走 CDN 回源，OSS 只收内网流量费，省了一大半
  2. 快照自动扣费：手动打了个快照忘了删，一年扣了好几百。现在定期清理不用的快照
  3. 安全组配置太宽：一开始把 0.0.0.0/0 放通了所有端口，第二天就被扫了，SSH 暴力破解日志几千条。安全组只放 80/443，SSH 用 VPN
  4. 云监控没配告警：磁盘满了导致服务挂了，用户反馈才发现。现在所有关键指标（CPU、内存、磁盘、带宽）都配了告警
  5. 镜像仓库私有：公司镜像推到容器镜像服务，忘了配 IP 白名单，CI/CD 拉镜像一直超时。检查了半天才发现

FAQ

阿里云新用户有免费额度吗？

有，新用户有免费试用套餐。但免费额度有限，ECS 就 2 个月。重要的是别用免费实例跑生产，性能限制多。

OSS 静态网站怎么配 HTTPS？

OSS 本身不直接配 HTTPS，要通过 CDN 加速。CDN 上配置域名 + SSL 证书，回源 OSS 就走内网。我一般用 Let's Encrypt 免费证书，CDN 自动续期。

函数计算冷启动怎么办？

两个办法：一是用预留实例（Provisioned Concurrency），保持一定数量的实例常驻，按小时计费但没有冷启动；二是用预热请求，定时发个空请求保持实例不被回收。

怎么从自建 MySQL 迁到 RDS？

用阿里云的 DTS（数据传输服务），在线迁移，不停服。先做全量同步，再增量同步，最后切流量。我迁过几个 100GB 的库，全程零停机。
