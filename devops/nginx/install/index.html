Nginx 源码安装

🏷️ Nginx 安装

💡 你的网站跑在 8080 端口，用户访问要加端口号，太不专业了。或者你想把一台服务器变成好几台，让负载分担一下。

为什么要源码编译安装

系统源装的 Nginx 版本太老了——Ubuntu 24.04 默认还是 1.18，连 HTTP/2 都支持得勉强。要上 HTTP/3、Brotli 压缩、第三方模块，必须源码编译。

下载源码

wget https://nginx.org/download/nginx-1.30.4.tar.gz
tar -zxvf nginx-1.30.4.tar.gz
cd nginx-1.30.4

configure：最关键的一步

configure 决定了编译哪些模块、装到哪、用哪些第三方库。这步配错了，后面全部白搭。

# 生产环境推荐配置
./configure \
    --prefix=/usr/local/nginx \
    --user=nginx --group=nginx \
    --with-pcre-jit \
    --with-http_ssl_module \
    --with-http_v2_module \
    --with-http_realip_module \
    --with-http_gzip_static_module \
    --with-http_stub_status_module \
    --with-http_auth_request_module \
    --with-stream \
    --with-stream_ssl_module \
    --with-threads \
    --with-cc-opt="-O2 -march=native"

configure 输出最后会打印一段 summary，确认你要的模块都是 yes。如果某个模块显示 no，说明缺依赖库。

configure 参数作用不加会怎样
--with-http_ssl_moduleHTTPS 支持不能配 ssl
--with-http_v2_moduleHTTP/2浏览器不能走 h2
--with-stream四层负载均衡不能代理 TCP/UDP
--with-pcre-jit正则 JIT 编译rewrite 正则慢很多
--with-threads线程池阻塞操作卡住 worker
--with-cc-opt="-O2"编译优化性能差一截

编译和安装

# 并行编译，利用所有 CPU 核心
make -j$(nproc)

# 安装到 prefix 指定的目录
make install

make 这步可能会报各种缺库的错。常见错误和解决方案：

错误信息原因解决
PCRE library is required缺 PCREapt install libpcre3-dev
OpenSSL library is required缺 OpenSSLapt install libssl-dev
zlib library is required缺 zlibapt install zlib1g-dev
lua.h: No such file缺 LuaJIT装 LuaJIT 并设环境变量

启动和验证

cd /usr/local/nginx/sbin

# 检查配置文件语法
./nginx -t

# 启动
./nginx

# 查看编译参数（确认模块是否编进去了）
./nginx -V
nginx -V 的输出很重要

出问题时第一个命令就是 nginx -V。它会打印 configure 时的所有参数和编译进去的模块列表。我见过有人折腾半天，最后发现 ssl 模块根本没编进去。

第三方模块

Nginx 的强大之处在于第三方模块。我常用的几个：

模块功能我什么时候用
echo-nginx-moduleecho/sleep 指令，调试用开发环境，快速验证配置
headers-more-nginx-module更灵活地操作响应头生产环境，改 Server 头等
ngx_brotliBrotli 压缩生产环境，比 gzip 小 20%
lua-nginx-moduleLua 脚本支持复杂逻辑（配合 OpenResty）
nginx-rtmp-moduleRTMP 直播直播推流
 
# 编译第三方模块
./configure \
    --prefix=/usr/local/nginx \
    --add-module=/path/to/echo-nginx-module \
    --add-module=/path.to/headers-more-nginx-module

make && make install

静态模块 vs 动态模块

Nginx 1.9.11 以后支持动态模块（.so 文件），不用每次都重编译主程序。

静态模块动态模块
编译方式打进二进制独立 .so 文件
增删模块必须重编译改配置就行
二进制体积大小
推荐核心模块（ssl/v2）可选模块（geoip/xslt）
 
# 动态模块编译方式
./configure --with-http_geoip_module=dynamic

# 配置文件里加载
load_module modules/ngx_http_geoip_module.so;

平滑升级

sequenceDiagram participant OLD as 旧 Master participant NEW as 新 Master participant W as Worker OLD->>NEW: USR2 启动新 master NEW->>W: fork 新 worker OLD->>W: WINCH 旧 worker 优雅退出 Note over OLD,W: 等旧 worker 处理完已有请求 OLD->>OLD: QUIT 旧 master 退出

生产环境升级 Nginx 不能停服务。Nginx 支持热升级：

# 1. 编译新版本（不要 make install，会覆盖旧的）
# 2. 替换旧二进制
mv /usr/local/nginx/sbin/nginx /usr/local/nginx/sbin/nginx.old
cp objs/nginx /usr/local/nginx/sbin/nginx

# 3. 给旧 master 发 USR2，启动新 master
kill -USR2 $(cat /usr/local/nginx/logs/nginx.pid)

# 4. 旧 worker 优雅退出（不处理新请求，等已有请求完成）
kill -WINCH $(cat /usr/local/nginx/logs/nginx.pid.oldbin)

# 5. 确认新版本正常后，退出旧 master
kill -QUIT $(cat /usr/local/nginx/logs/nginx.pid.oldbin)
平滑升级的坑

我第一次做平滑升级，第 4 步发完 WINCH 忘了等旧 worker 处理完，直接发了 QUIT，导致十几个正在下载的用户断了连接。后来固定流程：WINCH 后等 30 秒，确认旧 worker 都退出了再 QUIT。

配置 systemd 服务

cat > /etc/systemd/system/nginx.service << 'EOF'
[Unit]
Description=Nginx Web Server
After=network.target

[Service]
Type=forking
PIDFile=/usr/local/nginx/logs/nginx.pid
ExecStart=/usr/local/nginx/sbin/nginx
ExecReload=/usr/local/nginx/sbin/nginx -s reload
ExecStop=/usr/local/nginx/sbin/nginx -s quit

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable nginx
systemctl start nginx

8 个编译安装的坑

  1. 用系统源装了旧版本：Ubuntu 默认源的 Nginx 1.18 太老。一定要加官方 nginx.org 的源，或者源码编译
  2. 漏装依赖：编译时没装 libpcre3-dev，rewrite 模块编不进去。configure 输出里确认每个模块都是 yes
  3. --with-debug 用到生产：调试日志会写爆磁盘，性能差 30%。生产绝对不要带 --with-debug
  4. 多版本冲突：系统装了 apt 版，又源码装了一份，端口冲突。统一用一种方式
  5. 没配 systemd：手动 ./nginx 启动，重启服务器就没了。必须配 systemd service
  6. 平滑升级操作失误：步骤发错信号会导致服务中断。按 USR2 → WINCH → QUIT 三步走
  7. 没开编译优化：默认 -O0 性能差一截。加 --with-cc-opt="-O2 -march=native"
  8. OpenSSL 版本太低：要上 HTTP/3 必须 OpenSSL 3.5+。用 --with-openssl 指定源码路径

FAQ

apt 装和源码编译哪个好？

简单场景 apt 官方源就行。需要第三方模块或 HTTP/3 才源码编译。生产环境我推荐 apt 官方 nginx.org 源，省得自己维护编译。

编译一次要多久？

4 核机器，全量编译大概 3-5 分钟。加 -j$(nproc) 并行编译会快很多。调试 Nginx 本身的时候才频繁编译，平时编译一次用几个月。

怎么知道当前 Nginx 用的是哪个配置？

nginx -t 会打印配置文件路径。或者 ps -ef | grep nginx 找到进程，看 /proc/pid/exe 指向哪个二进制。

升级新版本要注意什么？

先看 changelog。跨大版本升级可能有废弃指令（比如老的 ssl on; 已经不推荐了）。先 nginx -t 测试，再做平滑升级。保留旧二进制便于回滚。
