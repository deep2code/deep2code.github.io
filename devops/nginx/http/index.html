Nginx 作为 HTTP 服务器：静态站点、TLS 与协议支持

🏷️ Nginx HTTP

Nginx 大部分时间被当成反向代理用，但它首先是一个 HTTP 服务器：自己从磁盘读文件、自己终止 TLS、自己协商 HTTP/2 与 HTTP/3、自己压缩和记日志。这一篇只讲这部分——文件怎么定位、server 怎么被选中、证书怎么配、协议怎么开、日志怎么不丢。

请求在 Nginx 内部经过的 11 个处理阶段、location 的匹配优先级、proxy_buffering 与上游长连接、超时参数全景，都在 ../ 主干篇，本文只在需要时指路。

root 与 alias：拼接还是替换

这是静态服务里第一个分水岭，也是路径穿越事故的主要来源。root 的语义是拼接：最终磁盘路径等于 root 的值加上完整请求 URI（包含 location 匹配掉的那段前缀）。alias 的语义是替换：把 location 匹配掉的那段前缀换成 alias 的值。

可能读到站点目录之外的文件"] T1 --> T2 --> T3 end R --> ROOT R --> ALIAS ALIAS --> TRAP

路径计算值加上完整 URI值替换掉 location 匹配的前缀
可用位置http、server、location只能写在 location 里
结尾斜杠写不写都不影响结果必须与 location 的结尾斜杠一致，不一致会拼出站外路径
正则 location正常工作必须把捕获组写进 alias 的值，否则路径错乱
与 try_files 配合行为直观历史上存在丢掉 alias 的边界行为，不建议混用
建议默认选它只有 URL 路径与磁盘目录名不一致时才用
# 推荐：能用 root 就用 root，让磁盘目录跟着 URL 走
location /static/ {
    root /data/www;                 # 实际目录是 /data/www/static/
    expires 30d;
    access_log off;                 # 静态资源日志量极大，通常关掉
}

# 必须用 alias 的场景：URL 是 /assets/ 但磁盘目录叫 dist
location /assets/ {
    alias /data/site/dist/;         # 两边结尾斜杠必须都有
}

# 正则 location 下的 alias：捕获组必须显式拼回去
location ~ ^/download/(?<fname>.+)$ {
    alias /data/files/$fname;       # 少了捕获组就会拼成错误路径
    # 大文件下载：绕过 page cache，避免一个大文件把热数据全冲掉
    directio 4m;                    # 超过 4MB 的文件走 directio
    output_buffers 2 1m;
    aio threads;                    # 需要编译时带 --with-threads
    sendfile off;                   # directio 生效时 sendfile 自动失效
    limit_rate_after 10m;           # 前 10MB 全速，之后限速
    limit_rate 2m;
}

大文件服务里 sendfile、aio、directio 三者的内核行为主干篇已经讲过，这里只强调一条容易忘的结论：directio 生效时 sendfile 对同一个文件自动失效，两者不能叠加，所以「全局开了 sendfile 就够了」在大文件场景并不成立。

try_files 与 SPA 回退

try_files 属于 precontent 阶段，它按顺序探测每个候选项，第一个存在的就用，全都不存在时把最后一个参数当作内部重定向目标或状态码。常见误用是把最后一个参数写成文件名而不是 URI。

写法行为适用场景
try_files $uri $uri/ =404文件与目录都不存在则 404纯静态站点的安全默认值
try_files $uri $uri/ /index.html回退到 SPA 入口，走一次内部重定向并重新匹配 locationVue 与 React 的 history 路由
try_files $uri /index.html =404中间参数后面还有参数时，=404 才是最终兜底希望入口文件缺失时明确报错
try_files $uri @backend回退到命名 location，交给上游静态优先、动态兜底的混合站点
try_files $uri $uri/ /index.php?$query_string回退时必须手动带上查询串前端控制器模式的 PHP 框架
⚠️
SPA 回退会把 404 变成 200

配了 try_files $uri $uri/ /index.html 之后，任何不存在的路径都会返回 200 加一个 HTML 页面，包括写错的 API 路径。前端拿到 HTML 去做 JSON 解析，报出一个和真实原因完全无关的错。解决办法是把 API 前缀单独写成 location ^~ /api/ 让它不落到回退规则里。同时入口文件必须短缓存：index.html 长缓存会让用户永远拿不到新版本，而它引用的带 hash 的资源早已不存在。

server 是怎么被选中的

一个请求先选端口（listen），再选虚拟主机（server_name）。很多人以为 server_name 是从上到下第一个命中，其实它有明确的优先级，与书写顺序无关。

# 显式兜底：任何没匹配上的 Host 都被这里接住
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;
    return 444;                      # 444 是 Nginx 私有码，直接断开不回响应
}

server {
    listen 443 ssl default_server;
    http2 on;
    server_name _;
    # 必须给证书，否则 TLS 握手根本进行不下去；用任意一张自有证书即可
    ssl_certificate     /etc/nginx/tls/placeholder.crt;
    ssl_certificate_key /etc/nginx/tls/placeholder.key;
    return 421;                      # 421 Misdirected Request，语义最准确
}

TLS 配置里最容易配错的几项

握手过程、证书信任链、对称与非对称加密的原理见站内 ../../../backend/auth/；部署层面的完整清单（HSTS、混合内容、协议下线）见站内 ../../security/ 的 HTTPS 工程实践篇。这里只讲 Nginx 配置本身。

配置项默认值建议配错的后果
ssl_certificate无用 fullchain，即叶证书加中间 CA只给叶证书时桌面浏览器常因缓存过中间证书而正常，移动端与命令行工具直接报证书链不完整，典型的「我这儿好着呢」类故障
ssl_session_cachenoneshared:SSL:20m不开则每条新连接都做完整握手，多一次 RTT 与一次非对称运算；20MB 约可存 8 万个会话
ssl_session_timeout5m1h 到 4h太短复用率低，太长削弱前向安全
ssl_session_ticketson多机集群要么关掉，要么共享 ssl_session_ticket_key各机器 ticket 密钥不同会导致复用全部失败，等于白开销
ssl_protocols随版本变化，老版本含 TLSv1TLSv1.2 TLSv1.3留着 1.0 与 1.1 过不了合规扫描
ssl_ciphers内置列表只对 TLS 1.2 生效，对 TLS 1.3 完全无效以为改了它就限制住 1.3 的套件，1.3 要用 ssl_conf_command Ciphersuites，细节见站内 HTTPS 篇
ssl_staplingoffon 且配 ssl_trusted_certificate 与 resolver不配 resolver 时 stapling 静默失效，只在 error.log 留一行 warn
ssl_prefer_server_ciphersoff保持 off强行开启可能反而选到客户端上更慢的套件

双证书是个被低估的能力：同一个 server 里可以同时配 RSA 和 ECDSA 两套证书，Nginx 依据 ClientHello 里声明的签名算法自动挑。ECDSA 握手更快、报文更小，现代客户端全都支持；RSA 留给极老客户端兜底。配置方式就是写两组 ssl_certificate 与 ssl_certificate_key，顺序无关。

HTTP/2 与 HTTP/3

维度HTTP/1.1HTTP/2HTTP/3
开启方式默认1.25.1 前是 listen 443 ssl http2；1.25.1 起改为独立的 http2 on;listen 443 quic 加 http3 on，需 1.25.0 以上并且 TLS 库支持 QUIC
传输层TCPTCPUDP 上的 QUIC，防火墙与安全组要放行 UDP 443
多路复用没有，靠多条连接单连接多 stream同上，且没有 TCP 层队头阻塞
关键参数keepalive_requestshttp2_max_concurrent_streams，默认 128quic_gso、quic_retry
客户端如何得知—TLS ALPN 协商要在 HTTP/2 响应里回 Alt-Svc 头做升级提示
对前端优化的影响合并文件、域名分片有收益合并与分片反而有害同 HTTP/2，细节见站内前端性能篇

关于「合并文件减少请求数」这条流传最广的前端优化建议：它在 HTTP/1.1 时代成立，因为浏览器对同域并发连接数有 6 个左右的上限。HTTP/2 单连接可以并行几十上百个 stream，把 20 个小文件合成一个大 bundle 反而破坏了缓存粒度——改一行代码整个 bundle 的 hash 就变了，用户要重新下载全部。域名分片更糟，它强迫浏览器额外建立多条 TLS 连接，握手成本远超收益。

压缩：实时压还是预压缩

方案CPU 开销压缩率适用与注意
gzip on每请求实时压缩，随 QPS 线性增长基准动态响应用它，gzip_comp_level 取 4 到 6，开到 9 体积只小几个百分点而 CPU 翻倍
brotli on略高于 gzip比 gzip 小约 15% 到 20%需第三方模块，编译方式见本组 ../install/
gzip_static on运行期几乎为零构建期可用最高级别静态资源的最优解，构建产物要同步更新
brotli_static on同上最好与 gzip_static 同时开，Nginx 按 Accept-Encoding 自动选
对 jpg、mp4、zip 开压缩纯浪费可能变大不要做，gzip_types 里不要塞图片与视频类型

gzip_min_length 默认只有 20 字节，实际应该抬到 1024 上下，否则几十字节的响应压完连额外的头部开销都盖不住。压缩与 proxy_buffering、Vary 头的交互在主干篇里有，这里不展开。

响应头与日志

add_header 有一个人人都会踩一次的行为：子 location 里只要出现任何一条 add_header，父级的全部 add_header 都会失效，是覆盖而不是合并（主干篇已展开）。所以安全头写在 server 级并不等于全站生效，要么用 include 片段在每个 location 里重复，要么确认子 location 没单独加头。安全头的完整清单与取值见站内 ../../security/ 总览篇。

stateDiagram-v2 [*] --> Writing: worker 持有 access.log 的 fd Writing --> Renamed: logrotate 执行 mv note right of Renamed 目录项改名了但 inode 没变 worker 仍然往同一个 inode 追加 新文件名下的内容持续增长 end note Renamed --> Reopened: postrotate 里发 USR1 note right of Reopened master 关闭旧 fd 按配置路径重新创建并打开文件 再通知各 worker 换 fd end note Reopened --> [*]: 轮转完成，旧文件可压缩可删除 Renamed --> Leaked: 忘记发 USR1 就直接删文件 note right of Leaked inode 仍被 fd 引用 df 显示磁盘满而 du 找不到大文件 必须补发 USR1 或重启才会释放 end note 
# /etc/logrotate.d/nginx —— postrotate 里的 USR1 是整段配置的关键
/var/log/nginx/*.log {
    daily
    rotate 14
    missingok
    notifempty
    compress
    delaycompress
    sharedscripts
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 "$(cat /var/run/nginx.pid)"
    endscript
}

log_format 字段作用不记的后果
$request_timeNginx 视角的整体耗时，含读请求体与把响应写给客户端无法区分后端慢还是客户端网络慢
$upstream_response_time上游耗时与上一项配合判读的方法见主干篇
$upstream_addr 与 $upstream_status实际打到哪台、上游返回什么单台机器异常时无法定位
$request_idNginx 自动生成的 16 字节十六进制 ID日志与链路追踪无法关联，用法见本组 ../use/

$remote_addr 与 $http_x_forwarded_for直连对端与真实客户端有前置 LB 时 IP 全错

另外建议按虚拟主机分文件（access_log /var/log/nginx/$host.access.log 这种写法可行但要注意变量路径会绕过打开文件缓存，高 QPS 下用固定路径分站点写更稳），并对静态资源目录直接 access_log off——静态请求往往占总量的八成以上，记下来除了烧磁盘没有价值。需要保留采样时可以配 access_log ... if=$sampled 搭配 split_clients。

一份可以直接抄的静态站点配置

# HTTP 只做跳转，但必须放行 ACME 挑战路径，否则证书自动续期会失败
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    location /.well-known/acme-challenge/ {
        root /var/www/acme;
        try_files $uri =404;
    }
    location / {
        return 301 https://$host$request_uri;   # 能用 return 就不要用 rewrite
    }
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    listen 443 quic reuseport;                  # HTTP/3 走 UDP，记得放行防火墙
    http2 on;                                   # 1.25.1 起的新写法
    http3 on;
    server_name example.com www.example.com;

    # 双证书：ECDSA 给新客户端，RSA 兜底老客户端
    ssl_certificate         /etc/nginx/tls/ecc/fullchain.pem;
    ssl_certificate_key     /etc/nginx/tls/ecc/privkey.pem;
    ssl_certificate         /etc/nginx/tls/rsa/fullchain.pem;
    ssl_certificate_key     /etc/nginx/tls/rsa/privkey.pem;

    ssl_protocols           TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_session_cache       shared:SSL:20m;     # 约可缓存 8 万个会话
    ssl_session_timeout     4h;
    ssl_session_tickets     off;                # 多机不共享密钥就关掉
    ssl_stapling            on;
    ssl_stapling_verify     on;
    ssl_trusted_certificate /etc/nginx/tls/ecc/chain.pem;
    resolver                223.5.5.5 1.1.1.1 valid=300s;   # stapling 必需
    resolver_timeout        5s;

    root  /data/site/dist;
    index index.html;
    charset utf-8;

    # 告诉支持 HTTP/3 的客户端可以升级
    add_header Alt-Svc 'h3=":443"; ma=86400' always;

    gzip on;
    gzip_vary on;
    gzip_min_length 1024;                       # 默认 20 太小，没有意义
    gzip_comp_level 5;
    gzip_types text/plain text/css application/json application/javascript
               application/xml image/svg+xml;
    gzip_static on;                             # 优先发构建期生成的 .gz
    brotli_static on;                           # 需要 ngx_brotli 动态模块

    # 带 hash 的构建产物：长缓存加 immutable
    location ~* \.(?:js|css|woff2|png|jpg|svg)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
        try_files $uri =404;                    # 不要让它落进 SPA 回退
    }

    # 入口文件绝不能长缓存，否则用户永远拿不到新版本
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    # API 单独隔离，避免写错路径时 404 被回退成 200 的 HTML
    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8080;
        include /etc/nginx/common/proxy-headers.conf;   # 必备头见本组 ../use/
    }

    # SPA 回退放最后
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 隐藏文件与编辑器备份文件一律拒绝
    location ~ /\.(?!well-known) { deny all; }
    location ~ ~$                { deny all; }
}

反模式对照

反模式症状正确做法
正则 location 里用 alias 却没拼捕获组路径错乱，严重时能读到站点目录之外的文件改用 root，或把捕获组显式写进 alias 的值
不显式写 default_server陌生域名解析到你的 IP 时落到第一个 server，HTTPS 下报证书不匹配写独立兜底 server，return 444 或 421
日志轮转不发 USR1df 显示磁盘满，du 找不到大文件postrotate 里 kill -USR1
对图片、视频、压缩包开 gzipCPU 白烧，体积可能反而变大gzip_types 只保留文本类
SPA 不配 try_files刷新非首页路径直接 404回退到 /index.html，同时隔离 API 前缀
用 if 判断 $host 来区分站点与 rewrite 阶段耦合，行为难以推理，即主干篇的 if is evil拆成多个 server 块
只配叶证书桌面浏览器正常，移动端与 curl 报链不完整换成 fullchain
还在写 listen 443 ssl http21.25.1 起打 deprecated 警告，未来版本会失效改成独立的 http2 on;
开了 HTTP/3 但没放行 UDP 443客户端悄悄回落到 HTTP/2，你以为已经生效放行 UDP，并用 $server_protocol 记日志验证
❌
最容易踩的坑
  • alias 与 location 的结尾斜杠不一致：一方有一方没有，拼出的路径会越过站点根目录。
  • 以为 server_name 按书写顺序匹配：只有正则那一级看顺序，精确名与通配名都有固定优先级。
  • HTTPS 的 server 选择发生在 TLS 握手期：靠 SNI 而不是 Host 头，所以证书错配的表现是安全警告而不是 404。
  • 子 location 里加了一个 add_header：父级所有安全头瞬间全部消失，是覆盖不是合并。
  • ssl_ciphers 管不到 TLS 1.3：1.3 的套件必须用 ssl_conf_command Ciphersuites 配。
  • ssl_stapling on 但没配 resolver：stapling 静默不工作，只在 error.log 留一行 warn。
  • 多机集群开着默认的 ssl_session_tickets：各机密钥不同，会话复用几乎全部失败。
  • index.html 跟静态资源一起长缓存：发版后用户一直加载旧入口，里面引用的 hash 文件早已不存在。
  • SPA 回退兜住了 API 路径：接口 404 返回 200 加 HTML，前端报 JSON 解析失败，排查方向被带偏。
  • gzip_min_length 留默认 20：几十字节的响应也去压，压完反而更大。
  • 配了全站 301 却忘记放行 ACME 挑战路径：证书自动续签失败，到期那天全站 HTTPS 一起挂。
  • directio 与 sendfile 一起开：两者互斥，实际只有一个生效，压测结论会得反。
