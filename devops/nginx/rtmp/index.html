RTMP 模块

🏷️ Nginx RTMP

用 Nginx 搭直播服务

我 2020 年做过一个在线教育直播平台，用的就是 Nginx RTMP 模块。当时学生 500 人同时看直播，服务器就一台 2 核 4G，扛住了。RTMP 虽然老，但够用、稳定、生态好。

编译安装 RTMP 模块

./configure --prefix=/usr/local/nginx \
    --add-module=/path/to/nginx-rtmp-module \
    --with-http_ssl_module \
    --with-openssl=/path/to/openssl-3.x \
    --with-debug

make && make install
RTMP 模块已停更

nginx-rtmp-module 最后更新是 2021 年。能用，但别指望新特性。新项目建议直接上 SRT 或 WebRTC。但老系统维护的话，这个模块还是最省事的。

基础配置

rtmp {
    server {
        listen 1935;
        chunk_size 4096;

        application live {
            live on;
            record off;

            # HLS 转封装
            hls on;
            hls_path /tmp/hls;
            hls_fragment 3;
            hls_playlist_length 60;
            wait_key on;
        }
    }
}

http {
    server {
        listen 8080;
        location /hls {
            types {
                application/vnd.apple.mpegurl m3u8;
                video/mp2t ts;
            }
            root /tmp;
            add_header Cache-Control no-cache;
            add_header Access-Control-Allow-Origin *;
        }
    }
}

推流和拉流

# OBS 推流设置
# 服务器: rtmp://your-server:1935/live
# 串流密钥: stream1

# FFmpeg 推本地文件
ffmpeg -re -i input.mp4 -c:v libx264 -c:a aac \
    -f flv rtmp://localhost:1935/live/stream1

# FFmpeg 推摄像头
ffmpeg -f avfoundation -i "0:0" -c:v libx264 \
    -f flv rtmp://localhost:1935/live/stream1

拉流：

# VLC 直接拉 RTMP
vlc rtmp://localhost:1935/live/stream1

# HLS 拉流（浏览器用）
# http://localhost:8080/hls/stream1.m3u8

推流鉴权

RTMP 本身没有鉴权机制，谁都能推。必须加鉴权：

application live {
    live on;
    on_publish http://localhost:8080/auth;  # 推流前回调验证
    on_play http://localhost:8080/auth_play;  # 拉流前验证
}

on_publish 是个 HTTP 回调，推流时 Nginx 会请求你的鉴权服务，返回 200 就允许推流，返回其他就拒绝。推流地址里带 token 参数，鉴权服务验证 token 是否有效。

不鉴权的后果

我刚搭好直播服务时忘了加鉴权，第二天发现有人推了个成人频道上来，500 多人在看。赶紧关了，加了 on_publish 鉴权。现在推流地址必须带动态 token，过期失效。

HLS 转封装

sequenceDiagram participant P as 推流端 participant N as Nginx RTMP participant H as HLS 分片 P->>N: RTMP 推流 音视频帧 N->>N: 缓存 GOP 等关键帧 N->>H: 切 TS 分片 关键帧边界 N->>H: 更新 m3u8 播放列表 H->>V: 浏览器拉 m3u8 播放

Nginx RTMP 模块能把 RTMP 流转封装成 HLS（TS 分片 + m3u8 播放列表）。转封装不重新编码，只是换容器格式，CPU 开销很小。

参数作用推荐值
hls_fragment每个 TS 分片时长（秒）3-6（要 >= GOP）
hls_playlist_lengthm3u8 保留多少秒30-60
wait_key on等关键帧再切分必须开

HLS 的延迟通常 15-30 秒（3-6 个分片）。要低延迟得用 LL-HLS（部分分片 + 阻塞请求），能压到 2-3 秒。

实际生产架构一般是混合的：推流用 RTMP 或 SRT，Nginx 转封装成 HLS 分发，互动场景用 WebRTC。

录制

application live {
    live on;
    record all;
    record_path /tmp/recordings;
    record_suffix -%Y%m%d-%H%M%S.flv;
    record_unique on;
}

录制文件推流断开时可能不完整。录完用 FFmpeg 检查：ffmpeg -v error -i file.flv -f null -。有需要转 MP4 的话：ffmpeg -i input.flv -c copy output.mp4。

监控统计

http {
    server {
        location /stat {
            rtmp_stat all;
            rtmp_stat_stylesheet stat.xsl;
        }
    }
}

访问 /stat 能看到当前推流数、拉流数、每个流的观看人数。关键指标：并发连接数、码率、丢帧率。

8 个直播坑

  1. 关键帧间隔太大：新观众进来要等下一个关键帧才能看画面。OBS 里设关键帧间隔 2 秒，HLS 分片 >= GOP
  2. TCP 队头阻塞：RTMP 基于 TCP，网络一丢包就卡顿。不稳定的网络用 SRT 推流
  3. HLS 分片不在关键帧：从非关键帧开始解码会花屏。wait_key on 强制从关键帧切
  4. 不鉴权：谁都能推流。on_publish 回调 + token 验证
  5. 多 worker 流不可见：推流在 worker A，拉流在 worker B 看不到流。rtmp_auto_push on 解决
  6. 录制文件损坏：推流异常断开 FLV 文件头没写对。录完用 FFmpeg 验证
  7. 音视频不同步：推流端时间戳不连续。ffprobe 查时间戳增量
  8. 内存泄漏：并发连接多了内存涨。控制 worker_connections，监控内存

FAQ

RTMP 还有必要学吗？

OBS 和 FFmpeg 默认还是推 RTMP。虽然模块停更了，但推流端生态最大。新项目可以直接上 SRT，但 RTMP 作为推流协议还能用很多年。

HLS 延迟太高怎么办？

三个方向：缩小 hls_fragment（2 秒）、用 LL-HLS（部分分片）、换 WebRTC。互动直播必须 WebRTC，普通点播 HLS 够了。

一台服务器能扛多少并发拉流？

RTMP 扇出模式下，每观众一个 TCP 连接。1000 观众大概 100Mbps 带宽。N100 小主机跑 1000 并发没问题。带宽才是瓶颈，不是 CPU。

Nginx RTMP 支持多码率自适应吗？

原生不支持。要做多码率（ABR），推流端推多个码率，Nginx 生成 master m3u8 包含多个子播放列表。或者用专门的流媒体服务器（如 SRS、MediaMTX）。
