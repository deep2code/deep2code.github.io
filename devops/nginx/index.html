Nginx 入门：从你遇到的问题出发

🏷️ Nginx 入门

你写了个网站，跑在 8080 端口，用户访问要加 :8080 才能打开，这也太不专业了。或者你想上 HTTPS，但改后端代码太麻烦。

这些问题，Nginx 全能解决。这篇不讲理论，就讲 Nginx 是什么、为什么要用它，以及最常用的几个配置。

场景一：用户访问你的网站要加 :8080

你遇到的问题

你用 Node.js 写了个网站，跑在 8080 端口。用户输入 www.example.com，浏览器默认找 80 端口，结果连不上，必须加 :8080 才行。这也太不专业了。

Nginx 怎么解决？让 Nginx 监听 80 端口，把请求转发给你跑在 8080 的后端。用户只知道访问 www.example.com，根本不知道后面还有个 8080 的服务。

server {
    listen 80;
    server_name www.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}

就这么简单。现在用户直接输入 www.example.com 就能访问你的网站了，不用加端口号。

场景二：一台服务器想跑好几个网站

你遇到的问题

你有 3 个小网站，想都部署在同一台服务器上。每个网站跑在不同端口？用户要在网址后面加端口号，太傻了。能不能用同一个 80 端口，根据域名自动分给不同网站？

Nginx 怎么解决？用 server_name 区分不同域名，同一个 80 端口，根据用户输入的域名，自动转发给对应的后端服务。

# 第一个网站
server {
    listen 80;
    server_name www.site1.com;
    location / {
        proxy_pass http://127.0.0.1:8081;
    }
}

# 第二个网站
server {
    listen 80;
    server_name www.site2.com;
    location / {
        proxy_pass http://127.0.0.1:8082;
    }
}

# 第三个网站
server {
    listen 80;
    server_name www.site3.com;
    location / {
        proxy_pass http://127.0.0.1:8083;
    }
}

现在 3 个网站都跑在同一台服务器的 80 端口，用户输入不同域名，自动访问对应的网站。完美。

场景三：浏览器提示不安全，想上 HTTPS

你遇到的问题

你的网站还是 HTTP，浏览器地址栏旁边有个"不安全"的提示。用户一看就不敢用了，搜索引擎也把你的排名往下压。你想换成 HTTPS，但不想改后端代码。

Nginx 怎么解决？SSL 证书只放在 Nginx 上，后端还是用 HTTP。用户和 Nginx 之间是加密的，Nginx 和后端之间是内网，不用加密。后端代码一行都不用改。

server {
    listen 80;
    server_name www.example.com;
    # HTTP 自动跳转到 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.example.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}

现在用户输入 www.example.com，自动跳转到 https://www.example.com，浏览器也不提示不安全了。后端还是跑在 8080，啥都不用改。

Nginx 能干什么什么时候用
反向代理把请求转发给后端服务
负载均衡一台服务器扛不住，多台一起扛
静态文件服务直接发 CSS、JS、图片，比后端快 10 倍
HTTPS 终止SSL 证书放 Nginx，后端不用改
限流防止恶意爬虫把你服务器打爆
缓存把经常访问的内容缓存起来，不用每次都查后端
新手最容易踩的坑
  • 改完配置一定要测试：nginx -t 测试语法，没问题再 nginx -s reload 重载。改坏了网站就挂了。
  • location 顺序：精确匹配 > 前缀匹配 > 正则匹配 > 最长匹配，别搞反了。
  • 静态文件直接让 Nginx 发：不要让后端处理静态文件，太慢了。
  • gzip 一定要开：减少传输体积，网站快一倍。
