Nginx 概述

🏷️ Nginx

💡 你的网站跑在 8080 端口，用户访问要加端口号，太不专业了。或者你想把一台服务器变成好几台，让负载分担一下。

你什么时候会需要 Nginx？

你写了个网站，跑在 8080 端口，用户访问要加 :8080 才能打开，这也太不专业了。或者你想上 HTTPS，但改后端代码太麻烦。

这些问题，Nginx 全能解决。从最早配个反向代理，到现在管着几十台服务器的负载均衡、HTTPS 终止、限流缓存，Nginx 始终是我工具箱里最可靠的那个。2026 年主流版本是 Nginx 1.26+，HTTP/3 和 QUIC 已经默认支持了。

为什么 Nginx 比 Apache 快

flowchart TD subgraph Apache prefork REQ1[请求1] --> P1[进程1] REQ2[请求2] --> P2[进程2] REQ3[请求3] --> P3[进程3] end subgraph Nginx 事件驱动 REQ10k[1万请求] --> EPOLL[epoll 事件循环] EPOLL --> W1[Worker 1
单线程处理] end style Nginx fill:#e3f2fd

这是面试常问的问题。说白了就是架构不同：Apache prefork 模式每个请求开一个进程，并发高了进程切换就把 CPU 吃满。Nginx 是事件驱动，一个 Worker 进程用 epoll 同时处理几万连接，没有进程切换开销。

实际测试下来（参考值）：

对比项NginxApache prefork
10K 并发内存占用~100MB~1GB
静态文件 QPS（4核）50000+~5000
连接模型事件驱动（epoll）每请求一进程
CPU 利用率高（无锁）低（频繁切换）

OpenSSL 分叉：大厂都自己搞了

2014 年 Heartbleed 漏洞把 OpenSSL 推到了风口浪尖。之后大厂纷纷搞自己的分支：

分支维护方特点
BoringSSLGoogle砍掉不用的接口，Chromium 在用
LibreSSLOpenBSD精简代码库，安全审计严格
QuicTLSCloudflare在 OpenSSL 3 基础上加 QUIC 支持

Nginx 编译时可以用 --with-openssl=源码路径 指定这些分支。2026 年要做 HTTP/3，官方推荐用 OpenSSL 3.5+ 或 BoringSSL，老的 OpenSSL 1.1 已于 2023 年 9 月 EOL。

版本选择：mainline 还是 stable

Nginx 的版本号规则很简单：奇数是 mainline（主线），偶数是 stable（稳定版）。比如 1.31 是 mainline，1.30 是 stable。

版本线当前版本（2026-08）推荐场景
1.31.x mainline1.31.4需要 HTTP/3、ECH 等新特性
1.30.x stable1.30.4生产环境首选
1.28.x 维护线1.28.3存量环境，安全补丁
我的建议

没有特殊要求就上 1.30.x stable。官方 2026 年其实推荐 mainline 用于生产，因为 mainline 经过充分测试后才合并到 stable，stable 更新慢反而容易落后。但金融、医疗这种要求极稳的行业，还是用 stable。

HTTP/3：2026 年终于能用了

HTTP/3 基于 QUIC 协议跑在 UDP 上，解决了 TCP 层的队头阻塞。Nginx 从 1.25.0 开始实验性支持，到 1.30 稳定版全量落地。

server {
    listen 443 ssl;
    listen 443 quic reuseport;  # 这行开 HTTP/3
    ssl_protocols TLSv1.3;
    add_header Alt-Svc 'h3=":443"; ma=86400';
}

注意：网上流传的 http3 on; 指令是不存在的。启用 HTTP/3 靠的是 listen 的 quic 参数。这个错误配置我见过不下五次，每次都浪费半天排查。

FAQ

Nginx 为什么要 master/worker 架构？

Master 以 root 运行，负责绑定 80/443 特权端口和管理 Worker。Worker 用普通用户运行，即使被攻破也拿不到 root 权限。这种设计既安全又能利用多核——每个 Worker 绑一个 CPU 核心。

worker_processes 设多少合适？

直接设 auto，Nginx 会自动等于 CPU 核心数。手动设多了没用，超过核心数反而增加上下文切换。

Nginx 能处理多少并发？

理论上限 = worker_processes × worker_connections。8 核 81920 连接是常见配置。实际上还受文件描述符限制（ulimit -n）和内存大小影响。

HTTP/3 为什么要 TLS 1.3？

QUIC 协议把 TLS 1.3 集成在了传输层，不再像 TCP+TLS 那样分开握手。TLS 1.3 的握手本身就快（1-RTT），加上 QUIC 的 0-RTT 恢复，连接建立比 HTTP/2 快一倍。
