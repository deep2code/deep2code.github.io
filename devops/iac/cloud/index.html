AWS/阿里云资源编排实战

🏷️ IaC / Terraform

一套能上生产的架构长什么样

前两篇把基础打牢了，这篇直接上真东西。我用一套典型的 Web 服务架构举例：VPC 网络隔离、安全组收口、ECS/EKS 跑应用、RDS 存数据、SLB 做入口。这套架构 AWS 和阿里云都能跑，代码我尽量写得通用，差异点单独标注。

flowchart TB USER[用户] --> SLB[SLB / ALB] SLB --> ECS1[ECS 实例 1] SLB --> ECS2[ECS 实例 2] ECS1 --> RDS[RDS 数据库] ECS2 --> RDS subgraph VPC SLB ECS1 ECS2 RDS end

先看整体分层：外层 SLB 暴露 80/443，安全组只放行 SLB 到 ECS 的 8080 端口，RDS 只放行 ECS 安全组的 3306。三层隔离，谁也不直接暴露公网。

VPC 网络：先把地基打好

所有云资源都得住在 VPC 里。一个生产 VPC 通常分公网子网（放 SLB、NAT）和私网子网（放 ECS、RDS）。我用阿里云举例，AWS 概念完全对应：

# network.tf
resource "alicloud_vpc" "main" {
  vpc_name   = "${var.env}-vpc"
  cidr_block = "10.0.0.0/16"
}

# 公网子网（2 个 AZ，提高可用性）
resource "alicloud_vswitch" "public" {
  vpc_id       = alicloud_vpc.main.id
  cidr_block   = "10.0.1.0/24"
  zone_id      = var.zone_a
  vswitch_name = "${var.env}-public-a"
}

# 私网子网
resource "alicloud_vswitch" "private" {
  vpc_id       = alicloud_vpc.main.id
  cidr_block   = "10.0.11.0/24"
  zone_id      = var.zone_a
  vswitch_name = "${var.env}-private-a"
}

# 公网网关
resource "alicloud_eip_address" "nat_eip" {
  address_name = "${var.env}-nat-eip"
  bandwidth    = "5"
}

resource "alicloud_nat_gateway" "main" {
  vpc_id        = alicloud_vpc.main.id
  nat_gateway_name = "${var.env}-nat"
  vswitch_id    = alicloud_vswitch.public.id
}
网段规划别偷懒
10.0.0.0/16 一个 VPC 用满就没了。我按环境分网段：dev 用 10.1.0.0/16，staging 用 10.2.0.0/16，prod 用 10.3.0.0/16。未来要做 VPC peering 或者专线打通，网段不重叠是前提。我见过没规划好，两个 VPC 撞网段，专线死活通不了的事故。

安全组：最小权限原则

安全组是网络防火墙，按"谁能访问谁"来配。我习惯拆成三个安全组：SLB、ECS、RDS，每层只放行必要端口：

# security.tf
# SLB 安全组：对公网开放 80/443
resource "alicloud_security_group" "slb" {
  name   = "${var.env}-sg-slb"
  vpc_id = alicloud_vpc.main.id
}

resource "alicloud_security_group_rule" "slb_in_http" {
  security_group_id = alicloud_security_group.slb.id
  type              = "ingress"
  ip_protocol       = "tcp"
  port_range       = "80/80"
  cidr_ip           = "0.0.0.0/0"
  policy            = "accept"
}

# ECS 安全组：只接受 SLB 的 8080
resource "alicloud_security_group" "ecs" {
  name   = "${var.env}-sg-ecs"
  vpc_id = alicloud_vpc.main.id
}

resource "alicloud_security_group_rule" "ecs_in_from_slb" {
  security_group_id    = alicloud_security_group.ecs.id
  type                 = "ingress"
  ip_protocol          = "tcp"
  port_range           = "8080/8080"
  source_security_group_id = alicloud_security_group.slb.id
  policy               = "accept"
}

# RDS 安全组：只接受 ECS 的 3306
resource "alicloud_db_security_group" "rds" {
  name        = "${var.env}-sg-rds"
  security_group_ips = [alicloud_vswitch.private.cidr_block]
}

关键设计：ECS 不对公网开放任何端口，RDS 只对私网子网开放。外部流量只能从 SLB 进，应用不能直接被公网摸到。这就是分层防御。

ECS 实例 + RDS 数据库

应用服务器和数据库一起编排。RDS 我用 Terraform 建，但第一次建 RDS 的密码别硬编码——用随机密码存进参数管理：

# compute.tf
resource "alicloud_instance" "app" {
  count                  = var.ecs_count
  instance_name          = "${var.env}-app-${count.index + 1}"
  image_id               = data.alicloud_images.ubuntu.ids[0]
  instance_type          = var.ecs_instance_type
  vswitch_id             = alicloud_vswitch.private.id
  security_groups        = [alicloud_security_group.ecs.id]
  system_disk_category   = "cloud_essd"
  system_disk_size       = 40

  tags = {
    Env = var.env
    Role = "app"
  }
}

# RDS
resource "alicloud_db_instance" "main" {
  engine              = "MySQL"
  engine_version      = "8.0"
  instance_type       = var.rds_instance_type
  instance_storage    = var.rds_storage
  vswitch_id          = alicloud_vswitch.private.id
  instance_name       = "${var.env}-rds"
  db_instance_class   = var.rds_instance_type
  db_instance_storage = var.rds_storage
  security_ips        = [alicloud_vswitch.private.cidr_block]
}

resource "alicloud_db_database" "app" {
  instance_id = alicloud_db_instance.main.id
  name        = "appdb"
  character_set = "utf8mb4"
}

SLB 负载均衡

SLB 把流量分发到多台 ECS。监听器配 80 端口，转发到 ECS 的 8080：

# slb.tf
resource "alicloud_slb_load_balancer" "main" {
  load_balancer_name   = "${var.env}-slb"
  vswitch_id           = alicloud_vswitch.public.id
  load_balancer_spec   = "slb.s2.small"
  address_type         = "intranet" # 配合公网 EIP 用
}

resource "alicloud_slb_listener" "http" {
  load_balancer_id    = alicloud_slb_load_balancer.main.id
  frontend_port       = 80
  frontend_protocol   = "http"
  backend_port        = 8080
  bandwidth           = 5
  scheduler           = "wrr"
  server_group_id    = alicloud_slb_server_group.main.id
}

resource "alicloud_slb_server_group" "main" {
  load_balancer_id = alicloud_slb_load_balancer.main.id
  name             = "${var.env}-app-group"

  servers {
    server_ids = alicloud_instance.app[*].id
    port       = 8080
    weight     = 100
  }
}

变量文件：tfvars 怎么组织

上面的代码里到处是 var.env、var.ecs_count。这些值不能硬编码，要按环境分文件。我团队的目录结构是：

infra/
├── main.tf           # 资源定义（所有环境共用）
├── variables.tf      # 变量声明
├── outputs.tf        # 输出
├── environments/
│   ├── dev.tfvars    # dev 环境的覆盖值
│   ├── staging.tfvars
│   └── prod.tfvars
└── modules/          # 第四篇讲

不同环境的 tfvars 内容：

# environments/dev.tfvars
env               = "dev"
ecs_count         = 1
ecs_instance_type = "ecs.t6-c1m2.large"
rds_instance_type = "mysql.n2.medium.1c"
rds_storage       = 20
zone_a            = "cn-shenzhen-a"

# environments/prod.tfvars
env               = "prod"
ecs_count         = 3
ecs_instance_type = "ecs.g7.large"
rds_instance_type = "mysql.n2.large.2c"
rds_storage       = 200
zone_a            = "cn-shenzhen-a"
zone_b            = "cn-shenzhen-b"

跑的时候指定 tfvars 文件：

# 部署 dev
terraform apply -var-file="environments/dev.tfvars"

# 部署 prod（要小心，建议先 plan）
terraform plan -var-file="environments/prod.tfvars" -out=prod.plan
terraform apply prod.plan

环境隔离：dev/staging/prod 怎么分

光靠 tfvars 还不够，state 也要分开。我按"环境+项目"两个维度拆 state：

环境state key网段ECS 数量谁能 apply
devdev/network/tfstate10.1.0.0/161所有人
stagingstaging/network/tfstate10.2.0.0/162Tech Lead
prodprod/network/tfstate10.3.0.0/163+审批后 CI 跑
flowchart LR subgraph dev DV[VPC 10.1.x] end subgraph staging ST[VPC 10.2.x] end subgraph prod PR[VPC 10.3.x] end DV -.state 独立.-> S1[S3: dev/] ST -.state 独立.-> S2[S3: staging/] PR -.state 独立.-> S3[S3: prod/]

三个环境用不同的 backend key，state 互不影响。dev 炸了随便重建，prod 的 state 单独保护。这就是为什么我反复说 state 拆分很重要。

outputs 设计：把有用的信息吐出来

apply 完你需要什么信息？SLB 的 IP、RDS 的连接串、ECS 的 IP 列表。这些做成 output：

# outputs.tf
output "slb_address" {
  description = "SLB 公网地址"
  value       = alicloud_slb_load_balancer.main.address
}

output "rds_connection_string" {
  description = "RDS 内网连接串"
  value       = "${alicloud_db_instance.main.connection_string}:3306"
  sensitive   = true   # 含敏感信息，标记后 terraform output 不直接显示
}

output "ecs_private_ips" {
  description = "ECS 私网 IP 列表"
  value       = alicloud_instance.app[*].private_ip
}
sensitive 输出
像数据库密码、连接串这种敏感值，output 块加 sensitive = true。terraform output 默认不打印它，要看就 terraform output -json rds_connection_string。别把敏感值明文写在普通 output 里。

多云 provider 切换

同一套架构要在 AWS 和阿里云之间切？Provider 不一样，资源类型也不一样。我的做法是把云相关的差异隔离在 Module 里，上层调用统一接口。第四篇会讲 Module，这里先给个思路：

# 用变量控制用哪个云
variable "cloud" {
  type    = string
  default = "aliyun"
}

# 按条件选 provider
provider "alicloud" {
  region = var.region
  alias  = "aliyun"
}

provider "aws" {
  region = var.region
  alias  = "aws"
}

# 上层调用时按 cloud 选
module "network" {
  source = "./modules/network"
  providers = {
    cloud = var.cloud == "aliyun" ? alicloud.aliyun : aws.aws
  }
}

实际操作中，我不建议真的写一套代码同时跑两个云——差异太多，维护成本高。更现实的做法是：同一套 Module 接口，分别维护 AWS 版和阿里云版的实现，业务代码不感知底层云。

FAQ

Q：RDS 密码放哪？
别放 tfvars。用云厂商的参数管理（阿里云 KMS/AWS Secrets Manager），Terraform 引用时用 sensitive。生产环境密码必须动态生成、定期轮转。

Q：ECS 数量用 count 还是 for_each？
同质的机器用 count 就行。但如果你要区分 web1/web2 这种不同角色，用 for_each 按名字建，避免 count 顺序变化导致重建。

Q：state 拆多了管理麻烦怎么办？
多环境多 state 是正路，麻烦是值得的。用 Terragrunt 或脚本封装一下 terraform apply -var-file=... 的重复操作，第四篇讲 CI/CD 时会涉及。

Q：能把 EKS 也编进去吗？
能，alicloud_cs_managed_kubernetes 或 AWS 的 aws_eks_cluster。但 EKS 比较重，我一般单独一个 state 文件管，不和网络混在一起。

我的结论

这套 VPC + 安全组 + ECS + RDS + SLB 的编排，是我团队每个业务的起点模板。核心原则三条：分层网络隔离、安全组最小权限、环境靠 tfvars + 独立 state 双重隔离。

代码不追求一次写完美，先跑通 dev 环境，再逐步加东西。别上来就想写一套能跑全平台所有云的"万能模板"——那是第四篇 Module 要解决的问题，不是现在。下一篇讲怎么把这些重复的东西抽成可复用的 Module。
