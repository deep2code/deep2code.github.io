监控告警：从你遇到的问题出发

🏷️ 监控告警

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及监控告警怎么帮你解决。

flowchart TB A[应用指标] --> B[采集] B --> C[存储] C --> D[看板展示] C --> E[告警通知]

1. 网站挂了用户先知道

你遇到的问题

网站宕机半小时，用户在群里骂了你才发现。

怎么解决？监控帮你盯着，挂了马上打电话告诉你。

2. 不知道服务慢在哪

你遇到的问题

用户说网站卡，你不知道是哪个接口慢。

怎么解决？监控每个接口的响应时间，一眼看出哪个慢。

3. 服务器资源不够不知道

你遇到的问题

磁盘快满了，CPU 快爆了，你不知道。

怎么解决？监控服务器 CPU、内存、磁盘，快满了就告警。

必监控指标

类型指标
服务器CPU、内存、磁盘、网络
应用QPS、响应时间、错误率
业务订单量、支付成功率
新手最容易踩的坑
  • 告警要分级电话只给最严重的，钉钉给一般的，邮件给通知类的。
  • 告警要能行动告警信息要告诉你哪出了问题、怎么处理。
