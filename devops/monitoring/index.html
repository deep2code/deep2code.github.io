监控入门：从你遇到的问题出发

🏷️ 监控入门

你的网站挂了，是用户打电话告诉你的，不是你自己发现的。或者服务器 CPU 跑满了，你根本不知道，等用户投诉了才去查。

这篇不讲理论，就讲你真的会遇到的问题，以及监控怎么帮你解决。

场景一：网站挂了，用户打电话告诉你，你才知道

你遇到的问题

你的网站突然挂了，你还在睡觉。早上起来打开手机，发现十几个用户发消息说网站打不开。你赶紧 SSH 上去查，折腾了半小时才修好。用户已经流失了一大半。

监控怎么解决？监控系统每隔 1 分钟访问一次你的网站，如果打不开，马上给你发微信、发短信告警。网站一挂你 1 分钟内就知道了，不用等用户投诉。

# Prometheus + Alertmanager 告警配置
groups:
- name: website
  rules:
  - alert: WebsiteDown
    expr: up{job="mywebsite"} == 0
    for: 1m
    labels:
      severity: critical
    annotations:
      summary: "网站挂了！"

现在网站一挂，1 分钟内你手机就收到告警，马上就能处理，用户根本感觉不到。

场景二：服务器 CPU 跑满了，你根本不知道

你遇到的问题

你的服务器 CPU 突然跑到 100%，响应越来越慢，用户开始投诉。你上去 top 一看，才发现某个进程吃满了 CPU。但是这时候已经过了 2 小时了。

监控怎么解决？监控系统实时看 CPU、内存、磁盘的使用率，超过阈值就告警。比如 CPU 超过 80% 就告警，你在 CPU 刚上来的时候就知道了，不会等到跑满了才发现。

监控指标什么时候要看
CPU 使用率超过 80% 就要告警
内存使用率超过 85% 就要告警
磁盘使用率超过 80% 就要告警，不然磁盘满了服务就挂了
接口响应时间超过 500ms 就要告警
错误率错误率超过 1% 就要告警

场景三：出了问题，不知道什么时候开始的

你遇到的问题

用户说网站很慢，你上去查，但是不知道从什么时候开始慢的，也不知道是哪个接口慢，查了半天都找不到原因。

监控怎么解决？监控系统把所有指标都存下来，你可以看过去 7 天、30 天的趋势，点一下就知道什么时候开始变慢的，是哪个接口慢。

新手最容易踩的坑
  • 不要告警太多：什么都告警，一天收几百条告警，你就麻木了，真正重要的告警反而忽略了。
  • 告警要能直接处理：告警信息要写清楚是什么问题、怎么处理，不要只发一句"有问题"。
  • 不要只监控服务器：还要监控业务指标，比如订单量、支付成功率，服务器正常不代表业务正常。
  • 告警一定要有人处理：告警发了没人看，等于没监控。
