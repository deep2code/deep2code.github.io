CI/CD 入门：从你遇到的问题出发

🏷️ CI/CD 入门

你每次改完代码，要手动打包、传服务器、重启服务，经常出错，还要熬夜部署。你想：能不能自动做这些事？

这篇不讲理论，就讲你真的会遇到的问题，以及 CI/CD 怎么帮你解决。

场景一：改完代码，要手动打包、传服务器、重启，太麻烦还容易错

你遇到的问题

你改了一行代码，要：本地打包 scp 传到服务器 SSH 上去解压重启服务 每次部署都要做这一套，5 分钟的事，但是经常出错：传错文件、忘重启、配置不对。半夜出问题还要爬起来部署。

CI/CD 怎么解决？你只要把代码 push 到 Git，剩下的打包、传服务器、重启，全部自动做。你喝杯咖啡的功夫，代码就上线了。

# GitHub Actions 配置，push 代码就自动部署
on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: 传文件到服务器
        uses: appleboy/scp-action@master
        with:
          host: ${{ secrets.HOST }}
          username: root
          key: ${{ secrets.KEY }}
          source: "."
          target: "/var/www/myapp"
      - name: 重启服务
        run: ssh ${{ secrets.HOST }} "systemctl restart myapp"

现在你只要 git push，剩下的全自动，再也不用手动部署了。

场景二：本地跑的好好的，一上线就出问题

你遇到的问题

你本地代码跑的好好的，一上线就报错：忘提交了某个文件、依赖没装、环境变量不对。每次上线都像开盲盒，提心吊胆。

CI/CD 怎么解决？每次 push 代码，自动跑测试、自动检查代码、自动打包。测试不通过就不让上线，问题在上线前就发现了。

# push 代码自动跑测试
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npm install
      - run: npm test

现在测试不通过，根本到不了部署那一步，问题在上线前就拦住了。

场景三：每次部署要等好久，开发效率低

你遇到的问题

你改完一个小功能，要等 20 分钟才能部署上去验证。一天改 5 个功能，光等部署就花了一个小时，开发效率很低。

CI/CD 怎么解决？全自动部署，从 push 到上线只要 2 分钟，改完马上就能看到效果，开发效率高很多。

概念通俗理解
CI（持续集成）每次 push 代码，自动跑测试、检查代码，保证代码质量
CD（持续部署）测试通过后，自动打包部署到服务器，不用手动操作
Pipeline（流水线）把这些步骤串起来：测试 → 打包 → 部署，一步一步自动跑
新手最容易踩的坑
  • 不要把密钥写在配置文件里：密码、密钥要存在 GitHub Secrets 里，不要直接写在 yaml 里，不然会泄露。
  • 不要跳过测试直接部署：测试不通过就部署，迟早出大问题。
  • 第一次部署先在测试环境跑：不要一上来就直接部署到生产环境，先在测试环境验证没问题了再上生产。
  • 部署失败要有告警：部署失败了要发通知，不要等用户发现了才知道。
