CI/CD 深度原理：自动化流水线

🏷️ CI/CD

CI/CD 不是点一下按钮，是自动化流水线：提交代码→自动测试→自动构建→自动部署。这篇讲透 CI/CD 底层原理。

核心原理1：CI/CD 是什么？

CI 持续集成：代码提交后自动跑测试，确保代码没问题。CD 持续部署：测试过了自动部署到生产，不用手动。

flowchart LR A[代码提交] --> B[CI 持续集成] B --> C[自动测试] C --> D[构建镜像] D --> E[CD 持续部署] E --> F[自动部署到环境]

['阶段', '做什么', '目的']

阶段 做什么 目的
CI 代码提交后自动构建测试 保证代码质量
CD 持续交付 自动部署到预发 快速验证
CD 持续部署 自动部署到生产 全自动发布

核心原理2：流水线原理

流水线是阶段化的：每个阶段跑不同的任务，前一个失败了后面就不跑了，并行阶段同时跑。

flowchart TD A[阶段1 构建] --> B[阶段2 单元测试] B --> C[阶段3 集成测试] C --> D[阶段4 构建镜像] D --> E[阶段5 部署预发] E --> F[阶段6 部署生产]

['流水线原则', '说明']

原则 说明
快速失败 前面阶段失败了后面就不跑了 省时间
并行执行 不依赖的阶段同时跑 流水线快
不可变构建 一次构建多环境用 避免环境不一致
自动化 不用手动点 减少人为错误

核心原理3：GitOps 原理

GitOps 是用 Git 仓库当唯一事实来源，部署什么版本都存在 Git 里，改了 Git 自动同步到 K8s。

flowchart LR A[Git 仓库 期望状态] --> B[Agent 监听 Git] B --> C[对比实际状态] C --> D[不一致 自动同步] D --> E[K8s 实际状态]

['对比', '传统 CI/CD', 'GitOps']

对比 传统 CI/CD GitOps
状态来源 部署工具里 Git 仓库
审计 看部署日志 看 Git 提交历史
回滚 重新部署 git revert
适用 虚拟机/物理机 K8s 云原生

新手最容易踩的坑

❌
避坑指南
  • CI/CD 不要把所有步骤都串成一条线，不依赖的步骤并行跑
  • 流水线要缓存依赖，不然每次都重新下载，很慢
  • 生产部署要有审批，不要自动直接上生产
  • GitOps 只适合 K8s，虚拟机部署用传统 CI/CD 就行
