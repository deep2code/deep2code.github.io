API 设计最佳实践：从你遇到的问题出发

🏷️ API 设计

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及API 设计怎么帮你解决。

flowchart TB A[好的 API] --> B[统一返回格式] A --> C[RESTful 风格] A --> D[合理错误码] A --> E[版本管理]

1. API 格式不统一

你遇到的问题

每个接口返回格式都不一样，前端很头疼。

怎么解决？统一返回格式：code、message、data 三个字段。

2. 错误码很乱

你遇到的问题

错误码有的用 200 有的用 400，不知道什么意思。

怎么解决？统一错误码规范，4xx 客户端错，5xx 服务器错。

3. 接口命名不统一

你遇到的问题

有的叫 getUser，有的叫 userList，很乱。

怎么解决？RESTful 风格，URL 用名词，方法表示操作。

最佳实践

实践说明
统一返回格式code + message + data
RESTful 风格URL 名词，方法操作
用 HTTP 状态码200 成功、400 参数错、500 服务器错
版本管理URL 里加版本号
新手最容易踩的坑
  • 返回格式要统一所有接口都按同一个格式，前端好处理。
  • 错误信息要清楚不要返回"系统错误"，要说清楚哪里错了。
