API 设计最佳实践：从你遇到的问题出发

🏷️ API 最佳实践

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及API 最佳实践怎么帮你解决。

flowchart TB A[API 设计] --> B[RESTful] B --> C[统一响应格式] C --> D[错误码规范]

1. API 格式不统一

你遇到的问题

不同接口返回格式不一样，前端处理麻烦。

怎么解决？统一响应格式：code、message、data 三个字段。

2. 错误码怎么设计

你遇到的问题

错误码怎么设计？

怎么解决？用统一规范，比如 200 成功、400 参数错、500 服务器错。

3. 接口文档怎么写

你遇到的问题

怎么让前端知道接口怎么调？

怎么解决？用 Swagger/OpenAPI 自动生成文档。

响应格式

字段说明
code业务状态码
message提示信息
data返回数据
新手最容易踩的坑
  • 统一格式所有接口返回格式一定要统一。
  • 错误码规范错误码要有规范，不要随便编。
