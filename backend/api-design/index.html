API 设计：让调用方少骂街

🏷️ API设计

接口返回格式乱七八糟，错误码不统一，参数名一会驼峰一会下划线，调用方天天骂街。好的 API 设计让调用方用着舒服，少踩坑。

flowchart LR A[API设计] --> B[RESTful风格] B --> C[统一返回格式] C --> D[错误码规范] D --> E[版本管理] E --> F[文档]

接口返回格式乱七八糟

⚠️
你遇到的问题

有的接口返回 {code:0, data:...}，有的直接返回数据，有的错误返回字符串，调用方一脸懵。

怎么解决？所有接口统一返回格式：code、message、data，不管成功失败都这个结构。

// 统一返回格式
{
  "code": 0,
  "message": "success",
  "data": { ... }
}

// 错误也一样
{
  "code": 40001,
  "message": "参数错误",
  "data": null
}

接口改了，调用方崩了

⚠️
你遇到的问题

接口字段改了，没通知调用方，前端直接白屏。

怎么解决？接口加版本号，不兼容的改动放新版本，老版本继续保留一段时间。

# 版本管理
/api/v1/users  →  老版本
/api/v2/users  →  新版本

# 不兼容的改动才升版本
# 加字段、加接口不用升

RESTful 风格

操作 方法 URL 说明
查列表 GET /users 获取用户列表
查详情 GET /users/123 获取单个用户
新建 POST /users 创建用户
更新 PUT /users/123 更新用户
删除 DELETE /users/123 删除用户

新手最容易踩的坑

❌
避坑指南
  • URL 用名词，别用动词，/getUser 不对，/users 才对
  • HTTP 方法别乱⽤，GET 不能改数据，POST 不是什么都往里塞
  • 错误码要分类，1xxx 参数错误，2xxx 业务错误，5xxx 服务器错误
  • 一定要写文档，Swagger 或者 Apifox 都行，别让调用方猜接口
