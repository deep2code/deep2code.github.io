测试入门：从你遇到的问题出发

🏷️ 测试

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及测试怎么帮你解决。

flowchart TB A[测试] --> B[单元测试] B --> C[集成测试] C --> D[E2E 测试]

1. 改完代码又出 bug

你遇到的问题

改完 A 功能，B 功能又坏了，回归测试靠人工太慢。

怎么解决？写自动化测试，改完跑一遍测试，马上知道有没有坏。

2. 测试分几种

你遇到的问题

测试分哪几种？

怎么解决？单元测试（函数）、集成测试（模块）、E2E（端到端）。

3. 为什么写测试

你遇到的问题

为什么要写测试？

怎么解决？防止改坏代码，重构有信心，文档作用。

测试类型

类型测什么速度
单元测试单个函数/类最快
集成测试模块之间中等
E2E整个流程最慢
新手最容易踩的坑
  • 先写核心逻辑测试先给核心业务逻辑写单元测试，其他慢慢来。
  • 不要追求覆盖率覆盖率不是越高越好，关键路径覆盖就行。
