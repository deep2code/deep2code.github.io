Kafka 入门：从你遇到的问题出发

🏷️ Kafka 入门

你要处理大量的异步消息：用户下单后要发短信、发邮件、更新积分，不能让用户等。或者你要做日志收集，几台服务器的日志要汇总到一起。

这些问题，Kafka 就是为解决这个而生的。这篇不讲理论，就讲你真的会遇到的问题，以及 Kafka 怎么帮你解决。

场景一：用户下单后，要发短信、发邮件、更新积分，不能让用户等

你遇到的问题

用户点了"下单"按钮，你要：扣库存、生成订单、发短信通知、发邮件、更新用户积分。这些事都做完了才返回成功。用户点了按钮等了 5 秒，直接跑了。

Kafka 怎么解决？用户下单后，只做最核心的扣库存、生成订单，马上返回成功。其他的发短信、发邮件、更新积分，发到 Kafka 里，后台慢慢处理。用户根本感觉不到。

# 下单接口，只做核心逻辑
def create_order():
    # 1. 扣库存
    # 2. 生成订单
    # 3. 发消息到Kafka
    kafka.send('order_created', order_info)
    return '下单成功'

# 另一个服务，消费Kafka消息，慢慢处理
def send_sms():
    for message in kafka.consume('order_created'):
        # 发短信
        # 发邮件
        # 更新积分

现在用户点了下单按钮，100ms 就返回成功了，其他事后台慢慢做。体验好太多了。

场景二：几台服务器的日志，要汇总到一起分析

你遇到的问题

你有 10 台服务器跑应用，每台服务器都有日志。你要分析所有日志，得一台一台上去看，太麻烦了。你想把所有日志都汇总到一个地方。

Kafka 怎么解决？每台服务器把日志发到 Kafka，然后一个集中的服务从 Kafka 消费日志，存到 Elasticsearch 或者数据库里。你只要查一个地方就行。

# 每台服务器都跑一个日志收集 agent，把日志发到Kafka

现在你不用一台一台服务器上去看日志了，在一个地方就能查所有服务器的日志。

场景三：大促的时候流量突然涨了 10 倍，数据库扛不住

你遇到的问题

大促的时候，用户疯狂点下单按钮，一秒钟 1 万个请求打到数据库，数据库直接挂了。你想：能不能先把请求存起来，慢慢处理？

Kafka 怎么解决？所有请求先发到 Kafka，然后后端按自己的处理能力，慢慢从 Kafka 里取消息处理。数据库不会被瞬间打垮。

概念通俗理解
Producer（生产者）发消息的人：往 Kafka 里写消息
Consumer（消费者）收消息的人：从 Kafka 里读消息
Topic（主题）消息分类：下单消息一个 Topic，日志一个 Topic
Broker（节点）Kafka 服务器：存消息的地方
新手最容易踩的坑
  • 消息一定要确认消费成功：不要消费完就提交 offset，要处理完了再提交，不然消息丢了。
  • 消息要有唯一 ID：防止重复消费，业务逻辑要能幂等。
  • 不要把 Kafka 当数据库：Kafka 是消息队列，不是持久化数据库，重要数据还是要存数据库。
  • 消费者挂了要能重启：offset 要存好，重启了能从上次的位置继续消费。
