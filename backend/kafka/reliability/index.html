Kafka 可靠性：从你遇到的问题出发

🏷️ Kafka 可靠性

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及Kafka 可靠性怎么帮你解决。

flowchart TB A[生产端确认] --> B[Broker 持久化] B --> C[消费端确认] C --> D[不丢消息]

1. 消息会不会丢

你遇到的问题

你把消息发到 Kafka，会不会半路丢了？

怎么解决？生产端 ack=all，Broker 副本持久化，消费端手动提交 offset。

2. 怎么保证消息不丢

你遇到的问题

知道有风险，不知道怎么配。

怎么解决？三个环节都要配好：生产端、Broker、消费端。

3. 会不会重复消费

你遇到的问题

消息会不会重复收到？

怎么解决？会的，所以消费者一定要做幂等。

可靠性配置

环节配置
生产端acks=all
Broker副本数 ≥ 2
消费端手动提交 offset
新手最容易踩的坑
  • 消费者一定要幂等重复消费是正常的，业务代码要处理。
  • 不要关 acksacks=0 最快但最容易丢消息。
