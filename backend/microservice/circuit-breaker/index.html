熔断降级实战：从你遇到的问题出发

🏷️ 熔断降级

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及熔断降级怎么帮你解决。

flowchart TB A[正常] --> B[异常多] B --> C[熔断打开] C --> D[降级返回] D --> E[恢复正常] E --> F[熔断关闭]

1. 一个服务挂了拖垮整个系统

你遇到的问题

库存服务挂了，订单服务一直调用超时，整个系统变慢。

怎么解决？加熔断降级，下游服务异常多就熔断，直接降级返回默认值。

2. 熔断是什么

你遇到的问题

熔断是什么？

怎么解决？熔断器，下游服务异常率到阈值就停止调用，直接降级，防止级联故障。

3. 常用框架

你遇到的问题

Java 常用熔断框架有哪些？

怎么解决？Sentinel（阿里）、Resilience4j。

熔断器状态

状态说明
关闭正常调用
打开熔断，不调用直接降级
半开试探调用，看是否恢复
新手最容易踩的坑
  • 一定要有降级熔断一定要配降级返回，不要直接报错。
  • 超时要配所有 RPC 调用一定要配超时，不要无限等。
