消息队列入门：为什么要发消息？

🏷️ 消息队列

下单后要扣库存、加积分、发短信，一个个同步调用，接口慢得要死。消息队列就是把这些事异步做，主流程快了，其他慢慢处理。

flowchart LR A[用户下单] --> B[订单服务] B --> C[发消息到MQ] C --> D[扣库存] C --> E[加积分] C --> F[发短信] B --> G[返回成功]

下单接口太慢

⚠️
你遇到的问题

下单要同时扣库存、加积分、发短信，一个接口调三个服务，等半天用户才看到"下单成功"。

怎么解决？把非核心流程放到消息队列异步处理，主流程只做核心的下单，马上返回。

# 同步调用 vs 异步调用
# 同步：等所有都做完才返回，慢
# 异步：发完消息就返回，其他慢慢做，快

消息发了，没人消费怎么办

⚠️
你遇到的问题

下单后发了消息，结果消费者挂了，消息丢了，库存没扣。

怎么解决？用持久化的消息队列，消息存到磁盘，消费者重启了还能接着消费。

# Kafka / RabbitMQ 都支持持久化
消息先存磁盘，消费者确认了才删
消费者挂了重启，消息还在，继续消费

新手最容易踩的坑

❌
避坑指南
  • 消息一定要加唯一ID，消费者要做幂等，不然重复消费就出问题
  • 不是所有场景都要用 MQ，小项目直接同步调用就行，别为了用而用
  • 消息积压是常见问题，一定要监控积压量，超了就告警
  • 死信队列要配置好，处理失败的消息别直接丢了
