Go GroupBy

🏷️ Go 语言

分组这件事，泛型之后终于通用了

Go 1.21 把 slices 和 maps 两个泛型包扶正，"分组"终于不用为每种类型重写代码。切片分组就是把 []T 按某个键函数变成 map[K][]T。

选型口诀
需要按键快速查找用 map[K][]T；需要保持顺序输出用 []Group{Key, Items}。实际最常见的是"先分组再按 key 排序输出"——map 分组 + keys 切片排序后遍历。

基础：泛型 GroupBy

import "slices"

func GroupBy[T any, K comparable](items []T, keyFn func(T) K) map[K][]T {
    result := make(map[K][]T)
    for _, item := range items {
        k := keyFn(item)
        result[k] = append(result[k], item)
    }
    return result
}

type Order struct{ ID string; Status string }

orders := []Order{{"1", "paid"}, {"2", "pending"}, {"3", "paid"}}
grouped := GroupBy(orders, func(o Order) string { return o.Status })
// grouped["paid"] = [{1 paid}, {3 paid}]
// grouped["pending"] = [{2 pending}]

1.23+ 迭代器版

1.23 把 range-over-func 扶正，slices.Values 产出迭代器，Collect 收回切片。分组可以走"切片→迭代器→map"的流式写法：

import "iter"
import "slices"

func GroupBySeq[T any, K comparable](seq iter.Seq[T], keyFn func(T) K) map[K][]T {
    out := make(map[K][]T)
    for v := range seq {
        k := keyFn(v) // 只算一次 key，别在 append 里重复调
        out[k] = append(out[k], v)
    }
    return out
}

groups := GroupBySeq(slices.Values(orders), func(o Order) string { return o.Status })

1.27 泛型方法时代

1.27 放开泛型方法，分组逻辑能直接长在具体类型上：

type Items[T any] []T

func (s Items[T]) GroupBy[K comparable](keyFn func(T) K) map[K][]T {
    out := make(map[K][]T)
    for _, v := range s {
        out[keyFn(v)] = append(out[keyFn(v)], v)
    }
    return out
}

我的建议：老手写泛型实现（1.21 版）完全兼容不用折腾；新代码数据量小图省事上迭代器；热路径数据量大还是手写循环（迭代器封装有间接开销）；samber/lo 这类三方库当备胎，标准库已覆盖大半分组场景。

map 分组 vs slice 分组

维度map[K][]T[]struct{K, []T}
查找速度O(1) 按 key 查找O(n) 线性扫描
遍历顺序随机（Go map 特性）保持插入顺序
内存开销较高（哈希桶）较低（连续数组）
适用场景按键快速查找按顺序遍历输出
多键分组结构体 key 天然支持需额外排序
并发安全需加锁或 sync.Map需加锁

分组变体

除了最基础的 map 分组，常用变体我列在这：

变体返回类型适用场景
完整分组map[K][]T拿到每组全部元素
分组计数map[K]int只要每组数量
分组聚合map[K]R边分组边求和/平均
有序分组keys 切片 + map按首次出现顺序输出
  • 分组计数：只要数量用 map[K]int，每次 m[k]++，比完整分组省内存。
  • 分组聚合：分组后直接求和/平均，一次遍历完成。
  • 分组去重：map[K]map[T]struct{}，T 须 comparable。
  • 多键分组：keyFn 返回结构体（type Key struct{Category string; Year int}），别用字符串拼接（有碰撞）。
  • 有序分组：Go map 遍历随机，要保顺序就用 keys 切片记录首次出现顺序再遍历。

五个常见坑

  • map 遍历顺序随机：直接遍历 map 输出每次结果不同，测试不稳定。收集 keys 排序后再遍历。
  • nil map 写入 panic：始终 make(map[K][]T)。读 nil map 不 panic，写才 panic。
  • 分组键不可比较：slice/map/func 不能作 key。把 keyFn 返回的 slice 转字符串或数组。
  • 大切片分组内存翻倍：值类型元素被复制进分组切片。用指针 []*T 或存索引 map[K][]int。
  • keyFn 有副作用或慢：keyFn 被调 n 次，要纯函数；复杂 key 计算预计算后再分组。

FAQ

Q：标准库有现成的 GroupBy 吗？
没有直接的（Go 团队认为返回类型不够通用）。用本文的泛型函数，或 samber/lo 的 lo.GroupBy。

Q：为什么分组后输出顺序每次都不一样？
Go map 遍历顺序故意随机化防哈希碰撞攻击。需要确定顺序就把 keys 收集到切片排序。

Q：分组函数需要显式写类型参数吗？
大多数情况编译器能推断。推断失败才写 GroupBy[Order, string](orders, keyFn)。

我的总结

切片分组在 1.21+ 就是一个二十行泛型函数的事：map 分组按键查找、keys 排序保序、预分配容量减少扩容。

我自己记三条：map 遍历随机、key 须 comparable、大切片用指针或索引省内存。再配合 1.23 迭代器和 1.27 泛型方法，这块就没有真正的难题了。
