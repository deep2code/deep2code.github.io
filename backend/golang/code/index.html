错误处理：带堆栈的那种

早些年我用 github.com/pkg/errors，%+v 一打印调用栈，调试很爽。2026 年我更倾向标准库这套——错误是值，用 errors.Is 和 errors.As 来判断，别再写一堆类型断言。

var ErrNotFound = errors.New("resource not found")

type AppError struct {
    Code    string
    Message string
    Cause   error
}

func (e *AppError) Error() string { return e.Message }
func (e *AppError) Unwrap() error  { return e.Cause }

func readFile(path string) ([]byte, error) {
    data, err := internalRead(path)
    if err != nil {
        return nil, fmt.Errorf("read %s: %w", path, err)
    }
    return data, nil
}

func check(err error) {
    if errors.Is(err, ErrNotFound) { /* 处理 not found */ }
    var ae *AppError
    if errors.As(err, &ae) { /* 拿到具体类型 */ }
}
我的习惯
错误包装用 %w，别用 %v。%v 包装完就断链了，上层 errors.Is 找不到原始错误。这个坑我踩过——线上一个"文件不存在"的错误，上层怎么都判不出来，最后发现中间被 fmt.Errorf("xxx: %v", err) 包了一层。

四个存储客户端怎么选

不是每个服务都要上全套存储，按数据特征选：

flowchart TD A[数据特征?] --> B[临时缓存/会话] A --> C[结构化查询] A --> D[文档/灵活 schema] A --> E[键值高频读] B --> M[Memcached] E --> R[Redis] C --> MY[MySQL] D --> MG[MongoDB] style M fill:#00add8,stroke:#fff,color:#fff

下面四个是我最常用的，DSN 和初始化都是线上验证过的写法。

Memcached

import "github.com/bradfitz/gomemcache/memcache"

client := memcache.New("127.0.0.1:11211")
_ = client.Set(&memcache.Item{Key: "/golang", Value: []byte("hello")})
item, _ := client.Get("/golang")
fmt.Println(string(item.Value))

Redis

redigo 这套按返回类型选 String/Strings/StringMap 的写法，看着绕但必须这么选，选不对类型就乱套：

conn, _ := redis.Dial("tcp", ":6379")
defer conn.Close()

redis.String(conn.Do("set", "firstKey", "firstValue"))            // String
redis.Strings(conn.Do("mget", "firstKey", "k1"))                  // List
redis.StringMap(conn.Do("hgetall", "myhash"))                     // Hash
redis.Strings(conn.Do("smembers", "myset"))                       // Set
redis.Int64Map(conn.Do("zrange", "zset", "0", "-1", "withscores")) // ZSet

MongoDB

MongoDB 是懒建库表的，你不写入它就不创建——这点和 MySQL 不一样，别瞎猜：

ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()

client, _ := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
defer client.Disconnect(ctx)

col := client.Database("firstDB").Collection("firstCol")
col.InsertOne(ctx, bson.D{{"name", "pai"}, {"value", 3.14159}})

MySQL

MySQL 的 DSN 我反复强调：parseTime=True 和 loc=Local 一个都不能少。少一个 DATETIME 字段就 Scan 不进 time.Time，报那种莫名其妙的 converting 错误。

db, err := sql.Open("mysql",
    "root:@(127.0.0.1:3306)/mytest?charset=utf8mb4&parseTime=True&loc=Local")
defer db.Close()

rows, _ := db.QueryContext(ctx, "SELECT v FROM js")
defer rows.Close()
for rows.Next() {
    var name string
    rows.Scan(&name)
}

Memcachedgomemcache无持久化，重启即丢，别拿来存重要数据
Redisgo-redis / redigo按返回类型选对应 helper，别用 interface{} 瞎接
MongoDBmongo-driverdatabase/collection 懒创建，别指望启动就建表
MySQLgo-sql-driverDSN 漏 parseTime 时间字段直接 Scan 失败

strings.Trim 那个万年坑

这是 Go 新手最容易写错的地方，没有之一。你想把路径的 "/api/" 前缀去掉，写 strings.TrimLeft(path, "/api/")——结果它把所有 /、a、p、i 字符当集合逐个吞掉，不是去前缀。

反例
TrimLeft 第二个参数是"字符集合"，不是"前缀字符串"。你传 "/api/"，它会把开头所有 /、a、p、i 全切掉，直到遇到第一个不在集合里的字符。想切固定前缀，永远用 TrimPrefix。
API第二参数含义规则例子
TrimLeft(s, cutset)字符集合连续吞，遇集合外字符停TrimLeft("aabHello","ab") → "Hello"
TrimPrefix(s, prefix)子串整串匹配，只切一次TrimPrefix("aabHello","aa") → "bHello"
TrimPrefix(s, prefix)子串不匹配原样返回TrimPrefix("aabHello","ab") → "aabHello"
 
var s = "aabHello"
strings.TrimLeft(s, "ab")    // "Hello"   字符集合逐个吃
strings.TrimPrefix(s, "aa")  // "bHello"  整串匹配只去一次
strings.TrimPrefix(s, "ab")  // "aabHello" 不匹配原样返回

pprof：性能问题怎么下手

出了性能问题别瞎猜。我的路子是：先看现象判断类型，再挑对应的 profile，拿到火焰图再下结论。分流图如下：

flowchart TD P[性能问题表象] --> Q[先判断问题类型] Q -->|CPU 高| CPUF[CPU Profile 火焰图] Q -->|内存涨| MEM[Memory Profile 看 inuse] Q -->|goroutine 疯涨| GR[Goroutine Profile 找阻塞栈] Q -->|并发卡顿| BLK[Block/Mutex Profile 找锁] CPUF --> T[go tool pprof 出结论] MEM --> T GR --> T BLK --> T style T fill:#00add8,stroke:#fff,color:#fff

抓 trace 的标准姿势：

import "runtime/trace"

trace.Start(os.Stderr)
defer trace.Stop()
go run main.go 2>trace.out   # 注意 2> 重定向
go tool trace trace.out       # 浏览器打开分析
Profile采样率排查什么
CPU每 10ms哪个函数吃 CPU
Memory每 512KB谁在分配、有没有泄漏
Goroutine瞬时快照goroutine 卡在哪个栈
Block默认关谁在等锁、谁在等 channel
Mutex默认关哪个锁被持得最久
实战经验
CPU profile 默认 10ms 采样，特别短的函数采不到。我调过一个热点函数只有 2ms，怎么都采不到，最后 runtime.SetCPUProfileRate(1000) 把采样率调上去才看到。或者换 trace，事件驱动不采样。

四个我反复栽过的坑

  • defer 在循环里：defer 到函数返回才执行，你在 for 循环里 defer Close，文件句柄会堆到函数结束才释放，量大了直接 fd 耗尽。用匿名函数包一层或者手动 Close。
  • for range 变量捕获：1.22 之前循环变量复用，你在 goroutine 里用它，所有人看到的都是最后一个值。升 1.22 或者循环内 i := i。
  • interface 比较 panic：底层是 slice/map/func 的 interface 用 == 比较直接 panic。用 reflect.DeepEqual，或者别比。
  • init 里写复杂逻辑：init 执行顺序不直观，依赖一多就乱。需要初始化就导出一个 Init()，main 里显式调，用 sync.Once 保证只跑一次。

FAQ

Q：TrimLeft 和 TrimPrefix 老记混怎么办？
一句话：Left 配"集合"，Prefix 配"子串"。要去固定前缀永远用 Prefix，别犹豫。

Q：pprof 短函数采不到？
调 SetCPUProfileRate(1000)，或者直接用 trace。

Q：MySQL 时间字段 Scan 不出来？
DSN 漏了 parseTime=True。加上，再配 loc=Local。

Q：defer 在循环里到底怎么改？
把循环体包成匿名函数 func() { ... defer f.Close() }()，或者直接手动 Close，别依赖 defer。
