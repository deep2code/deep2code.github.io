Go sort 包

🏷️ Go 语言总览

sort 包三十秒速览

标准库 sort 包的入口是三方法接口 Len/Less/Swap，实现即可排序；Sort/Slice/Stable 扛常规排序和稳定排序两条线，Search* 负责有序序列的二分查找。1.21 起 slices 泛型化排序成为新项目首选。

  • 三大接口：Len / Less / Swap，实现即可排序。
  • Sort / Slice / Stable 三种排序入口。
  • Search* 系列支持二分查找。
  • 1.21+ 优先走 slices 包的泛型排序函数。

优先用 slices 包

Go 1.21 正式带来 slices 包，泛型化的排序函数比老 sort 包更安全更顺手。pdqsort 运行时如何选算法：

import "slices"

slices.Sort(nums)                    // 升序
slices.SortFunc(nums, func(a, b int) int {
    return b - a                     // 降序
})
slices.SortStable(nums, cmp)        // 稳定排序

idx, found := slices.BinarySearch(nums, 42)

slices.Contains(nums, 42)
slices.Reverse(nums)
slices.Min(nums)
slices.Max(nums)

多字段排序用 Go 1.22+ 的 cmp.Or 把多个比较结果串起来：先比 Age，相同再比 Name。

import (
    "cmp"
    "slices"
)

slices.SortFunc(users, func(a, b User) int {
    return cmp.Or(
        cmp.Compare(a.Age, b.Age),
        cmp.Compare(a.Name, b.Name),
    )
})

底层：pdqsort 算法

Go 1.19+ 的 sort 包用 pdqsort（Pattern-Defeating Quicksort，模式击败快速排序），能识别并击败常见的"反模式"输入。

pdqsort 一句话
它不是单一算法，而是一个"算法路由器"——根据数据规模和模式自动切换插入排序、快速排序或堆排序，兼顾平均性能与最坏情况保证。
算法触发条件时间复杂度空间作用
插入排序元素数 ≤ 12O(n²) 但常数极小O(1)小数据量收尾，最快
快速排序中等规模，递归深度正常O(n log n) 平均O(log n) 栈主力排序算法
堆排序递归深度 > 2·log₂(n)O(n log n) 最坏O(1)兜底防退化

pdqsort 运行时如何根据数据特征选分支：

特殊模式优化：已有序/基本有序走插入排序；大量重复元素走三路分区（荷兰国旗）；锯齿模式用特殊基准选择。

性能 Benchmark

func BenchmarkSortInts(b *testing.B) {
    sizes := []int{100, 1000, 10000, 100000, 1000000}
    for _, size := range sizes {
        b.Run(fmt.Sprintf("size-%d", size), func(b *testing.B) {
            data := make([]int, size)
            for i := 0; i < b.N; i++ {
                b.StopTimer()
                for j := range data { data[j] = rand.Int() }
                b.StartTimer()
                sort.Ints(data)
            }
        })
    }
}

四个常见坑

  • Less 不满足严格弱序：必须非自反、反对称、传递。用 <= 代替 < 会导致结果不确定；浮点 NaN 与任何数比较都 false，会破坏排序。
  • Sort 不是稳定排序：相等元素相对顺序不保证。需要稳定用 Stable（约 1.5x 慢）。
  • 频繁排大切片：排序是 O(n log n)，热路径别重复排。只要 Top K 用堆（container/heap）。
  • 优先泛型排序：slices.Sort() 比 sort.Slice() 快 20-30%（避免接口调用开销）。

FAQ

Q：sort.Sort 和 slices.Sort 性能差多少？
内置类型切片用 slices.Sort 直接走泛型，绕开接口间接调用，通常快 20-30%。新项目无脑 slices。

Q：pdqsort 是稳定排序吗？
不是。它平均 O(n log n)、最坏也 O(n log n)，但不保持相等元素相对顺序。要稳定用 slices.SortStableFunc。

Q：只要 Top K 个元素要全排吗？
不用。堆或部分排序更省；全排再截断是 O(n log n)，堆是 O(n log K)。

我的选择

Go 1.19 起 sort 背后是 pdqsort 这个"算法路由器"：小数据插入排序、中等快速排序、退化切堆排序，平均和最坏都是 O(n log n)。

我 2026 年写排序直接上 slices.Sort/SortFunc/BinarySearch，多字段用 cmp.Or 串联比较，需要稳定再上 SortStableFunc。写 Less 守住严格弱序这条线，结果才确定。
