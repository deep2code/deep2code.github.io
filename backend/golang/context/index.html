Go Context

🏷️ Go 语言

context 是什么，不是什么

很多人学 context 只学了"传超时"，其实它干三件事：管 goroutine 的生死、带请求级的元数据、传取消信号。一句话定位：谁派生的，谁就得负责取消。

它最核心的哲学是协作式取消——它不会硬杀 goroutine，只是发个信号说"活干完了，收工"。goroutine 得自己监听 ctx.Done() 然后主动退出。你不监听，信号就白搭。

我常打的比方
context 就像对讲机。老板（父 context）喊"下班了"，所有下属 goroutine 都能在对讲机里听到。但你要是戴着耳机不听，喊破喉咙也没用——goroutine 泄漏十有八九就是这个原因。

四个派生函数，一张树图

Context 接口就四个方法，看着简单：

type Context interface {
    Deadline() (deadline time.Time, ok bool)
    Done() <-chan struct{}
    Err() error
    Value(key any) any
}

根节点只有两个：context.Background()（一切的起点，永不取消）和 context.TODO()（占位，上线前换掉）。从根上派生子 context 长成长，取消信号只能父→子传，子捅不破父。

HTTP 请求里怎么用

HTTP handler 里拿 r.Context() 当父链，客户端断了或者超时了，下游查数据库跟着取消——不会傻等：

func handler(w http.ResponseWriter, r *http.Request) {
    ctx, cancel := context.WithTimeout(r.Context(), 3*time.Second)
    defer cancel()

    result, err := fetchFromDB(ctx, query)
    if err != nil {
        if ctx.Err() == context.DeadlineExceeded {
            http.Error(w, "timeout", http.StatusGatewayTimeout)
            return
        }
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    json.NewEncoder(w).Encode(result)
}

goroutine 取消用 select 监听 ctx.Done()：

func worker(ctx context.Context, id int) {
    for {
        select {
        case <-ctx.Done():
            fmt.Printf("worker %d stop: %v\n", id, ctx.Err())
            return
        default:
            time.Sleep(500 * time.Millisecond)
        }
    }
}

func main() {
    ctx, cancel := context.WithCancel(context.Background())
    for i := 1; i <= 3; i++ { go worker(ctx, i) }
    time.Sleep(2 * time.Second)
    cancel()
}
血泪教训
最常见的泄漏：你起 goroutine 调 DB，结果 DB 驱动的方法没传 ctx，取消信号卡在半路，goroutine 永远等不回来。我线上见过一个服务 goroutine 涨到 8 万，最后发现就是一个 mysql 查询漏传 ctx。

WithValue：传元数据的正确姿势

把 requestID、userID 这种链路信息塞进 ctx 一路传下去，中间件取出来打日志。注意 key 必须用自定义类型，不然跨包会撞车：

type contextKey string

const RequestIDKey contextKey = "requestID"

func middleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        ctx := context.WithValue(r.Context(), RequestIDKey, generateID())
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

为什么 key 要用自定义类型？因为如果大家都用 string 当 key，A 包和 B 包都用 "userID"，就互相覆盖了。用 type contextKey string 把类型隔开，就不会撞。

底层：三种结构体撑起一切

标准库 context 包靠三个结构体实现全部能力，你看一眼源码就明白了：

结构体干什么关键字段
valueCtx存键值，形成链表key, val
cancelCtx可取消，维护子节点集合done chan, children map, err
timerCtx支持超时/截止时间内嵌 cancelCtx + timer, deadline

取消传播的关键在 propagateCancel。创建子 context 时，它会把自己注册进最近的 cancelCtx 祖先的 children 集合里：

  • 父取消时：递归 close(done)，所有后代同时收到信号。
  • Value 查找：沿 valueCtx 链表 O(n) 往上找，层级一般很浅。

1.21 之后的新东西

1.21 补了 WithoutCancel 和 AfterFunc：

// 父取消时不跟着取消：请求结束后还要做的清理
ctx := context.WithoutCancel(parentCtx)

// 取消后自动执行回调
stop := context.AfterFunc(ctx, func() {
    log.Println("context cancelled, cleaning up...")
})
defer stop()

这个 WithoutCancel 我用得很多——比如请求结束了我还要异步写个审计日志，总不能请求一断日志也不写了。以前得自己包一层，现在标准库直接给。

errgroup：扇出的正确姿势

想同时扇出一堆任务、"一个挂全员撤"，手写 select 很容易翻车。直接用 x/sync/errgroup：

g, ctx := errgroup.WithContext(r.Context())
g.Go(func() error { return fetchA(ctx) })
g.Go(func() error { return fetchB(ctx) })
g.Go(func() error { return fetchC(ctx) })

if err := g.Wait(); err != nil {
    http.Error(w, err.Error(), http.StatusInternalServerError)
    return
}
别忘
丢进 g.Go 的每个任务都得听 ctx.Done()，不然"全量取消"就是句口号。errgroup 只是帮你收错误和传 ctx，任务本身还得自己会退。

泄漏怎么查

最常见的泄漏就是：创建了可取消 context 却没调 CancelFunc，timer 和监听 goroutine 一直挂到超时才释放。

// 错：cancel 被丢了
ctx, _ := context.WithTimeout(req.Context(), 5*time.Second)

// 对：defer cancel 立即释放
ctx, cancel := context.WithTimeout(req.Context(), 5*time.Second)
defer cancel()

测试里我用 goleak.VerifyNone(t) 自动检测 goroutine 泄漏，CI 一跑就知道谁没退干净。

我的五条铁律

  • cancel() 永远 defer：cancel 幂等，多调无害，漏调就泄漏。
  • ctx 放函数第一个参数：func Do(ctx context.Context, ...)，别塞 struct 里。
  • nil context 是禁区：拿不准就 context.TODO()。
  • key 用自定义类型：type contextKey string，别用裸 string 字面量。
  • Value 只装请求级小对象：业务参数走函数参数，别什么都往 ctx 里塞。

FAQ

Q：context 能存数据库连接吗？
不该。它只存请求级的元数据（traceID、认证信息）。连接池这种共享资源用依赖注入。

Q：WithValue 会慢吗？
单次查找是 O(n) 链表遍历，但层级一般很浅（不到 10 层），可以忽略。别在 ctx 里塞大对象。

Q：父取消了子还能用吗？
不能。父取消会递归关所有后代的 done channel。要脱离就用 WithoutCancel。

Q：goroutine 泄漏怎么发现？
pprof 抓 goroutine profile。正常服务 goroutine 数应该平稳，只涨不跌就是泄漏了。

收口

context 是 Go 并发的红绿灯。记住三条：defer cancel() 必写、ctx 当第一参数、Value 只放小元数据。做到这三条，90% 的 goroutine 泄漏和请求悬挂都跟你没关系。
