Node.js 深度原理：事件循环为什么快？

🏷️ Node.js

Node.js 单线程为什么能扛高并发？不是因为它真的单线程，是因为事件循环 + 非阻塞 IO，一个线程处理几万个连接。这篇讲透底层原理。

核心原理1：事件循环原理

Node.js 不是真单线程，JS 引擎是单线程，IO 操作扔给线程池做，完成后把回调放到事件队列，事件循环挨个执行。

flowchart LR A[事件循环] --> B[执行 JS 代码] B --> C[遇到 IO 操作] C --> D[扔给线程池] D --> E[JS 继续执行别的] E --> F[IO完成 回调进队列] F --> G[事件循环执行回调]

['阶段', '做什么', '常见宏任务']

阶段 做什么 常见宏任务
timers 执行 setTimeout/setInterval setTimeout
pending callbacks 执行系统回调 TCP 错误
idle/prepare 内部使用
poll 获取新 IO 事件 读文件、网络请求
check 执行 setImmediate setImmediate
close callbacks 执行 close 事件 socket.on("close")

核心原理2：非阻塞 IO 原理

传统多线程模型是一个连接一个线程，IO 阻塞就等着。Node.js 非阻塞，IO 发起后不等，继续处理别的，完成了再通知。

flowchart TD A[传统多线程] --> B[连接1 → 线程1 → IO阻塞等待] A --> C[连接2 → 线程2 → IO阻塞等待] D[Node.js] --> E[一个线程] E --> F[连接1 IO → 不等] E --> G[连接2 IO → 不等] E --> H[都完成了再处理]

['对比', '多线程阻塞', 'Node.js 非阻塞']

对比项 多线程阻塞 IO Node.js 非阻塞
模型 一连接一线程 单线程事件循环
并发数 几千 几万~几十万
内存占用 每个线程几 MB 一个线程几 MB
适合场景 CPU 密集 IO 密集高并发

核心原理3：线程池原理

Node.js 不是所有操作都单线程，文件 IO、DNS 查询、加密这些 CPU 密集操作，是扔给 libuv 线程池（默认 4 个）做的。

flowchart LR A[主线程] --> B[JS 代码] A --> C[文件IO] A --> D[DNS查询] A --> E[加密] C --> F[线程池 4个线程] D --> F E --> F F --> G[完成后 回调进事件队列]

['操作', '在哪执行', '是否阻塞事件循环']

操作 在哪执行 是否阻塞事件循环
JS 代码 主线程 是，死循环会卡死
网络 IO 事件驱动 否
文件 IO libuv 线程池 否
加密压缩 libuv 线程池 否
DNS 查询 libuv 线程池 否

新手最容易踩的坑

❌
避坑指南
  • 不要在主线程写死循环或者 CPU 密集计算，会直接卡死整个事件循环
  • 回调地狱用 async/await 解决，不要嵌套一堆回调
  • 线程池默认 4 个，文件 IO 多了可以调大 UV_THREADPOOL_SIZE
  • CPU 密集型任务不要用 Node.js，用 worker_threads 或者直接用 Go/Java
