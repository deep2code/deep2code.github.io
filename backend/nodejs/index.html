Node.js 总览

🏷️ Node.js

我为什么写这一系列

我从 2014 年开始用 Node.js 写后端，那会儿 Express 4 刚出，回调地狱是每个 JS 后端程序员的噩梦。十多年过去，Node.js 从一个"前端玩具"进化成了成熟的后端运行时。

这一系列不是教程——我假设你已经会写 JS，也能跑起一个 Express 服务。我想讲的是那些面试不问、文档不写、但线上出事才会懂的东西：事件循环到底怎么转、NestJS 的 DI 容器背后在干什么、V8 为什么会把你的函数优化掉又 deopt、内存泄漏怎么在生产环境抓。

Node.js 到底是什么

一句话：V8 引擎 + libuv 事件循环 + 内置模块。它不是一门语言，也不是一个框架，是一个让 JavaScript 能跑在服务器上的 runtime。核心设计就一个字——单线程异步。你写的业务代码跑在一个线程里，靠事件循环把 IO 操作甩给操作系统和线程池，自己只负责调度回调。

flowchart TD V8[V8 引擎 执行 JS 代码] --> LOOP[libuv 事件循环 单线程调度] LOOP --> POOL[libuv 线程池 4个 默认] LOOP --> OS[操作系统内核 异步IO] POOL --> FS[文件读写] POOL --> DNS[DNS 解析] POOL --> CRYPTO[加密计算] OS --> NET[网络 socket] style V8 fill:#00add8,stroke:#fff,color:#fff style LOOP fill:#dc382d,stroke:#fff,color:#fff

这个模型最大的好处是没有线程切换开销，一个进程就能扛住几万并发连接。最大的坑也是它——你写的任何一段同步 CPU 密集代码，都会卡住整个事件循环。一个 JSON.parse 10MB 的字符串，所有请求都得排队等它跑完。

Node.js 适合什么，不适合什么

干了这么多年，我的判断很简单：IO 密集型服务选 Node.js，CPU 密集型服务别选。API 网关、BFF、实时推送、SSR 渲染——这些 Node.js 干得又快又好。但你要是写视频转码、大数据计算、机器学习推理，老老实实去用 Go 或 Rust。

一个判断标准
如果你的服务 80% 的时间在等数据库、等下游 RPC、等网络响应——Node.js 是最优解之一。如果 80% 的时间在算——换语言。别跟事件循环较劲。

版本怎么选

Node.js 官方每年 4 月发新主线，10 月转 LTS。2026 年我团队的标准：

版本状态值得关注建议
Node.js 24LTS原生 type-stripping，V8 13.x新项目直接上
Node.js 22LTS 维护中WebSocket 客户端内置存量项目可跟
Node.js 20安全维护—低于它必须升
别用奇数版本跑生产
Node.js 的偶数版本才转 LTS。21、23 这种奇数版本只维护半年，别图新特性往生产上怼。我见过团队用 Node 23 上线，三个月后官方停止维护，安全补丁都没人发。

第一个 Node.js 服务

2026 年了，Node.js 24 支持直接跑 TypeScript 文件（type stripping），连 ts-node 都不用装了：

# 装 Node.js 24 LTS
nvm install 24
nvm use 24

# 初始化项目
mkdir my-api && cd my-api
npm init -y
npm i fastify

# 直接写 .ts 文件，node 直接跑
node server.ts
// server.ts —— 2026 年的 Hello World
import Fastify from 'fastify'

const app = Fastify({ logger: true })

app.get('/health', async () => ({ status: 'ok', uptime: process.uptime() }))

app.get('/users/:id', async (request, reply) => {
  const { id } = request.params as { id: string }
  return { id, name: `user-${id}` }
})

app.listen({ port: 3000, host: '0.0.0.0' })
  .then(() => app.log.info('server on :3000'))

注意 process.params 要手动断言类型——原生 type stripping 不做类型检查，只做语法擦除。要类型检查还是得跑 tsc --noEmit。

FAQ

Q：Node.js 和 Bun 怎么选？
2026 年 Bun 1.2 已经挺能打了，启动快、内置测试和打包。但生产环境我还是选 Node.js——生态兼容性、调试工具链、招人成本摆在那。Bun 适合 CLI 工具和脚本，核心服务再等等。

Q：Node.js 单线程怎么利用多核？
用 cluster 模块或 PM2。主进程 fork 多个 worker，每个 worker 跑一个 Node 实例，内核做负载均衡。这是 Node.js 利用多核的标准做法，后面性能优化那篇会细讲。

Q：回调地狱真的还有吗？
2026 年基本没了。async/await 是 ES2017 的东西，现在谁还写嵌套回调？但 Promise 链的错误处理、未捕获 rejection 这些坑还在，事件循环那篇会讲。

Q：NestJS 是不是太重了？
看项目大小。一个三五个接口的小服务，Express 或 Fastify 直接写最爽。但如果你有 20 个以上模块、要团队协作、要写测试——NestJS 的约束反而是优势，它逼着你把代码组织好。

我的结论

Node.js 这十年最大的变化不是语法，是工程化成熟了。TypeScript 把类型安全补上了，NestJS 把架构约束补上了，Pino/Vitest/clinic.js 把可观测性补上了。2026 年用 Node.js 写后端，已经不是"凑合能用"，而是正经的工程选择。
