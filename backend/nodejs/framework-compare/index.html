Express vs NestJS vs Fastify

🏷️ Node.js 总览

三个框架，三种哲学

这三个框架我都在生产环境跑过。Express 是"你想怎么写就怎么写"，Fastify 是"快且规范"，NestJS 是"我来帮你定规矩"。没有绝对的好坏，只有适不适合你的项目。

Fastify 比 Express 快 50% 是真的，但这是空路由。真实业务里你的瓶颈在数据库查询、外部 API 调用、JSON 序列化。框架这 50% 的差距，在你真实接口里可能只占 5% 的总延迟。选型别只看性能。

三个框架的代码对比

同一个接口——获取用户列表——三个框架各写一遍，你感受一下差异：

Express 5：

import express from 'express'
const app = express()
app.use(express.json())

app.get('/users', async (req, res) => {
  const users = await db.users.findMany({
    take: Number(req.query.limit) || 20,
  })
  res.json({ data: users, total: users.length })
})

app.listen(3000)

Fastify 5：

import Fastify from 'fastify'
const app = Fastify({ logger: true })

// 声明 schema，自动校验请求 + 序列化响应
app.get('/users', {
  schema: {
    querystring: {
      type: 'object',
      properties: { limit: { type: 'number', default: 20 } },
    },
    response: {
      200: {
        type: 'object',
        properties: {
          data: { type: 'array' },
          total: { type: 'number' },
        },
      },
    },
  },
  handler: async (req) => {
    const users = await db.users.findMany({ take: req.query.limit })
    return { data: users, total: users.length }
  },
})

app.listen({ port: 3000 })

NestJS 11：

// users.controller.ts
@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get()
  findAll(@Query('limit', ParseIntPipe) limit = 20) {
    return this.usersService.findAll(limit)
  }
}

// users.service.ts
@Injectable()
export class UsersService {
  constructor(private prisma: PrismaService) {}

  async findAll(limit: number) {
    const users = await this.prisma.user.findMany({ take: limit })
    return { data: users, total: users.length }
  }
}

看出区别了吧？Express 最自由但全靠自觉；Fastify 用 schema 把请求校验和响应序列化管起来了；NestJS 把业务逻辑拆到 Service，Controller 只负责协议层。

NestJS 底层是 Express 还是 Fastify

很多人不知道——NestJS 默认用 Express，但你可以一键切到 Fastify。性能差距前面表格里也看到了，同样的 NestJS 代码，换 Fastify 底层 QPS 能涨 40%。

// main.ts —— 默认 Express
import { NestFactory } from '@nestjs/core'
import { AppModule } from './app.module'
const app = await NestFactory.create(AppModule)

// 切 Fastify
import { NestFactory } from '@nestjs/core'
import { FastifyAdapter } from '@nestjs/platform-fastify'
import { AppModule } from './app.module'
const app = await NestFactory.create(AppModule, new FastifyAdapter())
切 Fastify 要注意中间件兼容性
Express 的中间件 API 和 Fastify 的不完全兼容。如果你用了大量 Express 生态中间件（比如 express-session），切 Fastify 会报错。新项目可以直接 Fastify，老项目切之前先检查中间件依赖。

我的选型决策树

FAQ

Q：Express 5 值得升级吗？
Express 5 重写了路由层，修了一堆 bug，性能略好。但如果你现在 Express 4 跑得好好的，不急。Express 5 有 breaking change——路由通配符语法变了，老代码可能要改。

Q：Fastify 能替代 Express 吗？
90% 场景可以。Fastify 兼容大部分 Express 中间件。但如果你重度依赖 Express 生态的某个老牌中间件（比如某些古老的 upload 库），可能有坑。新项目选 Fastify 没问题。

Q：NestJS 是不是太重了？
看团队。1 个人的项目用 NestJS 确实有负担。但团队超过 5 人，NestJS 的架构约束帮你省的代码 review 时间，远大于你学它的时间。

Q：有没有更轻的选择？
Hono 很火，比 Fastify 还快，边缘运行时（Cloudflare Workers）支持好。但生态还年轻，企业级选型我再观望一年。2026 年的生产首选还是 Fastify/NestJS。

我的结论

别在论坛上问"Express 和 Fastify 哪个快"——这就像问"筷子和叉子哪个好用"。Express 胜在生态最大、招人最容易；Fastify 胜在性能和 Schema 驱动；NestJS 胜在架构纪律和 DI 容器。

我团队现在的做法：新项目优先 NestJS 11（底层切 Fastify），轻量服务用 Fastify 5，老 Express 服务维护到自然退役。下一篇我们讲性能优化——不管用哪个框架，V8 和事件循环的坑都躲不掉。
