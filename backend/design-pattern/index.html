设计模式入门：别上来就背 23 种

🏷️ 设计模式

一上来就学 23 种设计模式，背完就忘，工作里根本用不上。其实常用的就那么 7、8 种，先把这几种搞懂，遇到问题自然会用。

flowchart LR A[设计模式] --> B[创建型] A --> C[结构型] A --> D[行为型] B --> B1[单例/工厂] C --> C1[适配器/装饰器] D --> D1[策略/观察者]

new 对象太乱，到处都是

⚠️
你遇到的问题

代码里到处 new XXXService()，换个实现要改一堆地方。

怎么解决？用工厂模式，对象创建统一放到工厂里，换实现只改工厂。

// 坏例子
PayService pay = new AlipayService();

// 好例子：工厂模式
PayService pay = PayFactory.getPay("alipay");

if else 太多，改不动

⚠️
你遇到的问题

一个支付接口，if(alipay) 走支付宝，if(wechat) 走微信，加个渠道要改一大段。

怎么解决？用策略模式，每个渠道一个类，实现同一个接口，加渠道只要加新类。

// 策略模式
interface PayStrategy {
  void pay(BigDecimal amount);
}

class AlipayStrategy implements PayStrategy { ... }
class WechatStrategy implements PayStrategy { ... }

最常用的 6 种设计模式

模式 类型 解决什么问题 什么时候用
单例 创建型 全局只有一个实例 配置类、连接池
工厂 创建型 对象创建解耦 多种实现要切换
策略 行为型 消除 if else 多种算法可互换
观察者 行为型 事件通知 消息队列、事件总线
适配器 结构型 兼容不兼容接口 接入第三方SDK
装饰器 结构型 动态加功能 IO流、中间件

新手最容易踩的坑

❌
避坑指南
  • 不要为了用设计模式而用设计模式，先写能跑的代码，发现不好改了再重构
  • 设计模式是解决问题的方案，不是目标，遇到 if else 爆炸了再想策略模式
  • 单例模式要注意线程安全，Java 用双重检查锁，Python 用模块级单例
  • 23 种设计模式里，工作中真正常用的不超过 8 种，先把这几种搞透
