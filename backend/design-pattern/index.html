设计模式：从你遇到的问题出发

🏷️ 设计模式

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及设计模式怎么帮你解决。

flowchart LR A[代码重复难维护] --> B[用合适设计模式] B --> C[代码易扩展易维护]

1. 改一个功能要改 N 个地方

你遇到的问题

你加个支付方式，要改订单、退款、对账三个地方。

怎么解决？用策略模式，把不同支付方式封装成独立策略。

2. 对象创建太复杂

你遇到的问题

一个类有很多参数，new 的时候要传一堆。

怎么解决？用工厂模式，把创建逻辑封装起来。

3. 代码之间耦合太重

你遇到的问题

改 A 模块影响了 B 模块，不知道哪就坏了。

怎么解决？用观察者模式，模块之间松耦合。

常用设计模式

模式解决什么问题场景
策略模式多算法切换多种支付方式
工厂模式对象创建复杂根据类型创建对象
观察者模式对象间通知事件发布订阅
单例模式全局唯一对象配置、连接池
新手最容易踩的坑
  • 不要为了模式而模式设计模式是解决问题的，不是炫技的。
  • 先写能跑的代码不要上来就设计模式，先跑起来再重构。
