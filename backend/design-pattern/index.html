设计模式深度原理：为什么要这些模式？

🏷️ 设计模式

设计模式不是背的，是解决特定问题的套路。单例、工厂、观察者、策略模式，每个解决什么问题？底层原理是什么？这篇讲透。

核心原理1：单例模式：为什么要一个实例？

有些对象整个系统只需要一个实例，比如配置中心、连接池，多创建一个浪费资源，单例就是保证只有一个实例。

flowchart TD A[普通类] --> B[每次 new 新实例] B --> C[浪费内存] D[单例模式] --> E[构造方法私有] E --> F[静态方法 getInstance] F --> G[全局唯一实例]
实现方式 线程安全 问题
饿汉式 类加载就创建 没有懒加载，浪费内存
懒汉式 第一次用才创建 线程不安全，要加锁
双重检查锁 两次检查，加锁 指令重排可能有问题
静态内部类 类加载机制保证 推荐用，线程安全又懒加载

核心原理2：工厂模式：为什么要 new 出来？

直接 new 类，代码写死了，改实现要改所有 new 的地方。工厂模式把创建对象的逻辑集中，改一个地方就行。

flowchart LR A[客户端] --> B[工厂类] B --> C[创建对象A] B --> D[创建对象B] B --> E[创建对象C] C --> F[客户端不用管怎么创建]
工厂类型 原理 适用场景
简单工厂 一个工厂类 if/else 创建 对象少，简单场景
工厂方法 每个产品一个工厂类 产品多，扩展开放
抽象工厂 创建一族相关产品 产品族，比如跨 UI 主题

核心原理3：观察者模式：事件怎么通知？

一个对象状态变了，要通知很多依赖它的对象，不用轮询，用观察者模式：订阅了的对象，状态变了自动收到通知。

flowchart TD A[主题 Subject] --> B[维护观察者列表] B --> C[添加观察者] B --> D[状态变化] D --> E[通知所有观察者] E --> F[观察者1 更新] E --> G[观察者2 更新]
角色 作用 例子
Subject 主题，维护观察者列表 事件总线
Observer 观察者，收到通知更新 UI 刷新
应用场景 事件驱动、消息通知、响应式 Vue 响应式、消息队列

新手最容易踩的坑

❌
避坑指南
  • 设计模式不是越多越好，简单场景别硬套，过度设计反而乱
  • 单例注意线程安全，特别是懒汉式，高并发下要双重检查锁
  • 工厂模式不是为了 new 而 new，是为了解耦创建和使用
  • 观察者模式注意内存泄漏，不用了要及时取消订阅
