Java 深度原理：JVM 内存模型

🏷️ Java

Java 为什么"一次编写到处运行"？JVM 内存怎么分的？GC 怎么工作的？这篇从底层讲透 Java。

核心原理1：JVM 内存区域划分

JVM 把内存分成好几块：堆、栈、方法区、程序计数器，每块存的东西不一样，回收策略也不一样。

flowchart TD A[JVM 内存] --> B[线程共享] A --> C[线程私有] B --> B1[堆 存对象 GC主要区域] B --> B2[方法区 类信息常量] C --> C1[虚拟机栈 方法栈帧] C --> C2[程序计数器 当前行号] C --> C3[本地方法栈 Native]

JVM 内存区域

内存区域 存什么 是否GC
堆 对象实例、数组 是，GC 主战场
虚拟机栈 方法栈帧、局部变量 否，随线程销毁
方法区 类信息、常量、静态变量 是，GC 少
程序计数器 当前执行字节码行号 否，唯一不会OOM的区域

核心原理2：垃圾回收 GC 原理

GC 不是全部扫一遍，是分代回收：新生代朝生夕死用复制算法，老年代活得久用标记整理。

flowchart TD A[新对象] --> B[Eden区] B -->|Minor GC| C[Survivor 0] C -->|存活| D[Survivor 1] D -->|年龄到15| E[老年代] E -->|Full GC| F[标记整理]

JVM 分代 GC

GC 类型 回收区域 触发时机
Minor GC 新生代 Eden+Survivor Eden 满了
Major GC 老年代 老年代满了
Full GC 整个堆+方法区 老年代满/方法区满/System.gc()

核心原理3：类加载机制

Java 类不是一开始就全部加载，是用到才加载，分加载、验证、准备、解析、初始化五步。

flowchart LR A[加载] --> B[验证] B --> C[准备] C --> D[解析] D --> E[初始化] E --> F[使用] F --> G[卸载]

类加载生命周期

阶段 做什么 关键
加载 找 class 文件读入 ClassLoader
验证 检查 class 合法性 安全
准备 静态变量分配内存赋零值 不是最终值
初始化 执行静态代码块 赋真正的值

新手最容易踩的坑

❌
避坑指南
  • OOM 别慌，先看是堆溢出、栈溢出还是方法区溢出，对症下药
  • 不要手动调用 System.gc()，会触发 Full GC，停顿很久
  • 类加载器双亲委派模型要懂，不然写不出自定义类加载器
  • ThreadLocal 用完一定要 remove，不然内存泄漏
