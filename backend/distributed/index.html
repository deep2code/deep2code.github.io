分布式系统入门：从单机到集群

🏷️ 分布式

单机扛不住了，要拆成分布式，但一拆就出各种问题：数据不一致、服务挂了、网络超时。这篇讲分布式核心概念，从为什么要拆到常见问题怎么解决。

flowchart TD A[单机系统] --> B[性能瓶颈] B --> C[垂直拆分] C --> D[水平拆分] D --> E[分布式问题] E --> F[一致性] E --> G[可用性] E --> H[容错]

单机扛不住了怎么办

⚠️
你遇到的问题

用户量上来了，一台服务器 CPU 跑满，数据库也连不上了。

怎么解决？先垂直拆分：把不同功能拆成不同服务，再水平拆分：每个服务部署多个实例。

# 垂直拆分
用户服务、订单服务、支付服务分开部署

# 水平拆分
用户服务部署 3 个实例，负载均衡分发

分布式了，数据不一致怎么办

⚠️
你遇到的问题

下单成功了，库存没扣减，用户投诉。

怎么解决？用分布式事务保证，或者最终一致，用消息队列异步补偿。

# 最终一致：下单后发消息扣库存
order_service -> mq -> inventory_service
# 库存失败了，重试 + 人工补偿

CAP 三选二

特性 含义 牺牲哪个 适用场景
CP 一致性 + 分区容错 可用性 金融、账务
AP 可用性 + 分区容错 一致性 社交、Feed流
CA 一致性 + 可用性 分区容错 单机、小系统

分布式常见问题

问题 现象 解决方案
网络超时 请求发出去了，不知道成没成 重试 + 幂等设计
服务挂了 调用失败，接口报错 熔断 + 降级 + 兜底
数据重复 消息重复消费 幂等表，用唯一ID去重

新手最容易踩的坑

❌
避坑指南
  • 能不用分布式就不用，单机先优化到极致再说
  • 所有远程调用都要设超时，不然一个服务挂了整个系统都卡住
  • 重试一定要加幂等，不然重复请求会出问题
  • 分布式事务优先选最终一致，强一致代价太大
