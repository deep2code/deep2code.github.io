接口限流：从你遇到的问题出发

🏷️ 限流

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及限流怎么帮你解决。

flowchart LR A[请求] --> B{超过限制?} B -->|否| C[正常处理] B -->|是| D[拒绝请求]

1. 接口被刷爆了

你遇到的问题

有人写脚本每秒调你接口几百次，数据库直接挂了。

怎么解决？加限流，超过阈值就拒绝请求。

2. 怎么实现限流

你遇到的问题

知道要限流，不知道用什么方法实现。

怎么解决？常用固定窗口、滑动窗口、令牌桶、漏桶四种算法。

3. 分布式服务怎么限流

你遇到的问题

你有多个服务实例，怎么全局限流？

怎么解决？用 Redis 存计数，所有实例共享同一个限流计数器。

限流算法对比

算法特点适合
固定窗口简单一般场景
滑动窗口平滑精度要求高
令牌桶允许突发流量大部分场景
漏桶平滑流出保护下游
新手最容易踩的坑
  • 限流要分级不同接口限不同的流，不要一刀切。
  • 限流返回要友好不要返回 500，返回 429 + 提示信息。
