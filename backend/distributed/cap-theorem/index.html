CAP 与 BASE 理论

CAP 定理

分布式系统三个特性：一致性（Consistency）、可用性（Availability）、分区容错性（Partition tolerance）。三者最多满足两个。

特性说明
一致性 C所有节点同时看到相同的数据
可用性 A每个请求都能收到响应
分区容错 P网络分区时系统继续运行
graph TD A[分布式系统] --> B[CP 选择] A --> C[AP 选择] B --> B1[一致性优先] B --> B2[牺牲可用性] B --> B3[例：Zookeeper、etcd] C --> C1[可用性优先] C --> C2[牺牲一致性] C --> C3[例：Cassandra、DynamoDB]

CP vs AP 怎么选

场景选择原因
金融交易CP钱不能错
社交 FeedAP晚几秒看到没关系
配置中心CP配置不能错
商品详情AP价格晚几秒更新没关系

BASE 理论

  • Basically Available：基本可用
  • Soft state：软状态，允许中间状态
  • Eventually consistent：最终一致性

大部分互联网业务都是 BASE，最终一致性就够了。
