Go gRPC：从你遇到的问题出发

🏷️ Go gRPC

这篇不讲理论，就讲你做项目时会遇到的真实问题，以及Go gRPC怎么帮你解决。

flowchart LR A[写 proto] --> B[生成 Go 代码] B --> C[写服务端] C --> D[写客户端]

1. Go 服务之间怎么调用

你遇到的问题

你有两个 Go 服务，互相调用，用 HTTP+JSON 太麻烦。

怎么解决？用 gRPC，定义 proto 文件，自动生成代码，调用像本地函数。

2. 接口定义不统一

你遇到的问题

两个服务的接口字段经常对不上，联调半天。

怎么解决？proto 文件统一定义，改了自动重新生成，不会错。

3. 传输太慢

你遇到的问题

内部服务调用，JSON 太大，序列化反序列化慢。

怎么解决？gRPC 用 protobuf 二进制，又小又快。

gRPC 四种调用模式

模式说明
一元调用普通请求响应
服务端流服务端返回流
客户端流客户端发送流
双向流双向流
新手最容易踩的坑
  • 超时一定要设客户端调用一定要设超时，不然服务挂了会一直等。
  • 错误处理要规范用 gRPC 标准错误码，不要自己瞎定义。
