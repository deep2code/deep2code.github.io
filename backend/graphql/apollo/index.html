Apollo Server 与 Client 实战

🏷️ GraphQL

为什么是 Apollo，不是裸 graphql-js

上一篇我们用 startStandaloneServer 跑了个最小服务。真上生产，你要处理鉴权、插件、上传、订阅、错误格式化、指标采集——这些 graphql-js 都不管。Apollo Server 4.x 把这些全做成了插件体系，而且 4.x 重写了底层，不再依赖 express，性能比 3.x 好一截。

这篇我按"服务端搭起来 → 加 DataLoader → 接 React/Vue 客户端 → 缓存和订阅"的顺序走，每段都是我项目里的真实代码裁剪。

Apollo Server 4.x 标准工程结构

2026 年我新建的 Apollo 项目都是这套结构，按功能模块拆 schema，不堆在一个文件里：

src/
  schema/
    user.ts        # User type + resolver
    post.ts        # Post type + resolver
    index.ts       # 合并 typeDefs/resolvers
  context.ts       # 每个请求的 context
  datasource.ts    # 数据访问层
  server.ts        # 启动入口
  plugins.ts       # 插件（日志/埋点）

入口长这样，重点是 context 工厂和 plugins：

// server.ts
import { ApolloServer } from '@apollo/server';
import { expressMiddleware } from '@apollo/server/express4';
import express from 'express';
import { typeDefs, resolvers } from './schema';

const app = express();
const server = new ApolloServer({
  typeDefs,
  resolvers,
  formatError: (err) => {
    // 线上别把 stack 泄露给前端
    if (err.extensions?.code === 'INTERNAL_SERVER_ERROR') {
      return new Error('Internal server error');
    }
    return err;
  },
});
await server.start();

app.use('/graphql', express.json(), expressMiddleware(server, {
  context: async ({ req }) => ({
    user: authenticate(req.headers.authorization),
    loaders: createLoaders(), // 每请求新建，关键！
  }),
}));
app.listen(4000, () => console.log('🚀 on :4000'));
Apollo Server 3 → 4 的迁移大坑
很多老教程还在用 new ApolloServer({ typeDefs, resolvers }); server.applyMiddleware()。4.x 必须先 await server.start() 再挂中间件，而且 standalone 和 express 分了两个包。跟着老文档抄会直接报 You need to call the .start() method，别怀疑人生。

DataLoader：批量+缓存，GraphQL 的救星

刚学 GraphQL 时写 resolver 很容易这样：

// 反面教材：N+1
const resolvers = {
  Post: {
    author: async (post) => await db.users.findById(post.authorId),
  },
};

查 100 篇文章，就发 100 次查用户的 SQL。DataLoader 的思路是：把同一帧 tick 里的 id 攒起来，合并成一次 WHERE id IN (...) 查询。

// datasource/userLoader.ts
import DataLoader from 'dataloader';

export function createUserLoader() {
  return new DataLoader(async (ids: readonly string[]) => {
    const users = await db.users.find({ id: { $in: [...ids] } });
    // 关键：返回顺序必须和 ids 一一对应
    return ids.map((id) => users.find((u) => u.id === id) || new Error('未找到'));
  });
}
// resolver 里用 loader
const resolvers = {
  Post: {
    author: (post, _args, { loaders }) =>
      loaders.user.load(post.authorId),
  },
};
flowchart LR subgraph 没有DataLoader P1[post1] --> U1[查询user(1)] P2[post2] --> U2[查询user(2)] P3[post3] --> U3[查询user(3)] end subgraph 有DataLoader Q1[3个load()调用] --> BATCH[攒一批] BATCH --> ONE[SELECT * FROM users WHERE id IN (1,2,3)] end style ONE fill:#10b981,stroke:#fff,color:#fff

DataLoader 还自带"单请求内"的缓存：同一帧里 load(1) 调两次，第二次直接命中内存。但这个缓存是每请求一个实例的，所以前面 context 里一定要 createLoaders() 新造，别用单例——不然 A 用户的请求会读到 B 用户刚缓存的数据，越权。这个坑第四篇还会展开。

Apollo Client：React 集成

前端这边我用 Apollo Client 3.x，React 官方支持最好。装依赖：

npm install @apollo/client graphql

初始化 Client，注意 uri 和 cache：

// apollo/client.ts
import { ApolloClient, InMemoryCache, HttpLink } from '@apollo/client';

const client = new ApolloClient({
  link: new HttpLink({
    uri: 'https://api.example.com/graphql',
    credentials: 'include',
  }),
  cache: new InMemoryCache({
    typePolicies: {
      Query: {
        fields: {
          posts: {
            merge: false, // 分页用自定义合并策略
          },
        },
      },
    },
  }),
});

React 组件里用 useQuery，loading/error/data 三态全包了：

import { useQuery, gql } from '@apollo/client';

const GET_POSTS = gql`
  query GetPosts($limit: Int!) {
    posts(limit: $limit) {
      id
      title
      author { name }
    }
  }
`;

function PostList() {
  const { data, loading, error } = useQuery(GET_POSTS, {
    variables: { limit: 10 },
  });
  if (loading) return <p>加载中...</p>;
  if (error) return <p>出错了: {error.message}</p>;
  return data.posts.map((p) => <div key={p.id}>{p.title}</div>);
}

Vue 集成

Vue 生态官方支持是 @apollo/client + @vue/apollo-composable：

import { ApolloClient, InMemoryCache, createHttpLink } from '@apollo/client/core';
import { createApolloProvider } from '@vue/apollo-composable';

const client = new ApolloClient({
  link: createHttpLink({ uri: '/graphql' }),
  cache: new InMemoryCache(),
});
export const apolloProvider = createApolloProvider();

// main.ts
app.use(apolloProvider, { defaultClient: client });
<script setup lang="ts">
import { useQuery } from '@vue/apollo-composable';
const { result, loading, error } = useQuery(gql`
  query { posts { id title } }
`);
</script>

归一化缓存：Apollo Client 的杀手锏

这是 Apollo Client 最香的部分，也是新手最容易绕晕的。普通 REST 缓存是"按 URL 存响应"，同一个 User 在两个接口里要存两份。Apollo Client 按 对象 id 归一化：

// 第一次查询
query { user(id:1){ name } }
// 第二次查询
query { post(id:10){ author{ name } } }
// 两个查询的 author.id 都是 1，自动命中同一份缓存

默认靠 __typename + id 拼成 key（如 User:1）。如果你的主键不叫 id（比如叫 _id），要在 typePolicies 里指认：

new InMemoryCache({
  typePolicies: {
    User: { keyFields: ['_id'] },
  },
});
写操作后怎么刷新缓存
Mutation 返回新对象时，Apollo 会按 id 自动写回缓存——这就是为什么 createPost 要返回完整的新 Post 对象。如果你 mutation 没返回数据，就得手动 client.cache.evict() 或 refetchQueries: [{ query: GET_POSTS }]。别在 mutation 里只返回个 boolean，前端没法更新缓存。

错误处理：两层错误

Apollo Client 的错误分两层：网络层和 GraphQL 业务层。useQuery 的 error 默认两者都包，但你想分开处理，要用 errorPolicy：

const { error } = useQuery(GET_USER, {
  errorPolicy: 'all', // 即使部分字段报错也返回 data
  onError: ({ graphQLErrors, networkError }) => {
    if (graphQLErrors) {
      graphQLErrors.forEach(({ message, extensions }) => {
        if (extensions?.code === 'UNAUTHENTICATED') {
          router.push('/login');
        }
      });
    }
  },
});

服务端抛错要用 Apollo 自带的 GraphQLError，带上 extensions.code，前端才能结构化判断：

import { GraphQLError } from 'graphql';

throw new GraphQLError('未找到该用户', {
  extensions: { code: 'NOT_FOUND' },
});

Subscription 实时推送

订阅走 WebSocket，不能复用 HTTP link。要装 graphql-ws：

npm install graphql-ws
import { split, HttpLink } from '@apollo/client';
import { GraphQLWsLink } from '@apollo/client/link/subscriptions';
import { createClient } from 'graphql-ws';

const httpLink = new HttpLink({ uri: '/graphql' });
const wsLink = new GraphQLWsLink(createClient({ url: 'ws://localhost:4000/graphql' }));

// 订阅走 ws，查询走 http
const link = split(
  ({ query }) => {
    const def = getMainDefinition(query);
    return def.kind === 'OperationDefinition' && def.operation === 'subscription';
  },
  wsLink,
  httpLink,
);

服务端要给 Apollo Server 挂上 graphql-ws 的服务端插件，4.x 的写法和老教程差别很大，以官方文档为准。

FAQ

Q：Apollo Client 缓存怎么清？
登出时 client.resetStore() 全清；单个对象 client.evict({ id: 'User:1' })。别直接 window.location.reload()，那是治标。

Q：DataLoader 缓存能跨请求吗？
默认不能，也不应该。跨请求缓存是 Redis/服务端缓存的事，DataLoader 只管"同一请求内去重"。想跨请求就在 resolver 外面套一层 Redis。

Q：订阅在生产要注意什么？
WebSocket 连接是有状态的，多实例部署要配 sticky session 或用 Redis PubSub 广播，否则用户连到 A 实例、事件从 B 实例发，收不到。

我的结论

Apollo 这套 Server+Client 是目前 GraphQL 生产落地最完整的方案。服务端记住三件事：4.x 要 await server.start()、DataLoader 每请求新建、错误用 GraphQLError 带 code。客户端记住一件事：把归一化缓存用明白，你就理解了 GraphQL 前端 80% 的体验优势。
