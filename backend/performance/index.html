限流熔断深度原理：令牌桶与漏桶

🏷️ 高可用

系统扛不住的时候为什么会崩？怎么限流？令牌桶和漏桶有什么区别？熔断降级怎么实现的？这篇讲透高可用底层原理。

核心原理1：限流原理：为什么要限流？

系统处理能力有上限，流量超过了就排队、超时、OOM，最后整个系统崩。限流就是控制入口流量，超过阈值就拒绝或者排队。

flowchart TD A[请求进来] --> B{限流判断} B -->|没超阈值| C[正常处理] B -->|超阈值| D[拒绝/排队/降级] C --> E[返回结果]

限流算法对比

算法 原理 特点 适用场景
固定窗口 固定时间窗口计数 简单，窗口边界有突刺 简单限流
滑动窗口 窗口滑动，更平滑 解决突刺问题 接口限流
漏桶 请求像水倒进桶，匀速漏出 输出速率恒定，平滑 调用下游接口
令牌桶 桶里放令牌，请求拿令牌才处理 允许突发流量 API 网关限流

核心原理2：令牌桶 vs 漏桶

两个最常用的限流算法，区别是：令牌桶允许突发，漏桶匀速输出，不允许突发。

flowchart LR A[令牌桶] --> B[令牌 匀速生成] B --> C[请求 拿令牌] C --> D[没令牌 拒绝] E[漏桶] --> F[请求 倒进桶] F --> G[匀速漏出 处理] G --> H[桶满 拒绝]
对比项 令牌桶 漏桶
突发流量 允许，桶里有令牌就可以突发 不允许，匀速输出
输出速率 可以突发超过平均速率 恒定速率
适用场景 用户请求，允许突发 调用下游，保护下游
参数 桶大小 + 令牌生成速率 桶大小 + 漏出速率

核心原理3：熔断降级原理

调用下游服务，下游挂了，你还一直调用，自己线程都阻塞等着，最后自己也崩。熔断就是错多了就直接不调用了，降级返回兜底。

flowchart LR A[正常调用] --> B{熔断器} B --> C[错误率低] C --> D[正常调用下游] D --> E[错误率超阈值] E --> F[熔断打开 直接降级] F --> G[过冷却时间 半开 试一下] G --> H[成功 恢复正常] G --> I[失败 继续熔断]
熔断器状态 行为 触发条件
关闭 正常调用下游 默认状态
打开 直接降级，不调用下游 错误率/慢调用比例超阈值
半开 放少量请求试一下 熔断过了冷却时间

新手最容易踩的坑

❌
避坑指南
  • 限流不要只拒绝，要返回友好提示，不要让用户等超时
  • 令牌桶适合入口限流，漏桶适合调用下游，别用反了
  • 熔断要有半开状态，不能一直熔断，也不能一下全放进来
  • 降级要有兜底数据，比如推荐挂了返回热门列表，不要直接报错
