数据库优化：从慢查询到分库分表

🏷️ 数据库优化

数据库查询越来越慢，接口超时，CPU 跑满。数据库优化不是上来就分库分表，先把能优化的都优化了再说。

flowchart LR A[查询慢] --> B[索引优化] B --> C[SQL优化] C --> D[表结构优化] D --> E[读写分离] E --> F[分库分表]

查询越来越慢，接口超时

⚠️
你遇到的问题

一个列表接口原来 100ms，现在要 1 秒，用户都投诉了。

怎么解决？先查慢查询日志，看看是哪条 SQL 慢，然后 explain 分析，加索引优化。

# 开慢查询日志
slow_query_log = 1
long_query_time = 1

# 看慢查询
mysqldumpslow -s t slow.log

加了索引还是慢

⚠️
你遇到的问题

索引加了一堆，结果写入慢，查询也没快多少。

怎么解决？先分析是不是索引失效，是不是加了没用的索引，把没用的索引删掉。

# 查没用的索引
SELECT * FROM sys.schema_unused_indexes;

# 删掉没用的索引
DROP INDEX idx_name ON table_name;

优化步骤

步骤 做什么 效果
1. 慢查询分析 找慢SQL，explain分析 找到问题点
2. 索引优化 加合适的索引，删没用的 查询快 10-100 倍
3. SQL优化 优化写法，避免全表扫描 再快几倍
4. 读写分离 读走从库，写走主库 读性能翻倍
5. 分库分表 数据量太大了才拆 解决单点瓶颈

新手最容易踩的坑

❌
避坑指南
  • 优化顺序别搞反了，先索引，再SQL，再表结构，最后才分库分表
  • 索引不是越多越好，每个索引都会拖慢写入
  • 分库分表是最后手段，拆了后面跨库查询、分布式事务都是坑
  • 优化前一定要先测，优化后对比效果，别瞎改
