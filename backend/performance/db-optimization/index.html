数据库性能优化

💡 你想搞懂这个技术到底是干嘛的，什么时候该用它，什么时候不该用。不想上来就背一堆概念。

慢查询排查

-- 开启慢查询日志
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1; -- 超过1秒记录

-- 查看执行计划
EXPLAIN SELECT * FROM orders WHERE user_id = 123;

-- 看全表扫描
EXPLAIN SELECT * FROM orders WHERE user_id = 123;
-- type=ALL 就是全表扫描，要优化

索引优化

场景优化方式
WHERE 条件给 WHERE 字段加索引
ORDER BY排序字段加索引
GROUP BY分组字段加索引
联合查询关联字段加索引

连接池配置

# 数据库连接池
pool:
  maxOpen: 100  # 最大连接数
  maxIdle: 10   # 最大空闲连接
  maxLifetime: 3600000 # 连接最大存活时间(ms)
注意：连接数不是越大越好。连接太多反而会让数据库切换变慢，一般是 CPU 核数的 2-4 倍。

读写分离

主库写，从库读。适合读多写少的场景。

  • 主库：处理写操作、强一致读
  • 从库：处理普通读操作
  • 注意：主从延迟，刚写完可能读不到
