Python 深度原理：GIL、GC、协程

🏷️ Python

Python 写起来爽，但为什么多线程跑不快？为什么有 GIL？垃圾回收怎么工作的？asyncio 协程到底是什么？这篇从底层讲透 Python。

核心原理1：GIL：全局解释器锁

Python 多线程为什么 CPU 密集型跑不快？因为有 GIL，同一时刻只有一个线程执行 Python 字节码。

flowchart LR A[Python 解释器] --> B{GIL 锁} B --> C[线程1 执行] B --> D[线程2 等待] B --> E[线程3 等待] C -->|时间片到| F[释放 GIL] F --> G[切换到线程2]

GIL 影响

场景 影响 解决方案
CPU 密集型 多线程跑不快，比单线程慢 用多进程 multiprocessing
IO 密集型 等待 IO 时释放 GIL，多线程还行 多线程/asyncio 都可以
为什么有 GIL CPython 内存管理不是线程安全 历史原因，Java/Go 没有 GIL

核心原理2：垃圾回收原理

Python 用引用计数为主，标记清除和分代回收为辅。引用计数到 0 就回收，但循环引用会漏。

flowchart TD A[垃圾回收] --> B[引用计数] A --> C[标记清除] A --> D[分代回收] B --> B1[引用数=0 立即回收] C --> C1[解决循环引用] D --> D1[分0/1/2代 越老越少扫描]

Python 三种 GC 机制

回收机制 原理 触发时机
引用计数 每个对象记引用数，为0就回收 实时，随时
标记清除 从根对象遍历，不可达的回收 解决循环引用
分代回收 对象分三代，越老扫描越少 定期触发，提升性能

核心原理3：协程 asyncio 原理

协程是用户态的轻量级线程，一个线程里跑成千上万个协程，切换不进内核，比线程轻得多。

flowchart LR A[事件循环] --> B[协程1] B --> C[await 等待IO] C --> D[让出CPU 切换到协程2] D --> E[协程2 await] E --> F[IO好了 切回协程1]

三种并发模型对比

并发模型 切换开销 适用场景
多进程 大，复制整个进程 CPU 密集型
多线程 中，内核态切换 IO 密集型
协程 极小，用户态切换 高并发 IO 型

新手最容易踩的坑

❌
避坑指南
  • CPU 密集型任务别用多线程，用多进程绕开 GIL
  • 大循环里别频繁创建销毁对象，会触发频繁 GC，影响性能
  • 协程里不要写阻塞代码，会卡住整个事件循环
  • 循环引用虽然会回收，但大对象循环引用也占内存，注意手动 break
