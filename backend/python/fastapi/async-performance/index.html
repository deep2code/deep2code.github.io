异步与性能优化

异步不是银弹

FastAPI 原生支持 async，但很多人用错了。最常见的坑：在 async 函数里调用同步阻塞库（比如 requests、psycopg2），反而比同步路由更慢。

踩坑提醒：在 async def 路由里，不要调用同步阻塞的代码。要么用 def 路由（FastAPI 会放到线程池），要么换成异步版本。
场景用 async def用普通 def
调用异步库（asyncpg、httpx）✅ 推荐❌ 没必要
调用同步库（requests、psycopg2）❌ 会阻塞事件循环✅ FastAPI 自动放线程池
CPU 密集计算❌ 阻塞事件循环✅ 放线程池

异步数据库驱动

# 异步 SQLAlchemy
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine
from sqlalchemy.orm import sessionmaker

engine = create_async_engine("postgresql+asyncpg://user:pass@localhost/db")
AsyncSessionLocal = sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session

性能优化清单

  • 用异步驱动：asyncpg 替代 psycopg2，aioredis 替代 redis-py
  • 响应模型：显式声明 response_model，避免泄露内部字段
  • 后台任务：用 BackgroundTasks 处理非关键路径
  • 连接池：数据库连接池大小要合适，别开太大
