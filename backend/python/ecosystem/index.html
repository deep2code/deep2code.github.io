Python 2026 选型

🏷️ Python

概述：2026 年该用哪个 Python

Python 语言本身一直在悄悄进化：3.9 到 3.14，每一步都在补"工程化"和"性能"两块短板。版本选型不是追新，而是在稳定性、性能、生态兼容性之间找平衡。

3.12：工程化定型之作

3.12 是 2026 生产环境的稳妥基线，类型系统与标准库都补齐了：

from typing import override

class Base:
    def process(self, data: str) -> None: ...

class Derived(Base):
    @override                       # 类型检查器验证父类确有此方法
    def process(self, data: str) -> None: ...

import tomllib
with open("config.toml", "rb") as f:
    config = tomllib.load(f)        # 标准库内置 TOML 解析

  • TypeVar 默认值、type 语句、TaskGroup 结构化并发落地。

3.13：性能与自由线程的实验

3.13 的 JIT 和 free-threaded 仍是实验性：默认发行版不带，需显式安装，且大量 C 扩展尚未适配 no-GIL。尝鲜可以，生产慎选。

选型结论：生产以 3.12+ 起步，新项目可直接上 3.13/3.14；对 GIL 敏感的多线程热点，单独评估 free-threaded 构建；3.9 及以下有安全风险，尽快迁移。

生态趋势：AI / ML / 数据科学 / Web 自动化

  • AI 与 LLM 应用：Python 是事实标准，LangChain / LlamaIndex / vLLM / transformers 生态繁荣，Agent 开发工具链成熟。
  • 数据科学：numpy / pandas / Polars（Rust 重写，更快）/ Jupyter 仍是分析主力。
  • Web：FastAPI + Pydantic v2 成 API 标配，异步栈（asyncpg / aioredis）普及。
  • 自动化与脚本：Playwright（取代 Selenium）、httpx、uv 让脚本写得更现代。

最佳实践

  • 新项目 uv init + 3.13/3.14，pyproject.toml 声明依赖。
  • 生产基线 3.12+，升级前跑完整测试套件与类型检查。
  • 关注 free-threaded 进展，但不要为了它盲目升级——先确认 C 扩展兼容。
  • 工具链统一用 uv + ruff，减少团队间环境差异。

FAQ

Q1：新项目该选 3.12、3.13 还是 3.14？
追求稳定选 3.12；想尝鲜 free-threaded / JIT 且能接受边缘问题选 3.13/3.14。生产建议等 3.14 的小版本稳定后再上。

Q2：free-threaded 能直接替换默认 Python 吗？
不能。它是单独构建，且大量 C 扩展（numpy 等）需要适配无 GIL 模式，目前只适合评估性项目。

Q3：Python 2 还需要管吗？
2020 年已停止维护，所有新项目一律 Python 3。存量 Py2 脚本尽快迁移。

总结

2026 年的 Python 不再是"慢糙动态脚本语言"：3.12 补齐工程化、3.13 试水性能与自由线程、3.14 把它们推到稳定；工具链收敛到 uv + ruff + FastAPI + Pydantic v2。选型上"生产 3.12+、新项目 3.13/3.14、按需评估 free-threaded"即可。这一篇是整个系列的收尾——语言核心、内部原理、并发、工程化、Web、陷阱都讲过了，剩下的就是动手把现代栈跑起来。
