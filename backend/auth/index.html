HTTPS/TLS 深度原理：为什么安全？

🏷️ 安全

HTTPS 比 HTTP 安全，到底安全在哪？TLS 握手是怎么回事？对称加密和非对称加密怎么配合的？这篇讲透底层原理。

核心原理1：加密原理：对称 vs 非对称

对称加密快但密钥传输不安全，非对称加密安全但慢，TLS 是两个结合：用非对称加密协商出对称密钥，之后用对称加密传输数据。

flowchart TD A[加密方式] --> B[对称加密] A --> C[非对称加密] B --> B1[密钥一样 加解密快] B --> B2[密钥怎么传？] C --> C1[公钥加密 私钥解密] C --> C2[安全 但慢]

['对比', '对称加密', '非对称加密']

对比项 对称加密 非对称加密
密钥 加解密同一个密钥 公钥加密，私钥解密
速度 快 100 倍 慢
密钥传输 不安全 安全
TLS 用途 传输数据 协商对称密钥

核心原理2：TLS 1.3 握手原理

TLS 握手不是把密钥直接传过去，是双方各自生成随机数，用非对称加密协商出同一个会话密钥，之后用对称加密传数据。

flowchart LR A[Client Hello] --> B[客户端随机数] B --> C[Server Hello 服务端随机数] C --> D[服务器证书 公钥] D --> E[客户端验证证书] E --> F[生成 pre-master secret] F --> G[双方算出会话密钥] G --> H[开始加密传输]

['步骤', '做什么', '目的']

步骤 做什么 目的
Client Hello 客户端发支持的加密算法、随机数 协商算法
Server Hello 服务端选算法，发随机数、证书 服务器身份
密钥交换 双方协商出会话密钥 加密后续数据
Finished 验证握手数据 防篡改

核心原理3：证书原理：怎么验证服务器身份？

HTTPS 不是服务器随便发个公钥就信，是要有 CA 证书机构签名的证书，浏览器内置 CA 根证书，验证证书链，确认服务器是真的。

flowchart TD A[服务器证书] --> B[CA 用私钥签名] B --> C[浏览器用 CA 公钥验证] C --> D[验证通过 相信服务器] E[自签名证书] --> F[没有 CA 签名] F --> G[浏览器警告 不安全]

['证书类型', '说明', '适用场景']

证书类型 说明 适用场景
DV 域名证书 只验证域名所有权 个人小站
OV 组织证书 验证企业身份 企业官网
EV 扩展验证 严格验证企业，地址栏显示绿标 银行金融
自签名证书 自己签的，没有 CA 背书 内网测试

新手最容易踩的坑

❌
避坑指南
  • HTTPS 一定要配 HSTS，不然第一次访问可能被降级劫持
  • 证书要定期检查到期，提前续签，不然突然就挂了
  • 不要用自签名证书上生产，浏览器会警告用户不信任
  • TLS 1.2 以下有漏洞，生产环境要禁用，只开 TLS 1.2/1.3
