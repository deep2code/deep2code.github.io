Shell 脚本编程

🏷️ Bash,Shell脚本,严格模式

为什么要系统学 Shell：不只是胶水语言

Shell 是程序员与操作系统之间最直接的接口。无论是 CI/CD 流水线、服务器运维、数据处理，还是 AI 编码代理调用 rg/fd/gh，底层都是 Shell。

我见过很多人写了十几年脚本，却长期停留在"复制粘贴能跑就行"的阶段——变量不加引号、错误静默吞掉、管道里改不了计数器。本系列第一篇，把 Bash 语言核心讲透。

核心心法：Shell 的一切行为都可以用"展开（Expansion）"二字解释。写脚本时遇到诡异结果，先问自己——"这行经历了哪些展开？引号加对了吗？"

核心概念：变量、引号与参数展开

变量与引号规则

Shell 变量无需声明类型，默认就是字符串。引号是 Shell 中最容易踩坑的地方：

  • 双引号 "$var"：变量会被展开，但不做单词拆分和路径名展开——这是处理含空格文件名的正确姿势。
  • 单引号 '$var'：完全不展开，原样输出。
  • 不加引号 $var：经历单词拆分（按 IFS 切分）和路径名展开（* 会匹配文件）——90% 的诡异 bug 源于此。
file="hello world.txt"
# 错误：$file 被拆成两个参数，cp 报错
# cp $file dest/
# 正确：加双引号
cp "$file" dest/

# echo 会解释 -n/-e，输出任意内容用 printf 更安全
printf '%s\n' "$var"

参数展开（Parameter Expansion）速查

${var:-default} 系列是 Shell 最强大的字符串处理工具，能替代 80% 的 sed/awk 调用：

写法含义示例
${var:-default}未设置或为空时用 default${PORT:-8080}
${var:=default}未设置时赋值并使用${DIR:=/tmp}
${var:?msg}未设置时报错退出${TOKEN:?need token}
${var:+alt}已设置时才用 alt${DEBUG:+-x}
${#var}字符串长度${#name}
${var:0:3}子串（起始:长度）${name:0:3}
${var#prefix}删最短前缀${path#*/}
${var##prefix}删最长前缀（贪婪）${path##*/} 取文件名
${var%suffix}删最短后缀${file%.txt}
${var/search/repl}替换第一个${file/.txt/.md}
${var//search/repl}替换全部${path// /_}
${var^^} / ${var,,}大写 / 小写${name^^}

展开顺序：理解 Shell 的关键

Shell 处理一行命令时，按固定顺序做 7 类展开。理解这个顺序，才能预测输出：

graph TD A[读取一行输入] --> B[1.大括号展开 Brace] B --> C[2.波浪号展开 Tilde] C --> D[3.参数/变量展开] D --> E[4.命令替换] E --> F[5.算术展开] F --> G[6.单词拆分 Word Splitting] G --> H[7.路径名展开 Globbing] H --> I[重定向 + 执行] style A fill:#0d1117,stroke:#3ec96f,color:#3ec96f style I fill:#0d1117,stroke:#3ec96f,color:#3ec96f

注意：双引号内的变量展开不做第 6、7 步（单词拆分、路径展开），这就是为什么"加双引号"能保住含空格的文件名。

条件、循环与函数

条件判断：用 [[ ]] 不用 [ ]

test、[ ] 是老式写法，[[ ]] 是 Bash 增强版，支持正则匹配、&&/||、字符串比较无需转义：

file="app.log"
if [[ -f "$file" && -s "$file" ]]; then
  echo "文件存在且非空"
elif [[ -d "$file" ]]; then
  echo "是目录"
fi

# [[ ]] 中直接支持正则 =~
if [[ "$line" =~ ^[0-9]+$ ]]; then echo "纯数字"; fi

# 数字比较用 (( )) 更直观
if (( age >= 18 && age < 60 )); then echo "成年人"; fi
测试类型写法说明
文件存在-e/-f/-d/-L存在/普通文件/目录/软链接
权限-r/-w/-x可读/可写/可执行
字符串-z/-n/= /!=空/非空/相等/不等
数字-eq/-ne/-lt/-gt等于/不等/小于/大于

循环：for / while / until

遍历文件用 glob，不要用 for line in $(cat file)（会按空格拆行）。逐行读文件必须用 while read：

# 遍历文件（glob 自动处理空格）
for f in *.txt; do echo "处理 $f"; done

# C 风格循环
for ((i=0; i<10; i++)); do echo "$i"; done

# 逐行读文件（正确姿势，IFS 保留首尾空格）
while IFS= read -r line; do
  echo ">> $line"
done < file.txt

# 并发：& 后台 + wait 等待全部完成
for var in {0..2}; do
  { echo "任务 $var"; sleep 1; } &
done
wait   # 等所有后台任务结束

函数与返回值

Bash 函数的"返回值"只能是 0-255 的退出码；要返回数据用 stdout + 命令替换捕获：

greet() {
  local name="$1"          # local 声明局部变量
  echo "Hello, $name!"     # 通过 stdout 返回数据
  return 0                 # 返回码
}

result=$(greet "World")    # result="Hello, World!"
add() { echo $(( $1 + $2 )); }
sum=$(add 3 5)             # sum=8

set 严格模式与错误处理

生产脚本开头必须加严格模式，它能在错误发生时立即暴露，而不是让脚本带着错误继续跑：

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'

# -e：任何命令失败立即退出
# -u：使用未定义变量时报错（告别 typo 引发的空值）
# -o pipefail：管道中任一命令失败，整条管道视为失败
# IFS=$'\n\t'：只按换行和 Tab 拆分，避免空格误伤

# 自定义错误处理
die() { echo "ERROR: $*" >&2; exit 1; }
command_that_might_fail || die "启动失败"

# trap：退出时清理临时文件
tmp=$(mktemp)
cleanup() { rm -f "$tmp"; }
trap cleanup EXIT
trap 'echo "中断"; exit 130' INT
set 选项作用关闭
-e命令失败即退出set +e
-u未定义变量报错set +u
-o pipefail管道传递失败码set +o pipefail
-x打印执行的命令（调试）set +x
-v回显输入（不展开变量）set +v

调试三板斧：bash -n script.sh 只做语法检查不执行；bash -x script.sh 跟踪每条命令（展开变量）；set -v 回显原始输入。

脚本参数与命令行选项

特殊位置变量是脚本与外界交互的桥梁：

变量含义
$0脚本名
$1..$9 / ${10}第 N 个参数
$#参数个数
$@所有参数（独立单词，加引号最安全）
$*所有参数（合成一个单词）
$?上一命令退出码（0 成功）
$$ / $!当前 PID / 最近后台 PID

用 getopts 解析短选项，shift 移除已消费的参数：

verbose=false; output=""
while getopts "vo:h" opt; do
  case $opt in
    v) verbose=true ;;
    o) output="$OPTARG" ;;
    h) echo "Usage: $0 [-v] [-o FILE]"; exit 0 ;;
    *) echo "非法选项"; exit 1 ;;
  esac
done
shift $((OPTIND - 1))   # 剩下的位置参数在 "$@"

最佳实践

  • 永远加双引号："$var"，除非明确想要单词拆分。
  • 开头加严格模式：set -euo pipefail + IFS=$'\n\t'。
  • 用 [[ ]] 不用 [ ]，用 (( )) 做数字比较。
  • 用 $(cmd) 不用反引号：可嵌套、可读。
  • 检查命令是否存在：command -v jq >/dev/null || { echo "需安装 jq"; exit 1; }
  • 用 shellcheck 静态检查：shellcheck script.sh 能自动指出绝大多数坑。
  • 临时文件用 mktemp，并用 trap ... EXIT 保证清理。

常见问题 FAQ

Q1：为什么我的变量在管道里改了却不生效？

因为管道中的每个命令都运行在子 Shell 里，对外部变量的修改会在子 Shell 退出时丢弃。

解决办法：把 cat file | while read; do count=$((count+1)); done 改成 while read; do ... done < file（直接重定向，不经过管道），或用进程替换 while ... done < <(cat file)。我踩过这个坑整整半天，计数器永远是 0。

Q2：$* 和 $@ 到底有什么区别？

不加引号时几乎一样。加双引号后区别巨大："$@" 把每个参数保持为独立单词（完美转发参数），"$*" 把所有参数用 IFS 第一个字符粘成一个字符串。写"转发所有参数"的脚本时永远用 "$@"。

Q3：[ $? -eq 0 ] 这种写法有什么问题？

有两个问题：一是多此一举，直接 if command; then 即可；二是当 $? 是 0 而脚本开了 set -u 时没问题，但把错误判断拆开容易漏掉。正确做法是直接对命令本身做 if 判断，或依赖 set -e 自动退出。
