SSH 远程管理

🏷️ SSH,远程管理

SSH：远程管理的一切都建立在它之上

SSH 不只是 ssh user@host 登录一行命令。它是远程开发、CI/CD、端口转发、安全隧道的基石。我之前在公司维护了 20 多台服务器，靠 ~/.ssh/config 用别名一键直连，省了大量记忆 IP 的精力。

安全底线：私钥就是密码。~/.ssh 目录必须 700，私钥必须 600。一旦出现 Permissions 0644 are too open，立即 chmod 0600 ~/.ssh/id_ed25519。

SSH 握手与加密原理

SSH 登录不是明文传输，而是一次完整的密钥协商+身份认证：

sequenceDiagram participant C as 客户端 participant S as 服务器 C->>S: 1.版本协商 (SSH2_MSG_KEXINIT) S->>C: 2.算法交换+密钥交换 (生成会话密钥) C->>S: 3.服务器公钥指纹验证 S->>C: 4.客户端公钥认证 (签名挑战) C->>S: 5.建立加密通道,开始会话 Note over C,S: 之后所有流量对称加密

登录卡住时用 ssh -vvv user@host 看详细握手过程。经典坑：卡在 SSH2_MSG_KEXINIT sent 直到超时，多半是 MTU 设置过大——把网络 MTU 手动改成 1500 即可解决。

密钥生成与多密钥管理

现在很多平台不再支持 RSA，推荐用 ed25519。ssh-keygen 生成密钥对，公钥（.pub）放到服务器/GitHub，私钥留在本地：

# 生成 ed25519 密钥（推荐）
ssh-keygen -t ed25519 -C "you@example.com" -f ~/.ssh/id_ed25519
# -t 类型  -C 注释  -f 文件名  -b 位数
# 注意：从网页复制命令若报「不识别参数」，检查是否混入了不换行空格(U+00A0)

# ssh-agent 缓存私钥密码，避免每次输入
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# 复制公钥到剪贴板（按系统）
pbcopy < ~/.ssh/id_ed25519.pub      # macOS
xclip -sel clip < ~/.ssh/id_ed25519.pub  # Linux
clip < ~/.ssh/id_ed25519.pub        # Windows

~/.ssh/config 多主机管理

一台机器要连多个 GitHub 账号、多台服务器时，~/.ssh/config 是救星。每个 Host 别名对应一组配置：

~/.ssh/config 示例：

# 个人 GitHub 账号
Host github-personal
    HostName github.com
    PreferredAuthentications publickey
    IdentityFile ~/.ssh/id_ed25519_personal

# 公司 GitHub 账号
Host github-work
    HostName github.com
    PreferredAuthentications publickey
    IdentityFile ~/.ssh/id_ed25519_work

# 一台生产服务器
Host prod
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

配置好后用别名直连，Git 仓库的 remote 也用别名：

# 测试哪个密钥对哪个账号生效
ssh -T git@github-personal
# Hi username! You've successfully authenticated ...

# clone 时用别名（github-work 这个 Host 走 work 密钥）
git clone git@github-work:company/repo.git
配置项作用
Host自定义别名（连这个名字）
HostName真实服务器地址
User登录用户名
Port端口（非 22 时必配）
IdentityFile指定用哪个私钥
ProxyJump通过堡垒机跳转
ServerAliveInterval客户端保活秒数

端口转发三大姿势

SSH 隧道是它最被低估的能力，能穿透网络访问内网服务：

类型命令场景
本地转发 -Lssh -L 8080:内网:80 user@跳板本地访问内网服务
远程转发 -Rssh -R 9000:localhost:3000 user@公网把本地服务暴露到公网
动态转发 -Dssh -D 1080 user@跳板建 SOCKS5 代理
 
# 本地转发：访问 localhost:8080 = 访问内网 10.0.0.5 的 80 端口
ssh -L 8080:10.0.0.5:80 user@bastion

# 动态转发：浏览器走 socks5://localhost:1080 即可翻墙式访问内网
ssh -D 1080 user@bastion

断线保活与加速

长连接经常掉线或卡住，是因为中间网络设备超时断了连接。两端各加心跳即可：

# 客户端 ~/.ssh/config：每 30 秒发心跳，100 次无响应才断
ServerAliveInterval 30
ServerAliveCountMax 100

# 服务器端 /etc/ssh/sshd_config：服务器主动发心跳
ClientAliveInterval 30
ClientAliveCountMax 6

登录极慢还可能是服务器在做 DNS 反查客户端。关掉即可：

# /etc/ssh/sshd_config
UseDNS no
GSSAPIAuthentication no

sshd_config 安全加固

  • 禁用密码登录：PasswordAuthentication no，只允许密钥。
  • 改默认端口：Port 2222，过滤掉海量扫描。
  • 禁止 root 直登：PermitRootLogin no。
  • 限制用户：AllowUsers deploy ops。
  • 失败锁定：配合 fail2ban 自动封暴力破解 IP。

高级用法与现代替代

# ProxyJump：一跳到内网（不用先登跳板机）
ssh -J user@bastion user@internal

# ControlMaster：复用 TCP 连接，二次登录免握手、秒连
# ~/.ssh/config 加：
#   ControlMaster auto
#   ControlPath ~/.ssh/cm-%r@%h:%p
#   ControlPersist 10m

# sshfs：把远程目录挂载到本地
sshfs user@host:/remote/dir ./localdir

# rsync 增量同步（比 scp 智能）
rsync -avz --progress ./local/ user@host:/remote/

现代替代方案：mosh（UDP 漫游，断网重连不丢会话）、tailscale（组网直连，免开端口）、eterminal/et（断线自动恢复）。

最佳实践

  • 一把钥匙一个用途：GitHub 个人/公司、生产/测试各用不同密钥，靠 ~/.ssh/config 区分。
  • 私钥加 passphrase + ssh-agent：安全又不麻烦。
  • 服务器端禁用密码登录，只走密钥。
  • 长连接必配 ServerAliveInterval，告别掉线。
  • 传文件用 rsync 不用 scp：增量、断点续传。

常见问题 FAQ

Q1：为什么连 GitHub 用的是错误的账号？

因为你有多个密钥，SSH 默认按顺序试，可能先用了旧账号的密钥。解决：在 ~/.ssh/config 给不同 Host 别名（如 github-work）指定不同 IdentityFile，然后 clone 和 remote 都用别名，而不是直接用 github.com。

Q2：SSH 连上去就卡住，很久才出提示符？

多半是服务器在做反向 DNS 查询客户端 IP（UseDNS yes），或者 GSSAPI 认证超时。把 UseDNS no 和 GSSAPIAuthentication no 加到 sshd_config 重启即可。本地用 ssh -vvv 能看到卡在哪一步。

Q3：-L 和 -R 总是记反，怎么区分？

记"站在哪一端"：-L（Local）是在本地开端口，流量经 SSH 去访问远程内网服务；-R（Remote）是在远程服务器开端口，把流量拉回本地。-D 是动态 SOCKS 代理。

总结

SSH 的核心是"密钥 + config + 隧道"三件事：密钥管理多账号，config 用别名屏蔽复杂度，端口转发穿透网络。加上断线保活和禁用密码登录，你的远程管理就既安全又顺畅。下一篇聚焦日常最高频的文本处理。
