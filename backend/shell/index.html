Shell 深度原理：管道与重定向

🏷️ Shell

Shell 不是命令，是操作系统的命令解释器。管道 |、重定向 >、后台 & 这些操作底层是什么原理？这篇讲透 Shell 工作原理。

核心原理1：Shell 是什么？

Shell 是用户和内核之间的中间层，你敲命令，Shell 解析，调用 fork/exec 启动程序，等待执行完，输出结果。

flowchart LR A[用户敲命令] --> B[Shell 解析] B --> C[fork 子进程] C --> D[exec 启动程序] D --> E[程序执行] E --> F[返回结果给用户]

['Shell 类型', '说明', '特点']

Shell 类型 说明 特点
bash 大多数 Linux 默认 功能全，语法灵活
zsh macOS 默认 补全强，主题多
sh 最基础 POSIX 简单，兼容性好
fish 开箱即用 语法不兼容 bash

核心原理2：管道 | 原理

管道 | 本质是内核里的内存缓冲区，前一个命令的 stdout，变成后一个命令的 stdin，两个命令并行执行。

flowchart LR A[命令1 ls] -->|stdout| B[管道 内核缓冲区] B -->|stdin| C[命令2 grep] C -->|stdout| D[输出到屏幕]

['操作符', '含义', '原理']

操作符 含义 原理
| 管道，前输出当后输入 内核 pipe 缓冲区
> 1> 覆盖写 stdout 到文件 打开文件，写入
>> 追加写 stdout 到文件 打开文件，追加
2> 重定向 stderr 错误输出到文件
2>&1 stderr 和 stdout 合并 fd 复制

核心原理3：进程与信号原理

你按 Ctrl+C 为什么能停掉进程？因为 Shell 给前台进程组发 SIGINT 信号，进程收到信号就退出。

flowchart TD A[用户按 Ctrl+C] --> B[Shell 发 SIGINT] B --> C[前台进程组] C --> D[进程收到信号] D --> E[默认行为 退出] F[Ctrl+Z] --> G[发 SIGTSTP] G --> H[进程暂停 放后台]

['信号', '触发方式', '默认行为']

信号 触发方式 默认行为
SIGINT Ctrl+C 终止进程
SIGTSTP Ctrl+Z 暂停进程
SIGKILL kill -9 强制杀死，不能捕获
SIGTERM kill 默认 请求终止，可以捕获
SIGHUP 终端断开 退出，常用于 reload

新手最容易踩的坑

❌
避坑指南
  • 脚本开头一定要 #!/bin/bash，不然用默认 sh 跑可能语法不对
  • 管道是并行执行的，不是串行，前一个没执行完后一个就开始读了
  • set -euo pipefail 一定要加，脚本出错就停，不要继续往下跑
  • kill 不要上来就 kill -9，先 kill -15 让进程优雅退出，不行再 -9
