文本处理

🏷️ 文本处理,grep,sed,awk

文本处理：Unix 哲学的核心战场

"一切皆文件，文件即文本"——Unix 把复杂系统拆成一堆文本流，用管道串联小工具处理。grep 过滤、sed 编辑、awk 报表，这三件套是命令行的"瑞士军刀"。我平时分析日志、清洗 CSV、批量改配置，十次有八次用的还是这三个。日志分析、数据清洗、格式转换，全靠它们。

分工原则：grep 负责"选行"，sed 负责"改行"，awk 负责"按列汇总"。能 grep 不用 awk，能 cut 不用 awk——工具越简单越快。

grep 家族：选行

grep 按正则筛选行。三种正则语法要分清：

语法开关元字符
BRE 基本grep^ $ . * [ ]，+ ? | ( ) 需转义
ERE 扩展grep -E / egrep所有元字符直接可用
PCRE 兼容grep -P支持 \d \w \s 等 Perl 语法
 
grep 'error' app.log            # 含 error 的行
grep -i 'error' app.log         # 忽略大小写
grep -v 'debug' app.log         # 反向：不含 debug 的行
grep -rn 'funcName' src/        # 递归+行号
grep -E 'error|warn' app.log    # 或（ERE）
grep -oE '[0-9]+\.[0-9]+\.[0-9]+' app.log  # 只输出匹配部分（提取版本号）
grep -c 'error' app.log         # 统计匹配行数
# 现代替代：rg（ripgrep），默认递归+尊重 .gitignore
rg 'error' src/

sed 流编辑器：改行

sed 逐行处理流，s 替换是最高频用法。地址范围控制作用到哪些行：

sed 's/old/new/' file           # 每行替换第一个
sed 's/old/new/g' file          # 全行替换
sed 's/old/new/gi' file         # g 全局 + i 忽略大小写
sed -n '10,20p' file            # 只打印 10-20 行
sed '/error/d' file             # 删除含 error 的行
sed '3a\新增一行' file          # 第 3 行后追加
sed -i 's/old/new/g' file       # 原地修改（macOS: sed -i '' '...'）

# 分组捕获：\1 \2 引用
echo "2026-09-17" | sed -E 's/([0-9]+)-([0-9]+)-([0-9]+)/\2\/\3\/\1/'
sed 命令作用
s/a/b/[g]替换（g 全行）
p打印（配合 -n）
d删除行
a\ / i\追加 / 插入
c\替换整行
-i原地修改文件

awk：按列报表

awk 把每行按分隔符切成字段（$1 $2...，$0 是整行），是文本统计报表利器：

awk '{print $1}' file              # 打印第一列
awk -F: '{print $1}' /etc/passwd   # 用 : 做分隔符
awk '{sum+=$1} END {print sum}' n.txt   # 第一列求和
awk 'NR==3' file                    # 第三行（NR=行号）
awk '$3 > 100 {print $0}' data.csv # 第三列大于100才打印

# 内置变量：FS 输入分隔符 OFS 输出分隔符 NF 列数 NR 行号
awk -F, 'BEGIN{OFS=","} {print $1,$2}' data.csv

awk 还支持数组和函数，能做分组统计：

# 按第二列分组计数
awk '{cnt[$2]++} END {for (k in cnt) print k, cnt[k]}' access.log

其他命令行工具箱

命令用途
find按名/类型/大小找文件
xargs把标准输入转成命令参数
sort排序（-n 数字 -k 指定列 -r 逆序）
uniq去重（需先 sort，-c 计数）
cut截取列（-d 分隔 -f 字段）
tr字符替换/删除（tr a-z A-Z）
wc统计行/词/字符（-l）
head/tail取头/尾（tail -f 实时跟踪）
paste/join合并列 / 按键连接

管道 vs xargs是经典易错点：管道把前一个命令的标准输出变成后一个的标准输入；xargs 则把标准输入转成命令行参数：

# find 输出文件名
# 管道：grep 在"文件名"这些文本里找 protobuf（搜的是文件名本身）
find . -name "*.mod" | grep protobuf
# xargs：grep 在"这些文件名对应的文件内容"里找 protobuf
find . -name "*.mod" | xargs grep protobuf
# 找名为 html 的目录
find . -type d -name 'html'

统计 Nginx 日志里访问最多的 URL，一条管道搞定：

# 取第 7 列（URL），排序去重计数，再按次数逆序取前 20
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20

# 统计 4xx/5xx 错误率
total=$(wc -l < /var/log/nginx/access.log)
errors=$(awk '$9 ~ /^4|^5/' /var/log/nginx/access.log | wc -l)
echo "错误率: $((errors * 100 / total))%"

并发执行

# xargs -P 并行：4 路同时 curl
cat urls.txt | xargs -P 4 -I {} curl -s -o /dev/null {}

# GNU parallel：更直观，失败重试
cat urls.txt | parallel -j 10 curl -s -o /dev/null {}

# 当前目录文件总数（ls 普通文件计数）
ls -l | grep "^-" | wc -l

最佳实践

  • 分工明确：grep 选行、sed 改行、awk 算列，别用一个工具干所有事。
  • 管道从左到右读：想清楚每一步"输入是什么、输出是什么"。
  • uniq 前必 sort：uniq 只合并相邻重复行。
  • 大文件用流式管道，别全读进内存。
  • 用 rg 替代 grep：默认递归、忽略 .gitignore、快很多。

常见问题 FAQ

Q1：为什么 uniq 没去掉重复行？

因为 uniq 只合并相邻的重复行。不排序直接 uniq，分散的重复行去不掉。正确用法是 sort file | uniq 或一步到位 sort -u file。

Q2：find | grep 和 find | xargs grep 区别？

前者 grep 搜的是 find 打印出来的文件名字符串；后者 xargs 把文件名变成 grep 的参数，grep 搜的是文件内容。一个搜文件名、一个搜内容，别搞混。

Q3：for line in $(cat file) 为什么按空格拆而不是按行？

因为 $(cat file) 的输出会经过单词拆分，遇到空格就当分隔符。逐行读必须用 while IFS= read -r line; do ... done < file。

总结

文本处理三件套各有分工：grep 选行、sed 改行、awk 按列汇总。再配上 sort/uniq/cut/tr 和 xargs 并行，你就能用一条管道完成大多数日志分析和数据清洗。下一篇把视角拉高到整个系统管理。
