泛型基础

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • 约束写法二选一：func Sub[T int|string|float32] 内联，或抽出具名接口复用
  • 约束用了 == 则每个成员都必须可比较
  • 1.26/1.27 补上泛型最后两块拼图，2026 泛型实践已成熟

关键结论与取舍

  • 约束有变时具名接口只改一处，优先推荐
  • 1.27 后不必再等语法能力，放胆用泛型重构
适合谁读刚上手 Go 泛型、或想系统补课的人 读完可获得泛型约束写法、可比性规则与 2026 实践建议

泛型约束有两条等价写法：func Sub[T int | string | float32] 直接内联写约束，或者抽成具名接口 SubType 来复用；约束日后要增删，后者只需动一处。Sub 里用了 == ，要求约束里的每个成员都能比int/string/float32 都符合）。它会把所有等于 ele 的元素清干净：下面两个调用分别打印 [a c] 和 [20 30] 。

// go 1.18+
package main

import (
 "fmt"
)
type SubType interface {
 int | string | float32
}

// func Sub[T int | string | float32](array []T, ele T) []T {
func Sub[T SubType](array []T, ele T) []T {
 res := make([]T, 0, len(array))

 for _, a := range array {
  if a == ele {
   continue
  }
  res = append(res, a)
 }
 return res
}

func main() {
 fmt.Println(Sub([]string{"a", "b", "c", "b"}, "b"))

 fmt.Println(Sub([]int{10, 20, 30, 10}, 10))
}

泛型从 1.18 一路迭代：1.21 带来 cmp 包，1.24 坐实泛型类型别名；迈入 2026 年，Go 1.26 / 1.27 把泛型推上了「类型自引用 + 泛型方法」的新台阶。展开看 泛型进阶 那一页。

Go 1.26 / 1.27：泛型的最后两块拼图

站在 2026 年 8 月回看，泛型在类型系统上基本收官：

  • Go 1.26 （2026-02-10 发布）：类型参数支持自引用，递归式约束不再绕弯子，直接写 type Adder[A Adder[A]] interface { Add(A) A } 就行，辅助接口可以退休；
  • Go 1.27 （2026-08-19 发布）：泛型方法（generic methods）转正，方法声明也能带类型参数，泛型第一次摸到了类型命名空间；顺带把函数类型推断扩散到泛型函数赋值 / 转换的每个角落；
  • 泛型类型别名 ：1.23 预览、1.24 转正，到现在稳了两年，type List[T any] = []T 这类写法尽管放心用。

2026 年的泛型实践建议

这一轮的主线是「迭代器 + 泛型」：1.23 之后 iter 包和 range-over-func 默认开门迎客，标准库 slices / maps / cmp 全部泛型化，业务代码里手搓的切片、map 工具函数删掉大半。1.27 放开泛型方法后，GroupBy / Filter / Map 这类操作能直接长在具体类型上，读起来比包级泛型函数更顺（参考本站切片分组那页的新写法）。

升级零破坏：1.26 绿茶 GC 默认打开、new(expr) 语法更精简，1.27 加进 encoding/json/v2 、内置 uuid 包全是增量福利，老库升级成本约等于零。想扎实吃透泛型，先翻官方 Go 1.27 Release Notes 的 Language Changes 章节。
