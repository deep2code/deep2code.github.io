泛型基础

泛型约束两种写法等价：func Sub[T int | string | float32] 内联约束，或抽出具名接口 SubType 复用，约束有变时后者只改一处。Sub 里用了 ==,约束的每个成员都必须可比较(int/string/float32 都满足)。它会删掉全部等于 ele 的元素：下面两个调用分别输出 [a c] 与 [20 30]。

// go 1.18+
package main

import (
 "fmt"
)
type SubType interface {
 int | string | float32
}

// func Sub[T int | string | float32](array []T, ele T) []T {
func Sub[T SubType](array []T, ele T) []T {
 res := make([]T, 0, len(array))

 for _, a := range array {
  if a == ele {
   continue
  }
  res = append(res, a)
 }
 return res
}

func main() {
 fmt.Println(Sub([]string{"a", "b", "c", "b"}, "b"))

 fmt.Println(Sub([]int{10, 20, 30, 10}, 10))
}

Go 泛型更新

Go 泛型自 1.18 引入以来不断改进。1.21 引入 cmp 包，1.24 正式支持泛型类型别名；2026 年发布的 Go 1.26 / 1.27 又把泛型推进到「类型自引用与泛型方法」的新阶段。详见 泛型进阶 页面。

Go 1.26 / 1.27：泛型的最后两块拼图

以 2026 年 8 月为观察点，泛型在类型系统侧完成了收尾：

  • Go 1.26（2026-02-10 发布）：泛型类型支持自引用，递归约束可以直接写 type Adder[A Adder[A]] interface { Add(A) A }，不再需要绕道辅助接口；
  • Go 1.27（2026-08-19 发布）：正式支持泛型方法（generic methods），方法声明可以携带自己的类型参数，泛型能力首次进入类型命名空间；同时函数类型推断（function type inference）推广到泛型函数赋值 / 转换的所有上下文；
  • 泛型类型别名：Go 1.23 预览、1.24 正式落地后已稳定两年，type List[T any] = []T 这类写法可以放心使用。

2026 年的泛型实践建议

这轮更新的主线是「迭代器 + 泛型」：Go 1.23 起 iter 包与 range-over-func 默认启用，标准库 slices / maps / cmp 已全部泛型化，业务里手写的切片、映射工具函数大部分可以删除。1.27 泛型方法落地后，GroupBy / Filter / Map 这类操作可以直接挂在具体类型上，代码比包级泛型函数更自然（参见本专题的切片分组页新写法）。

升级方面没有破坏性变更：1.26 的绿茶 GC 默认启用、new(expr) 语法精简，1.27 新增 encoding/json/v2、内置 uuid 包都是增量福利，老代码升级成本基本为零。想把泛型用扎实，优先看官方 Go 1.27 Release Notes 的 Language Changes 一节。
