Shell

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • -ldflags "-w -s" 去 DWARF 与符号表，二进制可瘦 30%—50% 且不影响运行
  • -X main.GitHash=... 在链接期注入 git describe 版本号，线上定位直达 commit
  • WaitDelay 为什么能避免 exec.Command Wait 卡死，以及进程树清理与注入防护

关键结论与取舍

  • 发布脚本标配 -w -s -X，代价是调试信息缺失，需用注入字段补偿定位能力
  • 用 Shell 拼命令传参注意注入面，多参数改用 exec 数组传递
适合谁读做 Go 二进制发布、需要瘦身与版本注入的工程同学 读完可获得一套现成的编译发布 Makefile/Shell 模板与防卡死、防注入要点

编译常用示例

编译发布的老套路，精髓全在 -ldflags "-w -s -X"：-w 负责剥掉 DWARF 调试信息，-s 负责清掉符号表——瘦身幅度常在 30%–50%，运行完全不受影响；-X main.GitHash=... 则在链接期把构建信息灌进变量，配合 git describe 给出的版本号，线上排查时一眼就能看出手里跑的是哪次提交。想产出一颗扔到任何 Linux 都能直接跑的纯静态二进制？加上 CGO_ENABLED=0 再去 go build。反过来，只要牵扯到需要 cgo 的库（比如 sqlite 驱动），这条就别碰。

#! /bin/bash

target=local

set -x #回显执行命令

GOPATH=$(go env GOPATH)
GITVERSION=$(git describe --tags --always)
GITBRANCH=$(git symbolic-ref -q --short HEAD)
DATETIME=$(date "+%Y-%m-%d_%H:%M:%S")
HOSTNAME=$(hostname)

golangci-lint run --timeout=1h

revive -formatter friendly ./...

rm -rf ${target}*

go build -o ${target} -ldflags "-w -s -X main.GitHash=${GITVERSION}-${GITBRANCH} -X main.CompileTime=${DATETIME} -X main.HostName=${HOSTNAME}" .

./${target}

Go 调用 Shell 更新

sequenceDiagram participant Go as Go程序 participant OS as 操作系统 participant Sh as Shell Go->>OS: exec.Command("ls", "-la") OS->>Sh: fork+exec Sh->>Sh: 执行命令 Sh-->>OS: stdout/stderr OS-->>Go: 输出结果

Go 1.21 之后执行命令的正确姿势：

// 使用 context 控制超时
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()

cmd := exec.CommandContext(ctx, "git", "status")
output, err := cmd.CombinedOutput()
if err != nil {
    log.Printf("命令执行失败: %v, 输出: %s", err, output)
}

WaitDelay：避免 Wait 卡死

光传 context 并不保险：子进程再派生的孙进程很可能还攥着 stdout/stderr 管道，把 cmd.Wait() 卡到死不返回。Go 1.20 新加的 Cmd.WaitDelay 专治这种僵局——上下文取消后，Wait 迟迟超过 WaitDelay 还没收尾，就先把子进程杀掉再报错返回。

cmd := exec.CommandContext(ctx, "git", "status")
cmd.WaitDelay = 2 * time.Second // 兜底超时，防子进程残留管道
out, err := cmd.CombinedOutput()

2024 年之后再碰「调 Shell」这档子事，exec.CommandContext + WaitDelay 才是标准组合，别只拿 context 超时硬撑。

进程树清理与防止注入

在 Unix 上，CommandContext 一取消，默认只杀直接子进程，孙进程变孤儿照样跑。想端掉整个进程组，得自己配 Setpgid：

cmd := exec.CommandContext(ctx, "./worker.sh")
if cmd.SysProcAttr == nil {
    cmd.SysProcAttr = &syscall.SysProcAttr{}
}
cmd.SysProcAttr.Setpgid = true // 让子进程自成进程组

// 在 ctx 取消触达的 goroutine 里
_ = syscall.Kill(-cmd.Process.Pid, syscall.SIGKILL) // 负 PID = 整个进程组

安全上有两条铁律：其一，参数必须切片化传给 exec.Command，禁止拼 sh -c 字符串（这是命令注入的命门）；其二，用户输入原样塞进参数同样是大坑，尽量只把参数交给信得过的命令。Windows 平台还得留心 cmd.exe /C 的引号转义差异——跨平台脚本建议直接用 Go 原生实现或交叉编译产物，彻底绕开系统 shell 的行为差异。
