Go 1.21 正式带来 slices 包，泛型化的排序函数比老 sort 包更安全、更顺手：

import "slices"

// 泛型排序
slices.Sort(nums)                    // 升序
slices.SortFunc(nums, func(a, b int) int {
    return b - a                    // 降序
})
slices.SortStable(nums, cmp)        // 稳定排序

// 搜索
idx, found := slices.BinarySearch(nums, 42)

// 其他常用操作
slices.Contains(nums, 42)
slices.Reverse(nums)
slices.Min(nums)
slices.Max(nums)

底层原理：pdqsort 算法

Go 1.19+ 的 sort 包使用 pdqsort（Pattern-Defeating Quicksort），这是一种智能快速排序，能识别并击败常见的"反模式"输入。

pdqsort 核心思想

pdqsort 决策流程：

1. 短序列（< 12 元素）→ 插入排序（Insertion Sort）
   - 小数据量下常数因子优于 O(n log n) 算法

2. 中等序列 → 快速排序（Quick Sort）
   - 基准选择：三数取中（median-of-three）
   - 分区方案：Hoare 分区（双向扫描）
   
3. 检测到"坏模式" → 切换到堆排序（Heap Sort）
   - 递归深度超过 log2(n) * 2 时触发
   - 保证最坏情况 O(n log n)

4. 特殊模式优化：
   - 已有序/基本有序 → 插入排序
   - 大量重复元素 → 三路分区（Dutch National Flag）
   - 锯齿模式（sawtooth）→ 特殊基准选择

源码分析（sort.go 关键函数）

// src/sort/zsortinterface.go

func pdqsort(data Interface, a, b, limit int) {
    maxInsertion := 12
    for b-a > maxInsertion {
        // 1. 检测递归深度，超过限制则用堆排序
        if limit == 0 {
            heapSort(data, a, b)
            return
        }
        limit--

        // 2. 三数取中选择基准
        m := a + (b-a)/2
        if less(data, m, a) { swap(data, m, a) }
        if less(data, b-1, m) { swap(data, b-1, m) }
        if less(data, m, a) { swap(data, m, a) }

        // 3. Hoare 分区
        pivot := m
        swap(data, a, pivot)
        i := a + 1
        j := b - 1
        for {
            for i < b && less(data, i, a) { i++ }
            for j > a && less(data, a, j) { j-- }
            if i >= j { break }
            swap(data, i, j)
            i++
            j--
        }
        swap(data, a, j)

        // 4. 递归排序较小的一侧，较大一侧用循环（尾递归优化）
        if j-a < b-1-j {
            pdqsort(data, a, j, limit)
            a = j + 1
        } else {
            pdqsort(data, j+1, b, limit)
            b = j + 1
        }
    }
    // 5. 最后用插入排序收尾
    insertionSort(data, a, b)
}

常见陷阱与最佳实践

  • 陷阱1：Less 方法不满足严格弱序
    • 必须满足：非自反性（!less(a,a)）、反对称性（less(a,b) → !less(b,a)）、传递性
    • 常见错误：用 <= 代替 <，导致排序结果不确定
    • 浮点 NaN 比较：NaN 与任何数比较都返回 false，会破坏排序
  • 陷阱2：Sort 不是稳定排序
    • sort.Sort() 不保证相等元素的相对顺序
    • 需要稳定排序时用 sort.Stable()，但性能略差（约 1.5x）
    • 多字段排序时，优先字段相同时次字段顺序可能被打乱
  • 陷阱3：频繁排序大切片
    • 排序是 O(n log n)，大数据量下避免在热路径中重复排序
    • 如果只需要 Top K，用 sort.Slice + 截断，或用堆（container/heap）
    • 部分排序用 sort.Partition（Go 1.22+ 实验性 API）
  • 最佳实践：泛型排序（Go 1.21+）
    • slices.Sort() 比 sort.Slice() 快 20-30%（避免接口调用开销）
    • slices.SortFunc() 支持自定义比较函数
    • slices.BinarySearch() 二分查找，O(log n)
