泛型进阶

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • Go 1.18 引入类型参数，是 Go 自 1.0 以来最大的语法变更
  • 泛型函数：T 是类型参数，any 等同于 interface{}，约束用接口表达
  • 从基础到进阶：泛型函数、泛型类型、约束组合与实际应用模式

关键结论与取舍

  • 泛型能显著减少样板代码，但复杂度也随约束增长，先用简单约束起步
  • 生产代码里优先核：工具函数（集合操作）用泛型，业务实体慎用

Go 泛型进阶（1.18-1.24）

泛型（Type Parameters）是 Go 1.18 空降的，号称自 1.0 以来最猛的一次语法地震。这篇把泛型的核心概念和落地姿势过一遍。

基本语法

// 泛型函数：T 是类型参数，any 是约束（等同 interface{}）
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}

// 使用
nums := []int{1, 2, 3, 4, 5}
fmt.Println(Reverse(nums)) // [5 4 3 2 1]

strs := []string{"a", "b", "c"}
fmt.Println(Reverse(strs)) // [c b a]

类型约束

// cmp.Ordered：Go 1.21+ 标准库的排序约束（替代已废弃的 golang.org/x/exp/constraints）
import "cmp"

// Ordered 约束：支持 < <= > >= 的类型
func Min[T cmp.Ordered](a, b T) T {
    if a < b {
        return a
    }
    return b
}

// 自定义约束
type Number interface {
    int | int8 | int16 | int32 | int64 |
    float32 | float64
}

func Sum[T Number](nums []T) T {
    var total T
    for _, n := range nums {
        total += n
    }
    return total
}

// 使用 ~ 表示底层类型
type StringList []string
func Process[T ~[]string](v T) {
    // T 可以是 []string 或 StringList
}

泛型工具函数

// Map: 对切片每个元素应用函数
func Map[T, U any](s []T, f func(T) U) []U {
    result := make([]U, len(s))
    for i, v := range s {
        result[i] = f(v)
    }
    return result
}

// Filter: 过滤切片
func Filter[T any](s []T, pred func(T) bool) []T {
    result := make([]T, 0, len(s))
    for _, v := range s {
        if pred(v) {
            result = append(result, v)
        }
    }
    return result
}

// Reduce: 聚合
func Reduce[T, U any](s []T, init U, f func(U, T) U) U {
    result := init
    for _, v := range s {
        result = f(result, v)
    }
    return result
}

// 使用示例
nums := []int{1, 2, 3, 4, 5}
doubled := Map(nums, func(n int) int { return n * 2 })
evens := Filter(nums, func(n int) bool { return n%2 == 0 })
sum := Reduce(nums, 0, func(acc, n int) int { return acc + n })

泛型类型

// 泛型栈
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) {
    s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 {
        return zero, false
    }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

// 泛型 Map
type Map[K comparable, V any] struct {
    data map[K]V
}

func (m *Map[K, V]) Set(key K, value V) {
    if m.data == nil {
        m.data = make(map[K]V)
    }
    m.data[key] = value
}

func (m *Map[K, V]) Get(key K) (V, bool) {
    v, ok := m.data[key]
    return v, ok
}

Go 1.22+ 改进

Go 1.22 把泛型类型推断的水准又抬了一截：

// Go 1.22 前需要显式指定类型
func Compare[T cmp.Ordered](a, b T) int { ... }
result := Compare[int](1, 2)

// Go 1.22+ 可以推断
result := Compare(1, 2) // 自动推断 T=int

// 支持从函数参数推断类型参数
func NewSet[T comparable](items ...T) *Set[T] { ... }
s := NewSet(1, 2, 3) // 自动推断 T=int

Go 1.24+：泛型类型别名

Go 1.24（2025-02）把「带类型参数的别名」扶正（type alias with type parameters），总算补上 Go 1.9 别名与泛型之间的最后一块拼图：

// Go 1.24 前非法，1.24 起合法——带类型参数的别名
// 实例化别名：与直接定义等价，可用于 API 演进而不断言

此前这种 type X[T any] = Y[T] 一律编译报错；1.24 之后，库作者终于敢把「别名形态」的泛型 API 摆上台面。再加上 1.21 的 slices/maps、1.23 的 iter （range-over-func），到 2026 年，Go 的「泛型 + 函数式」工具箱已经相当趁手。

使用建议

  1. 泛型不是装饰品：只有真要多类型复用代码时才值得上。
  2. 标准库优先：slices、maps 包（1.21 起）把常用泛型工具备齐了。
  3. 约束越松越好：没到非要特定操作的地步，就用 any 或 comparable 。
  4. 留神编译速度：泛型上瘾会拖慢编译。
  5. 泛型也有水土不服的场景：就两种三种类型的话，直接码具体类型反而更清爽。
