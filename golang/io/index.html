IO

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • Read 可返回 n < len(p) 且 err == nil，必须循环读或用 io.ReadFull
  • 返回 n > 0 时可能同时带错误，先处理 n 再判断 err
  • io.Copy 自带 32KB 缓冲并探测 ReaderFrom/WriterTo 走直拷路径

关键结论与取舍

  • 接口抽象：Reader/Writer/Seeker/Closer；便利函数覆盖开箱惯用场景
  • “能读多少读多少”是 Go IO 调用的根本心法，遇 Bug 先检查读循环
适合谁读写过 Go 但被 IO 边界坑过的开发者 读完可获得Reader/Writer 契约、类型体系与 2024—2026 新增 IO 便利函数的速查

  • Reader 接口
type Reader interface {
    // 读取len(p)字节到p里面
    // 返回读取成功字节数
    // eof表示正常结束
    Read(p []byte) (n int, err error)
}
  • Writer 接口
type Writer interface {
    // 写入p里面内容,len(p)字节
    // 返回写入成功字节数
    Write(p []byte) (n int, err error)
}

Go IO 更新（2024-2026）

下面这批能力多数是 Go 1.16–1.21 陆续落地的，2026 年的工程实践基本都按这套思路写 IO，旧的 ioutil 那套写法已彻底出局：

  • io/fs 从 Go 1.16 起转正，虚拟文件系统成了标配：同一份读路径，生产环境能跑在 os.DirFS 、embed.FS 上，测试时切到 fstest.MapFS 就行。
  • ioutil 已经废弃，迁移路径很固定：ioutil.ReadAll 换 io.ReadAll ，ioutil.ReadFile 换 os.ReadFile ，ioutil.TempFile 换 os.CreateTemp 。
  • errors.Join （Go 1.20 引入）能把多个独立操作的错误攒成一个，批量读、批量校验时特别好用。
  • log/slog （Go 1.21 引入）是官方结构化日志库，日志流可以接到任意 io.Writer 上，测试时直接断言 buffer 里写了什么就行。

老手视角：io.Reader 的契约从来都是"能读多少算多少"——返回 n < len(p) 而且 err == nil 是完全合法的，得循环读到吐，或者干脆上 io.ReadFull ；反过来，哪怕返回 n > 0 ，错误也可能同时在场，先看 n 再判 err 才不出错。io.Copy 自己就带 32KB 缓冲，还会探测对方有没有实现 ReaderFrom /WriterTo 这类接口，直接走零拷贝路径；搬数据这类粗活交给它，别自己写循环。
