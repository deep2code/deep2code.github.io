核心观点

  • 经典泛型 GroupBy：func Groupby[T any, K comparable](items, keyFn) map[K][]T
  • Go 1.23+ 可用迭代器（iterator）版 group by，惰性更省内存
  • 泛型方法时代的选型建议：普通切片用 slices/maps 组合

关键结论与取舍

  • 数据量小优先简洁的 map 版本；大数据流转迭代器版
  • 避免每次分组手写循环，统一为小组件复用

func GroupBy[T any, U comparable](collection []T, iteratee func(T) U) map[U][]T {
 result := map[U][]T{}

 for _, item := range collection {
  key := iteratee(item)

  result[key] = append(result[key], item)
 }

 return result
}

Go 1.21 带来的 slices 与 maps 两个包把「分组」这操作简化了不少：

import "slices"
import "maps"

// 泛型分组函数
func GroupBy[T any, K comparable](items []T, keyFn func(T) K) map[K][]T {
    result := make(map[K][]T)
    for _, item := range items {
        k := keyFn(item)
        result[k] = append(result[k], item)
    }
    return result
}

// 使用
type Order struct{ ID string; Status string }
orders := []Order{{"1", "paid"}, {"2", "pending"}, {"3", "paid"}}
grouped := GroupBy(orders, func(o Order) string { return o.Status })
// grouped["paid"] = [{1 paid}, {3 paid}]
// grouped["pending"] = [{2 pending}]

Go 1.23+：迭代器版的 group by

Go 1.23（2024-08）把 range-over-func 扶正，还给 slices / maps 补全了整套迭代器 API：slices.Values / All / Backward 负责产出迭代器，Collect / AppendSeq 负责收回切片，Chunk 直接原地切成等长子切片；map 那头有 maps.Keys / Values / All 和 maps.Collect。于是分组可以走「切片 → 迭代器 → map」的流式写法：

// Go 1.23+：迭代器风格
import "iter"
import "slices"

func GroupBySeq[T any, K comparable](seq iter.Seq[T], keyFn func(T) K) map[K][]T {
    out := make(map[K][]T)
    for v := range seq {
        k := keyFn(v) // 只算一次 key,别在 append 里重复调用函数
        out[k] = append(out[k], v)
    }
    return out
}

// 切片通过 Values 转成迭代器传入
groups := GroupBySeq(slices.Values(orders), func(o Order) string { return o.Status })

泛型方法时代的选型

Go 1.27（2026-08-19 发布）放开了泛型方法，分组逻辑因此能直接长在具体类型上——读起来更像「给数据结构加方法」：

// Go 1.27+：泛型方法
type Items[T any] []T

func (s Items[T]) GroupBy[K comparable](keyFn func(T) K) map[K][]T {
    out := make(map[K][]T)
    for _, v := range s {
        out[keyFn(v)] = append(out[keyFn(v)], v)
    }
    return out
}

选型建议：线上那些手写泛型实现（上面 1.21 那版）完全兼容，不用折腾；新代码看场景——数据量小、图省事就上迭代器写法；热路径且数据量大，还是留着手写循环（迭代器封装本身有一层间接开销）；samber/lo 这类三方泛型工具库（2026 年还在活跃发版）可以当备胎，不过标准库早已覆盖绝大多数分组场景。
