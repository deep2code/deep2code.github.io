regexp 包

AI 导读一分钟导读，先掌握全文主干。▼

核心观点

  • Go regexp 实现 RE2 语法，支持 Unicode 字符类
  • 不支持回溯引用（backreferences）与零宽断言（lookaround），这是刻意的权衡
  • 换来的是线性时间匹配，杜绝正则回溯攻击（ReDoS）

关键结论与取舍

  • 有回溯/断言需求时改用手写解析或用其它引擎（如 PCRE 的第三方包装）
  • 编译期可感知的代价换来性能确定性，服务端首选
适合谁读在 Go 里做文本处理、校验与解析的开发者 读完可获得Go 正则能力边界清单与替代方案，明白正则怎么“选对用对”

Go 标准库的 regexp 包自带 RE2 方言的正则引擎：Unicode 字符类完整支持，代价是刻意砍掉了回溯引用（backreferences）与零宽断言（lookaround）两类能力。

基本用法

package main

import (
    "fmt"
    "regexp"
)

func main() {
    // 编译正则表达式（MustCompile 遇到错误会 panic）
    // 连续的汉字字母数字
    maxHanDigitAlphaReg := regexp.MustCompile(`[\p{Han}[:digit:][:alpha:]]+`)
    // 单个汉字字母数字（非贪婪）
    minHanDigitAlphaReg := regexp.MustCompile(`[\p{Han}[:digit:][:alpha:]]+?`)

    text := "Hello世界123!"

    // 查找所有匹配
    matches := maxHanDigitAlphaReg.FindAllString(text, -1)
    fmt.Println(matches) // [Hello世界123]

    // 查找第一个匹配
    first := minHanDigitAlphaReg.FindString(text)
    fmt.Println(first) // H
}

Compile vs MustCompile

// Compile 返回错误，适合正则来自用户输入
re, err := regexp.Compile(`[invalid`)
if err != nil {
    log.Fatal(err)
}

// MustCompile 遇到错误时 panic，适合正则是硬编码的场景
re = regexp.MustCompile(`\d+`)

常用操作

re := regexp.MustCompile(`(\w+)@(\w+)\.(\w+)`)
email := "user@example.com"

// 1. 匹配测试
matched := re.MatchString(email) // true

// 2. 提取子匹配
submatch := re.FindStringSubmatch(email)
// ["user@example.com", "user", "example", "com"]

// 3. 提取命名子匹配
namedRe := regexp.MustCompile(`(?P\w+)@(?P\w+)\.(?P\w+)`)
result := namedRe.FindStringSubmatch(email)
names := namedRe.SubexpNames()
for i, name := range names {
    if name != "" {
        fmt.Printf("%s: %s\n", name, result[i])
    }
}

// 4. 替换
replaced := re.ReplaceAllString(email, "$1 at $2 dot $3")
// "user at example dot com"

// 5. 分割
splitRe := regexp.MustCompile(`[,\s]+`)
parts := splitRe.Split("a, b, c d", -1)
// ["a", "b", "c", "d"]

Unicode 支持

// 匹配中文字符
hanRe := regexp.MustCompile(`[\p{Han}]+`)
fmt.Println(hanRe.FindAllString("Hello世界，你好", -1)) // [世界 你好]

// 匹配中文、字母、数字
allRe := regexp.MustCompile(`[\p{Han}\p{L}\p{N}]+`)
// 注意：[:digit:] [:alpha:] 等 POSIX 类只匹配 ASCII，中文数字、全角字母必须用 \p{N} \p{L}

// 匹配日文假名
jpRe := regexp.MustCompile(`[\p{Hiragana}\p{Katakana}]+`)

性能建议

  1. 预编译要养成习惯：把正则挪到包级变量或 init 里编译一次，别让热路径上的每次调用都重建引擎。
  2. 入口选 regexp.Compile：正则来自外部输入的一定要走 Compile，把编译失败当业务错误处理，别悄悄吞掉。
  3. 别把 PCRE 的「防回溯」心智带进 Go：RE2 是线性时间、无回溯执行，灾难性回溯（ReDoS）在这里根本不成立；+?/*? 只切换最短/最长这层匹配偏好，按当前场景挑一个就行。
  4. RE2 的两条硬限制：回溯引用、零宽断言 Go 的 RE2 都给不了，确有需求就去借 github.com/dlclark/regexp2 这类兼容层。
  5. 2026 年回头看：regexp 是标准库最省心的组件之一，1.18 到 1.27 行为零变化。除非业务必须回溯引用/零宽断言，否则别引 regexp2——日志解析、文本抽取这类日常活，RE2 完全够用，还顺带把 ReDoS 风险归零。
