常见编译变量参数

SHELL := /usr/bin/env bash -o pipefail

GIT_VERSION ?= $(shell git describe --always --tags --match 'v*' --dirty)
COMMIT     ?= $(shell git rev-parse HEAD)
BRANCH     ?= $(shell git rev-parse --abbrev-ref HEAD)
BUILD_DATE ?= $(shell date +%s)
BUILD_HOST ?= $(shell hostname)
BUILD_USER ?= $(shell id -un)

变量不同赋值区别

= 是最基本的赋值
:= 是覆盖之前的值
?= 是如果没有被赋值过就赋予等号后面的值
+= 是添加等号后面的值

= 是递归展开：值里的变量引用到使用时 才展开，写起来宽松，但变量互相引用时容易「套娃」出意外；`:=` 立即展开，赋值瞬间解析完毕，多数场景用 := 更稳。+= 的展开风格跟随它前面定义用的符号（= 或 :=）；?= 只在变量尚未赋值时生效，正是用来给参数提供默认值的——比如上面的 GIT_VERSION，命令行传 make GIT_VERSION=v1.2.3 即可覆盖。

Makefile 更新

GNU Make 的现行稳定版仍是 4.4.1 （2023-02 发布），至今没出新 major——Make 并没消亡，在 C/C++、内核、系统级项目里依然是事实标准（依赖时间戳的增量构建模型无可替代）。真正的变化发生在应用层：Go / Rust / Node 项目纷纷引入更现代的「任务运行器」。2026 年主流选择如下：

现代任务运行器对照

工具语言/配置特点
Task（go-task）Go / YAML（Taskfile.yml，version 3）无 Tab 缩进坑、跨平台、支持依赖与并行，Go 项目事实标准，brew 可装
JustRust / Justfile语法贴近 Make 但更干净，适合当「项目命令手册」，别名与参数支持好
MageGo / 纯 Go 代码用 Go 写任务（mage build），类型安全、可调试，适合重度 Go 项目
XmakeLua / xmake.luaC/C++ 构建 + 包管理一体化，可对标 Ninja 速度

选型判断

先分清两件事：Make 是「构建系统」（依赖图 + 时间戳增量），Task / Just / Mage 是「任务运行器」（把一串命令变成具名任务）——想省重复命令选后者，需要可靠增量编译仍得靠前者，两者不冲突可以并存。2026 年的新观察：YAML / Justfile 的声明式写法对 AI 生成和审计更友好（Makefile 的 Tab 规则是 LLM 输出的高频出错点），新
