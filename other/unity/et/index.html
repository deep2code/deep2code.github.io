游戏热更目前主流的解决方案

  1. 分 Lua(ulua/slua/xlua/tolua)系

  2. ILRuntime 代表的 C# 系

  3. HybridCLR（原 huatuo）代表的 IL2CPP 解释器系——2021 年后国内 Unity 热更的主流选择

ET 框架介绍

  1. 早期版本采用基于 C# 的 ILRuntime 热更；ET 7+ 已切换为 HybridCLR（原 huatuo）

  2. 客户端目录结构

ET 框架更新

  • 热更方案：ET 7+ 从 ILRuntime 切换为 HybridCLR（原 huatuo），补丁代码经 IL2CPP 解释器模式运行；
  • 架构：双端共享 C# 逻辑、ECS 组件化与基于 KCP 的网络层是核心设计，近年版本持续迭代；
  • 仓库：主仓库 egametang/ET 在 GitHub，新项目建议从最新 release 分支起步。

ET 框架概述

ET（Entity Threading）是一个开源的游戏服务器框架，使用 C# 开发，支持热更新。框架设计理念是"简单、易用、功能强大"，广泛应用于手游服务端开发。

核心特性

  • 双端合一：客户端和服务端使用同一套代码，逻辑可复用
  • ECS 架构：Entity-Component-System 设计模式
  • 热更新：支持运行时更新代码，无需重新启动
  • 高并发：基于 KCP 的可靠 UDP 通信
  • 多线程：Actor 模式支持多线程处理

快速开始

环境要求

  • .NET 8.0+
  • Unity 2021.3+
  • MySQL 8.0+ 或 MongoDB

克隆项目

# 克隆 ET 仓库
git clone https://github.com/egametang/ET.git

# 切换到对应版本
cd ET
git checkout release/7.0

# 还原依赖
dotnet restore

运行服务器

# 启动 Gate 服务器
cd ./Server/Model/Module/Message/
dotnet run --project ET.exe -- --AppType=Gate

# 启动 Map 服务器
dotnet run --project ET.exe -- --AppType=Map

# 启动 Manager 服务器
dotnet run --project ET.exe -- --AppType=Manager

运行客户端

在 Unity 中打开 ./Unity/Assets/Bundles/ET.Client 项目，加载 Scenes 目录下的启动场景即可运行。

网络通信

通信协议

ET 使用自定义的 .protoc 协议文件定义消息格式：

// 消息定义示例
message C2G_LoginGateRequest
{
    int32 RpcId = 1;
    string Account = 2;
    string Password = 3;
}

message G2C_LoginGateResponse
{
    int32 RpcId = 1;
    int32 Error = 2;
    string Message = 3;
    int64 PlayerId = 4;
}

KCP 协议

ET 使用 KCP（可靠 UDP）作为底层传输协议，相比 TCP 具有更低的延迟：

  • RTO 优化：快速重传机制
  • 拥塞控制：自适应拥塞窗口
  • 流式传输：支持大文件分片

消息分发

// 消息处理示例
[MessageHandler]
public class C2G_LoginGateHandler : AMHandler
{
    protected override async ETTask Run(Session session, C2G_LoginGateRequest request)
    {
        // 处理登录逻辑
        var response = new G2C_LoginGateResponse
        {
            Error = 0,
            PlayerId = session.PlayerId
        };
        session.Reply(response);
    }
}

HybridCLR 热更新

HybridCLR 简介

HybridCLR 是 Unity 的 C# 原生运行时热更方案，基于 IL2CPP 解释器实现：

  • 完全兼容：99% 代码兼容 IL2CPP
  • 高性能：解释器性能优化
  • 无缝集成：与 Unity 编辑器完美配合

配置步骤

  1. 从 Package Manager 安装 HybridCLR
  2. 在 Player Settings 中启用 IL2CPP
  3. 配置热更程序集
  4. 打包时勾选 "HybridCLR Data"

使用方法

// 加载热更程序集
var assembly = HybridCLR.RuntimeApi.LoadAssemblyForHotUpdate("HotUpdate.dll");

// 调用热更方法
var type = assembly.GetType("HotUpdate.TestClass");
var method = type.GetMethod("HotUpdateMethod");
method.Invoke(null, null);

数据库操作

MongoDB 支持

ET 内置 MongoDB 组件，支持实体持久化：

// 保存实体到数据库
await EntityDB.Instance.SaveComponent(playerId, player.GetComponent());

// 从数据库加载
var playerData = await EntityDB.Instance.GetComponent(playerId);

MySQL 支持

使用 MongoDB 之外的 MySQL 进行数据存储：

// 使用 Dapper 进行 MySQL 操作
using var connection = DBComponent.Instance.GetConnection();
var players = await connection.QueryAsync("SELECT * FROM player WHERE Level > 10");

最佳实践

代码组织

  • 服务端代码放在 Server/ 目录
  • 客户端代码放在 Unity/Assets/ 目录
  • 共享代码使用 Linkshare 机制

性能优化

  • 使用对象池减少 GC
  • 批量处理数据库操作
  • 合理使用消息队列缓冲
  • 启用 AOI 区域管理减少同步量

调试技巧

  • 使用 ET 提供的日志系统
  • 开启 Debug 模式查看网络包
  • 使用 Unity Profiler 分析性能
  • 配置本机多进程调试
