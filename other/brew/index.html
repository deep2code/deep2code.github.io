官网

  • Homebrew 类似一个软件中心，可以理解成 App Store 或 Google Play 那样的软件商店，只不过 Homebrew 比它们以及 Mac App Store 的资源更丰富，管理也更高效。
  • Homebrew Cask 建在 Homebrew 之上，专门装 GUI 应用，是 Homebrew 的扩展（formula 负责命令行工具，cask 负责 .app 应用）。
  • homebrew——自家酿酒（名字梗）
  • formula——配方（描述怎么装某个软件的 Ruby 脚本）
  • keg——酒桶（单个已安装版本的目录，在 Cellar 下面）
  • Cellar——地窖（/opt/homebrew/Cellar，存放所有已安装版本）

Homebrew 6.0 时代

Homebrew 6.0：信任机制与性能

2026-06-11 发布 Homebrew 6.0.0，自 5.1.0 以来最要紧的变化：

  • Tap 信任机制（tap trust）：新的安全机制约束第三方 tap 的权限和影响范围，降低供应链风险——安装第三方 tap 时能拿到更明确的信任边界。
  • 默认内部 JSON API 更快更小：默认数据通道升级成新的内部 JSON API，体积更小、解析更快。
  • Linux 沙箱化（sandboxing）：Linux 上的安装操作默认在沙箱里跑，隔离安装副作用。
  • brew bundle 大量改进：bundle 能力明显扩展（含 uv tools 等新形态依赖的声明式支持）。
  • macOS 27 Golden Gate 初步支持：跟上 Apple 新系统线（仅 Apple Silicon）。
  • 默认值改进：由用户调查驱动的默认行为调整和整体性能优化。

Homebrew 架构深度解析

Homebrew 内部原理

Homebrew 是 macOS（和 Linux）最流行的包管理器，理解其内部原理有助于排查问题和优化使用：

  • 核心组件：
    • brew（Ruby 脚本）：Homebrew 的主程序，是一个 Ruby 脚本（/opt/homebrew/bin/brew），解析命令行参数，调用对应的子命令。brew 本身是一个 shell 脚本包装器，设置环境变量后调用 Ruby
    • Library/Homebrew：Homebrew 的 Ruby 代码库，包含：CLI 解析（cli.rb）、公式加载（formula.rb）、构建系统（build.rb）、下载（download.rb）、安装（install.rb）、依赖解析（dependency.rb）、升级（upgrade.rb）等核心逻辑
    • Taps（仓库）：Formula 和 Cask 的定义仓库，默认是 homebrew/core（Formula）和 homebrew/cask（Cask）。Taps 是 Git 仓库，通过 brew tap 添加，存储在 /opt/homebrew/Library/Taps/。第三方 tap 可以添加自定义公式
    • Formula（配方）：Ruby 类，继承自 Formula，定义包的名称、版本、源码 URL、依赖、编译选项、安装步骤（install 方法）。Formula 是 Ruby DSL，可以使用 Ruby 的所有特性（条件判断、循环、函数）
    • Bottle（瓶子）：预编译的二进制包，是 .tar.gz 格式，包含编译好的文件。Bottle 由 Homebrew 核心团队在 CI（GitHub Actions）上编译，针对特定 macOS 版本和 CPU 架构。Bottle 的 URL 在 Formula 中定义（bottle do 块）。安装时优先使用 Bottle，只有没有 Bottle 或指定 --build-from-source 时才从源码编译
  • 安装流程：
    1. 依赖解析：递归解析 Formula 的依赖（depends_on），构建依赖图，按拓扑排序确定安装顺序。Homebrew 的依赖解析是纯函数式的，不依赖外部状态
    2. 下载：下载源码包（.tar.gz/.zip/.tar.xz）或 Bottle（.tar.gz），存储到 ~/Library/Caches/Homebrew/。下载支持缓存（相同 URL 不重复下载）、校验和验证（SHA256）、镜像（mirror，主 URL 失败时使用镜像）
    3. 解压与构建：如果使用 Bottle，直接解压到临时目录。如果从源码编译，解压源码到临时目录（/tmp/brew-xxx），执行 Formula 的 install 方法（通常是 system "./configure", "--prefix=..."; system "make"; system "make install" 或 CMake/Meson 等构建系统）。构建环境是隔离的（设置 PATH、PKG_CONFIG_PATH、编译器标志等）
    4. 安装到 Cellar：构建产物安装到 /opt/homebrew/Cellar/<name>/<version>/（Cellar 目录），每个版本独立。Cellar 目录包含 bin、lib、include、share、etc 等子目录
    5. 链接到 Prefix：通过符号链接（symlink）将 Cellar 中的文件链接到 /opt/homebrew/bin、/opt/homebrew/lib、/opt/homebrew/include 等 Prefix 目录。brew link 创建链接，brew unlink 移除链接。同一时间只有一个版本被链接（默认最新版本），可以用 brew switch 切换版本
    6. 清理：删除临时构建目录，旧版本可以用 brew cleanup 清理（删除旧版本和下载缓存）
  • 依赖管理：Homebrew 的依赖分为：
    • 运行时依赖（depends_on）：包运行时需要的依赖，会被安装并链接。如 depends_on "openssl@3"
    • 构建依赖（depends_on => :build）：只在编译时需要，运行时不需要。如 depends_on "cmake" => :build。Bottle 安装时不需要构建依赖
    • 测试依赖（depends_on => :test）：只在 brew test 时需要
    • 可选依赖（depends_on => :optional）：通过 --with-xxx 选项启用。Homebrew 核心仓库已弃用可选依赖（因为 Bottle 是固定配置，可选依赖会导致 Bottle 不匹配）
    • 推荐依赖（depends_on => :recommended）：默认启用，通过 --without-xxx 禁用。同样已被核心仓库弃用

8大常见陷阱与最佳实践

  1. Apple Silicon 与 Intel 路径差异导致脚本失效：Homebrew 在 Apple Silicon（M1/M2/M3/M4）上安装到 /opt/homebrew，在 Intel 上安装到 /usr/local。硬编码路径的脚本（如 /usr/local/bin/ffmpeg）在 Apple Silicon 上会失败。解决：使用 brew --prefix 获取当前 Homebrew 前缀（$(brew --prefix)/bin/ffmpeg），或使用 which ffmpeg 查找路径。在 shell 配置中添加 eval "$(/opt/homebrew/bin/brew shellenv)"（Apple Silicon）或 eval "$(/usr/local/bin/brew shellenv)"（Intel），自动设置 PATH、MANPATH、INFOPATH。编写跨架构脚本时，检测架构（uname -m，arm64 或 x86_64）选择正确路径。注意：Rosetta 2 下运行的 x86_64 Homebrew 安装到 /usr/local，与原生 ARM64 Homebrew（/opt/homebrew）可以共存，但不建议同时使用（可能混淆）
  2. 权限问题导致 brew update/install 失败：Homebrew 要求 /opt/homebrew（或 /usr/local）目录及其子目录的所有者是当前用户（不是 root）。如果目录权限被破坏（如使用 sudo 运行 brew、手动修改权限、迁移用户账户），会导致 brew update 失败（Git 无法 pull）、brew install 失败（无法写入 Cellar）。解决：运行 brew doctor 诊断权限问题，按提示修复。通常需要 sudo chown -R $(whoami) /opt/homebrew（或 /usr/local）修复所有者。永远不要用 sudo 运行 brew（Homebrew 设计为不需要 root 权限，使用 sudo 会破坏权限并可能引入安全风险）。如果 brew 提示需要 sudo，说明权限已经被破坏，需要先修复权限。多用户共享一台 Mac 时，考虑使用管理员组（admin）并设置目录组权限（chgrp -R admin /opt/homebrew; chmod -R g+w /opt/homebrew），但 Homebrew 官方不推荐多用户共享
  3. brew cleanup 误删仍在使用的旧版本：brew cleanup 会删除所有旧版本的 Formula（只保留最新版本）和下载缓存。如果某些软件依赖特定旧版本（如 Python 脚本依赖 python@3.9，而最新是 python@3.11），cleanup 后旧版本被删除，依赖会失效。解决：使用 brew cleanup -n（dry-run）先查看会删除什么，确认无误后再执行。使用 brew pin <formula> 固定特定版本（pin 后 cleanup 不会删除该版本），brew unpin 取消固定。对于需要多版本共存的场景（如 Python 3.9 和 3.11），使用版本化的 Formula（python@3.9、python@3.11），它们是独立的 Formula，不会互相覆盖。定期运行 cleanup（释放磁盘空间），但在关键环境（生产服务器、CI）中谨慎使用，先测试
  4. 从源码编译失败（build from source）：Homebrew 优先使用 Bottle（预编译二进制），但在某些情况下会从源码编译：没有对应 macOS 版本/架构的 Bottle、指定 --build-from-source、Formula 被修改（brew edit）。从源码编译可能失败，原因包括：Xcode Command Line Tools 未安装或版本过旧、依赖库版本不兼容、编译选项错误、网络问题导致依赖下载失败。解决：确保安装最新的 Xcode Command Line Tools（xcode-select --install，或 sudo xcode-select --switch /Applications/Xcode.app 如果安装了完整 Xcode）。优先使用 Bottle（不要随意使用 --build-from-source）。编译失败时查看完整日志（brew install -v <formula> 显示详细输出，日志存储在 ~/Library/Logs/Homebrew/）。常见缺失依赖：pkg-config、cmake、autoconf、automake、libtool，可以先 brew install 这些构建工具。对于持续编译失败的 Formula，考虑使用替代包（如 ffmpeg 有多个 tap 版本）或使用 Docker/Linux 环境
  5. Cask 应用更新与 App Store 冲突：Homebrew Cask 安装的 GUI 应用（brew install --cask google-chrome）和 App Store 安装的应用是独立的，可能同时存在两个版本（一个在 /Applications，一个也在 /Applications 但来源不同），导致混淆。Cask 应用的更新通过 brew upgrade --cask，而 App Store 应用通过 App Store 更新，两者不同步。解决：选择一种安装方式并保持一致（要么都用 Cask，要么都用 App Store，不要混用）。Cask 的优势：可以脚本化安装/更新、支持非 App Store 应用、统一管理。App Store 的优势：自动更新、沙盒安全、购买记录。对于需要自动更新的应用（如浏览器、编辑器），Cask 安装后应用自身也会提示更新（与 brew 管理的版本可能冲突），可以在应用设置中关闭自动更新，统一用 brew upgrade --cask 更新。使用 brew list --cask 查看已安装的 Cask 应用，brew outdated --cask 查看可更新的 Cask。注意：Cask 升级（brew upgrade --cask）默认会覆盖现有应用，即使应用正在运行（可能导致崩溃），升级前关闭相关应用
  6. PATH 顺序错误导致使用了错误的命令版本：Homebrew 的 bin 目录（/opt/homebrew/bin）需要在 PATH 中优先于系统路径（/usr/bin、/bin），否则会使用系统自带的旧版本命令（如系统的 bash 3.2 而非 brew 安装的 bash 5.x，系统的 python 2.7 而非 brew 的 python 3.x）。解决：确保 shell 配置文件（~/.zshrc、~/.bashrc）中 Homebrew 的 bin 目录在 PATH 最前面。使用 eval "$(brew shellenv)" 自动设置（推荐，会处理 PATH、MANPATH、INFOPATH）。验证：which bash 应该返回 /opt/homebrew/bin/bash（而非 /bin/bash），bash --version 应该是 5.x。注意：eval "$(brew shellenv)" 应该放在 shell 配置文件的最前面（在其他 PATH 修改之前），确保 Homebrew 路径优先。某些 shell 框架（Oh My Zsh、Prezto）可能修改 PATH，确保它们不会将系统路径放在 Homebrew 前面。使用 echo $PATH 查看实际 PATH 顺序
  7. brew update 慢或失败（网络问题）：brew update 需要从 GitHub 拉取 homebrew/core、homebrew/cask 等 tap 的 Git 更新，国内网络访问 GitHub 可能慢或失败（超时、连接重置）。解决：使用国内镜像源。中科大镜像：git -C "$(brew --repo)" remote set-url origin https://mirrors.ustc.edu.cn/brew.git，git -C "$(brew --repo homebrew/core)" remote set-url origin https://mirrors.ustc.edu.cn/homebrew-core.git，git -C "$(brew --repo homebrew/cask)" remote set-url origin https://mirrors.ustc.edu.cn/homebrew-cask.git。设置环境变量 export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles（使用国内 Bottle 镜像，加速下载）。其他镜像：清华 TUNA（https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git）、阿里云。注意：切换镜像后，brew update 从镜像拉取，但镜像可能比官方滞后几小时到一天。如果需要最新版本，可以临时切回官方源。使用代理（export ALL_PROXY=socks5://127.0.0.1:1080）也是一种方式（如果有代理）。诊断网络问题：brew update --verbose 查看详细输出，curl -v https://github.com 测试 GitHub 连通性
  8. 卸载不彻底导致残留文件：brew uninstall <formula> 只删除 Cellar 中的文件和符号链接，但不会删除 Formula 安装时创建的配置文件（通常在 ~/.config/、~/Library/Application Support/、/opt/homebrew/etc/）、数据文件（数据库、日志）、服务文件（~/Library/LaunchAgents/）。这些残留文件会占用磁盘空间，且重新安装时可能使用旧配置导致问题。解决：卸载前先停止服务（brew services stop <formula>）。使用 brew uninstall --zap <cask>（Cask 专用，--zap 会删除应用相关的配置和数据文件）。对于 Formula，手动查找并删除残留：配置文件在 /opt/homebrew/etc/（Homebrew 管理的配置）和用户目录（~/.config/<name>、~/Library/Application Support/<name>），数据文件在 /opt/homebrew/var/（数据库、日志），服务文件在 ~/Library/LaunchAgents/homebrew.mxcl.<name>.plist。使用 brew list <formula> 查看 Formula 安装的文件列表（只包含 Cellar 中的文件，不包含用户配置）。对于重要数据（如数据库），卸载前先备份（mysqldump、pg_dump）。注意：brew uninstall 不会删除依赖（依赖可能被其他包使用），使用 brew autoremove 删除不再被任何包依赖的孤儿依赖

Apple Silicon 安装前缀仍是 /opt/homebrew；macOS Intel 已进入弃用倒计时（官方博客公布了时间表，Intel Mac 用户建议规划迁移）。常用姿势：
