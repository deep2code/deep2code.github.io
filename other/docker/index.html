container容器管理

#默认显示运行的容器
docker ps

#显示所有容器
docker ps -a

# attach模式, 类似运行于前台的进程，会占据本地的STDIN和STDOUT
docker run nginx

# detach模式,可以用docker container attach id改为attach模式,类似于后台运行
docker run -d nginx

# 与容器的交互

docker run -it id(container id) command 当command运行结束之后，container的状态也变成了exited的状态
docker exec -it id command 当command运行结束之后，container的状态保持running状态不变

docker stop $(docker ps -q)

#已经停止的，正在运行的不能删除
docker rm $(docker ps -a -q)

私有部署dockerhub

# 利用docker公司提供的工具
docker pull registry

# -v 主机目录:容器目录,registry存储仓库中镜像到/var/lib/registry
docker run -d -p 5000:5000 --restart=always -v /opt/dockerhub:/var/lib/registry registry

# 从dockerhub拉取nginx最新版
docker pull nginx
# 打上特定hub的标签
docker tag nginx localhost:5000/nginx
# 推送nginx到目标hub中去
docker push localhost:5000/nginx

# http://主机ip:5000/v2/_catalog 查看信息

# 增加配置,docker默认走https，但是registry默认走http /etc/docker/daemon.json
"insecure-registries":[
    "主机:5000"
]

golang示例

docker 新版本引入多阶段，主要用来优化不同阶段的要求差异，比如编译时需要编译工具，但运行时不需要。运行时只要引入编译产物就行。

# syntax=docker/dockerfile:1

## Build
FROM golang:1.16-buster AS build  # 官方教程示例期的版本,现值机用 golang:1.26+

WORKDIR /app

COPY go.mod ./
COPY go.sum ./
RUN go mod download

COPY *.go ./

RUN go build -o /docker-gs-ping

## Deploy
FROM gcr.io/distroless/base-debian10

WORKDIR /

COPY --from=build /docker-gs-ping /docker-gs-ping

EXPOSE 8080

USER nonroot:nonroot

ENTRYPOINT ["/docker-gs-ping"]
docker build -t docker-gs-ping:multistage -f Dockerfile.multistage .

Docker 29 与 AI 平台演进（2024-2026 更新）

版本现状（2026-08）

Docker Engine 29 于 2025-11-10 发布，成为当前稳定主线，维护到最新 29.7.2 （2026-08-05）；28.x 已于 2026-05-13 停止安全支持，25.0.x 维护到 2026-12-04。生产环境建议尽快落到 29.x。

版本线发布时间状态
29.x2025-11-10当前稳定（29.7.2 @ 2026-08）
28.x2025-02-202026-05-13 已停止支持
25.0.x2024-01维护至 2026-12-04

2024-2026 特性盘点

  • Docker Desktop 4.77（2026-06-08）：内置 Engine 29.5.3、Buildx 0.34.1，Logs 视图支持导出。
  • Docker Agent / MCP Gateway：官方 AI 助手和 MCP 网关随 Desktop 持续更新，容器操作可以被 AI 代理编排。
  • 外部服务（External Services）：Compose 里可以引用外部服务（比如云数据库）。
  • 镜像卷（volume.type=image）：用镜像作为卷内容源，适合数据库初始化。
  • 静默模式：--quiet 和 --quiet-build 选项，适合 CI/CD。
  • 多架构构建：docker compose build --platform linux/amd64,linux/arm64 。
  • Model Runner：Desktop 内置的 AI 模型运行能力持续增强，本地 LLM 推理进入容器生态。
  • containerd 集成：Docker Engine 可以直接用 containerd 作为运行时。

  • CVE-2026-41567：docker cp 上传压缩归档时，守护进程从容器文件系统解析解压二进制（xz / unpigz），恶意镜像可以借此逃逸到宿主机 root；修复于 29.5.1 和 moby v2.0.0-beta.14。
  • CVE-2026-41568：docker cp 挂载竞态，恶意容器可以在宿主机任意路径创建文件；29.5.1 修复。
  • 供应链可信：基础镜像签名、内容校验和「镜像来源可审计」被列为官方重点方向。

AI 时代的 Docker（2026）

  • AI Agent 运行时安全治理：官方把「AI 代理操作的容器怎么做到安全、可审计」列为核心议题。
  • 软件供应链与基础镜像可信：镜像签名、内容校验成为产品化能力。
  • 本地开发环境可审计可控：开发环境即代码，治理能力下沉到本地。
  • 整体观察：Docker 正从「容器工具」走向「AI 开发时代的运行平台」。

Docker Compose v2（已替代 v1）

Docker Compose v2 用 Go 重写，已经成为默认的 compose 工具（命令为 docker compose ，不再是 docker-compose ）。截至 2026 年最新版本是 v2.37+。

# docker-compose.yml（v2 格式，无需 version 字段）
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    depends_on:
      - api
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost"]
      interval: 30s
      timeout: 10s
      retries: 3

  api:
    build:
      context: ./api
      dockerfile: Dockerfile
    environment:
      - DB_HOST=db
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '1.0'
          memory: 512M

  db:
    image: postgres:16
    volumes:
      - db_data:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: secret

volumes:
  db_data:

Bake 构建引擎（v2.37+ 默认启用）

Bake 是 Docker 的新型构建引擎，支持并行构建、多目标构建和优化缓存：

# Bake 并行构建多个服务
docker compose build --print  # 输出等效 Bakefile
docker compose build --platform linux/amd64,linux/arm64  # 多架构构建

# 直接使用 bake
docker buildx bake web api db  # 并行构建三个目标

BuildKit / buildx

BuildKit 是 Docker 的新一代构建引擎，支持并行构建、缓存挂载和密钥管理：

# Dockerfile with BuildKit features
# syntax=docker/dockerfile:1.7

FROM golang:1.26 AS builder

# 缓存挂载 - 加速依赖下载
RUN --mount=type=cache,target=/go/pkg/mod     --mount=type=cache,target=/root/.cache/go-build     go build -o /app ./...

# 密钥挂载 - 安全使用私有仓库
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc     npm install

FROM alpine:3.20
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
