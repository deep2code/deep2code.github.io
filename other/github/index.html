pages服务

  1. User/Organization Pages 个人或公司站点

    1. 创建username.github.io仓库
    2. 仓库设置自定义域名,项目下面会自动增加CNAME文件
    3. 域名解析增加相应的CNAME记录

  2. Project Pages 项目站点

    1. gh-pages分支用于构建和发布；
    2. 如果user/org pages使用了独立域名，那么托管在账户下的所有project pages将使用相同的域名进行重定向，除非project pages使用了自己的独立域名； 如果没有使用独立域名，project pages将通过子路径的形式提供服务http://username.github.com/projectname；

名词

  • Sponsor：打赏

  • Watch：如有更新，通知提醒。

  • Fork：分支一份到你的仓库。

  • Code：默认页面，通常会有一个 README.md 文件，用于介绍该项目。

  • Pull requests：请求代码合并，如果你想为项目贡献代码，可以在这里提交。

  • Actions：工作流。

    大家知道，持续集成由很多操作组成，比如抓取代码、运行测试、登录远程服务器，发布到第三方服务等等。GitHub 把这些操作就称为 actions。 很多操作在不同项目里面是类似的，完全可以共享。GitHub 注意到了这一点，想出了一个很妙的点子，允许开发者把每个操作写成独立的脚本文件，存放到代码仓库，使得其他开发者可以引用。 如果你需要某个 action，不必自己写复杂的脚本，直接引用他人写好的 action 即可，整个持续集成过程，就变成了一个 actions 的组合。这就是 GitHub Actions 最特别的地方。 GitHub 会监控到，然后分配一台虚拟机先将你的项目 checkout 过去，然后按照你指定的 step 顺序执行定义好的 action

  • Wiki：说明文档

  • Insights：数据统计

配套网站-Netlify

  • 用最快的方法构建最快的网站

当使用 Github 将网站项目文件夹里的所有东西上传完毕之后，那么就可以打开 Netlify 给予它访问 Github 仓库的权限。 当 Netlify 读取完你的网站所属仓库时，会自动识别你所用的静态网页生成器的程序，然后只要点击部署并发布，你的网站就会在 Netlify 被构建并且被发布.

  • 能够托管服务，免费 CDN

  • 能够绑定自定义域名

  • 能够启用免费的TLS证书，启用HTTPS

  • 支持自动构建

  • 提供 Webhooks 和 API

  • 开源有趣项目-介绍

Host github3
   HostName github.com
   PreferredAuthentications publickey
   IdentityFile ~/.ssh/id_rsa

Host github2
   HostName github.com
   PreferredAuthentications publickey
   IdentityFile ~/.ssh/id_ecdsa

# git@github.com:xxx/yyy -> git@github3:xxx/yyy
# git@github.com:xxx/yyy -> git@github2:xxx/yyy

GitHub 2026：Agent 工作流与供应链安全

Copilot：从编辑器走向 Agent

  • Copilot app（agent-native 桌面体验）：Microsoft Build 2026（2026-06-02）官方发布，Agent 以开发者习惯的方式直接工作；自定义 Copilot Agents 已覆盖可观测性、IaC、安全等场景。
  • 会话远程控制 GA（2026-05-18）：在 VS Code / CLI 里开起的 Copilot 会话，可以转到 github.com 或手机端继续，本地任务随处可续。
  • Copilot CLI 1.0.68（2026-07-02）：终端里的 agentic 编码助手；内置 GitHub MCP server，支持自定义 MCP 扩展；可在 Actions 中以程序化模式跑（配合 GitHub Agentic Workflows，默认使用 GITHUB_TOKEN 认证、自带护栏）。
  • 新 embedding 模型：Copilot 定位代码与理解仓库的能力明显增强，代码检索准确率进一步提升。

Actions 2026 安全路线图：依赖锁定

2026-03-26 官方发布 Actions 2026 安全路线图，核心是 workflow 级依赖锁定：

  • workflow YAML 新增 dependencies: 段，把直接+传递依赖全部锁定到 commit SHA——相当于 Workflow 版的 go.mod + go.sum，完整可复现、可审计。
  • 效果：每次执行都运行「被 review 过」的精确版本；依赖更新以 PR diff 呈现；哈希不匹配在 job 运行前 fail-fast 拦截；composite action 的嵌套依赖不再被隐藏。
  • 公开预览预计 3-6 个月内、GA 约 6 个月内落地，建议提前规划升级节奏。

配合 actions/attest（工件签名 attestation，in-toto 格式）与 Actions 核心架构重建（2025-12 起性能/可靠性升级），CI/CD 供应链正从「引用可变 tag」走向「可审计、可复现」。

gh CLI 2.9x：读仓库、skills、Copilot

  • v2.95.0（2026-06-17）：新增 gh repo read-file / gh repo read-dir——不 clone 直接读取远程仓库文件与目录，支持 --ref 指定分支/tag/commit、支持 --json/--jq/--template，对 AI agent 与自动化脚本非常友好。
  • v2.96.0（2026-07-02）：当前最新稳定版。
  • gh skills（v2.90.0+）：gh skill install 让 AI 技能变成可安装、可组合的软件包，支持作用域、子目录定位（--subpath）与交互式列表。
  • gh copilot 子命令：直接在终端进入 Copilot CLI，支持 /init 初始化仓库指令；Copilot CLI 1.0.x 稳定迭代中。
# gh CLI 常用命令（2026）

gh pr merge --squash --delete-branch
gh issue list --assignee @me
gh run watch  # 监控 Actions 运行

# 不 clone 直接读远程仓库（v2.95+，preview）

gh repo read-dir script --repo cli/cli

# 安装 AI 技能包（v2.90+）
gh skill install github/awesome-copilot --skill code-reviewer
