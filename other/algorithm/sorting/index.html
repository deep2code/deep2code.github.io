排序算法

🏷️ 算法,排序

💡 你要找工作，面试要刷算法题，LeetCode 刷了 100 道，换个题型又不会了。你想搞懂算法的核心思路，而不是背题。

为什么排序是算法的基石

排序是计算机科学被研究得最透彻的问题之一，从 1950 年代的卡片排序机到今天的 GPU 并行排序，八十年间演进了几十种算法。我在工程中几乎从不手写排序——直接调标准库就行——但面试和性能调优时，理解排序原理能帮你选对方案。

排序之所以重要，是因为它是很多算法的前置步骤：

  • 二分查找要有序
  • 双指针要有序
  • 归并求交集要有序
  • Top-K 要分治

排序算法的设计思想——分治、贪心、堆、稳定性——本身就是算法思维的浓缩。面试常问：为什么快排平均 O(n log n) 最坏 O(n²)？为什么归并需要 O(n) 额外空间？什么是稳定性？

快速排序：分治与分区

快排是实践中最快的通用排序。核心是分区（Partition）：选一个 pivot，把小于它的放左边、大于它的放右边，然后递归左右子区间。下图展示分区过程：

flowchart LR A[数组 5 3 8 1 2 7] --> B[选 pivot 5] B --> C[分区后 3 1 2 5 8 7] C --> D[递归左 3 1 2
递归右 8 7] D --> E[最终 1 2 3 5 7 8]

Go 实现（ Lomuto 分区）：

package main

import "fmt"

// quickSort 快排：平均 O(n log n)，最坏 O(n²)，原地排序
func quickSort(nums []int, lo, hi int) {
    if lo >= hi {
        return
    }
    p := partition(nums, lo, hi)
    quickSort(nums, lo, p-1)
    quickSort(nums, p+1, hi)
}

func partition(nums []int, lo, hi int) int {
    pivot := nums[hi] // 选末尾做 pivot
    i := lo           // i 指向"小于 pivot 区"的末尾
    for j := lo; j < hi; j++ {
        if nums[j] < pivot {
            nums[i], nums[j] = nums[j], nums[i]
            i++
        }
    }
    nums[i], nums[hi] = nums[hi], nums[i]
    return i
}

func main() {
    nums := []int{5, 3, 8, 1, 2, 7, 4}
    quickSort(nums, 0, len(nums)-1)
    fmt.Println(nums) // [1 2 3 4 5 7 8]
}

Python 对照：

from typing import List

def quick_sort(nums: List[int]) -> List[int]:
    if len(nums) <= 1:
        return nums
    pivot = nums[len(nums) // 2]
    left = [x for x in nums if x < pivot]
    mid = [x for x in nums if x == pivot]
    right = [x for x in nums if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)

if __name__ == "__main__":
    print(quick_sort([5, 3, 8, 1, 2, 7, 4]))  # [1, 2, 3, 4, 5, 7, 8]

注意 Python 版用了额外空间（更易读），Go 版是原地排序。生产中 Go 标准库 sort.Slice 实际是混合排序：数据 < 12 个用插入排序，否则用快排，并在递归过深时切换堆排序（Introsort）。

归并排序：稳定分治

归并排序是稳定的（相等元素相对顺序不变），且最坏也是 O(n log n)。代价是需要 O(n) 额外空间。它是外部排序、链表排序、逆序对计数的首选：

package main

import "fmt"

// mergeSort 归并排序：稳定，O(n log n)，O(n) 额外空间
func mergeSort(nums []int) []int {
    if len(nums) <= 1 {
        return nums
    }
    mid := len(nums) / 2
    left := mergeSort(nums[:mid])
    right := mergeSort(nums[mid:])
    return merge(left, right)
}

func merge(left, right []int) []int {
    result := make([]int, 0, len(left)+len(right))
    i, j := 0, 0
    for i < len(left) && j < len(right) {
        if left[i] <= right[j] { // <= 保证稳定性
            result = append(result, left[i])
            i++
        } else {
            result = append(result, right[j])
            j++
        }
    }
    result = append(result, left[i:]...)
    result = append(result, right[j:]...)
    return result
}

func main() {
    nums := []int{5, 2, 4, 7, 1, 3, 2, 6}
    fmt.Println(mergeSort(nums)) // [1 2 2 3 4 5 6 7]
}

Python 对照：

from typing import List

def merge_sort(nums: List[int]) -> List[int]:
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])
    return _merge(left, right)

def _merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

if __name__ == "__main__":
    print(merge_sort([5, 2, 4, 7, 1, 3, 2, 6]))  # [1, 2, 2, 3, 4, 5, 6, 7]

实战技巧：Top-K 问题

求第 K 大的元素，用快排的 快速选择（Quickselect）：每次分区后只递归目标侧，平均 O(n)。或者用大小为 K 的最小堆：遍历数组，堆不满就 push，满了就比较堆顶。堆解法 O(n log K)，适合数据流：

package main

import "container/heap"
import "fmt"

// 最小堆，用来求第 K 大
type MinHeap []int

func (h MinHeap) Len() int            { return len(h) }
func (h MinHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h MinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func findKthLargest(nums []int, k int) int {
    h := &MinHeap{}
    heap.Init(h)
    for _, n := range nums {
        if h.Len() < k {
            heap.Push(h, n)
        } else if n > (*h)[0] {
            heap.Pop(h)
            heap.Push(h, n)
        }
    }
    return (*h)[0]
}

func main() {
    fmt.Println(findKthLargest([]int{3, 2, 1, 5, 6, 4}, 2)) // 5
}

解题技巧与最佳实践

💡 我的选型建议：工程上永远调标准库，但你要知道底层在干嘛。Go 的 sort.Slice 是 Introsort（快排+堆排+插入排序混合），Python 的 list.sort() 是 Timsort。我唯一手写过排序的场景是嵌入式设备内存只有 64KB——标准库放不下，只能手写一个 20 行的插入排序。

  • 小数据插入排序，大数据快排/归并：标准库的混合排序策略。数据量 < 12 时插入排序常数极小、缓存友好，比递归快排还快。
  • 稳定性何时重要：多关键字排序（先按价格排，再按日期排）必须用稳定排序，否则前一个关键字会被打乱。归并、插入、冒泡稳定；快排、堆排、选择不稳定。
  • Top-K 选堆还是快速选择：一次性内存中求第 K → 快速选择 O(n)；数据流求 Top-K → 大小 K 的堆 O(n log K)。
  • 基数排序适用范围极窄：只能排"长度固定且每一位有限"的元素（如身份证、32 位整数），不是通用算法。
  • 工程上永远调标准库：Go 的 sort.Slice、C++ std::sort、Python list.sort() 都是 Introsort 或 Timsort（归并+插入混合），自己写只会更慢更错。

常见问题 FAQ

Q1：快排最坏 O(n²) 什么时候会出现？

当 pivot 选得极差——比如数组已经有序，而你每次都选第一个或最后一个当 pivot，分区永远是 1 和 n-1，递归树退化成链表。工程解决方案：随机选 pivot、三数取中、或切换为三向切分（处理大量重复元素）。标准库通常加了这些保护，几乎不会触发最坏情况。

Q2：为什么 Java 的 Arrays.sort 对基本类型用快排，对对象用归并？

因为对象需要稳定排序。业务中常常多轮排序（先按名字排，再按部门排），不稳定会让上一次排序结果丢失。快排不稳定，归并稳定，所以对象用归并/TimSort。基本类型不区分"相等的两个对象"，稳定性无所谓，用快排省空间。

Q3：堆排和快排都是 O(n log n)，为什么实际快排更快？

虽然同阶，但常数和缓存差异巨大。快排分区是顺序扫描数组，CPU 缓存预取友好；堆排每次从堆顶跳到孩子，跳来跳去，缓存命中率低。实测快排通常比堆排快 2-3 倍。堆排的优势是最坏也是 O(n log n)，且能流式处理 Top-K。

Q4：Python 的 list.sort() 是什么排序？

是 Timsort（Tim Peters 2002 年发明），归并排序的优化版。它利用现实数据中已存在的"自然有序段"（run），把有序段合并，平均 O(n log n)，最坏 O(n log n)，且稳定。Java 7+ 的对象排序、Android 也用 Timsort。

总结

排序算法的学习不是背 API，而是理解分治、稳定性、空间权衡这三条主线。工程上用标准库，但面试和性能调优时，知道"为什么这个算法适合这个场景"才是真功夫。下一篇我们进入算法中最难也最迷人的分支——动态规划。
