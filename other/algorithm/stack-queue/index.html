栈与队列

🏷️ 算法,栈,队列

受限线性表：栈与队列

栈和队列都是操作受限的线性表——不允许你在任意位置读写，只能在特定端操作。恰恰是这种"限制"，让它们在算法中不可替代：

  • 栈（LIFO）：天然匹配嵌套、撤销、括号匹配、函数调用栈
  • 队列（FIFO）：天然匹配任务排队、BFS、消息缓冲

我的判断口诀：看到"最近"、"嵌套"、"回退"就想栈；看到"按顺序处理"、"层级遍历"、"生产者消费者"就想队列。

结构示意与基本操作

flowchart TB subgraph Stack[栈 LIFO 只能栈顶操作] S1[栈顶 top 值 3] --- S2[值 2] --- S3[值 1 栈底] end subgraph Queue[队列 FIFO 队尾入队头出] Q1[队头 front 值 1] --- Q2[值 2] --- Q3[值 3] --- Q4[值 4 队尾 rear] end

栈的典型应用

  • 函数调用栈：每次函数调用压栈，返回时弹栈，这就是递归的底层实现。
  • 括号匹配：遇左括号压栈，遇右括号弹栈匹配，最后栈空则合法。
  • 表达式求值：中缀转后缀、后缀表达式计算（双栈法：操作数栈 + 运算符栈）。
  • 单调栈：O(n) 解决"下一个更大元素"类问题。
  • 浏览器前进后退、编辑器撤销：两个栈分别存历史与前进。

队列的典型应用

  • BFS 广度优先搜索：层序遍历的骨架。
  • 消息队列、任务队列：解耦生产与消费速率。
  • 滑动窗口：单调队列维护窗口内最值。
  • 并发池：worker pool 从队列取任务。

常见用途

栈和队列看着简单，实际到处都是：

结构典型场景我在项目里的实际用法
栈函数调用栈、表达式求值、括号匹配、撤销操作JSON 解析、模板引擎的作用域管理，还有浏览器的后退按钮

双端队列工作窃取、滚动窗口、浏览器渲染任务队列需要两端都能进出的场景，比如 LRU 的头尾操作

一句话总结：栈是"后进先出"，适合回溯/撤销；队列是"先进先出"，适合排队/调度。单调栈/队列是为了在 O(1) 内拿到极值，面试必考但实际项目也常用。

经典例题 1：有效的括号

判断括号字符串是否有效。核心思路：左括号压栈，右括号弹栈并检查是否匹配。遍历结束栈必须为空。这是栈的入门模板题：

package main

import "fmt"

func isValid(s string) bool {
    if len(s)%2 != 0 {
        return false
    }
    pair := map[rune]rune{')': '(', '}': '{', ']': '['}
    stack := []rune{}
    for _, ch := range s {
        switch ch {
        case '(', '{', '[':
            stack = append(stack, ch) // 左括号压栈
        default:
            if len(stack) == 0 || stack[len(stack)-1] != pair[ch] {
                return false // 右括号没有匹配的左括号
            }
            stack = stack[:len(stack)-1] // 弹栈
        }
    }
    return len(stack) == 0
}

func main() {
    fmt.Println(isValid("()[]{}")) // true
    fmt.Println(isValid("(]"))     // false
    fmt.Println(isValid("([)]"))   // false
    fmt.Println(isValid("{[]}"))   // true
}

Python 对照：

def is_valid(s: str) -> bool:
    if len(s) % 2 != 0:
        return False
    pair = {')': '(', '}': '{', ']': '['}
    stack = []
    for ch in s:
        if ch in "({[":
            stack.append(ch)
        else:
            if not stack or stack[-1] != pair[ch]:
                return False
            stack.pop()
    return not stack

if __name__ == "__main__":
    print(is_valid("()[]{}"))  # True
    print(is_valid("(]"))      # False
    print(is_valid("([)]"))    # False
    print(is_valid("{[]}"))    # True

经典例题 2：每日温度（单调栈）

给定每日气温，求还需要等几天才会变暖，等不到则填 0。暴力 O(n²) 超时，用单调递减栈一次遍历 O(n) 解决。这是单调栈的标准模板，必须背熟：

flowchart LR A[遍历温度] --> B{当前温度 > 栈顶索引温度?} B -->|是| C[弹出栈顶
计算答案 = i - 弹出索引] C --> B B -->|否| D[当前索引入栈
（保持栈内温度递减）] D --> A 
package main

import "fmt"

// dailyTemperatures 单调栈：O(n) 时间，O(n) 空间
func dailyTemperatures(temperatures []int) []int {
    n := len(temperatures)
    ans := make([]int, n)
    stack := []int{} // 存索引，对应温度单调递减
    for i, t := range temperatures {
        for len(stack) > 0 && temperatures[stack[len(stack)-1]] < t {
            prev := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            ans[prev] = i - prev
        }
        stack = append(stack, i)
    }
    return ans
}

func main() {
    temps := []int{73, 74, 75, 71, 69, 72, 76, 73}
    fmt.Println(dailyTemperatures(temps))
    // 输出 [1 1 4 2 1 1 0 0]
}

Python 对照：

from typing import List

def daily_temperatures(temps: List[int]) -> List[int]:
    n = len(temps)
    ans = [0] * n
    stack = []  # 存索引，对应温度单调递减
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            prev = stack.pop()
            ans[prev] = i - prev
        stack.append(i)
    return ans

if __name__ == "__main__":
    print(daily_temperatures([73, 74, 75, 71, 69, 72, 76, 73]))
    # [1, 1, 4, 2, 1, 1, 0, 0]

经典例题 3：用栈实现队列

用两个栈模拟队列：一个负责入队（inStack），一个负责出队（outStack）。outStack 空了就把 inStack 全部倒腾过来。均摊每个操作 O(1)。这道题考察"为什么倒腾一次 O(n) 却均摊 O(1)"：每个元素最多被 push/pop 各两次。

package main

import "fmt"

type MyQueue struct {
    inStack, outStack []int
}

func Constructor() MyQueue { return MyQueue{} }

func (q *MyQueue) Push(x int) { q.inStack = append(q.inStack, x) }

func (q *MyQueue) inOut() {
    if len(q.outStack) == 0 {
        for len(q.inStack) > 0 {
            last := len(q.inStack) - 1
            q.outStack = append(q.outStack, q.inStack[last])
            q.inStack = q.inStack[:last]
        }
    }
}

func (q *MyQueue) Pop() int {
    q.inOut()
    last := len(q.outStack) - 1
    v := q.outStack[last]
    q.outStack = q.outStack[:last]
    return v
}

func (q *MyQueue) Peek() int {
    q.inOut()
    return q.outStack[len(q.outStack)-1]
}

func main() {
    q := Constructor()
    q.Push(1)
    q.Push(2)
    fmt.Println(q.Peek()) // 1
    fmt.Println(q.Pop())  // 1
    q.Push(3)
    fmt.Println(q.Pop())  // 2
    fmt.Println(q.Pop())  // 3
}

解题技巧与最佳实践

⚠️ 我踩过的坑：单调栈题目看着简单，但我面试时被"柱状图中最大矩形"这道题卡住了。它和"每日温度"是同一个模板，只是方向反过来了——存的是"当前高度往左能延伸多远"。后来我总结：凡是看到"下一个更大/更小"、"最近的比我大/小"，直接套单调栈模板，不用犹豫。

  • 单调栈三问：① 栈里存索引还是值？（通常存索引，方便算距离）；② 维持递增还是递减？（求"下一个更大"用递减栈）；③ 什么时候弹栈？（新元素比栈顶大时）。
  • 队列用环形数组避免假溢出：头尾都移动时，用 (tail+1)%cap 回绕，而不是每次搬数组。Go 标准库 container/list 或 ring 都可。
  • BFS 套队列模板：入队时就标记 visited，而不是出队时——否则同一节点会被多个邻居重复入队。
  • 递归就是隐式栈：能用递归写的都能用显式栈改写，避免栈溢出。深度大的树遍历要用显式栈。
  • 表达式求值用双栈法：操作数栈 + 运算符栈，遇到高优先级运算符先算。LeetCode 224 基本计算器是经典题。

常见问题 FAQ

Q1：为什么 BFS 必须用队列，DFS 用栈/递归？

因为 BFS 要求按层扩展：先处理完当前层所有节点，再处理下一层。队列的 FIFO 正好保证"先入队的先出队"，即先发现的节点先扩展。DFS 要求"走到底再回头"，栈的 LIFO 保证刚访问的节点先扩展。反过来用也能做，但顺序就变了。

Q2：单调栈为什么能做到 O(n)？每个元素真的只进出栈一次吗？

是的。每个元素最多被 push 一次、被 pop 一次，总操作次数 ≤ 2n，所以摊到每个元素上是 O(1)，整体 O(n)。这是"均摊分析"的典型应用，和动态数组扩容一个道理。

Q3：Go 语言没有内置 stack/queue，用什么实现？

栈直接用切片：s = append(s, x) 入栈，x = s[len(s)-1]; s = s[:len(s)-1] 出栈。队列可以用 container/list（链表）或环形切片。并发安全用 chan 本身就是一个带缓冲的队列，非常适合 worker pool。

Q4：单调队列和单调栈有什么区别？

单调栈只能从一端操作（栈顶），单调队列是双端队列：头部出队、尾部入队。单调队列用于"滑动窗口最值"——既要从队尾维护单调性，又要从队头把离开窗口的元素删掉。滑动窗口最大值是它的招牌题。

总结

栈和队列看似简单，但它们的变体（单调栈、单调队列、双栈队列、双端队列）覆盖了面试近半的线性表题。识别题目关键词——"下一个更大"→单调栈、"滑动窗口最值"→单调队列、"层级遍历"→BFS 队列——是提速关键。下一篇我们进入非线性结构：树与二叉树。
