数组与链表

🏷️ 算法,数组,链表

线性表的两大基石

数组和链表是面试出现频率最高的考点之一，我面过不下 20 个候选人，这两题几乎没人能完全不写 bug。

本质区别只有一句话：数组用一段连续内存存储元素，支持 O(1) 随机访问；链表用指针串联散落内存，插入删除 O(1) 但访问要 O(n) 遍历。这个差异决定了各自的擅长领域——

  • 数组：适合"读多写少、按下标访问"
  • 链表：适合"频繁插入删除、不需要随机访问"

很多人觉得"链表手写过就懂了"，但工程上真正难的是边界条件处理：空指针、单节点、头尾插入、循环终止条件。我踩过的坑：90% 的链表 bug 都出在指针还没赋值就被使用、或者 while 循环少判了一个条件。

内存布局对比

数组在内存中是连续的一块，CPU 缓存预取友好，访问极快；链表节点散落在堆上，每个节点多存一个指针（8 字节），且访问下一个节点常常缓存不命中。下图直观对比两者的内存模型：

40] end subgraph LinkedList[链表：指针串联] H[head] --> N1[10 ／*] --> N2[20 ／*] --> N3[30 ／*] --> N4[40 ／ nil] end

数组的关键操作

  • 随机访问：arr[i] 直接算出地址 base + i×size，O(1)。
  • 尾部追加：均摊 O(1)（需扩容时拷贝）。
  • 中间插入/删除：要挪动后续元素，平均 O(n)。
  • 扩容策略：Go slice 按 2 倍（小容量）/1.25 倍（大容量）增长，Java ArrayList 1.5 倍，Python list 约 1.125 倍。

链表的关键操作

  • 已知前驱节点处插入：改两个指针即可，O(1)。
  • 头插法建链表：O(1)，常用于反转、LRU 等。
  • 查找/按索引访问：只能从头遍历，O(n)。
  • 删除节点：若直接拿到待删节点，可以用"后继覆盖"技巧 O(1) 删除（不删尾节点）。

常见用途

经典例题 1：反转单链表

反转链表是面试必考题，核心是三指针逐个翻转 next 指向。用"哑节点 + 三指针"模板可以从容应对大多数链表题。迭代写法比递归更优（无递归栈开销），也是工程首选：

package main

import "fmt"

type ListNode struct {
    Val  int
    Next *ListNode
}

// reverseList 迭代反转单链表：O(n) 时间，O(1) 空间
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode
    curr := head
    for curr != nil {
        next := curr.Next // 暂存下一个
        curr.Next = prev  // 反转指针
        prev = curr       // 前进一步
        curr = next
    }
    return prev
}

// 辅助：从切片构造链表并打印
func build(vals []int) *ListNode {
    dummy := &ListNode{}
    tail := dummy
    for _, v := range vals {
        tail.Next = &ListNode{Val: v}
        tail = tail.Next
    }
    return dummy.Next
}
func printList(head *ListNode) {
    for p := head; p != nil; p = p.Next {
        fmt.Print(p.Val, " -> ")
    }
    fmt.Println("nil")
}

func main() {
    head := build([]int{1, 2, 3, 4, 5})
    printList(head)          // 1 -> 2 -> 3 -> 4 -> 5 -> nil
    printList(reverseList(head)) // 5 -> 4 -> 3 -> 2 -> 1 -> nil
}

Python 对照实现：

from typing import Optional

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def reverse_list(head: Optional[ListNode]) -> Optional[ListNode]:
    prev = None
    curr = head
    while curr:
        nxt = curr.next   # 暂存
        curr.next = prev  # 反转
        prev = curr       # 前进
        curr = nxt
    return prev

def build(vals):
    dummy = ListNode()
    tail = dummy
    for v in vals:
        tail.next = ListNode(v)
        tail = tail.next
    return dummy.next

def to_list(head):
    res = []
    while head:
        res.append(head.val)
        head = head.next
    return res

if __name__ == "__main__":
    head = build([1, 2, 3, 4, 5])
    print(to_list(reverse_list(head)))  # [5, 4, 3, 2, 1]

经典例题 2：LRU 缓存

LRU（Least Recently Used）是"哈希表 + 双向链表"的经典组合：哈希表 O(1) 定位节点，双向链表 O(1) 移动/删除节点。这道题综合考察了两种结构，也是 Redis 淘汰策略、浏览器缓存的核心原理：

flowchart LR subgraph LRU[LRU 缓存结构] HEAD[head 哨兵] <--> N1[k1 v1] <--> N2[k2 v2] <--> N3[k3 v3] <--> TAIL[tail 哨兵] end HASH[('哈希表 key 到节点指针')] -.- N1 HASH -.- N2 HASH -.- N3 style HEAD fill:#eee style TAIL fill:#eee

Go 实现（基于标准库 container/list）：

package main

import (
    "container/list"
    "fmt"
)

type LRUCache struct {
    cap   int
    cache map[string]*list.Element
    ll    *list.List // 前端为最近使用，后端为最久未使用
}

type entry struct {
    key string
    val int
}

func Constructor(capacity int) LRUCache {
    return LRUCache{
        cap:   capacity,
        cache: make(map[string]*list.Element),
        ll:    list.New(),
    }
}

func (c *LRUCache) Get(key string) int {
    if ele, ok := c.cache[key]; ok {
        c.ll.MoveToFront(ele) // 访问即提升到最近使用
        return ele.Value.(*entry).val
    }
    return -1
}

func (c *LRUCache) Put(key string, value int) {
    if ele, ok := c.cache[key]; ok {
        ele.Value.(*entry).val = value
        c.ll.MoveToFront(ele)
        return
    }
    // 淘汰最久未使用
    if c.ll.Len() == c.cap {
        oldest := c.ll.Back()
        delete(c.cache, oldest.Value.(*entry).key)
        c.ll.Remove(oldest)
    }
    ele := c.ll.PushFront(&entry{key, value})
    c.cache[key] = ele
}

func main() {
    lru := Constructor(2)
    lru.Put("a", 1)
    lru.Put("b", 2)
    fmt.Println(lru.Get("a")) // 1，a 被提升为最近使用
    lru.Put("c", 3)           // 淘汰 b
    fmt.Println(lru.Get("b")) // -1
    fmt.Println(lru.Get("c")) // 3
}

Python 用 OrderedDict 等价实现：

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.cache = OrderedDict()

    def get(self, key: str) -> int:
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)  # 最近使用移到末尾
        return self.cache[key]

    def put(self, key: str, value: int) -> None:
        if key in self.cache:
            self.cache.move_to_end(key)
        elif len(self.cache) == self.cap:
            self.cache.popitem(last=False)  # 淘汰头部最久未使用
        self.cache[key] = value

if __name__ == "__main__":
    lru = LRUCache(2)
    lru.put("a", 1)
    lru.put("b", 2)
    print(lru.get("a"))  # 1
    lru.put("c", 3)      # 淘汰 b
    print(lru.get("b"))  # -1
    print(lru.get("c"))  # 3

解题技巧与最佳实践

💡 我的血泪经验：写链表题时，先在纸上画出 null → 1 → 2 → 3 的指针图，把每一步改哪个指针标清楚，再敲代码。我有次在线上因为链表反转漏了 next := curr.Next 这行暂存，直接把链表绕成了环，CPU 100% 跑了半小时才被监控发现。

  • 哑节点（Dummy Node）统一边界：链表头插、删头节点时，加一个 dummy := &ListNode{Next: head}，就能把"头节点和中间节点"的操作统一，不再写一堆 if head == nil。
  • 快慢指针解决环问题：判环（Floyd 龟兔）、找中点、找环入口，都用一快一慢两个指针。快指针每次走 2 步，慢指针走 1 步。
  • 双指针（对撞/快慢）在数组上无敌：两数之和 II、三数之和、接雨水、移动零，都是排序后双指针 O(n) 解决。
  • 扩容要预留余量：预分配 make([]int, 0, n) 避免反复拷贝；Python 用 [0]*n 预分配。
  • 链表删除的 O(1) 技巧：要删节点 p（非尾节点），直接 p.Val = p.Next.Val; p.Next = p.Next.Next，省掉找前驱。

常见问题 FAQ

Q1：既然数组连续内存更快，为什么还要用链表？

因为插入删除的成本。数组中间插入要挪后面所有元素 O(n)，链表已知前驱后 O(1)。在 LRU、事件队列、操作系统的就绪队列这种"频繁头尾操作、不需要随机访问"的场景，链表完胜。另外链表不需要连续大块内存，对内存碎片严重的长驻进程友好。

Q2：Go 的 slice 到底是数组还是链表？

是动态数组。底层仍是连续数组，slice 只是"指针 + 长度 + 容量"三元组的视图。append 超容量时按策略分配新数组并拷贝——这就是为什么大 slice append 会有偶发的 O(n) 抖动。共享底层数组时，多个 slice 会互相影响，这是 Go 经典坑。

Q3：反转链表为什么推荐迭代而不是递归？

递归写法简洁（4 行），但递归深度等于链表长度，链长 n=10⁵ 时直接栈溢出。迭代版本用三指针，O(1) 额外空间、无栈风险。面试写迭代是工程正确答案。

Q4：链表题如何避免空指针？

三条铁律：① 访问 p.Next.Val 前一定确认 p != nil && p.Next != nil；② 循环条件写 for cur != nil 而不是 for cur.Next != nil，看你需不需要处理最后一个节点；③ 用哑节点屏蔽头节点特殊情况。

总结

数组和链表是"空间局部性"与"修改灵活性"这对矛盾的两种极端。我选型时就问自己两个问题——需要随机访问吗？需要频繁中间插入吗？前者选数组，后者选链表。下一篇我们看建立在它们之上的两种受限结构：栈与队列。
