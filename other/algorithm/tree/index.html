树与二叉树

🏷️ 算法,树,二叉树

从线性到非线性：为什么需要树

前面的数组、链表、栈、队列都是线性结构，一个元素只有一个前驱一个后继。但现实世界大量数据是层级关系——文件系统、组织架构、HTML DOM、数据库索引——用线性表表示会丢失"父子"语义，查找也慢。树就是为层级而生的。

我用得最多的是二叉树：每个节点最多两个孩子。它的魅力在于递归定义的简洁性——整棵树 = 根 + 左子树 + 右子树，子树本身又是一棵二叉树。这种定义让几乎所有树算法都能写成"对左右子树递归"的极简模板。

二叉树基础与遍历

二叉树有四种深度优先遍历方式，区别只在于"访问根节点"的时机：

  • 前序（Preorder）：根 → 左 → 右。用于复制树、前缀表达式。
  • 中序（Inorder）：左 → 根 → 右。对 BST 而言中序遍历就是升序序列，这是 BST 的核心性质。
  • 后序（Postorder）：左 → 右 → 根。用于删除树、计算目录大小。
  • 层序（Level Order）：BFS 一层一层访问，用队列。

经典例题：二叉树层序遍历（BFS）

层序遍历是 BFS 在树上的直接应用，用队列按层处理。Go 实现：

package main

import "fmt"

type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// levelOrder 层序遍历：BFS，O(n) 时间 O(n) 空间
func levelOrder(root *TreeNode) [][]int {
    if root == nil {
        return nil
    }
    result := [][]int{}
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        levelSize := len(queue)
        level := []int{}
        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]
            level = append(level, node.Val)
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        result = append(result, level)
    }
    return result
}

func main() {
    root := &TreeNode{Val: 1,
        Left:  &TreeNode{Val: 2, Left: &TreeNode{Val: 4}, Right: &TreeNode{Val: 5}},
        Right: &TreeNode{Val: 3, Right: &TreeNode{Val: 6}},
    }
    fmt.Println(levelOrder(root)) // [[1] [2 3] [4 5 6]]
}

Python 对照：

from collections import deque
from typing import List, Optional

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def level_order(root: Optional[TreeNode]) -> List[List[int]]:
    if not root:
        return []
    result, queue = [], deque([root])
    while queue:
        level_size = len(queue)
        level = []
        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result

if __name__ == "__main__":
    root = TreeNode(1,
        left=TreeNode(2, left=TreeNode(4), right=TreeNode(5)),
        right=TreeNode(3, right=TreeNode(6)))
    print(level_order(root))  # [[1], [2, 3], [4, 5, 6]]

经典例题：验证二叉搜索树（BST）

二叉搜索树（BST）的性质：左子树所有节点值 < 根 < 右子树所有节点值，且左右子树也是 BST。陷阱在于：不能只比较当前节点和它的左右孩子，必须用"上界下界"递归约束整个子树：

package main

import "math"

type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// isValidBST 递归 + 区间约束：左子树必须 < root，右子树必须 > root
func isValidBST(root *TreeNode) bool {
    return helper(root, math.MinInt64, math.MaxInt64)
}

func helper(node *TreeNode, lower, upper int) bool {
    if node == nil {
        return true
    }
    if node.Val <= lower || node.Val >= upper {
        return false
    }
    return helper(node.Left, lower, node.Val) &&
        helper(node.Right, node.Val, upper)
}

Python 对照（中序遍历必须严格升序，更简洁）：

from typing import Optional

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def __init__(self):
        self.prev = float("-inf")

    # 中序遍历：BST 的中序必须严格升序
    def is_valid_bst(self, root: Optional[TreeNode]) -> bool:
        if not root:
            return True
        if not self.is_valid_bst(root.left):
            return False
        if root.val <= self.prev:
            return False
        self.prev = root.val
        return self.is_valid_bst(root.right)

平衡树：AVL 与红黑树

普通 BST 在极端情况（按插入顺序 1,2,3,4,5）会退化成链表，查找从 O(log n) 退化到 O(n)。平衡二叉搜索树通过旋转操作维持高度平衡。

  • AVL 树：严格平衡，任意节点左右子树高度差（平衡因子）绝对值 ≤ 1。查找极快，但插入删除旋转多，适合"查多写少"。
  • 红黑树（Red-Black Tree）：近似平衡，通过五条性质保证从根到叶子最长路径不超过最短路径 2 倍。插入删除最多 3 次旋转，工程上更常用——Linux 进程调度、C++ map/set、Java TreeMap、Redis 有序集合底层都是红黑树。

解题技巧与最佳实践

💡 我的递归心法：写二叉树题别在脑子里展开整棵树，就想三件事——当前节点要做什么？左子树返回什么？右子树返回什么？然后把结果合并。这个思路我在面试中用了不下 30 次，几乎所有二叉树题（最大深度、LCA、路径和、直径）都套这个模板。

  • 二叉树题 90% 用递归：先想"对当前节点要做什么"，再递归左右子树。不要试图在脑子里展开整棵树。
  • 后序遍历用于"自底向上"的统计：求高度、求直径、判断平衡——先收集左右子树信息再合并。
  • 最近公共祖先（LCA）：经典后序递归。若 p、q 分别在左右子树，当前节点就是 LCA；否则递归到那一侧。
  • 用"返回值"传递结果：不要用全局变量（面试容易出错），让递归函数直接返回所需信息。
  • 层级处理用 BFS + 队列：深度用 DFS 递归，宽度用 BFS 队列。看到"每一层"、"距离"就用 BFS。
  • 工程上优先用语言内置树结构：Go 没有内置，用 map 兜底；C++/Java 直接用 map/TreeMap；Python 用 sortedcontainers。

常见问题 FAQ

Q1：前序 + 中序能唯一确定一棵二叉树吗？

能。前序第一个元素是根，在中序中找到根的位置，左边是左子树、右边是右子树，递归划分即可。但前序 + 后序不能唯一确定（缺孩子时无法区分左右），必须有中序。

Q2：红黑树和 AVL 怎么选？

AVL 更严格平衡，查找略快（约快一倍常数），但插入删除时可能要多轮旋转。红黑树近似平衡，插入删除最多 3 次旋转，写多读少场景更优。工程实践中红黑树是绝对主流——Linux 内核、Java 集合、C++ STL 全是红黑树。

Q3：递归遍历二叉树会栈溢出吗？

会。树高 h 等于递归深度，普通平衡树 h≈log n 没问题；但斜树（1→2→3→…→n）h=n，递归直接爆栈。工程实现要用显式栈（模拟调用栈），或保证树是平衡的。

Q4：为什么数据库索引用 B+ 树而不是红黑树？

红黑树是二叉，一个节点只存一个 key；B+ 树是多叉，一个节点存几百个 key，树高低得多（3-4 层就能存亿级数据）。磁盘 I/O 按页读取，多叉树让一次 I/O 能加载更多索引，减少磁盘寻道。这是"内存里用红黑树、磁盘上用 B+ 树"的根本原因。

总结

二叉树的核心是递归思维：定义问题→分解为左右子问题→合并结果。BST 靠中序有序性支撑查找，AVL/红黑树靠旋转保平衡。下一篇我们走向更复杂的非线性结构——图，把树推广到"允许任意节点间连边"。
