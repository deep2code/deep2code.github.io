核心观点

  • Harbor 是企业级 Docker Registry，2022 年捐赠给 CNCF 后由社区独立维护
  • 演示 docker-compose 脚本转发与 common.sh、配置修改，最好在 Linux 机器上部署
  • 免费制品管理可参考 Nexus 对比

关键结论与取舍

  • 生产建议 Linux 部署；配置项集中在 common.sh
  • 2024-2026 更新对齐版本线与安全维护
适合谁读自建私有镜像仓库的团队 读完可获得Harbor 部署与配置要点，以及 Nexus 备选视角

简介

  • 官网 github

  • Harbor 最早由 VMware 开源，定位企业级 Docker Registry，目标是帮用户快速搭起能用的私有镜像仓库；2022 年捐给 CNCF，现在由社区独立维护。

  • Harbor 在 Docker 公司开源 Registry 的基础上，补齐了图形管理 UI、角色访问控制（RBAC）、AD / LDAP 集成、审计日志（Audit Logging）这些企业级能力，原生支持中文。

  • Harbor 每个组件都打成 Docker 容器，统一用 docker compose 部署；部署模板在 harbor/docker-compose.yml。

  • 官方最低要求 2 核 4G，生产环境建议 4 核 8G 起步

docker-compose 脚本转发命令

  • docker compose 自带，不用额外装（2026 年 Docker Engine / Desktop 都已内置 compose v2 插件，这个转发脚本只对老环境有用）。
  • harbor 安装脚本会检查 docker-compose 命令，所以得弄个转发脚本让它通过检查

Harbor 更新（2024-2026）

Harbor v2.11+ 主要更新：

  • CNCF 毕业项目：2022 年捐给 CNCF，2023 年成为毕业项目，维护主体早已脱离 VMware（被 Broadcom 收购后由社区独立运作，版本迭代和安全修复保持稳定）；
  • 供应链安全：支持 Cosign 签名验证、SBOM 导出和组件级漏洞扫描，配合准入策略构成 OCI 供应链闭环；
  • 制品与复制：支持 OCI Artifact（Helm Chart 这类非镜像制品）、Proxy 缓存仓库代理 Docker Hub / 镜像站，异地多集群复制已是多云标准姿势；
  • 运维体验：机器人账户、Webhook 和审计能力持续改进，内部镜像加速和安全扫描已成了 Kubernetes 集群标配。
