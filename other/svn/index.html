SVN

SVN 命令速查

  1. 下载
svn checkout svn://host/svn/IOS/remote_dir(远端仓库路径) project_dir(本地目录路径) --username 用户名 --password 密码

svn checkout 简写：svn co

  1. 添加新文件
svn add file（文件名）
svn add *.php(添加当前目录下所有的php文件)
  1. 提交到版本库
svn commit -m "LogMessage" PATH
svn commit -m "提交当前目录下所有受版本控制的文件" *   # * 表示全部文件

svn commit 简写：svn ci

  1. 更新文件
svn update
svn update 文件名

提交时提示过期冲突，需先 update（拉取最新），手工解决冲突后执行 svn resolved 清除冲突状态，最后再 commit。

svn update 简写： svn up

  1. 查看文件或者目录状态
svn status [-v] path（目录下的文件和子目录的状态，正常状态不显示）

?：不在svn的控制中；

M：内容被修改；

C：发生冲突；

A：预定加入到版本库；

K：被锁定

D：文件、目录或是符号链接（symbolic link）预定从版本库中删除。

I:忽略

svn status 简写：svn st

  1. 查看日志（显示文件的所有修改记录，及其版本号的变化）
# 查看最近3条日志
svn log [path] -l 3
  1. 解决冲突
# 手工解决冲突后,移除工作副本的目录或文件的“冲突”状态,再提交
svn resolved PATH
  1. 删除文件
# 本地先删,再提交
svn delete test.php
svn ci -m 'delete test file'
  1. 恢复本地修改
# 用法: revert PATH...
svn revert: 恢复原始未改变的工作副本文件 (恢复大部分的本地修改)。

注意： 本子命令不会存取网络，并且会解除冲突的状况。但是它不会恢复被删除的目录

# 丢弃对一个文件的修改
svn revert foo.c
# 恢复一整个目录的文件，. 为当前目录
svn revert --recursive .
  1. 版本库下的文件和目录列表
svn list [path]
  1. 忽略目录
# 注意没有目录斜杠
svn propset svn:ignore .idea .
  1. 查看文件详细信息
# svn info path
svn info test.php
  1. 比较差异
# svn diff path(将修改的文件与基础版本比较)
svn diff test.php

# svn diff -r m:n path(对版本m和版本n比较差异)
svn diff -r 200:201 test.php

svn diff 简写：svn di

  1. SVN 帮助
svn help 全部功能选项
svn help ci 具体功能的说明
  1. 上传
svn import project_dir（本地项目全路径） http://host/svn/IOS/Ben/remote_dir（svn项目全路径） -m "必填, 不填此命令执行不会成功."

服务器上remote_dir若不存在， 会自动创建；

只会上传project_dir目录下的文件到remote_dir的目录下

import之后， project_dir并没有自动转化为工作目录， 需要重新checkout(后面会用到)

SVN 更新

2024-2026 年 SVN 已不是新项目的主流选择（Subversion 1.14.x LTS 仍在维护，存量项目仍会长期存在）。新项目建议直接用 Git；老仓库需要迁移可借助 git-svn：

# 使用 git-svn 迁移
git svn clone -s http://svn.example.com/repo
git remote add origin git@github.com:user/repo.git
git push -u origin main
