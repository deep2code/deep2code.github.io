WSL2 完整指南

安装 WSL2

# 简单方法（推荐）
wsl --install

# 或者手动启用功能
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

# 重启后安装
wsl --install -d Ubuntu-22.04

常用命令

# 查看已安装的发行版
wsl -l -v

# 启动特定的发行版
wsl -d Ubuntu-22.04

# 关闭所有发行版
wsl --shutdown

# 导出/导入发行版
wsl --export Ubuntu ~/ubuntu.tar
wsl --import Ubuntu ~/ubuntu ~/ubuntu.tar

# 在 Windows 中运行 Linux 命令
wsl ls -la
wsl cat /etc/passwd

WSL2 + CUDA

WSL2 架构与底层原理

WSL2（Windows Subsystem for Linux 2）是微软在 2019 年发布的 Linux 子系统，与 WSL1 的系统调用翻译不同，WSL2 使用轻量级虚拟机运行真实的 Linux 内核，提供完整的系统调用兼容性和接近原生的性能。

WSL2 架构深度解析

WSL2 的核心组件：

  • 轻量级虚拟机（Lightweight VM）：基于 Hyper-V 技术，但不是完整的 Windows 虚拟机。启动时间约 2 秒，内存占用约 200MB（空闲时）。使用动态内存分配，Linux 进程需要多少就分配多少
  • Linux 内核：微软维护的定制 Linux 内核，基于主线内核，包含针对 WSL2 的优化（如 9P 文件系统、Hyper-V 集成服务、init 系统）。内核通过 Windows Update 更新，也可以自行编译替换
  • init 进程：WSL2 的 init 不是 systemd（默认），而是微软定制的轻量级 init，负责启动发行版、管理进程、与 Windows 通信。WSL 0.67+ 支持启用 systemd
  • 9P 文件系统：Windows 文件系统（C:、D:）通过 9P 协议挂载到 Linux 的 /mnt/c、/mnt/d。这是跨文件系统性能差的根本原因——每次文件操作都要经过 9P 协议转换
  • 互操作（Interop）：Linux 可以直接运行 Windows 可执行文件（如 code .、explorer.exe .），Windows 也可以运行 Linux 命令（wsl ls -la）。通过 /mnt/c/Windows/System32 在 PATH 中实现

性能特性与优化

WSL2 的性能表现：

  • Linux 文件系统（ext4）：在 WSL2 的虚拟磁盘（VHDX）中，性能接近原生 Linux，IO 操作比 WSL1 快 5-20 倍
  • Windows 文件系统（NTFS via 9P）：跨文件系统操作慢，尤其是大量小文件的操作（如 npm install、git status）。比原生慢 3-10 倍
  • 网络：WSL2 使用 NAT 网络模式，Linux 有独立的 IP 地址。localhost 转发由 Windows 自动处理（WSL2 的 localhost 转发）。但某些场景（如 Docker 端口映射）需要额外配置
  • 内存：WSL2 默认最多使用 50% 的系统内存（或 8GB，取较小值），不会自动释放。在 %UserProfile%/.wslconfig 中配置 memory=4GB、processors=4 限制资源

最佳实践：项目代码放在 Linux 文件系统中（~/projects/），而不是 /mnt/c/。用 VS Code Remote - WSL 扩展编辑，用 Windows 浏览器访问 localhost。这样可以获得最佳性能。

GPU 加速与 CUDA

WSL2 支持 GPU 直通（GPU Passthrough），可以在 Linux 中直接使用 NVIDIA GPU：

  • WSL2 的 CUDA：NVIDIA 提供了 WSL2 专用的 CUDA 驱动，不需要在 Linux 中安装驱动，驱动由 Windows 端提供。安装 nvidia-cuda-toolkit 即可使用 nvcc、nvidia-smi
  • Docker + GPU：在 WSL2 中运行 Docker Desktop 或原生 Docker，可以通过 --gpus all 将 GPU 暴露给容器。适合运行 PyTorch、TensorFlow 等深度学习框架
  • 限制：WSL2 的 GPU 支持目前仅限 NVIDIA GPU，AMD 和 Intel 的 GPU 支持有限。不支持 GPU 热插拔，不支持 SLI/CrossFire

开发工具链深度配置

包管理器对比与选择

Windows 有多个包管理器，各有适用场景：

  • winget：微软官方包管理器，Windows 11 内置。使用 YAML 清单，支持安装、升级、卸载、导出。软件源是 winget 社区仓库和微软商店。适合安装桌面应用和开发工具
  • Chocolatey：最老牌的 Windows 包管理器，社区包数量最多（超过 9000 个）。使用 PowerShell 脚本安装，支持安装、升级、卸载。适合需要大量软件包的场景
  • Scoop：专注于命令行工具和开发者工具，安装到用户目录（不需要管理员权限），不污染系统 PATH。适合安装 CLI 工具、开发环境、便携式应用
  • 选择建议：日常桌面应用用 winget，开发工具和 CLI 用 Scoop，特殊软件用 Chocolatey 补充。避免混用多个包管理器安装同一软件

Windows Terminal 深度配置

Windows Terminal 是微软开发的现代终端，支持多标签、多面板、GPU 加速渲染、Unicode/Emoji 支持。

关键配置项（settings.json）：

  • 默认配置文件：defaultProfile 设置默认启动的 Shell（推荐 WSL2 Ubuntu 或 PowerShell 7）
  • 外观：fontFace（推荐 Cascadia Code / FiraCode / JetBrains Mono，支持连字）、fontSize、colorScheme（内置多种主题，如 One Half Dark、Solarized Dark）
  • 透明度：opacity（0-100）、useAcrylic（亚克力模糊效果，需要 Windows 10 1903+）
  • 快捷键：actions 自定义快捷键，如 splitPane（分屏）、newTab（新标签）、copy/paste（复制粘贴）
  • 启动目录：startingDirectory 设置启动时的工作目录。WSL2 配置文件需要用 //wsl$/Ubuntu/home/username 格式

VS Code + WSL2 开发环境

VS Code Remote - WSL 是 Windows 上 Linux 开发的最佳实践：

  • 架构：VS Code UI 运行在 Windows，VS Code Server 运行在 WSL2 Linux 中。扩展分为 UI 扩展（运行在 Windows 端）和 Workspace 扩展（运行在 Linux 端）
  • 文件访问：在 WSL2 中打开项目（code ~/projects/myapp），文件操作在 Linux 文件系统中，性能好。VS Code 通过 VS Code Server 访问文件，不需要经过 9P
  • 终端：VS Code 的集成终端自动使用 WSL2 的 Shell，可以直接运行 Linux 命令。端口自动转发，在 Windows 浏览器中访问 localhost:3000 即可
  • Git：在 WSL2 中使用 Linux 版 Git，与 Windows 端的 Git 配置分离。注意行尾符问题，在 .gitattributes 中设置 * text=auto eol=lf

8大常见陷阱与最佳实践

  1. 项目放在 /mnt/c 导致性能差：这是 WSL2 最常见的性能问题。9P 文件系统的 IO 性能远低于 ext4。解决方案：项目放在 ~/projects/，用 VS Code Remote - WSL 编辑，用 explorer.exe . 在 Windows 资源管理器中打开
  2. WSL2 内存不释放：WSL2 的虚拟机会缓存文件系统页面，内存占用只增不减。在 %UserProfile%/.wslconfig 中设置 memory=4GB 限制上限，或运行 wsl --shutdown 释放
  3. Git 行尾符混乱：Windows 和 Linux 的行尾符不同（CRLF vs LF），在 WSL2 中操作 Windows 文件可能导致行尾符混乱。在 .gitattributes 中明确指定，设置 git config core.autocrlf false（在 WSL2 中）
  4. Docker Desktop 与 WSL2 集成问题：Docker Desktop 默认使用 WSL2 后端，但需要在设置中启用对应发行版的集成。否则在 WSL2 中运行 docker 命令会提示找不到。检查 docker context ls 和 Docker Desktop 设置
  5. localhost 转发不工作：WSL2 的 localhost 转发依赖 Windows 的 wslhost 进程，如果被防火墙或 VPN 拦截会失效。尝试 wsl --shutdown 后重启，或直接用 WSL2 的 IP 地址访问（ip addr show eth0）
  6. Windows 杀毒软件扫描 WSL2 文件：Windows Defender 会扫描 WSL2 的 VHDX 文件，导致 IO 性能下降。将 WSL2 的虚拟磁盘目录（%LocalAppData%/Packages/CanonicalGroupLimited.../LocalState/）添加到 Defender 排除列表
  7. 在 WSL2 中运行 GUI 应用的性能问题：WSLg（WSL2 的 GUI 支持）通过 RDP 协议渲染，性能不如原生 Windows 应用。对于需要高性能的 GUI 应用（如浏览器、IDE），建议使用 Windows 原生版本，通过 Remote 扩展连接 WSL2
  8. 多个 WSL2 发行版管理混乱：安装多个发行版（Ubuntu、Debian、Arch）后，容易混淆哪个是默认的。用 wsl -l -v 查看状态，wsl --set-default Ubuntu 设置默认，wsl --export/--import 备份和迁移发行版
