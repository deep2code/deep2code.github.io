        字段类型 说明
        text / keyword 字符串：text 全文搜索（分词+相关性打分），keyword 精确匹配、聚合、排序（ES 5.0 起已取代旧 string 类型）
        byte, short, integer, long 整数，按取值范围选最小的类型
        float, double, half_float 浮点
        boolean 布尔
        date, date_nanos 日期（毫秒 / 纳秒精度）
        object, nested 对象与嵌套数组（只有 nested 能按数组内对象属性做正确查询）
        dense_vector 向量（kNN / 语义检索，8.x 起）

        text vs keyword 取舍：这是 ES 新手第一个坑。需要 match 全文搜索与相关性打分 → text；只需要精确过滤、terms 聚合、排序 → keyword。2026 年的默认写法是用 multi-fields：title 配 text + title.keyword 子字段，两边都要；对不需要分词的字段（状态码、ID、标签数组）直接用 keyword 省内存与索引开销。

    • 采用倒序存储，关键字 → [文档 1, 文档 2, 文档 3 …]，所以能快速搜索

    • 插入的数据自动地创建类型（type）及其映射（mapping）

    • 没有事务一致性，采用乐观版本，文档每更新一次，文档元数据中版本号就增加

    • 传统数据库更关注数据一致性、永久存储等，在于操作数据；ES 则偏重于快速搜索

    • 通常用数据库数据初始化 ES 索引

    • 查询语法

      • Leaf query clauses

        • match，全文搜索，支持 text、number、date or boolean

          GET /_search
{
    "query": {
        "match": {
        "message": "this is a test"
        }
    }
}

        • term，精确相等，不要查询 text 字段

          GET /_search
{
    "query": {
        "term": {
            "user.id": {
                "value": "kimchy",
                "boost": 1.0
            }
        }
    }
}

        • range，范围过滤：数值、日期、IP 区间都支持

          GET /_search
{
    "query": {
        "range": {
            "age": {
                "gte": 18,
                "lte": 35
            }
        }
    }
}

      • Compound query clauses，生产环境用得最多的组合容器：bool

        GET /_search
{
    "query": {
        "bool": {
            "must":     [{ "match": { "title": "golang" } }],
            "filter":   [{ "term": { "status": "published" } },
                         { "range": { "publish_date": { "gte": "2026-01-01" } } }],
            "must_not": [{ "term": { "author": "spam-bot" } }],
            "should":   [{ "term": { "tags": "grpc" } }]
        }
    }
}

        filter 子句不参与相关性打分、可被缓存，能放 filter 的尽量别放 must——这是 ES 最容易拿到手的性能优化。

Elasticsearch 9.0 关键变化（2025-07）

Elasticsearch 9.0.0 于 2025 年 7 月发布，基于 Lucene 10.1，是 8.x 之后时隔三年的重大版本；8.x 系列以 8.19 收官，升级 9.x 可平滑迁移。截至 2026-08，当前稳定线为 9.5.x（9.5.2 @ 2026-08-20）。

  • rank_vectors 字段类型：late-interaction（交互式）向量检索，document embedding 与 query embedding 分离，精度更优。
  • semantic_text 字段类型 GA：内置推理模型自动生成嵌入，声明式语义搜索，告别手动 pipeline。
  • ES|QL 增强：新增 LOOKUP JOIN（技术预览），管道查询语言持续演进。
  • 安全加固：API key 存储改为 SSHA-256 散列（不再明文可读），keystore 加密升级 AES-256。
  • 非主节点支持：只读/负载均衡节点类型，适配大规模横向扩展。

自 8.15 起 Elasticsearch / Kibana 采用多许可模式：免费功能可选 SSPL 1.0、AGPLv3、Elastic License v2 三种之一，官方对外口径回归「open source」。生产部署选型时，AGPLv3 选项让开源社区分支与二次分发更灵活。

Elasticsearch 8.x 关键特性（8.19 收官）

  • 向量搜索（kNN）：原生支持近似最近邻搜索，支持 HNSW 算法。
    // 创建向量索引
PUT /products {
  "mappings": {
    "properties": {
      "name": { "type": "text" },
      "embedding": {
        "type": "dense_vector",
        "dims": 768,
        "index": true,
        "similarity": "cosine"
      }
    }
  }
}

// 向量搜索
POST /products/_search {
  "knn": {
    "field": "embedding",
    "query_vector": [0.1, 0.2, ...],
    "k": 10,
    "num_candidates": 100
  }
}
  • ES|QL：新的管道查询语言，比 DSL 更简洁（8.14 起 GA）。
    POST /_query
{
  "query": "FROM logs | WHERE status >= 400 | STATS count = COUNT(*) BY status | SORT count DESC"
}
  • 语义搜索：内置 ELSER 模型，无需自行生成 embedding。
  • 安全默认开启：8.x 默认启用 TLS 和安全认证。
  • 处理大型数据集：支持 frozen tier 和 searchable snapshots。

数据文件存储与结构

Elasticsearch 底层基于 Lucene，每个分片是一个独立的 Lucene 索引。理解段文件和倒排索引结构是性能调优的关键。

分片目录结构

elasticsearch_data_dir/nodes/0/indices/{index_uuid}/0/
├── index/                          # Lucene 索引目录
│   ├── segments_1                  # 段提交点（记录所有活跃段）
│   ├── segments.gen                # 段生成号
│   ├── _0.cfe                      # 复合文件（封装多个小文件）
│   ├── _0.cfs                      # 复合文件数据
│   ├── _0.si                       # 段元信息
│   ├── _0.fdt                      # 存储字段数据（Stored Fields）
│   ├── _0.fdx                      # 存储字段索引
│   ├── _0.tim                      # 词项词典（Term Dictionary）
│   ├── _0.tip                      # 词项索引（Term Index，FST）
│   ├── _0.doc                      # 跳跃表（文档频率、位置）
│   ├── _0.pos                      # 位置信息（短语查询、邻近查询）
│   ├── _0.pay                      # 载荷信息（Payloads）
│   ├── _0.nvd                      # 归一化向量数据（Norms）
│   ├── _0.nvm                      # 归一化向量元数据
│   ├── _0.dvd                      # Doc Values 数据（列式存储）
│   ├── _0.dvm                      # Doc Values 元数据
│   ├── _0.kdd                      # BKD 树数据（数值/地理空间索引）
│   ├── _0.kdi                      # BKD 树索引
│   ├── _0.vem                      # 向量元数据（KNN 向量搜索）
│   └── _0.vec                      # 向量数据
├── translog/                       # 事务日志（写前日志 WAL）
│   ├── translog-1.tlog             # translog 数据文件
│   └── translog.ckp                # translog 检查点
└── _state/                         # 分片状态元数据
    └── state-{version}.st

倒排索引（Inverted Index）

倒排索引是搜索引擎的核心，将"词项 → 文档列表"建立映射。

文档集合：
  Doc1: "The quick brown fox"
  Doc2: "The lazy dog"
  Doc3: "A quick brown dog"

倒排索引（分词后）：
┌──────────┬─────────────┬──────────────────┐
│  Term    │  Doc Freq   │  Posting List    │
├──────────┼─────────────┼──────────────────┤
│  quick   │  2          │  [Doc1, Doc3]    │
│  brown   │  2          │  [Doc1, Doc3]    │
│  fox     │  1          │  [Doc1]          │
│  lazy    │  1          │  [Doc2]          │
│  dog     │  2          │  [Doc2, Doc3]    │
└──────────┴─────────────┴──────────────────┘

Posting List 还包含：
  - 词频（TF）：词在文档中出现的次数
  - 位置（Position）：词在文档中的位置（短语查询）
  - 偏移（Offset）：词的起始/结束字符位置（高亮）
  - 载荷（Payload）：自定义元数据

FST 词项词典（Finite State Transducer）

Lucene 使用 FST（有限状态转换器）压缩词项索引，将所有词项存储在一个极小的状态机中。

词项集合：mop, moth, pop, star, stop, top

FST 状态机（共享前缀和后缀）：
  (s) --m--> [1] --o--> [2] --p--> [3] (mop)
                          [2] --t--> [4] --h--> [5] (moth)
  (s) --p--> [6] --o--> [7] --p--> [3] (pop)  ← 共享后缀 "p"
  (s) --s--> [8] --t--> [9] --a--> [10] --r--> [11] (star)
                          [9] --o--> [12] --p--> [3] (stop) ← 共享
  (s) --t--> [13] --o--> [7] --p--> [3] (top)  ← 共享

优势：
  - 内存占用极小（通常几 MB 即可存储百万级词项）
  - O(1) 词项查找
  - 支持前缀查询、范围查询

Doc Values（列式存储）

Doc Values 是在索引时创建的列式存储结构，用于排序、聚合和脚本访问，避免从倒排索引中逐文档查找。

行式存储（Stored Fields .fdt）：
  Doc1: {name: "Alice", age: 30, city: "Beijing"}
  Doc2: {name: "Bob", age: 25, city: "Shanghai"}
  Doc3: {name: "Carol", age: 35, city: "Beijing"}

列式存储（Doc Values .dvd）：
  name:  [Alice, Bob, Carol]
  age:   [30, 25, 35]
  city:  [Beijing, Shanghai, Beijing]

聚合时只需读取 age 列，无需扫描所有文档的所有字段。
- 默认对非 analyzed 字段启用
- analyzed 字段需手动设置 fielddata=true（内存消耗大，不推荐）

BKD 树（Block K-D Tree）

BKD 树用于数值、日期和地理空间字段的索引，支持高效的范围查询。

BKD 树是 K-D 树的变体，将多维数据点组织成平衡树：

  根节点（分割维度 0，值 50）
  ├── 左子树（< 50）
  │   ├── 分割维度 1，值 30
  │   │   ├── 叶子块（4个点）
  │   │   └── 叶子块（4个点）
  │   └── ...
  └── 右子树（>= 50）
      └── ...

特点：
  - 每个叶子块存储 512-1024 个数据点
  - 支持 1-8 维数据（数值、经纬度等）
  - 范围查询 O(log N + 匹配点数)
  - 替代了旧的 Trie 树和 FieldCache

段合并机制

  • 不可变段：Lucene 段一旦写入就不可修改，删除是标记（.del 文件），更新是删除+新增
  • refresh：默认每秒将内存中的写入刷新为新段（近实时搜索）
  • flush：将段持久化到磁盘，清空 translog
  • force merge：手动触发段合并，将多个小段合并为一个大段（适合只读索引）
  • 合并策略：TieredMergePolicy，根据段大小分层合并
