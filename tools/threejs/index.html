Three.js WebGL 3D 渲染

🏷️ 代码生图

💡 你在工作中遇到了这个问题，查了很多资料还是没搞懂。或者你面试的时候被问到，答不上来。

Three.js：把 WebGL 的复杂度藏起来

我第一次碰 Three.js 是想给产品做个 3D 展示页。直接学 WebGL 简直是噩梦——要手写矩阵变换、着色器，光个三角形都要搞半天。

三个词入门

Scene（场景）是所有东西的容器，Camera（相机）决定你从哪看，Renderer（渲染器）把画面画到 canvas 上。加个 Mesh、转个相机动一动，就出画面了。先把这三者关系想明白，别的都是细节。

flowchart LR SCENE[Scene 场景] --> MESH[Mesh 物体] MESH --> GEO[Geometry 几何体] MESH --> MAT[Material 材质] CAM[Camera 相机] --> RENDER[Renderer] SCENE --> RENDER RENDER --> CANVAS[Canvas 显示]

渲染循环：60 帧背后在干嘛

Three.js 默认用 requestAnimationFrame 跑渲染循环。每一帧它做三件事：更新物体变换、跑着色器、交换前后缓冲。你要做动画，就是在这个循环里改物体的 rotation/position：

function animate() {
  requestAnimationFrame(animate);
  mesh.rotation.y += 0.01;
  renderer.render(scene, camera);
}
animate();

这里有个性能关键：别每帧 new 对象。我早期在 animate 里 new 一个 Vector3 做插值，跑五分钟内存就涨几百 MB——垃圾回收疯狂工作导致掉帧。正确做法是复用预先创建好的向量。

性能：移动端 60fps 的代价

3D 页面最容易「电脑流畅、手机幻灯片」。我的经验值：

指标桌面目标移动目标（参考值）
三角面数<100 万<10 万
draw call<1000<200
纹理分辨率20481024
帧率60fps30fps 可接受

最有效的优化是合并几何体（mergeBufferGeometries）和实例化（InstancedMesh）。画 1000 个相同的树，别建 1000 个 Mesh，用 InstancedMesh 一次画完，draw call 从 1000 降到 1。这是新手最容易忽略的。

必坑

移动端发热严重时浏览器会降频，帧率暴跌。别只在桌面机测，一定要拿真手机测。我做的一个产品页桌面 60 帧，旧 iPhone 直接掉到 15 帧，临时砍了三个后处理特效才救回来。

2024-2026：Three.js 生态的变化

  • r160+ 用 WebGPU：Renderer 支持 WebGPU，比 WebGL2 快不少，旧浏览器自动回退 WebGL；
  • R3F（React Three Fiber）：把 Three.js 变成声明式 React 组件，做交互 3D 应用首选；
  • drei / postprocessing：R3F 的工具集和后处理库，预设了相机控制、加载器、bloom 等效果；
  • Blender 导出 glTF：模型别在代码里手搓，Blender 建好导出 .glb，Three.js 直接加载；
  • 3D Tiles：大规模 GIS/城市渲染开始普及。
方案定位适合
原生 Three.js直接命令式 API小 demo、学习
R3F + drei声明式 React交互 3D 应用、产品页
model-viewer官方 Web Component只展示个 3D 模型
Babylon.js游戏引擎级复杂游戏、物理仿真

加载模型：别在代码里造几何体

正经项目都是 Blender 建模导出 glTF，Three.js 用 GLTFLoader 加载。这才是正经流程：

import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
const loader = new GLTFLoader();
loader.load('model.glb', (gltf) => {
  scene.add(gltf.scene);
});

关键点：模型文件要走 CDN、要 loading 进度、要 Draco 压缩（.glb 能从几十 MB 压到几 MB）。我早期没开 Draco，一个模型 40MB，首屏白屏半分钟才出画面。

flowchart TD A[Blender 建模] --> B[导出 glTF glb] B --> C[Draco 几何压缩] C --> D[CDN 分发] D --> E[GLTFLoader 异步加载] E --> F[加入 Scene 显示]

我的实战清单

  • 动画循环里别 new 对象，复用变量；
  • 相同物体用 InstancedMesh，别建一堆 Mesh；
  • 模型走 glb + Draco，别用 obj/fbx；
  • 后处理（bloom 等）很耗性能，移动端能砍就砍；
  • 加载模型加进度条，别让用户对着黑屏等。

FAQ

Q：Three.js 和 Babylon.js 选哪个？
做产品展示页、交互可视化选 Three.js——生态大、例子多。做正经 3D 游戏、要物理引擎（碰撞、刚体）选 Babylon。两者都是 WebGL 封装，Three.js 更流行。

Q：手机上跑不动怎么办？
降分辨率（renderer.setPixelRatio）、砍三角面、关后处理、用 InstancedMesh。还不行就降级成 2D 或预渲染视频——别死撑。

Q：需要学 WebGL 原生吗？
做 3D 应用不用，Three.js 够用。但想调优、写自定义着色器时，懂一点着色器语言（GLSL）很有帮助。我的路径是先用 Three.js 做东西，卡壳了再补着色器。

Q：2026 了，AI 能帮我写 3D 吗？
能帮你写交互逻辑、相机控制这种样板代码，但模型美术、材质调优还得靠 Blender 和审美。AI 生成的 Three.js 代码你得懂原理才能调，别盲信。

小结

Three.js 把 3D 开发的门槛从「会图形学」降到「会写 JS」。做产品页、数据可视化它够了；真要做游戏级效果，Babylon 或 Unity 走 WebAssembly 路线。下一篇 Vim，看一个终端里活了三十年的编辑器。
