Wireshark 抓包

🏷️ Wireshark

Wireshark：网络出问题时的照妖镜

我被一个线上 bug 折磨过三天：App 在某些地区偶发「登录超时」，日志里查不出来。最后开 Wireshark 抓了一段包，一眼看到——那个地区的运营商把 TLS ClientHello 里的 SNI 字段给劫持/篡改了，导致 TLS 握手失败。这种问题，不抓包你永远猜不到。Wireshark 是网络问题的终极裁判，别信推测，看包。

两个过滤器别混

捕获过滤器（Capture Filter）在抓包前用，BPF 语法，决定哪些包进文件；显示过滤器（Display Filter）在抓完后用，决定哪些包显示出来。新手最大的坑就是把这俩语法混了。记住：抓的时候用 BPF，看的时候用 display filter。

抓包的基本流程

flowchart LR A[选网卡] --> B[捕获过滤器 过滤进文件] B --> C[开始抓包] C --> D[复现问题] D --> E[停止抓包] E --> F[显示过滤器 过滤显示] F --> G[追踪流 Follow TCP Stream] G --> H[分析根因]

关键是先抓全、再过滤。别一开始就把过滤器设得太严，漏掉关键包。我习惯先抓个干净的全量包存成 .pcapng，然后在里面慢慢用显示过滤器挖。

显示过滤器：最常用的那几个

不用全背，记住这几个我天天用的：

过滤器作用
http只看 HTTP
tcp.port == 443只看 443 端口
ip.addr == 1.2.3.4按 IP 过滤
tcp.flags.syn == 1看 SYN 包
dns只看 DNS 查询
!arp && !icmp排除噪音

语法是 == 比较，&& 且，|| 或，! 非。Wireshark 会边打边提示补全，错了会标红。

TCP 三次握手：看包才懂为什么慢

理论课都学过三次握手，但抓过包才知道它在哪一步耗时。一个 TCP 连接的时间线是：

sequenceDiagram participant C as 客户端 participant S as 服务器 C->>S: SYN S->>C: SYN ACK C->>S: ACK Note over C,S: 三次握手完成 C->>S: HTTP 请求 S->>C: HTTP 响应

线上「接口慢」我就看这张时序图里每一步的间隔。如果 SYN 到 SYN-ACK 间隔几百毫秒，是网络往返延迟或服务器积压；如果 ACK 后等很久才出 HTTP 响应，是应用处理慢。定位完全不一样。

常用分析动作

  • Follow TCP Stream：右键一个包，看这条连接的完整对话，最常用；
  • Statistics → Conversations：看哪些 IP 之间流量最大；
  • Expert Information：Wireshark 自动标红错误（重传、乱序、零窗口）；
  • IO Graph：看时间-流量曲线，发现丢包突刺。
必坑：重传是信号

Expert 里看到大量 TCP Retransmission、Duplicate ACK，说明网络丢包严重或对端处理不过来。别光盯着应用层——很多「接口慢」其实是底层丢包重传。我遇到过一次「服务端响应慢」，根因是中间链路丢包 3%，应用日志完全看不出来。

命令行 tshark：服务器上的 Wireshark

服务器上没有 GUI，用 tshark。这是我运维时的救命工具：

# 抓 80 端口 100 个包存文件
tshark -i eth0 -f "tcp port 80" -c 100 -w out.pcap

# 统计访问最多的 IP
tshark -r out.pcap -T fields -e ip.src_host | sort | uniq -c | sort -rn

我习惯在服务器上抓个 .pcap，下载回本地用 Wireshark 图形界面分析——服务器上跑 tshark 抓，本地 GUI 看，这是标准做法。

标准流程：服务器上 tcpdump 抓包，下载到本地用 Wireshark 分析。别在生产服务器上跑 Wireshark GUI。

我的实战清单

  • 抓包前先想清楚要复现什么，别漫无目的地抓；
  • 存成 .pcapng 留档，方便事后回溯；
  • 大文件用显示过滤器，别把全量加载进 GUI；
  • HTTPS 抓包要装根证书，否则只能看到加密的 TLS 握手；
  • 生产环境抓包注意合规——抓明文密码是隐私事故。

FAQ

Q：HTTPS 加密了，Wireshark 还能看内容吗？
只能看到 TLS 握手（SNI、证书），看不到加密后的 HTTP 内容。要解密得客户端导出 TLS 密钥（SSLKEYLOGFILE），Wireshark 加载密钥才能解。这也是为什么我开头那个案例——SNI 是明文，运营商能搞鬼。

Q：抓到一大堆包，从哪开始看？
先看 Expert Information 标红的错误，再 Follow TCP Stream 看异常连接的完整对话。别从第一个包开始逐行读，那是浪费生命。

Q：Wireshark 能抓 wifi/手机的包吗？
电脑开热点，手机连热点，Wireshark 抓热点网卡。或者手机 root 后用 tcpdump。iPhone 比较麻烦，一般用 Charles/mitmproxy 做 HTTP 代理抓，比 Wireshark 方便。

Q：2026 了，eBPF 和可观测性会取代 Wireshark 吗？
不会完全取代。eBPF 工具（bpftrace、Pixie）擅长持续监控和聚合，但「精确看某一次握手的每个字段」还是 Wireshark 直观。两者是互补，不是替代。

小结

Wireshark 不是用来天天用的，是网络出问题时的「法医工具」。学会过滤器和 Follow Stream，你就能定位 80% 的「偶发网络问题」。别猜，看包。下一篇 Firefox，看浏览器内部是怎么工作的。
