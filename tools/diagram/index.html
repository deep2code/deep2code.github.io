代码生图工具

🏷️ 代码生图

💡 你在工作中遇到了这个问题，查了很多资料还是没搞懂。或者你面试的时候被问到，答不上来。

什么是代码生图

代码生图（Diagram as Code）是用文本或代码描述来生成图表的技术范式。跟传统 GUI 拖拽工具比，它把"图"变成了"可被版本控制的源代码"。

核心优势就这几条：

  • 版本可控：图源文件是纯文本，进 Git，支持 diff、review、回滚
  • 可复现：相同输入永远生成相同输出，没有"谁改了图"的协作混乱
  • 自动化：能接 CI/CD，文档构建时自动生成最新图
  • 易协作：文本格式适合多人协作、评论、合并请求
一句话心智模型

GUI 工具产出"图片"，代码生图产出"图纸 + 渲染管线"。前者是结果，后者是结果的可重建配方。你跟同事争执"这图到底谁画的"，用代码生图就不会发生——git blame 一查便知。

一、Diagram as Code（文本描述 → 结构图）

这类工具用类 Markdown 的简洁语法描述图表结构，自动布局渲染，最适合文档配图和软件架构图。

Mermaid ⭐ 最流行

Mermaid 是基于 JavaScript 的图表绘制工具，类似 Markdown 的文本语法创建图表。

最大优势

GitHub / GitLab / Notion 原生支持渲染，在 README 和技术文档里不用额外配置就能显示。这是 Mermaid 成为最流行代码生图工具的核心原因——你写在 README 里，读者打开就能看到图，不用下载、不用装插件。

  • 图表类型：流程图、时序图、甘特图、ER 图、类图、状态图、饼图、Git 图、思维导图、看板
  • 语法难度：极低，5 分钟上手
  • 适合：日常文档配图、README、技术方案草稿

PlantUML ⭐ 专业 UML

PlantUML 是开源的 UML 绘图工具，支持 UML 全系列图表（时序 / 类 / 用例 / 活动 / 组件 / 部署 / 状态），以及 C4 架构模型、Archimate、甘特图。底层默认用 Graphviz 布局引擎。

  • 图表类型：UML 全系列 + C4 + 架构图 + 甘特图
  • 语法难度：中等，要了解 UML 规范
  • 适合：专业架构设计、UML 建模、系统设计文档

Graphviz ⭐ 底层布局引擎

Graphviz 是 AT&T 实验室开发的图形可视化工具，用 DOT 语言描述图结构。它是 PlantUML、Doxygen 等众多工具的底层布局引擎，提供 dot / neato / fdp / sfdp / twopi / circo 六种布局算法。

  • 特点：布局算法最强、极其灵活、适合复杂网络拓扑
  • 缺点：语法原始、没有开箱即用的图表类型、要本地安装
  • 适合：复杂依赖图、网络拓扑、编译器 IR 可视化

D2 ⭐ 新兴架构专用

D2 是 2022 年发布的图表语言，专为软件架构图设计。相比 Mermaid，D2 的自动布局质量更高，支持容器、云图标、动画和可交互输出。

四个 Diagram-as-Code 工具横向对比，我选型时直接看这张：

工具上手成本自动布局质量GitHub 原生最适合
Mermaid极低中是文档配图、快速草稿
PlantUML中中（依赖 Graphviz）需渲染插件专业 UML / C4 建模
Graphviz高高（算法丰富）否复杂依赖 / 拓扑图
D2低高需渲染软件架构图、可交互输出

二、2D 数据可视化图表库

这类是 JavaScript 图表库，用配置对象或代码生成交互式数据图表，适合仪表盘、数据报告和监控面板。

Apache ECharts ⭐ 国内最流行

百度开源、Apache 顶级项目。配置驱动（option 对象），支持 20+ 种图表类型，自动选 SVG / Canvas 渲染。中文文档完善，国内互联网公司广泛使用。做国内项目我基本默认 ECharts。

Chart.js ⭐ 轻量入门

Canvas 渲染的轻量图表库，支持 8 种基础图表，响应式设计。包体积约 200KB（gzip 60KB），最简单的图表库，适合快速原型。做活动页、内部小工具首选。

D3.js ⭐ 灵活度天花板

关键区别

D3（Data-Driven Documents）不是图表库，而是底层数据可视化工具集。它把数据绑到 DOM / SVG，让你完全控制每个像素。学习曲线极陡，但能实现任何视觉效果——纽约时报、Observable 这些顶级数据新闻产品都在用。做简单图表别碰它。

三、3D 可视化 / 渲染引擎

Three.js ⭐ 最流行 WebGL 库

轻量级 3D 渲染库，API 直观，社区最大，学习资源丰富。适合数据可视化 3D 图表、产品 3D 展示、创意编码。React 生态有 React Three Fiber 封装。做产品展示我默认它。

Babylon.js ⭐ 微软全功能引擎

微软出品的完整 3D 游戏 / 仿真引擎，TypeScript-first。内置物理引擎、粒子系统、GUI、空间音频、Inspector 调试器。WebGPU 优先支持（8.0+），适合数字孪生、工业仿真、3D 游戏。

选型决策树

不知道选哪个时，沿着这棵决策树走一遍就能收敛：

flowchart TD Q[需要生图?] --> A[文档配图 README] Q --> B[数据图表 仪表盘] Q --> C[3D 可视化] A --> A1{图表类型?} A1 -->|简单流程图| A2[Mermaid GitHub 原生] A1 -->|专业 UML| A3[PlantUML] A1 -->|复杂拓扑| A4[Graphviz] B --> B1{项目需求?} B1 -->|国内项目| B2[ECharts] B1 -->|快速原型| B3[Chart.js] B1 -->|高度定制| B4[D3.js] C --> C1{场景?} C1 -->|产品展示| C2[Three.js] C1 -->|仿真游戏| C3[Babylon.js]

最佳实践

  • 优先选有原生渲染的：README 配图首选 Mermaid，避免读者打开插件或下载图片
  • 把图源文件进 Git：无论用哪套工具，源文件（.mmd / .puml / .dot / .d2）都提交，产物由 CI 渲染
  • 图表宁简勿繁：一张图超过 30 个节点就该拆成多张子图，否则失去沟通价值
  • 数据图表看场景选渲染器：大数据量（万级点）用 Canvas / WebGL，少量交互图用 SVG 更清晰
  • 团队先定规范再上手：统一用哪套、文件放哪、谁负责维护，比学语法更重要

FAQ

Q1：Mermaid 和 PlantUML 到底选谁？
个人文档 / README / 轻量架构 → Mermaid（GitHub 原生、语法简单）；正式 UML 建模、C4 架构、要严格规范 → PlantUML。

Q2：D3.js 和 ECharts 都是图表库，区别在哪？
ECharts 是"开箱即用的图表库"，配 option 就出图；D3 是"作图工具集"，给你原始图元自己拼，灵活但要写很多代码。业务仪表盘用 ECharts，艺术化定制用 D3。

Q3：Three.js 和 Babylon.js 怎么选？
产品展示、数据 3D、创意编码 → Three.js（生态大、上手快）；游戏、物理仿真、数字孪生 → Babylon.js（引擎完整、调试器强）。

Q4：AI 生成哪种图最靠谱？
Mermaid 最靠谱，语法简单模型不容易写错；ECharts option 配置对象次之；PlantUML 语法复杂，生成后要人工检查。

总结

选型速记：文档配图 → Mermaid；专业 UML → PlantUML；国内数据图表 → ECharts；轻量原型 → Chart.js；高度定制 → D3.js；3D 展示 → Three.js；仿真游戏 → Babylon.js。
