画图工具选型

🏷️ 代码生图

为什么选型这件事很重要

代码生图工具一大堆，定位、能力、学习曲线、生态差得很远。我见过不少团队在这个坑里反复跳：拿 Mermaid 画复杂架构图，结果一团乱麻；拿 Chart.js 扛百万级数据，卡到怀疑人生；又或者反过来，...

我的选型第一原则

别用最强大的工具，用学习成本最低、刚好能满足需求的那个。Mermaid 能搞定的别上 D3，Chart.js 能做的别上 ECharts。我自己的习惯是：先问"这张图最复杂的部分是什么"，再去找最小够用的工具。

授权坑

Highcharts 免费但商用要授权，我见过公司没买授权用 Highcharts 做商业产品，最后收到律师函。做商业产品前一定看一眼授权协议，ECharts（Apache 2.0）、Chart.js（MIT）、D3（ISC）都是随便用。

按场景直接推荐

技术文档 / README

首选 Mermaid。GitHub/GitLab/Notion 原生支持，零配置，5 分钟上手。流程图、时序图、ER 图、甘特图都能上。

  • 简单流程图/时序图 → Mermaid
  • 专业 UML/架构图 → PlantUML（需 CI 生成图片）
  • 复杂网络拓扑 → Graphviz

数据仪表盘 / 监控面板

国内项目首选 ECharts。图表类型 20+，中文文档完善，大数据性能好，配置驱动开发快。

  • 国内项目 / 复杂仪表盘 → ECharts
  • 简单图表 / 轻量页面 → Chart.js
  • 高度定制 / 数据艺术 → D3.js
  • 商业级 / 股票金融 → Highcharts（记得买授权）

3D 可视化 / 产品展示

  • 产品 3D 展示 / 数据可视化 3D / 创意编码 → Three.js（轻量、灵活、社区大）
  • 数字孪生 / 工业仿真 / 3D 游戏 → Babylon.js（功能全、物理引擎、Inspector）
  • VR/AR 网页 → A-Frame（基于 Three.js）

Python 数据分析

  • 论文 / 出版 / 静态报告 → Matplotlib（矢量输出、出版级质量）
  • 统计分析 / 数据探索 → Seaborn（基于 Matplotlib，统计图表专用）
  • 交互式报告 / Jupyter / Web → Plotly（HTML 输出、交互丰富）
  • 国内项目 / ECharts 生态 → pyecharts

实际项目怎么组合用

真实项目里很少只用一个工具，都是按场景组合。我自己做技术博客站是这么配的：

项目类型主力组合
技术博客 / 文档站Mermaid（流程图）+ ECharts（交互图表）+ Draw.io（复杂架构，导 SVG）
数据平台 / BIECharts（前端渲染）+ D3（ECharts 不支持的定制）+ Plotly（后端探索）
3D 产品站Three.js + React Three Fiber + GSAP（动画）+ Blender（模型）
数据科学研究Jupyter + Pandas + Seaborn（探索）+ Matplotlib（出版）+ Plotly（分享）

我踩过的选型陷阱

  1. 用 Mermaid 画复杂架构图：布局控制弱，超过 20 个节点就乱，复杂架构应该用 PlantUML 或 Draw.io
  2. 用 Chart.js 做大数据仪表盘：超过 10000 点就卡，大数据量应该用 ECharts 或 D3 + Canvas
  3. 用 D3.js 做简单柱状图：杀鸡用牛刀，做简单图表用 Chart.js 或 ECharts
  4. 用 Three.js 做游戏：Three.js 是渲染库不是游戏引擎，没有物理、碰撞、场景管理，做游戏用 Babylon.js
  5. 用 Matplotlib 做 Web 交互图表：静态库，Web 交互用 Plotly 或 ECharts
  6. 忽略包体积：ECharts 完整包 1MB+，Three.js 700KB+，移动端首屏要按需引或选轻量方案
  7. 忽略中文支持：Matplotlib 默认不支持中文，要配字体；国内项目优先 ECharts

同一需求，四种工具各写一遍

光看表格不够直观。同一个"用户登录"流程图，用四种工具各写一遍，感受下手速：

Mermaid（5 行）

flowchart LR
    A['用户输入'] --> B{'密码正确?'}
    B -->|是| C['跳转首页']
    B -->|否| D['提示错误']

PlantUML（10 行）

@startuml
start
:用户输入账号密码;
if (密码正确?) then (是)
  :跳转首页;
else (否)
  :提示错误;
endif
@enduml

ECharts 配置对象（折线图）

const option = {
    xAxis: { type: 'category', data: ['周一','周二','周三'] },
    yAxis: { type: 'value' },
    series: [{ data: [120, 200, 150], type: 'line' }]
};

D3.js（30+ 行起步）

const svg = d3.select('#chart').append('svg')
    .attr('width', 600).attr('height', 400);
const x = d3.scaleBand().domain(data.map(d => d.name)).range([0, 600]);
svg.selectAll('rect').data(data).enter().append('rect')
    .attr('x', d => x(d.name)).attr('width', x.bandwidth());

同样是"出一张图"，Mermaid 5 行，ECharts 一个配置对象，D3 要写选择集、比例尺、数据绑定。这就是学习曲线的直观差距。

总结

代码生图工具选型没有"最好"，只有"最合适"。文档配图选 Mermaid，专业 UML 选 PlantUML，国内数据图表选 ECharts，轻量原型选 Chart.js，高度定制选 D3.js，3D 展示选 Three.js，仿真游戏选 Babylon.js。工具是手段，清晰传达信息才是目的。把精力放在数据和内容上，别放在工具上。
