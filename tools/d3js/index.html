D3.js 数据驱动文档

🏷️ 代码生图

D3.js 简介

D3.js（Data-Driven Documents）是 Mike Bostock 2011 年做的数据可视化库，现在 GitHub 上最有影响力的可视化项目，100K+ Stars。

我的真实感受

做一张柱状图，Chart.js 五分钟，D3 可能要五十分钟。但 D3 能做出来 Chart.js 这辈子做不出来的东西。它是"图表零件"，不是"图表成品"。我做商业仪表盘基本不用它，做纽约时报那种数据新闻、做高度定制的交互可视化，才上 D3。

flowchart LR A[数据] --> B[D3 选择集] B --> C[数据绑定] C --> D[enter 进入] C --> E[update 更新] C --> F[exit 退出] D --> G[创建 DOM] E --> H[更新 DOM] F --> I[删除 DOM] G --> J[SVG Canvas HTML] J --> K[比例尺 坐标轴 布局] K --> L[过渡 交互]

核心特性

  • 数据驱动：数据绑到 DOM，数据变了视图自动跟着变
  • 完全控制：操作 SVG/Canvas/HTML，效果灵活度天花板
  • 模块化：d3-selection、d3-scale、d3-axis、d3-force 等 30+ 独立模块，按需引
  • 布局算法：力导向、树、打包、分区、弦图、桑基、蜂巢、日历等 20+
  • 比例尺系统：线性、对数、时间、序数、阈值、分位数等 12 种
  • 过渡动画：d3-transition 流畅的属性过渡和缓动函数
  • 交互强：d3-drag、d3-zoom、d3-brush、d3-contour

设计哲学：不抽象

D3 的核心哲学就是"不抽象"。它不藏 DOM，不封装图表类型，给你最小原语直接操作 Web 标准。这意味着：

  • 学习曲线极陡，但天花板极高
  • 做柱状图比 Chart.js 多花十倍时间，但能实现 Chart.js 不可能实现的效果
  • 跟 React/Vue 的心智模型不一样——D3 直接操作 DOM，框架是声明式的

快速开始

安装

# 完整引入
npm install d3

# 按需引入（推荐，包小一半）
npm install d3-selection d3-scale d3-axis d3-shape

第一个柱状图

从数据到坐标轴到柱子，完整走一遍，这就是 D3 的典型写法：

import * as d3 from 'd3';

const data = [
    { name: 'Mon', value: 30 }, { name: 'Tue', value: 80 },
    { name: 'Wed', value: 45 }, { name: 'Thu', value: 60 },
    { name: 'Fri', value: 20 }, { name: 'Sat', value: 90 }
];

// 边距约定，D3 的经典模式
const margin = { top: 20, right: 20, bottom: 30, left: 40 };
const width = 600 - margin.left - margin.right;
const height = 400 - margin.top - margin.bottom;

const svg = d3.select('#chart')
    .append('svg')
    .attr('width', width + margin.left + margin.right)
    .attr('height', height + margin.top + margin.bottom)
    .append('g')
    .attr('transform', `translate(${margin.left},${margin.top})`);

// 比例尺：数据域映射到视觉范围
const x = d3.scaleBand().domain(data.map(d => d.name)).range([0, width]).padding(0.2);
const y = d3.scaleLinear().domain([0, d3.max(data, d => d.value)]).range([height, 0]);

// 坐标轴
svg.append('g').attr('transform', `translate(0,${height})`).call(d3.axisBottom(x));
svg.append('g').call(d3.axisLeft(y));

// 柱子（数据绑定核心）
svg.selectAll('.bar')
    .data(data)
    .enter()
    .append('rect')
    .attr('class', 'bar')
    .attr('x', d => x(d.name))
    .attr('y', d => y(d.value))
    .attr('width', x.bandwidth())
    .attr('height', d => height - y(d.value))
    .attr('fill', 'steelblue');

核心概念

数据绑定（enter-update-exit）

这是 D3 的命门，搞不懂这个你永远写不好 D3。数据数组跟 DOM 元素数量对不上时，产生三种状态：

  • enter（进入）：数据比元素多，要创建新元素
  • update（更新）：数据和元素一一对应，更新现有元素
  • exit（退出）：元素比数据多，删掉多余的
flowchart LR A[数据数组] --> B{数据绑定?} B --> C[enter 数据大于元素] B --> D[update 数据等于元素] B --> E[exit 数据小于元素] C --> F[append 创建元素] D --> G[attr 更新属性] E --> H[remove 删除元素]

完整的 enter-update-exit 三段式，这是 D3 动态图表的标准模板，背下来：

function update(data) {
    const bars = svg.selectAll('.bar')
        .data(data, d => d.id);  // 第二个参数是 key 函数，必须用！

    // 1. exit：删掉多余元素，带个收缩动画
    bars.exit().transition().duration(300)
        .attr('height', 0).attr('y', height).remove();

    // 2. enter：创建新元素，初始高度 0
    const enter = bars.enter().append('rect').attr('class', 'bar')
        .attr('x', d => x(d.name)).attr('y', height)
        .attr('width', x.bandwidth()).attr('height', 0)
        .attr('fill', 'steelblue');

    // 3. enter + update 合并，统一做过渡
    enter.merge(bars).transition().duration(500)
        .attr('x', d => x(d.name))
        .attr('y', d => y(d.value))
        .attr('height', d => height - y(d.value));
}
新手必踩的坑

不写 key 函数（.data(data, d => d.id)），数据更新时 DOM 就会错乱——柱子该动的不动、该消失的不消失。这是我见过最多的 D3 新手 bug，没有之一。

比例尺（Scale）

比例尺把数据域（domain）映射到视觉范围（range），是可视化的核心。常用这几种：

比例尺类型适用场景
scaleLinear连续→连续数值数据，最常用
scaleLog连续→连续指数增长数据
scaleTime时间→连续时间序列
scaleBand离散→连续柱状图 x 轴，算带宽
scaleOrdinal离散→离散分类数据映射颜色
scaleThreshold连续→离散热力图分段配色
 
// 线性比例尺
const x = d3.scaleLinear().domain([0, 100]).range([0, width]).clamp(true);

// 序数比例尺（分类颜色）
const color = d3.scaleOrdinal().domain(['A', 'B', 'C', 'D']).range(d3.schemeCategory10);

// 时间比例尺
const x = d3.scaleTime()
    .domain([new Date(2026, 0, 1), new Date(2026, 11, 31)])
    .range([0, width]);

// 阈值比例尺（热力图颜色）
const color = d3.scaleThreshold()
    .domain([0, 10, 20, 30, 40, 50])
    .range(['#f7fbff', '#deebf7', '#c6dbef', '#9ecae1', '#6baed6', '#2171b5']);

布局算法（Layouts）

D3 的布局模块不直接画图，只算位置和形状数据，你再拿这些数据去画 SVG。这个"算布局"和"画图"分离的设计很妙。

力导向图（d3-force）

关系图、社交网络都用力导向。节点带电互斥、边是弹簧，迭代到能量最小：

const simulation = d3.forceSimulation(nodes)
    .force('link', d3.forceLink(links).id(d => d.id).distance(100))
    .force('charge', d3.forceManyBody().strength(-300))
    .force('center', d3.forceCenter(width / 2, height / 2))
    .force('collision', d3.forceCollide().radius(30));

const node = svg.append('g').selectAll('circle')
    .data(nodes).enter().append('circle').attr('r', 20)
    .attr('fill', d => color(d.group))
    .call(d3.drag().on('start', dragstarted).on('drag', dragged).on('end', dragended));

// 每帧更新位置
simulation.on('tick', () => {
    node.attr('cx', d => d.x).attr('cy', d => d.y);
});

饼图与折线（d3-shape）

d3-shape 提供各种"生成器"——饼图算角度、折线算路径：

// 饼图布局算角度
const pie = d3.pie().value(d => d.value).sort(null);
const arc = d3.arc().innerRadius(80).outerRadius(150);  // innerRadius>0 就是环形

svg.selectAll('path')
    .data(pie(data)).enter().append('path')
    .attr('d', arc).attr('fill', (d, i) => color(i));

// 折线生成器
const line = d3.line().x(d => x(d.date)).y(d => y(d.value)).curve(d3.curveCatmullRom);
svg.append('path').datum(data).attr('d', line).attr('fill', 'none').attr('stroke', 'steelblue');

过渡动画（d3-transition）

D3 的过渡动画是一绝，属性变化自动补间：

d3.selectAll('.bar')
    .transition()
    .duration(750)           // 持续时间
    .delay((d, i) => i * 50) // 交错动画，柱子逐个长出来
    .ease(d3.easeCubicOut)    // 缓动
    .attr('height', d => height - y(d.value));

交互（拖拽/缩放/框选）

三个最常用的交互模块：

// 缩放
const zoom = d3.zoom().scaleExtent([0.5, 10]).on('zoom', (event) => {
    svg.attr('transform', event.transform);
});
svg.call(zoom);

// 框选（brush），选一段时间范围
const brush = d3.brushX().extent([[0, 0], [width, height]])
    .on('end', (event) => {
        const [x0, x1] = event.selection.map(x.invert);
        update(data.filter(d => d.date >= x0 && d.date <= x1));
    });
svg.append('g').call(brush);

大数据量：SVG 还是 Canvas

这是 D3 性能的关键决策。SVG 是 DOM 元素，精细好交互，但元素多了就卡：

渲染方式适合元素量优点缺点
SVG< 1 万DOM 可交互、可 CSS、矢量清晰元素多了 DOM 爆炸
Canvas> 1 万一次性绘制，百万级不卡无 DOM，hover 要自己算
经验线

元素少于 1 万、要精细交互，用 SVG（D3 默认）；超过 1 万点只需要 hover 检测，切 Canvas，配 d3.quadtree 做空间索引加速命中。这是我做万级散点图的标准操作。

// Canvas 画 10 万个散点
const ctx = canvas.node().getContext('2d');
ctx.fillStyle = 'steelblue';
for (let i = 0; i < data.length; i++) {
    const d = data[i];
    ctx.beginPath();
    ctx.arc(x(d.x), y(d.y), 2, 0, 2 * Math.PI);
    ctx.fill();
}

// quadtree 加速 hover 命中
const quadtree = d3.quadtree().x(d => x(d.x)).y(d => y(d.y)).addAll(data);
canvas.on('mousemove', (event) => {
    const [mx, my] = d3.pointer(event);
    const found = quadtree.find(mx, my, 10);  // 10 像素内找最近点
});

跟 React 怎么配合

D3 直接操作 DOM，跟 React 的声明式模型天生冲突。两种策略，我项目里都用过：

策略一：D3 算坐标，React 渲染（推荐）

function BarChart({ data }) {
    const { bars, xScale, yScale } = useMemo(() => {
        const x = d3.scaleBand().domain(data.map(d => d.name)).range([0, width]).padding(0.2);
        const y = d3.scaleLinear().domain([0, d3.max(data, d => d.value)]).range([height, 0]);
        return { bars: data.map(d => ({ x: x(d.name), y: y(d.value), width: x.bandwidth(), height: height - y(d.value) })), xScale: x, yScale: y };
    }, [data]);

    return (
        <svg width={width} height={height}>
            {bars.map((bar, i) => (
                <rect key={i} x={bar.x} y={bar.y} width={bar.width} height={bar.height} fill="steelblue" />
            ))}
        </svg>
    );
}

策略二：useRef + useEffect，D3 完全接管

function ForceGraph({ data }) {
    const svgRef = useRef();
    useEffect(() => {
        const svg = d3.select(svgRef.current);
        const simulation = d3.forceSimulation(data.nodes)...
        return () => simulation.stop();  // 记得 cleanup！
    }, [data]);
    return <svg ref={svgRef} width={width} height={height} />;
}

FAQ

Q1：D3 数据更新时图表不重绘或元素错乱？
几乎都是没走 enter-update-exit 三段式，或没写 key 函数。务必 .data(data, d => d.id) 绑定 key，显式处理 .exit().remove()。

Q2：D3 和 React 到底怎么配合？
推荐"D3 算坐标、React 渲染 DOM"，避免双方同时操作 DOM。完整力导/拖拽才用 useRef + useEffect，cleanup 里停掉 simulation。

Q3：一万个散点就卡？
SVG 节点太多。切 Canvas 手绘，配 d3.quadtree 做 hover 命中，别指望 SVG 扛万级元素。

Q4：比例尺要不要每次重建？
不要。提到渲染函数外，数据更新只改 .domain()，range 和 axis 复用。

Q5：D3 跟 Observable 什么关系？
Observable 是 Mike Bostock 离开 NYT 后做的交互式笔记本，D3 最佳实践和示例都在那儿，遇到问题先去那儿搜。

总结

D3 是"零件级"的可视化工具：不给你成品图，把选择集、数据绑定、比例尺、布局、过渡这五类原语交给你，所以天花板最高、上手最陡。把 enter-update-exit 和 key 函数吃透，再按数据量选 SVG 或 Canvas，就具备做任何定制可视化的能力。常规仪表盘优先 ECharts，别拿 D3 杀鸡。
