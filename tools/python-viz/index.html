Python 可视化栈的分层与场景匹配

🏷️ 代码生图

四层视角：这套栈到底在分什么工

浏览器端的图表库解决的是「页面上怎么显示」，Python 这套栈解决的是另一件事：在没有屏幕的机器上，把数据变成一个交付物——一张进论文的 PDF、一批进报告的 PNG、一个发给业务方的 HTML。约束因此完全不同：字体要自己带，尺寸要按模板定死，内存要自己管，同一份代码明年重跑得出同样的结果。

把这套栈按四层切开，选型问题就变成了「我要换哪一层」。

层代表关心什么换掉它意味着
渲染后端Agg、PDF、SVG、Cairo、交互后端图元怎么变成字节换输出格式与运行环境，代码基本不用改
对象模型Figure、Axes、Artist图的结构、坐标系、元素层级等于换整套绘图代码
语法糖seaborn、pandas.plot、plotnine少写样板，内置统计变换与分面只影响写法，底层仍然是同一个对象模型
声明式前端plotly、altair、bokeh产出一份规格，渲染和交互在浏览器里交付物从图片变成网页或 JSON

注意第三层和第二层是同一套底座：seaborn 和 DataFrame.plot 最终都在操作 Axes。这意味着语法糖的天花板就是对象模型的天花板，它省的是样板代码，不会带来新能力。而第四层是另一条路径——它不产生图元，它产生规格，所以「怎么调 DPI」这类问题在那里根本不存在。

Figure 与 Axes 的对象模型，以及状态机的代价

对象模型只有三级：Figure 是画布，持有尺寸、DPI 和保存逻辑；Axes 是一个坐标系，持有两个 Axis、数据变换和图例；Artist 是画上去的东西。所有绘图方法都挂在 Axes 上。

pyplot 在这之上加了一层状态机：一个「当前 Figure」、一个「当前 Axes」，还有一个持有所有已创建 Figure 的注册表。这一层是给交互式探索设计的，它有两个后果，混用时特别容易中招。

第一个后果是内存：用 plt 创建的 Figure 即使局部变量失效也不会被回收，因为注册表还持有引用。第二个后果是并发：当前 Figure 是进程级状态，多线程下两个任务会往同一张图上画。所以规则很简单——探索分析用 pyplot，产线代码用 Figure 对象。中间态（用 pyplot 创建、再面向对象操作）可以，但必须自己负责关闭。

# Web 服务与批量任务里不要碰 pyplot：全局状态在并发下会串图，且不 close 就不回收。
import io
from matplotlib.figure import Figure
from matplotlib.backends.backend_agg import FigureCanvasAgg

def render_png(index, values, width_in=8.0, height_in=4.5, dpi=144) -> bytes:
    fig = Figure(figsize=(width_in, height_in), dpi=dpi, layout='constrained')
    FigureCanvasAgg(fig)              # 显式绑定位图后端，不依赖全局 backend 设置
    ax = fig.subplots()               # 不进 pyplot 注册表，没有「当前图」的概念
    ax.plot(index, values, linewidth=1.0)
    ax.set_ylabel('QPS')
    buf = io.BytesIO()
    fig.savefig(buf, format='png')    # 像素尺寸 = figsize 英寸 × dpi
    return buf.getvalue()             # fig 出作用域即可回收，无需 close

后端选择与无显示环境

后端决定图元怎么落地。它必须在导入 pyplot 之前确定——要么用环境变量，要么在导入前显式设置；导入之后再改属于未定义行为。服务器上没有显示设备时，交互后端会报错或直接挂住，而用 Figure 加显式画布的写法根本不需要考虑这件事。

后端输出什么时候用坑
AggPNG 等位图服务端、CI、批量出图基础镜像通常没有中文字体，字形要自己带
PDF / PS矢量论文投稿、印刷字体类型默认是 Type 3，不少期刊直接拒收
SVG矢量网页、交付后还要编辑默认把文字转成路径，不可搜索；保留文本则依赖查看端字体
Cairo 系位图与矢量需要更好的文本整形额外系统依赖，镜像变大
交互后端（Qt、Tk、macOS）窗口本地调试需要 GUI 环境与事件循环，服务器上报无显示或卡住
笔记本内联笔记本输出探索分析单元格结束就把图关掉，后面拿不到那个 Figure 继续改

语法糖的收益与天花板

seaborn 真正的价值不是「更好看」，是把统计变换内置了：分箱、核密度估计、置信区间、分面分组。这些在纯 matplotlib 里要自己算。代价是它的函数分成两类，而这条分界线是新手报错最集中的地方。

类型函数举例返回能否传 ax尺寸怎么控越界表现
坐标系级histplot、boxplot、scatterplot、lineplot、heatmapAxes能外面自己建画布并给尺寸不涉及
图级relplot、displot、catplot、lmplot、jointplot、pairplot网格对象不能用单元格高度与宽高比传 ax 直接报错，传画布尺寸静默无效
主题与样式set_theme、set_style修改全局配置不涉及不涉及会影响同进程内其他模块的出图风格

DataFrame.plot 是更薄的一层：它返回 Axes，所以可以和 matplotlib 无缝混用；它的绘图后端还可以整体替换成 plotly 这类库，同一份调用产出交互图。但分组聚合它不做，复杂图仍然要退回到显式循环。

一句话判断该停在哪一层：图的结构是标准的就用语法糖，需要控制单个元素的位置、层级、剪裁时退回对象模型。在语法糖里强行拧出特殊布局，代码通常比直接写 Axes 更长。

交付形态决定约束：报告、论文、大屏、网页

同一份数据画同一张图，交付给四个地方要求是冲突的。这张表是返工最多的地方。

交付格式尺寸策略字体常见返工原因
论文投稿PDF 或 EPS 矢量按栏宽给定英寸，禁止事后缩放必须嵌入 TrueType交了位图；字体没嵌入；用了按内容裁剪导致尺寸走样
内部报告与幻灯片高 DPI PNG 或 SVG固定画布，DPI 200 起系统需装中文字体中文方块；标签被裁掉
大屏SVG 或大尺寸 PNG像素尺寸被模板定死字号按观看距离放大用了按内容裁剪，每张图尺寸不一致，拼版错位
网页交互HTML响应式交给前端依赖浏览器字体把整个 JS 库内联进 HTML，单文件几 MB
流水线批量统一 PNG 或 PDF模板化参数镜像内预装并预热字体缓存冷启动慢；内存持续上涨

两个细节值得单独点出来。按内容裁剪的保存选项会改变输出尺寸，它按实际内容边界重算画布，数据一变尺寸就变——这在需要拼版的场景里是错误的，应该改用约束布局在固定画布内排。DPI 只对位图有意义，矢量输出里 DPI 只影响内嵌位图与线宽换算，把 PDF 的 DPI 调到 600 并不会让它更清晰。

import matplotlib as mpl
import matplotlib.pyplot as plt
from matplotlib import font_manager

# 中文字形必须真的存在。随代码发布字体文件并显式注册，比赌系统里有某个字体名可靠。
font_manager.fontManager.addfont('/opt/fonts/NotoSansSC-Regular.otf')
mpl.rcParams['font.sans-serif'] = ['Noto Sans SC', 'DejaVu Sans']
mpl.rcParams['axes.unicode_minus'] = False   # 默认用的排版减号，中文字体常缺这个字形

# 投稿用矢量：默认字体类型是 3，改成 42 走 TrueType 嵌入
mpl.rcParams['pdf.fonttype'] = 42
mpl.rcParams['ps.fonttype'] = 42
mpl.rcParams['svg.fonttype'] = 'none'        # 保留文本而不是转成路径，代价是依赖查看端字体

fig, ax = plt.subplots(figsize=(3.5, 2.6), dpi=300, layout='constrained')
# 十万级散点如果逐个存成矢量路径，PDF 会膨胀到几十 MB，给重图层单独栅格化
ax.scatter(x, y, s=4, rasterized=True)
ax.set_xlabel('延迟 毫秒')
# 单栏宽 3.5 英寸是按投稿模板定的，所以这里不能用按内容裁剪
fig.savefig('fig1.pdf')

批量出图：内存、字体缓存与矢量膨胀

出几千张图的任务里，真正拖垮你的通常不是绘图本身。

现象根因修法
内存线性上涨直到被杀pyplot 注册表持有每张图，不关闭就不回收循环里显式关闭，或改用 Figure 对象
跑到第二十张开始刷警告未关闭图数量超过默认阈值这是提示不是原因，按上一行修
每个进程冷启动都慢几秒只读容器里写不了字体缓存，每次重建把缓存目录指到可写路径，并在镜像构建期预热一次
输出 PDF 几十 MB海量散点或网格逐个进了矢量流给重图层开栅格化，或按层级设置栅格化阈值
超长折线渲染极慢单条超长路径在位图后端上退化调整路径分块大小，并确认路径简化开着
并发出图偶发串图或崩溃pyplot 全局状态被多线程共用全程用 Figure 加显式画布，不碰 pyplot
两次构建产物字节不同矢量文件里写入了创建时间与随机 id固定时间戳环境变量与 SVG id 的哈希盐

并行化的正确方式是多进程而不是多线程：绘图是 CPU 密集且这套栈不保证线程安全，每个子进程独立导入、独立持有 Figure，互不干扰。

声明式与交互栈的定位

第四层的共同点是：Python 只负责产出一份规格，渲染和交互都在浏览器里。所以选型的第一个问题不是「哪个好看」，而是交互要不要 Python 参与。

这一层和浏览器端图表库的关系也要说清：它们最终都落到 JS 渲染库上，所以渲染性能、大数据量策略这些问题和前端是同一套，不必在 Python 侧重复研究——浏览器端的渲染架构与大数据量手段详见站内《ECharts 的渲染架构与大数据量优化》与《Chart.js 的配置模型与容量边界》。

把出图纳入数据流水线

一次性脚本和产线出图的区别，在于后者要回答三个问题：这张图是哪份数据、哪组参数画的？换台机器重跑还一样吗？没变的图能不能不重画？

内容没变则字节也不变
控制点手段不做的后果
样式单独的样式文件加上下文管理器风格散落在各脚本里，改一处要改十处
尺寸与 DPI参数化传入，不写死同一张图为报告和大屏各画一遍
字体镜像内预装并显式指定字族换机器就出方块

import hashlib, json, os
from pathlib import Path
import matplotlib as mpl
import matplotlib.pyplot as plt

os.environ.setdefault('MPLCONFIGDIR', '/var/cache/mpl')   # 可写缓存目录，避免每进程重建字体缓存
os.environ.setdefault('SOURCE_DATE_EPOCH', '315532800')   # 固定矢量文件里的创建时间
mpl.rcParams['svg.hashsalt'] = 'report-v1'                # 固定 SVG 内部 id，避免无意义 diff

def emit(name: str, params: dict, data_fp: str, draw, outdir=Path('build/figs')) -> Path:
    # 缓存键 = 数据指纹 + 出图参数，任一变化才重画
    key = hashlib.sha1((data_fp + json.dumps(params, sort_keys=True)).encode()).hexdigest()[:12]
    out = outdir / f'{name}-{key}.pdf'
    if out.exists():
        return out
    out.parent.mkdir(parents=True, exist_ok=True)
    with plt.rc_context(fname='report.mplstyle'):   # 样式集中管理，不散在业务代码里
        fig, ax = plt.subplots(figsize=params['figsize'], dpi=params['dpi'],
                               layout='constrained')
        try:
            draw(ax)
            tmp = out.with_suffix('.pdf.tmp')
            fig.savefig(tmp)      # 先写临时文件再改名，任务被打断不会留下半张图
            tmp.replace(out)
        finally:
            plt.close(fig)        # 注册表持有引用，不关就不回收
    return out

最容易踩的坑

1. 在 Web 服务或线程池里用 pyplot：当前图是进程级状态，并发请求会画到同一张图上。用 Figure 对象加显式画布。

2. 循环里 plt.subplots 不关闭：注册表持有引用，内存线性上涨，「打开图超过阈值」的警告只是提示不是原因。

3. 只改 rcParams 就指望中文出来：字形必须真的存在，容器里得装字体或随代码注册字体文件。

4. 中文字体下负号变方块：默认用的是排版减号，要把 unicode 负号选项关掉。

5. 在导入 pyplot 之后再换后端：属于未定义行为，要用环境变量或在导入前设置。

6. 需要固定尺寸时用了按内容裁剪的保存选项：输出尺寸随数据变化，拼版必错，改用约束布局。

7. 以为矢量输出也靠 DPI 提升清晰度：矢量里 DPI 只影响内嵌位图和线宽换算。

8. 投稿 PDF 用默认字体类型：默认是 Type 3，很多期刊拒收，要改成 42。

9. 把十万点散点直接存进 PDF：文件膨胀到几十 MB，给重图层开栅格化。

10. 给 seaborn 的图级函数传 ax 或画布尺寸：前者报错，后者静默无效，尺寸要用单元格高度与宽高比。

11. 在共享库里调用 seaborn 的全局主题函数：污染同进程其他模块的出图风格，改用上下文管理器。

12. 只读容器不设字体缓存目录：每个进程都重建缓存，冷启动无谓变慢，并伴随临时目录警告。
