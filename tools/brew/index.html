Homebrew 6.0

🏷️ Homebrew

概述：macOS 的软件中心

Homebrew 是 macOS / Linux 上用得最多的包管理器，你可以把它理解成命令行版的 App Store，但资源比 App Store 多得多，管理也更高效。它的命名全是酿酒梗，刚接触会一脸懵，搞懂了就挺好玩：

  • Formula（配方）：一段 Ruby 脚本，告诉你某个软件怎么装；
  • Bottle（瓶子）：预编译好的二进制包，装的时候直接下，不用现编译；
  • Keg（酒桶）：单个已安装版本的目录；
  • Cellar（地窖）：/opt/homebrew/Cellar，所有版本都堆这儿。

Cask 建在 Homebrew 之上，专门装 GUI 应用（.app 那种）。简单记：Formula 管命令行工具，Cask 管桌面应用。

名词一句话理清

Formula 是"怎么装"的配方，Bottle 是"装好的二进制"，Cellar 是"存所有版本的地窖"，Keg 是"单个版本的酒桶"。最后通过 symlink 软链到 Prefix 目录，你的 PATH 才能找到。这一套搞明白，装包慢、版本乱、删不干净这些破事就都有答案了。

安装与日常命令

一行命令装完。国内网络慢的话先配镜像（后面讲），不然 brew install 能把人等睡着：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

日常高频命令就这几条，我天天用：

# 在 .zshrc 里关掉自动更新（省时间，每次装包不再傻等 git pull）
export HOMEBREW_NO_AUTO_UPDATE=true

# 装 / 看信息 / 搜索
brew install hugo
brew info memcached
brew search redis

# 后台服务管理
brew services start nginx
brew services start unbound   # 验证型递归 DNS

# unrar 因为版权从 core 移除了，2026 直接用 unar
brew install unar

Homebrew 6.0：信任机制与性能

2026-06-11 出了 Homebrew 6.0.0，是 5.1.0 以来最重要的一个版本。我自己升级后最直接的感受是 brew update 快了一截：

  • Tap 信任机制（tap trust）：给第三方 tap 的权限划边界，供应链投毒的风险降了一大截；
  • 默认内部 JSON API：数据通道升级，体积更小、解析更快；
  • Linux 沙箱化：Linux 上装包默认在沙箱里跑；
  • brew bundle 大改进：支持 uv tools 这类新形态依赖；
  • macOS 27 Golden Gate 初步支持（仅 Apple Silicon）。

架构深度解析

Homebrew 的核心链路就一条：依赖解析 → 下 Bottle/源码 → 解压/编译到临时目录 → 装进 Cellar → 软链到 Prefix → 清临时文件。我自己排查 brew 问题全靠这条链路定位，知道卡在哪一段就知道该看哪。

组件作用
brewRuby 脚本包装器，解析命令行调子命令
Library/HomebrewRuby 代码库：CLI、公式加载、构建、下载、依赖解析
TapsFormula/Cask 的 Git 仓库，默认 homebrew/core 与 homebrew/cask
FormulaRuby 类，定义名称、版本、源码 URL、依赖、安装步骤
BottleCI 上预编译的 .tar.gz，装包优先用它

依赖分五类，搞懂它们你就明白"为什么这个包莫名其妙被装进来了"：

  • 运行时依赖（depends_on）：装并链接，跑的时候要用；
  • 构建依赖（:build）：只编译时需要，装 Bottle 的时候跳过；
  • 测试依赖（:test）：只在 brew test 时用；
  • 可选/推荐依赖：核心仓库已经弃用了，因为 Bottle 是固定配置，选代会不匹配。

跟 Linux 包管理器放一起看，Homebrew 最特别的就是"不用 root"这件事：

设计哲学

不用 root、装到用户目录——这是跟 apt/yum 最大的区别。靠 symlink 而不是复制管版本，同一时间只链一个版本，但旧版本留在 Cellar 里随时能切回来。这套设计让"装软件"这件事在 macOS 上终于不用 sudo 了。

2026 日常使用姿势

现在命令行工具全家桶我基本是这么装的，新机器半小时配完：

# 现代命令行工具全家桶
brew install ripgrep fd bat eza zoxide fzf
brew install --cask raycast orbstack warp zed

# 装指定大版本（5.1 新增）
brew version-install

# Brewfile 声明式管理，新机器一键还原
brew bundle dump     # 导出当前安装列表
brew bundle install  # 从 Brewfile 安装

# 服务与内置 MCP
brew services start mysql
brew mcp-server      # 4.6 起，供 AI 工具链调用

两个 2026 年要注意的变化：

  • 提交签名换了：2025-02 起官方提交从 PGP 切到 SSH 签名，校验 git 历史时用新密钥；
  • 国内加速：配中科大或清华镜像，换完源 brew update 生效。

生产案例：换镜像救了我半条命

说个真事。有次公司给开发配新 Mac，十几台机器统一 brew install，结果 GitHub 源慢得要死，单台装完要四十多分钟，IT 同事直接崩溃。后来我们配了中科大镜像，Bottle 域名也一起换，同样一套包二十分钟不到全装完。核心就这几行，建议直接写进公司的装机脚本：

# 换中科大镜像（Brew 源 + Bottle 二进制源）
export HOMEBREW_BREW_GIT_REMOTE="https://mirrors.ustc.edu.cn/brew.git"
export HOMEBREW_CORE_GIT_REMOTE="https://mirrors.ustc.edu.cn/homebrew-core.git"
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.ustc.edu.cn/homebrew-bottles"
# 写进 ~/.zshrc 永久生效

八大常见陷阱

  • 路径差异：Apple Silicon 在 /opt/homebrew，Intel 在 /usr/local。脚本里别硬编码路径，用 $(brew --prefix)，再 eval "$(brew shellenv)" 自动配 PATH。
  • 权限问题：永远别 sudo brew，越用越乱。目录权限坏了用 brew doctor 诊断，chown -R $(whoami) /opt/homebrew 修。
  • cleanup 误删：先 brew cleanup -n 预览一下再动手；关键版本 brew pin 固定住。
  • 源码编译失败：确保 Xcode Command Line Tools 是最新的；优先用 Bottle，别手贱加 --build-from-source。
  • Cask 与 App Store 冲突：同一个应用别两种方式都装，升级 Cask 前先把正在跑的应用关掉。
  • PATH 顺序：Homebrew 的 bin 必须在系统路径前面，which bash 应该指向 /opt/homebrew/bin/bash。
  • update 慢：换镜像，设 HOMEBREW_BOTTLE_DOMAIN 加速 Bottle 下载。
  • 卸载残留：brew uninstall 只删 Cellar；Cask 用 --zap 清配置，Formula 的配置得手动清 ~/Library/Application Support/。

FAQ

Q1：Apple Silicon 和 Intel 能共用一份 Homebrew 吗？
不建议。Rosetta 下的 x86_64 Homebrew 在 /usr/local，原生 ARM64 在 /opt/homebrew，虽然能共存但容易混。

Q2：HOMEBREW_NO_INSTALL_CLEANUP 什么时候设？
默认每 30 天或装完自动 cleanup。CI 或需要保留旧版本的环境，设 HOMEBREW_NO_INSTALL_CLEANUP=true 关掉。

Q3：brew 装的命令行工具找不到？
八成是 PATH 没配。eval "$(brew shellenv)" 写进 ~/.zprofile，新开终端就有了。

Q4：brew doctor 报一堆 warning 要紧吗？
多数是 PATH 顺序或未链接依赖，按提示一条条修就行；只要没 error，日常用着没问题。

总结

Homebrew 的精髓就三句：用户级装、Cellar 加 symlink 管版本、Bottle 优先保速度。6.0 之后 tap trust 把供应链安全补上了，JSON API 让 update 更快。记住路径用 $(brew --prefix)、别 sudo、cleanup 先预览，日常基本不踩坑。下一篇 Hugo，看静态站点生成器。
