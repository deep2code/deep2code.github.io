Mermaid

🏷️ 代码生图

我对 Mermaid 的感情是爱恨交加

先说好的：Mermaid 让我终于不用在 Visio 里拖框了。你直接写文字描述图，它帮你画，这对工程师太友好了——图能进 git、能 code review、能跟着文档一起改。这篇博客里的图全是 Mermaid 生成的。

再说坑：Mermaid 是 JS 库，解析失败就整块不渲染。我经历过最尴尬的一次：在生产文档里改了个标签，结果线上整张图变成一段报错文字，开会时投屏演示直接社死。从那以后我立了条规矩——改 Mermaid 必须本地 mermaid.live 跑一遍再提交。

血泪教训

Mermaid 的标签里只要出现一个它不认识的字符（没转义的括号、未闭合引号），整张图就渲染失败。改完先去 mermaid.live 贴一遍，绿色通过再提交。别信「我就改了一个字」。

Mermaid 是什么，为什么火

它的思路是「图即代码」：用文本 DSL 描述图，渲染成 SVG/PNG。GitHub、GitLab、Notion、Obsidian 全内置了它。生态起来后，2024-2026 年它已经是文档画图的事实标准。下图是它的渲染链路：

flowchart LR A[mermaid 文本] --> B[解析器 语法树] B --> C[布局 dagre elk] C --> D[SVG 输出] D --> E[交互 点击 悬浮]

v11 以后性能提升明显，官方号称比 v10 快 40% 以上（参考值），我自己的体感是复杂流程图（几十节点）从「卡一下」变成「秒出」。

六种常用图，记住就够日常

Mermaid 图种很多，别贪多，日常就这六类够用：

图种关键字我用来画什么
流程图flowchart业务流程、算法步骤
时序图sequenceDiagram接口调用、请求链路
类图classDiagram代码结构、继承关系
状态图stateDiagram-v2订单/任务状态机
ER 图erDiagram数据库表关系
甘特图gantt项目排期

流程图：最常用的一张

flowchart TD
    A[开始] --> B{判断}
    B -->|是| C[执行]
    B -->|否| D[结束]
    C --> D

方向字母记一下：TD/TB 从上到下、LR 从左到右、RL 反过来、BT 从下到上。我习惯用 TD 画业务流程，LR 画调用链。

时序图：排查接口问题的利器

sequenceDiagram
    participant U as 用户
    participant GW as 网关
    participant S as 服务
    U->>GW: 请求
    GW->>S: 转发
    S-->>GW: 响应
    GW-->>U: 返回

这种图我画得最多。排查线上问题时，把一条真实请求从用户到 DB 的走向画成时序图，比看十行日志清楚。

ER 图：理数据库表关系

erDiagram
    USER ||--o{ ORDER : 下单
    ORDER ||--|{ ITEM : 包含

关系符号记法：|| 是一个、o{ 是零或多个、|{ 是一个或多个。别死记，画错了 mermaid.live 会提示。

标签里的特殊字符怎么处理

这是我踩过最多的坑。Mermaid 节点标签如果有括号、书名号、冒号，必须用引号包起来：

flowchart TD A[函数调用 process（输入）] --> B[判断 参数是否合法？] B -->|合法| C[继续处理] B -->|不合法| D[报错返回]

上面这段我特意把半角括号 () 换成了全角 （）——因为 Mermaid 节点标签里出现半角括号，解析器会懵，经常整张图挂掉。这是本博客自己写 mermaid 脚本的硬规矩：标签里的特殊字符一律全角化。你自己用的时候，如果标签必须带括号，就用引号包起来试试。

和 PlantUML 怎么选

这俩经常被拿来比较。我的经验是：文档里嵌着画、追求简单用 Mermaid；要画 UML 大图、团队已有 PlantUML 服务器用 PlantUML。

MermaidPlantUML
渲染方式浏览器端 JS服务端 Java 渲染
GitHub 支持原生支持需额外渲染
图种丰富度流程/时序/ER/甘特UML 全家桶、部署图、架构图
布局控制自动，较难微调可控性强
学习成本低中（语法更繁琐）
适合技术文档、博客严肃 UML 设计
flowchart TD A[你要画什么?] -->|流程/时序/ER| B[Mermaid 够了] A -->|复杂 UML 部署/组件图| C[PlantUML] A -->|超大型依赖关系图| D[Graphviz dot] B --> E[文档内嵌 开箱即用] C --> F[服务器渲染 精细控制]

主题和样式

Mermaid 默认主题丑得我受不了。改主题就一行 %%{init: {'theme':'dark'}}%% 或 base/forest/neutral。更细的样式用 classDef：

%%{init: {'theme':'base'}}%%
flowchart TD
    A['起点']:::start --> B['中间']
    classDef start fill:#2a9d8f,stroke:#264653,color:#fff;

我一般用 base 主题 + 自定义 classDef 给关键节点上色，别的不动。

我的几条规矩

  • 改完必去 mermaid.live 验证；
  • 节点别超过 15 个，多了就拆成两张图；
  • 标签里的括号用全角，避免解析崩溃；
  • 方向统一用 TD 或 LR，别一张图里混用；
  • 时序图参与者控制在 5 个以内，不然泳道乱成一团。

FAQ

Q：为什么我的 Mermaid 图在 GitHub 上显示，在本地 HTML 里不显示？
因为本地 HTML 没有加载 Mermaid 的 JS 渲染器。GitHub 内置了 Mermaid，你自己的静态站得引入 mermaid.js 并初始化。这个博客就是引了 mermaid 库才渲染的。

Q：节点太多，图变成一大坨怎么办？
两个办法：一是用 subgraph 分组，把相关节点框进子图；二是拆图，一张图只讲一件事。硬塞 30 个节点的图没人看得懂，拆成三张流程清晰多了。

Q：Mermaid 能画流程图以外的图吗，比如思维导图？
v11 加了 mindmap 和 treemap，实验性地支持了。但成熟度还不如流程图，生产环境我建议思维导图还是用专门的工具。

Q：Mermaid 和 AI 怎么结合？
现在很多 AI 编程助手（Cursor、Copilot）已经能直接根据你描述生成 Mermaid 代码。我常用的提示是「把这段业务流程画成 mermaid flowchart，节点标签用中文」，让 AI 出初稿我来调。

小结

Mermaid 把「画图」从 Visio 里解放出来，让图也能进 git、能 review。它解析脆是脆了点，但只要养成「改完先验证」的习惯，它就是工程师最好用的画图工具。下一篇 PlantUML，看它在严肃 UML 上比 Mermaid 强在哪。
