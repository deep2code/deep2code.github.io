PlantUML UML 绘图

🏷️ 代码生图

PlantUML：在严肃 UML 上比 Mermaid 强在哪

我和 PlantUML 的第一次打交道是在给一个老金融系统画架构图。那系统有十几个服务、上百个接口，用 Mermaid 画完布局乱得没法看，导出 PlantUML 后，靠它的皮肤和布局控制，终于画出一张能放进评审 PPT 的图。

PlantUML 本质是个 Java 程序：你写 .puml 文件，它调 Graphviz 或 Smetana 引擎布局，输出 PNG/SVG。它不跑在浏览器里，得本地装 Java + Graphviz，或者用 PlantUML Server 在线渲染。

一句话定位

Mermaid = 浏览器端 JS，轻、快、适合文档内嵌；PlantUML = 服务端 Java 渲染，重、可控、适合复杂 UML 大图。别拿 PlantUML 画个三节点流程，那是杀鸡用牛刀。

环境搭起来

最省事的方式是装个 PlantUML Server 或者直接用 VS Code 插件。本地命令行：

# macOS
brew install plantuml graphviz

# 渲染
plantuml -tsvg diagram.puml    # 输出 diagram.svg
plantuml -tpng diagram.puml

装完第一件事是确认 Graphviz 装上了——PlantUML 默认靠 dot 布局，缺了它图根本出不来，只报一个莫名其妙的错误。我第一次就卡在这，折腾半小时才想起 brew install graphviz。

flowchart LR A[.puml 源文件] --> B[PlantUML Java 程序] B --> C[Graphviz 或 Smetana 布局] C --> D[PNG 或 SVG 输出]

七种图，我实际用得上的四种

PlantUML 支持的图种比 Mermaid 多，但很多我十年没碰过。真正高频的就这四种：

图种关键字用途
时序图@startuml接口调用链（最常用）
类图class代码结构、领域模型
组件图component系统模块划分
部署图node服务器/容器拓扑

时序图：和 Mermaid 比语法更啰嗦但更精确

@startuml
actor 用户 as U
participant 网关 as GW
participant 服务 as S
U -> GW: 请求
GW -> S: 转发
S --> GW: 响应
GW --> U: 返回
@enduml

你看，PlantUML 要 @startuml / @enduml 包裹，参与者要 as 起别名，语法比 Mermaid 啰嗦。但它支持 Mermaid 时序图做不到的事：分组 alt/opt/loop、并行 par、注释 note。画复杂业务流程的时序图，PlantUML 表达力强一个档次。

部署图：画系统拓扑

@startuml
node "用户浏览器" as browser
node "CDN 边缘节点" as cdn
node "应用服务器" as app
database "MySQL 主库" as db
browser --> cdn: HTTPS
cdn --> app: 回源
app --> db: SQL
@enduml

这种拓扑图是 Mermaid 的弱项——它没有真正的「节点（node）」概念。生产环境评审架构，部署图基本只能靠 PlantUML。

DOT 引擎 vs Smetana

PlantUML 2024 后引入了 Smetana 作为内置布局引擎，不再强依赖 Graphviz。这对 CI 是个利好——以前 CI 上为了渲染图得装整个 Graphviz，现在 Smetana 纯 Java 实现，-engine smetana 就行。我在 CI 上的做法是优先 Smetana，布局不满意再切 Graphviz。

2026 趋势

PlantUML 现在也能通过 mermaid.ink 之类的服务和 Mermaid 互转。但我不建议真这么转——两种 DSL 语义不完全对等，转出来的图经常要人工修。不如一开始就选对工具。

我的实战习惯

  • skinparam 集中调样式，别每张图单独调；
  • 大图拆成多文件，用 !include 引用公共样式；
  • CI 里固定渲染成 SVG 提交，别让读者装 Java；
  • 命名用 as 起短别名，类图长名一多就看不清。

FAQ

Q：PlantUML 一定要装 Java 吗？
本地命令行要。但如果你用 VS Code 插件，它后台自己起一个小服务；或者直接用在线的 plantuml.com，贴代码就出图。不追求本地化的话，在线版最省事。

Q：为什么我的图渲染出来节点全叠在一起？
多半是 Graphviz 没装对，或者图太复杂 Smetana 排不下。先确认 dot -V 能跑，再用 left to right direction 调整方向，拆图是终极办法。

Q：Mermaid 和 PlantUML 学哪个？
先学 Mermaid——它用得多、上手快、文档内嵌刚需。等你真要画严肃架构图、类图时再补 PlantUML。两个都要会，但入门顺序是 Mermaid 在前。

Q：PlantUML 生成的图能编辑吗？
不能，它是代码生成的单向产物。这其实是优点——你改的是 .puml 源文件，图自动重生成，比在 Visio 里手动拖框靠谱多了。

小结

PlantUML 不抢 Mermaid 的饭碗，它守的是「严肃 UML 大图」这块阵地。你日常写文档用 Mermaid，真到了架构评审、系统设计的场合，PlantUML 依然是最专业的选择。下一篇 Python 可视化，看数据怎么变成图。
