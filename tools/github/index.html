GitHub 简介

GitHub 2008 年上线，2018 年被微软 75 亿美元收购，现在是全球最大的代码托管平台，2026 年用户数已经破 1.5 亿。它本质上是"Git + 一堆协作功能"——托管代码、Issue、PR、Actions、Discussions，一个平台把研发流程全包了。

GitHub 解决了什么

光有 Git 只能解决"代码版本"，解决不了"人怎么协作"。GitHub 把分支策略、Code Review、CI/CD、文档、社区讨论全接到一起，这才是它成为事实标准的原因。下一篇 GitLab 会讲自托管方案。

核心功能

  • 代码托管：Git 仓库托管，支持公共和私有
  • Pull Request：代码审查和合并请求
  • Issues：任务追踪和 Bug 管理
  • Actions：CI/CD 自动化
  • Discussions：社区讨论
  • Projects：看板管理项目
  • Packages：包管理（npm、Docker 等）
flowchart LR A[开发者 Fork 仓库] --> B[在本地开发] B --> C[推送分支] C --> D[创建 Pull Request] D --> E[Code Review 审查] E --> F{通过?} F -->|是| G[合并到主分支] F -->|否| H[修改后再提交] H --> E G --> I[触发 GitHub Actions CI/CD]

快速开始

注册与创建仓库

注册 GitHub 账号后，创建新仓库：

  1. 点右上角 "+" → "New repository"
  2. 填仓库名、描述、选公开 / 私有
  3. 勾选 "Add a README file"
  4. 点 "Create repository"

SSH 密钥配置

配 SSH key 比每次输密码舒服多了，强烈建议：

ssh-keygen -t ed25519 -C "your_email@example.com"
# 一路回车，然后把公钥加到 GitHub Settings → SSH Keys
cat ~/.ssh/id_ed25519.pub

# 测试连接
ssh -T git@github.com

克隆与推送

git clone git@github.com:username/repo.git
cd repo

# 创建分支开发
git checkout -b feature/login
# ... 开发 ...
git add .
git commit -m "feat: 登录功能"
git push origin feature/login

Pull Request 工作流

PR 是 GitHub 协作的核心。我自己团队的流程就是标准的 Fork-and-PR：

步骤操作
1Fork 目标仓库到自己账号
2Clone 自己的 Fork
3创建特性分支开发
4推送分支到自己的 Fork
5在 GitHub 上创建 Pull Request
6Code Review，讨论修改
7合并到主分支
PR 写好标题和描述

我要求团队 PR 描述必须写清楚"改了什么、为什么改、怎么测的"。好的 PR 描述能让 review 效率翻倍，也方便以后回溯。模板可以放 PULL_REQUEST_TEMPLATE.md 里。

GitHub Actions

Actions 是 GitHub 内置的 CI/CD，YAML 描述工作流，放在 .github/workflows/ 下。一次 push 触发的流水线长这样：

flowchart LR A[push 或 PR] --> B[checkout 拉代码] B --> C[setup-node 装环境] C --> D[npm ci 装依赖] D --> E[npm test 跑测试] E --> F[npm run build 构建] F --> G{成功?} G -->|是| H[部署 Pages 或 Packages] G -->|否| I[通知作者修复]

下面这个工作流是我新项目都用的模板——push 到 main 就跑测试和构建：

name: CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm test
      - run: npm run build

常用 Actions 市场

Action用途
actions/checkout拉取代码
actions/setup-node安装 Node.js
actions/upload-pages-artifact部署到 GitHub Pages

高级功能

GitHub Pages

静态网站直接托管，我的技术博客就跑在这：

.github/workflows/deploy.yml
# push 到 main 自动部署到 GitHub Pages

GitHub Codespaces

云端开发环境，浏览器里写代码，不用本地配环境。出差或者临时在别人电脑上干活特别方便。

GitHub Copilot

AI 结对编程，编辑器里自动补全代码。2026 年它已经能根据注释生成整个函数、解释代码、写单测。我用下来感受是：样板代码效率提升明显，但核心业务逻辑还是得自己想。

最佳实践

  • 仓库名用小写、连字符分隔（如 my-project）
  • 每个仓库必须有 README、LICENSE、.gitignore
  • 提交信息遵循 Conventional Commits 规范
  • PR 必须经过 Code Review 才能合并
  • 用 branch protection rules 保护主分支
  • 敏感信息（密钥）永远别提交，用 Secrets 管理

FAQ

Q：GitHub 和 GitLab 选哪个？
开源项目、想借社区流量选 GitHub；企业自托管、要内网合规选 GitLab。云服务对比见下一篇。

Q：私有仓库免费吗？
GitHub 免费版支持无限私有仓库，团队协作（超过 3 人）要付费。个人用免费版足够。

Q：怎么把大文件从仓库历史里删掉？
用 git filter-repo（官方推荐），别用过时的 BFG 以外的老方法。删完要 force push，通知协作者重新 clone。

Q：Actions 免费额度多少？
公开仓库无限免费，私有仓库每月 2000 分钟（免费版）。超了要付费。

总结

GitHub 是事实标准的代码托管平台，核心是 Git + PR + Actions。记住三件事：SSH key 配好省得输密码、PR 描述写清楚、主分支加保护规则。下一篇 GitLab，看自托管方案怎么选。
