Shell 的语法核心与陷阱

🏷️ Bash,Shell脚本,严格模式

Bash 的语法量不大，但它的语义密度很高：同一个符号在不同上下文里做的事完全不同，而且大量行为没有编译期检查。这篇把语法核心按「你会用到的能力」和「它会咬你的地方」成对地过一遍。

参数展开：Bash 最被低估的内置能力

参数展开是纯内置的，不 fork 任何进程。一个循环里把 basename、dirname、sed 换成参数展开，性能差距是几十倍到上百倍。下面这张表以 var=/var/log/app.tar.gz 为例。

写法语义结果典型用途
${var:-d}未定义或为空则取 d，不写回—默认端口、默认目录
${var:=d}未定义或为空则取 d，并写回变量—只想初始化一次的配置项
${var:?msg}未定义或为空则打印 msg 到 stderr 并非零退出—必填参数校验
${var:+alt}有值才取 alt，否则空—拼可选参数，例如有 DEBUG 才加 -x
${#var}字符串长度21长度校验
${var#*/}删最短匹配的前缀var/log/app.tar.gz剥掉一层路径
${var##*/}删最长匹配的前缀app.tar.gz等价 basename
${var%/*}删最短匹配的后缀/var/log等价 dirname
${var%%.*}删最长匹配的后缀/var/log/app去掉所有扩展名
${var%.gz}删指定后缀/var/log/app.tar批量改扩展名
${var/log/data}替换第一处/var/data/app.tar.gz路径改写
${var//a/A}替换全部/vAr/log/App.tAr.gz字符清洗，替代 tr
${var/#\/var/\/opt}只替换开头/opt/log/app.tar.gz换前缀而不误伤中间
${var/%.gz/}只替换结尾/var/log/app.tar换后缀
${var:5:3}切片（起点:长度）log定长字段解析
${var: -2}取末尾 N 个字符gz冒号后必须有空格，否则被当默认值语法
${var^^} / ${var,,}转大写 / 转小写（Bash 4 起）—环境名归一化
${!PREFIX@}列出所有以 PREFIX 开头的变量名—批量读 APP_ 前缀配置
${var@Q}输出可安全重新解析的带引号形式（Bash 4.4 起）—拼命令、写日志

「带不带冒号」是这里最容易搞错的一件事。带冒号的版本把「未定义」和「已定义但为空」视为同一件事，不带冒号的只看「未定义」：

写法var 未定义var 为空串var=x
${var-d}d空串x
${var:-d}ddx
${var+a}空串aa
${var:+a}空串空串a
${var?m}报错退出空串x
${var:?m}报错退出报错退出x

实务上必填校验一律用冒号版本，因为「传了个空值」几乎总是错误输入；只有在明确要区分「没传参数」和「传了空参数」时才用不带冒号的形式。

echo "${path##*/}"        # access.log.2026-09-23.gz
echo "${path%/*}"         # /var/log/nginx
echo "${path##*.}"        # gz
base="${path##*/}"; echo "${base%%.*}"   # access

# 批量改扩展名，循环里不调 sed；两个减号防止文件名以减号开头
for f in ./*.jpeg; do mv -- "$f" "${f%.jpeg}.jpg"; done

# 只替换开头或结尾，避免误伤路径中间同名的片段
echo "${path/#\/var/\/data}"   # /data/log/nginx/access.log.2026-09-23.gz
echo "${path/%.gz/}"           # 去掉结尾的 .gz

# 取末尾字符必须写成 ${var: -2}：冒号后少了空格会被解析成默认值语法而报错
echo "${#path}"; echo "${path:0:8}"; echo "${path: -2}"

# 批量读取同前缀环境变量，做配置注入时很有用
for name in "${!APP_@}"; do printf '%s=%s\n' "$name" "${!name}"; done

展开顺序，以及双引号到底挡住了哪两步

Bash 处理一行命令时按固定顺序做展开。双引号只影响其中的最后两步——单词拆分和路径名展开——这就是「加双引号能保住带空格的文件名」的全部原因。

两个推论值得记住：一是大括号展开发生在变量展开之前，所以 {1..$n} 不会按你想的展开，要用 seq 或 C 风格 for 循环；二是路径名展开在「没有任何文件匹配」时，Bash 默认把模式原样保留，于是 for f in ./*.log 在没有日志文件时会得到一个字面量 ./*.log——要么开 shopt -s nullglob 让它变成空列表，要么在循环体里加 [[ -e $f ]] || continue。

数组与关联数组

Bash 只有一维数组和关联数组，没有嵌套。但把「一堆主机名」「一份键值配置」装进数组，比拼字符串再拆要安全得多。

操作写法必须知道的点
声明索引数组arr=(a b "c d")下标从 0 开始，可以稀疏
声明关联数组declare -A m必须显式声明，否则键名会被当算术表达式求值
安全取全部元素"${arr[@]}"每个元素一个词，遍历与转发唯一正确写法
拼成一个词"${arr[*]}"用 IFS 首字符连接，只适合拼日志
元素个数${#arr[@]}注意不是 ${#arr}（那是第 0 个元素的长度）
所有下标或键"${!arr[@]}"遍历关联数组必须用它
追加arr+=(x)写成 arr+=x 是给第 0 个元素追加字符串
切片"${arr[@]:1:2}"按「位置」切，稀疏数组上结果可能反直觉
删除元素unset 'arr[1]'留下空洞，下标不重排；必须加引号防 glob
按行读入数组mapfile -t arr < file不受 IFS 与通配符影响，优于 arr=($(cat f))
空数组配 set -u"${arr[@]+"${arr[@]}"}"Bash 4.3 及更早对空数组报 unbound variable
 
#!/usr/bin/env bash
set -Eeuo pipefail

# 元素里有空格也不会串味，前提是取值时写成双引号包住 at 符号
hosts=(web-01 web-02 "db 01")
for h in "${hosts[@]}"; do printf 'host=[%s]\n' "$h"; done
echo "count=${#hosts[@]}"

# 关联数组必须先 declare -A。不声明的话 port[web-01] 里的 web-01 会被当算术表达式，
# 未定义变量按 0 处理、减号被当减法，结果所有键都塌缩到下标 0——这个坑很难看出来
declare -A port=()
port[web-01]=8080
port["db 01"]=5432
for k in "${!port[@]}"; do printf '%s -> %s\n' "$k" "${port[$k]}"; done

# 把命令输出安全地读进数组：mapfile 按行切分，不受 IFS 与通配符干扰
mapfile -t confs < <(find /etc/myapp -maxdepth 1 -name '*.conf' -print)
echo "found ${#confs[@]} conf files"

# 用关联数组当集合去重，比 sort -u 少一次排序，且保持原顺序
declare -A seen=()
uniq_keep_order=()
for x in "$@"; do
  [[ -n ${seen[$x]:-} ]] && continue
  seen[$x]=1
  uniq_keep_order+=("$x")
done
printf '%s\n' "${uniq_keep_order[@]+"${uniq_keep_order[@]}"}"

条件判断与算术：三套完全不同的语义

[ 是一个命令，它的参数要经过普通的单词拆分；[[ 是 Bash 关键字，在解析阶段就被特殊处理；(( 是算术求值。它们不是同一个东西的三种写法。

维度[ ] 即 test[[ ]](( ))

逻辑与或-a / -o（已不推荐）原生 && / ||原生 && / ||
通配符匹配不支持[[ $f == *.log ]]（右侧不要加引号）不适用
正则匹配不支持=~，捕获组进 BASH_REMATCH不适用
数字比较-eq -lt -gt同左，或改用 ((直接写 > < ==
小于号的含义需转义为 \<，比的是字典序字典序，受 locale 影响数值比较
POSIX 可移植是否（bash / ksh / zsh）否
结论只在必须跑 /bin/sh 时用默认选它纯数字与自增用它

算术方面，Bash 只有有符号整数，除法向零取整，写小数点直接语法错误。还有一个每年都有人踩的坑：算术上下文里以 0 开头的数字被当成八进制，所以从日志里切出来的 08 会报 value too great for base。

a=7 b=2
echo $(( a / b ))        # 3，整数除法向零取整，不是 3.5
echo $(( a % b ))        # 1
echo $(( a ** b ))       # 49，幂运算
(( a++ )); echo "$a"     # 8，自增

# 陷阱一：((  )) 作为命令时，「结果为 0」的退出码是 1。配 set -e 会直接终止脚本
count=0
(( count ))              # 退出码 1！写成 (( count )) || true 或用 if 包起来

# 陷阱二：前导零被当八进制。日志里切出来的 08、09 会直接报错
month=09
echo $(( 10#$month + 1 ))   # 10，用 10# 强制按十进制解析

# 陷阱三：需要小数只能外调。awk 适合格式化输出，bc 适合高精度
awk -v a=7 -v b=2 'BEGIN { printf "%.2f\n", a / b }'    # 3.50
echo "scale=4; 7/2" | bc                                 # 3.5000
# 两者都是外部进程，别放进循环里逐行调用

# 正则匹配与捕获组
line='2026-09-23 12:00:01 ERROR code=503'
if [[ $line =~ code=([0-9]{3}) ]]; then
  echo "status=${BASH_REMATCH[1]}"     # 503
fi

# 模式匹配：右侧的通配符不要加引号，加了就变成字面量比较
f=access.log
[[ $f == *.log ]] && echo "是日志文件"

函数、作用域与「返回值」

Bash 函数有两个必须记住的约束：变量默认是全局的，return 只能返回 0 到 255 的退出码。

不写 local 的后果比「命名冲突」严重得多——递归函数会直接错乱，因为每层调用共享同一个变量；两个独立函数都用 i 做循环变量时，嵌套调用会互相把对方的循环打乱。local 是动态作用域：在函数 A 里 local x，A 调用的 B 也能看到并修改这个 x，这跟大多数语言的词法作用域不同。

「返回字符串」只能靠 stdout 加命令替换，或者写入一个由调用方指定的变量名（nameref）：

#!/usr/bin/env bash
set -Eeuo pipefail

# 写法一：用 stdout 返回数据，调用方用命令替换接。代价是一次子 shell
latest_tag() {
  local repo="$1"          # 每个内部变量都要 local，否则污染全局
  local tag
  tag=$(git -C "$repo" describe --tags --abbrev=0) || return 1
  # 注意不能写 local tag=$(...)：local 的退出码会盖掉 git 的失败
  printf '%s\n' "$tag"
}
tag=$(latest_tag /srv/app) || { echo "no tag found" >&2; exit 1; }

# 写法二：nameref（Bash 4.3 起），让被调方直接写调用方的变量，零子 shell
parse_kv() {
  local -n out="$1"        # out 成为调用方变量的别名
  local line="$2"
  out[key]="${line%%=*}"
  out[value]="${line#*=}"
}
declare -A kv=()
parse_kv kv "timeout=30"
echo "${kv[key]} / ${kv[value]}"    # timeout / 30

# return 只能是 0-255。想表达「找不到」就用非零退出码 + stderr 说明，
# 不要试图 return 一个字符串或大于 255 的数字（会按 256 取模）
has_port() { ss -lntH "sport = :$1" | grep -q .; }
if has_port 8080; then echo "8080 已被监听"; fi

命令替换、here-doc 与 here-string

$(...) 相比反引号有两个实质优势：可嵌套（反引号嵌套要层层转义反斜杠），以及内部的引号规则更直观。反引号除了兼容老 sh 没有任何理由再用。

here-doc 最高频的事故是终止符加不加引号：不加引号时内部会做变量展开与命令替换，于是 Nginx 配置里的 $host、awk 程序里的 $1、SQL 里的占位符全被 Bash 吃成空串。

写法变量与命令替换去掉行首缩进用途
<<EOF会展开否渲染带变量的模板
<<'EOF' 或 <<"EOF"不展开，原样输出否写 SQL、awk 程序、Nginx 配置
<<-EOF会展开只去制表符，不去空格缩进代码块里嵌 here-doc
<<-'EOF'不展开只去制表符上面两者的组合，最常用
<<<"$var"会展开—here-string，替代 echo "$v" |，少一次 fork
 
# 不加引号：内部做展开。这是渲染模板时想要的行为
table=orders
cat <<EOF
SELECT count(*) FROM ${table} WHERE created_at >= '$(date -I -d '-1 day')';
EOF

# 加引号：完全不展开。写含美元符号的内容必须这样，否则全被 Bash 吃掉
cat <<'EOF' > /etc/nginx/snippets/proxy.conf
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
EOF

# 减号形式只吞掉行首的「制表符」，不吞空格。
# 所以下面这段的缩进必须是真 Tab，用空格会导致找不到终止符而报 unexpected EOF
run_report() {
	mysql -N -B <<-'EOF'
	SELECT status, count(*) FROM orders GROUP BY status;
	EOF
}

# here-string：比 echo 管道少一个进程，且不会进子 shell
IFS=. read -r major minor _ <<< "$BASH_VERSION"
echo "bash ${major}.${minor}"

# 命令替换要嵌套时，反引号需要层层转义，$() 不需要
echo "root=$(dirname "$(readlink -f "$0")")"

退出码约定与 PIPESTATUS

退出码是 Shell 世界里唯一的「异常类型」，所以约定必须记牢。

退出码含义你该怎么反应
0成功—
1通用失败看 stderr
2多数工具约定的「用法错误」；Bash 内建误用也是 2检查参数拼写
126文件找到了但不可执行chmod +x，或挂载带了 noexec
127command not found命令拼错，或 PATH 在 cron / 容器里不同
128 + N被信号 N 杀掉：130 是中断、137 是强杀、143 是终止137 通常意味着被 OOM killer 或容器内存限制杀了
255exit 参数越界，例如 exit -1退出码只取低 8 位，别传负数
grep 的 1「没有匹配」，不是错误在 set -e 下要显式 || true
diff 的 1「有差异」，同样不是错误用它做变更检测时要区分 1 和 2
 
#!/usr/bin/env bash
set -Eeuo pipefail

# pipefail 只说「管道失败了」，不说是哪一段。PIPESTATUS 按顺序存着每一段的退出码，
# 但它会被下一条命令覆盖，所以必须在第一时间整体拷出来
if ! curl -sSf "https://example.com/dump.sql.gz" | gzip -dc | mysql app; then
  codes=("${PIPESTATUS[@]}")
  printf 'curl=%s gzip=%s mysql=%s\n' "${codes[0]}" "${codes[1]}" "${codes[2]}" >&2
  # curl 的 22 表示 HTTP 返回了 4xx/5xx；gzip 的 1 表示流不是合法 gzip
  exit 1
fi

# grep 无匹配返回 1，这是正常语义。严格模式下要显式处理，否则脚本会莫名退出
errors=$(grep -c 'ERROR' app.log || true)
echo "errors=${errors:-0}"

# 用 diff 做「配置有没有变」的判断：0 相同、1 有差异、2 才是真出错
if diff -q /etc/app.conf /tmp/app.conf.new >/dev/null; then
  echo "配置未变化，跳过 reload"
else
  rc=$?
  (( rc == 1 )) || { echo "diff 执行失败 rc=$rc" >&2; exit 1; }
  echo "配置有变化，执行 reload"
fi

语法层面最容易翻车的十二处
  • ${var: -2} 的冒号后必须有空格，写成 ${var:-2} 语义完全变成「取默认值 2」。
  • ${#arr[@]} 是元素个数，${#arr} 是第 0 个元素的字符串长度——两者只差一对方括号。
  • 关联数组忘写 declare -A：m[web-01] 的键被当算术表达式求值成 0，所有写入都覆盖同一个槽位。
  • unset 'arr[1]' 只留空洞，下标不重排，之后 ${#arr[@]} 与最大下标不再对应。
  • (( )) 作为命令时，表达式结果为 0 会返回退出码 1，在 set -e 下直接终止脚本。
  • 算术上下文里 08、09 被当八进制报错，必须写 $((10#$var))。
  • [[ $f == "*.log" ]] 加了引号就变成字面量比较，模式匹配的右侧不能加引号。
  • [[ a < b ]] 比的是字典序且受 locale 影响，数值比较必须用 (( ))。
  • 大括号展开发生在变量展开之前，所以 {1..$n} 不会展开，要用 seq 或 C 风格 for。
  • 通配符没匹配到任何文件时 Bash 默认保留字面量，for f in ./*.log 会拿到一个不存在的 ./*.log；要开 shopt -s nullglob。
  • <<-EOF 只吞制表符不吞空格，用空格缩进会报 unexpected end of file。
  • PIPESTATUS 会被下一条命令覆盖，必须在管道结束后立刻整个数组拷出来再用。
