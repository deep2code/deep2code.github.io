Tesseract OCR

🏷️ OCR

OCR：让机器认字这件事

我接过一个需求：把几万张扫描发票里的金额、日期自动录进系统。一开始想的是「装个 Tesseract 就完事了」，结果跑起来——手写发票、盖章压字、倾斜扫描——识别率惨不忍睹，金额识别错一个字就是财务事故。这才明白 OCR 的难不在认标准字体，在真实世界的噪声。

先判断要不要本地 OCR

Tesseract 适合离线、隐私敏感、量不大的场景。如果量大、要高精度、不在乎联网，直接上云 OCR（百度/腾讯/Azure），别死磕 Tesseract。选本地还是云，先看这一条。

Tesseract 是什么

Tesseract 是 HP 开源、现在由 Google 维护的 OCR 引擎，2024 年已经在 5.x 稳定版。它从 Leptonica 图像处理开始，过 LSTM 神经网络识别字符。下图是它的处理链路：

flowchart LR A[图片输入] --> B[二值化 去噪 倾斜矫正] B --> C[字符分割 切单字] C --> D[LSTM 序列识别] D --> E[文本输出]

关键认知：喂给 Tesseract 的图越干净，识别越准。它对图的质量很敏感，你花在预处理（二值化、去噪、纠斜）上的功夫，比调识别参数重要得多。

命令行上手

# macOS
brew install tesseract tesseract-lang

# 基本识别
tesseract invoice.png stdout

# 指定语言（中文简体 chi_sim + 英文 eng）
tesseract invoice.png stdout -l chi_sim+eng

# 只识别某区域 / 指定 psm 模式
tesseract invoice.png stdout -l chi_sim --psm 6

-l chi_sim+eng 这个组合我用得最多。纯英文图用 eng，混排就加号拼上。--psm 是页面分割模式，--psm 6 假设是一个统一文本块，比自动模式在规整表格上准。

必坑：语言包

只装 tesseract 默认不带中文。要 brew install tesseract-lang（macOS）或下 chi_sim.traineddata 放到 tessdata 目录。报 Failed to load language 就是语言包没到位。

预处理决定一切

我做发票项目时，识别率从 60% 提到 95% 全靠预处理，不是靠换模型。几个有效步骤：

预处理步骤解决什么问题效果（参考值）
灰度 + 二值化彩色背景干扰准确率 +10%
倾斜矫正扫描歪了准确率 +15%
去噪 / 锐化扫描仪噪点准确率 +5%
放大 2x字太小准确率 +8%
只裁 ROI背景干扰准确率 +10%

最有效的一招是只裁你要的那块区域。发票金额就在右下角一小块，你把整张图丢给 Tesseract，它连背景的印章阴影都得「认」。裁出 ROI 再识别，准度立刻上来。

Tesseract.js：浏览器里跑 OCR

不想装本地环境，Tesseract.js 把 Wasm 版引擎搬到浏览器。这对做「用户上传图片本地识别不上传服务器」的隐私场景很有用：

import { createWorker } from 'tesseract.js';
const worker = await createWorker('chi_sim+eng');
const { data: { text } } = await worker.recognize(imageFile);
console.log(text);
await worker.terminate();

但它慢——Wasm 跑 LSTM，一张图几秒到十几秒。而且要下载十几 MB 的语言模型。只适合小工具，别指望批量处理。

Tesseract vs 云 OCR vs PaddleOCR

这是选型的核心问题。我把实际对比放下面：

Tesseract云 OCR（百度/Azure）PaddleOCR
部署本地离线调 API本地离线
中文准确率中（70-85%）高（95%+）高（95%+）
手写/复杂版式差好好
成本免费按调用量付费免费开源
隐私好数据出网好
适合标准印刷体小量高精度大批量中文自研部署
我的结论

纯中文、要本地、要高精度——直接上 PaddleOCR，别死磕 Tesseract。它的检测+识别两阶段 pipeline 对中文支持比 Tesseract 好太多。Tesseract 留作「标准英文印刷体、离线、免费」的简单场景。

flowchart TD A[要做 OCR?] -->|英文标准印刷体 离线| B[Tesseract] A -->|中文 高精度 本地| C[PaddleOCR] A -->|大批量 不在乎联网| D[云 OCR API] A -->|浏览器端隐私| E[Tesseract.js]

我的实战踩坑

  • 识别率低先查图，别先怪模型：90% 的低识别率是图的问题，不是 Tesseract；
  • 手写体别用 Tesseract：它对手写几乎无能为力，上云 OCR 或专门手写模型；
  • 表格识别烂：Tesseract 输出纯文本，表格结构全丢，要表格用专门工具；
  • 多列文字会串行：表格/多栏文档，先切块再分别识别。

FAQ

Q：Tesseract 识别率上不去，怎么办？
按优先级：先做预处理（二值化、纠斜、放大），再裁 ROI，然后换 psm 模式，最后才考虑换模型。我见过太多人一上来就换大模型，其实图预处理完就够了。

Q：能识别二维码/条码吗？
Tesseract 不擅长。用专门的库：zbarimg、OpenCV 的 WeChatQRCode。别让 OCR 引擎干二维码的活。

Q：2026 了，大模型能直接看图认字了吧？
能，GPT-4o、Qwen-VL 这种多模态模型直接「读图说话」，OCR 任务很多场景被它们替代。但它贵、慢、有联网，大批量离线场景还是 PaddleOCR/Tesseract 这种专用方案划算。

Q：中文识别乱码怎么办？
八成是语言包没装对，或者 -l 写成了 eng。确认装了 chi_sim.traineddata，命令行 tesseract --list-langs 看有没有 chi_sim。

小结

OCR 这件事，工具选对只占三成，图预处理占七成。Tesseract 是个诚实的工具——标准印刷体、干净图，它免费又好用；真实世界的脏数据，别硬撑。下一篇 Three.js，看怎么在浏览器里玩 3D。
