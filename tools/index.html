开发工具与工程效率

文档与图 · Shell · 数据可视化 · 版本控制 · 开发环境 · 操作系统（共 31 篇）

先有判断框架，再谈具体工具

工具类内容最容易变成「安利清单」，但真正影响效率的不是装了多少工具，而是哪些操作被固化下来了。下面五个问题构成一个可复用的判断框架，任何工具进你的工作流之前过一遍，能省掉大量折腾时间。

要问的问题为什么它重要答案不同时的处理方式
这件事一年做几次频率决定投入上限，也决定该不该记住细节每天做：值得配快捷键与别名；每月做：写脚本；一年一次：写一份清单，别写脚本
步骤稳定到可以写死吗步骤不稳定的脚本会变成需要维护的负债稳定就进脚本；不稳定先写成带判断点的清单，稳定后再固化
需要团队统一吗只影响自己的工具可以随便选，影响共同产物的必须统一编辑器与终端个人自由；格式化、提交规范、图的源格式必须统一
能在干净机器上复现吗不可复现的环境等于把配置锁死在一台机器里安装清单、点文件、插件列表、构建入口全部进版本库，并在新环境验证一遍
退出成本有多高迁移成本决定了它值不值得承载核心流程产物是通用文本格式的可以放心用；输出被私有格式绑定的，不要放进关键路径

六个二级方向各自解决什么

这个分类现在有六个方向，混在一张清单里比较是选不出工具的真正原因——它们的选择标准根本不同：有的看团队统一，有的看个人手感，有的看一次性排查够不够快。操作系统这一块是新并进来的：对后端工程师来说，它既不是内核开发也不是桌面技巧，而是开发机与服务器上那些绕不开的系统机制。

团队产物必须统一的三件事

其余都可以各随其便，但这三件事一旦不统一，代价会以「评审噪声」和「没人敢改」的形式长期收利息。

要统一的东西「会用」的标准「能负责」的标准
版本控制的心智模型会提交、切分支、解决冲突能把一次改动拆成若干个自洽提交；清楚变基会重写提交标识因此只在未共享分支上做；能用引用日志找回丢失的提交
格式化与静态检查的落点本地装了插件，记得时会跑一下把格式化与检查放进项目配置、提交钩子或流水线，不依赖任何人的自觉
图与文档的源格式需要图时随手画一张导出图片长期演进的图用文本描述（差异可读、可评审），一次性汇报图才用拖拽工具；文档结构与方言在项目里有明确约定

选画图工具的第一原则不是好不好看，而是这张图要不要跟着代码一起演进：需要长期维护的用文本即图，因为文本能进版本库、改动在评审里能看出差异；只用一次、需要精确排版的汇报图，拖拽工具更快。第二原则是按要表达的结构选图类型：分层归属用带分组的流程图，协议往返用时序图，生命周期用状态图，大规模依赖关系用自动布局的图工具，数值分布才用图表库。

后端工程师需要的操作系统知识地图

操作系统这一块不需要读内核源码，但有几块知识是排查线上问题的前提——没有它们，很多现象只能归结为「玄学」。

知识块为什么后端必须懂典型的现场问题
进程、线程与信号优雅退出、僵尸进程、被杀原因都落在这里容器停止时请求被截断，因为进程没处理终止信号
文件描述符与网络连接连接数上限、端口耗尽、长连接复用都受它约束并发一高就报「打开文件过多」，其实是描述符上限没调
内存与页缓存容器内存统计包含页缓存，这直接影响被杀判定看着内存占用很高，实际是可回收缓存，却被误判为泄漏
权限、路径与环境变量脚本在本地能跑、在流水线跑不了，多半在这三项上同一份脚本在不同机器上行为不同，因为 PATH 与 shell 初始化文件不同
跨平台差异开发机与服务器往往不是同一个系统家族换行符、大小写敏感、默认工具版本的差异造成构建结果不一致

这一块的具体内容见 操作系统方向、macOS 作为开发机的系统机制 与 Windows 开发环境；命令层面的排查手法在 系统排查的命令与判读，Shell 自身的执行机制见 进程、重定向与信号。

这个专题各子方向怎么读

三条常见路线：刚配新环境，按操作系统、包管理与开发环境、Shell、版本控制的顺序过一遍；要给项目补文档和图，先看上面的选图原则，再挑具体工具；临时排查问题，直接进 Shell 的系统排查篇。

❌
工具选择上最容易走错的判断
  • 把「装了很多工具」当成效率提升，实际高频操作一个都没固化下来
  • 一年做一次的事也写成脚本，脚本半年后失效，出问题时还不如手工来得快
  • 格式化与检查依赖每个人自觉执行，没有放进项目配置或流水线，风格必然漂移
  • 环境靠手工搭建，没有安装清单和点文件，换机器等于重来一天
  • 长期演进的架构图用拖拽工具画，源文件进了仓库但差异不可读，最终没人敢改
  • 把结构关系硬做成数据图表，或把数值趋势硬画成流程图，图类型和内容对不上
  • 大文件直接提交进版本库，之后仓库体积再也降不回来
  • 在共享分支上重写历史，同事拉取时被迫处理冲突甚至丢提交
  • 脚本不支持干跑、也不幂等，中断后重跑造成二次破坏
  • 忽略开发机与服务器的系统差异，构建在本地通过、在流水线因权限或换行符失败
