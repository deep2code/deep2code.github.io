开发环境

Homebrew · Make · Vim 与 Neovim

三篇讲的是同一件事的三个面：换一个人、换一台机器，还能不能装出同一个环境、跑出同一个结果。工具本身的用法排在它后面。

篇目它回答什么什么时候读
Homebrew 的机制与开发环境可复现性Cellar、opt 与逐文件符号链接的目录模型、bottle 命中与源码编译的触发条件、为什么升级一个带走一串、它不做版本锁定、Brewfile 的边界与 mise、nix 的分工同事之间版本不一致、装过的工具突然换了行为，或 CI 里正打算依赖 brew
Make 的依赖图与工程化用法时间戳驱动的依赖模型、.PHONY 为什么必要、变量四种赋值的展开时机、每行一个独立 shell 的后果、并行 -j 与依赖声明不全、make 与 just、Task 的分界要把构建、生成、部署步骤编排进一个入口，或并行执行出过怪问题
Vim 与 Neovim：编辑模型与配置工程化计数加操作符加作用范围的编辑模型、寄存器与宏的语义、缓冲区/窗口/标签页三层、Neovim 的分叉点、启动时间归因与配置可移植、什么场景该交给 IDE想真用上模与寄存器、启动越来越慢，或在争论要不要继续折腾编辑器

三篇共同的结论是默认值不为团队设计：包管理器记录的是「装过什么」而不是「装的是哪个版本」，Make 的每行是独立进程，编辑器的配置会长成只在这台机器上生效的样子。

判断标准因此统一成一句话能检验的形式：能不能说清这台机器和那台机器的差异在哪、能不能在新机器上一遍装回来。说不清就先别加第二个工具。

版本控制与 Shell 脚本本身、文档与图在 开发工具与工程效率 的其它分组。
