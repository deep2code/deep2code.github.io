Git 实战：从你遇到的问题出发

🏷️ Git 入门

你写了个代码，改了一下午，结果改坏了，想回到上午的版本，怎么办？你是不是直接 copy 了一份 "xxx_v1_最终版_真的最终版" 的文件夹？

或者：你和同事一起写代码，他改了 A 文件，你改了 B 文件，合并的时候发现冲突了，根本不知道怎么解决。

这些问题，Git 就是为解决这个而生的。这篇不讲理论，就讲你真的会用到的 Git 命令，以及怎么不被版本控制搞疯。

场景一：改了一下午，结果改坏了，想回到上午的版本

你遇到的问题

你写了一下午代码，改了 10 个文件，结果跑不起来了。你想回到上午的版本，但是已经覆盖了，怎么办？

Git 怎么解决？你只要早上提交过一次，就能随时回去。

# 早上：提交一次，保存当前状态
git add .
git commit -m "上午写的登录功能"

# 下午：改坏了，想回到上午的版本
git checkout .
# 或者回到某个提交
git log  # 找到上午那个提交的ID
git reset --hard abc123

现在不管你改成什么样，只要提交过，就能随时回去。再也不用 copy "最终版_真的最终版_打死不改版" 文件夹了。

场景二：和同事合并代码，冲突了不知道怎么解决

你遇到的问题

你和同事都改了同一个文件的同一行，他提交了，你提交了，合并的时候 Git 报错说有冲突，你根本不知道怎么解决。

Git 怎么解决？打开冲突的文件，你会看到这样的标记：

<<<<<<< HEAD
你写的代码
=======
同事写的代码
>>>>>>> origin/main

你手动改成正确的版本，然后删掉那些 <<<<<<< 和 >>>>>>> 标记，再提交就行。

# 解决完冲突后
git add .
git commit -m "解决冲突"

场景三：提交错了，想删掉最后一次提交

你遇到的问题

你把配置文件里的密码也提交了，刚 push 上去，想删掉这次提交。怎么办？

Git 怎么解决？用 reset 命令回退。

# 撤销最后一次提交，代码还在工作区
git reset --soft HEAD~1

# 撤销最后一次提交，代码也删掉
git reset --hard HEAD~1

# 如果已经 push 到远程了，要强制推送
git push -f origin main
常用命令什么时候用
git add .把所有改动暂存，准备提交
git commit -m "说明"提交改动，写清楚改了什么
git push把本地提交推到远程仓库
git pull拉取远程最新代码到本地
git log查看提交历史
git checkout .撤销所有未提交的改动
git branch查看/创建分支
git merge合并分支
新手最容易踩的坑
  • 一定要写清楚 commit 信息：不要每次都写 "update"，几个月后你自己都不知道改了什么。
  • 不要在主分支上直接开发：新开一个分支，开发完了再合并回去。
  • 不要把配置文件、密码文件提交上去：用 .gitignore 忽略掉。
  • push 之前一定要先 pull：先拉最新代码，解决冲突了再 push，不然很容易冲突。
