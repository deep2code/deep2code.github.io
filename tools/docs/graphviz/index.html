Graphviz 的布局算法与大图治理

🏷️ 代码生图

布局不是样式：dot 在解四个优化问题

对 Graphviz 的挫败感几乎都来自同一个错误预期——以为 rankdir、nodesep 这些属性是 CSS，调一调就能把节点摆到想要的位置。实际上 dot 走的是分层布局（Sugiyama 风格，对应 Gansner、Koutsofios、North、Vo 1993 年那篇 A Technique for Drawing Directed Graphs），整条流水线是四个前后依赖的优化问题，属性只是往这些问题里塞约束和权重。

这四个阶段依次是：把回边反转成有向无环图后用网络单纯形求解分层；用减少交叉的启发式决定每层内部的顺序；再解一次优化问题得到坐标；最后把长边在中间层打成虚拟节点串，用分段贝塞尔穿过它们。理解这个顺序，你就知道每个属性能影响哪一步、不能影响哪一步。

阶段在解什么真正的控制点默认值调坏后的表现
一、分层最小化加权层差之和，约束是每条边层差不小于 minlenminlen、weight、rank=same/min/max、constraint=falseminlen=1、weight=1一条边把无关节点整串拉下去；回边没排除掉，整图被它拉歪
二、层内排序减少边交叉（两层情形就已是 NP 难），靠启发式迭代逼近节点与边的书写顺序、style=invis 辅助边、ordering=out迭代上限由 mclimit 倍率缩放，默认 1.0交叉一团；源文件里挪动一行导致整图重排，diff 噪音巨大
三、坐标分配让边尽量竖直，同层间距不小于 nodesep；虚拟节点间的边权重远高于真实节点间nodesep、ranksep、weight、nslimitnodesep=0.25 英寸、ranksep=0.5 英寸长边被拉直而真实节点被挤偏；nslimit 调太小后边普遍歪斜
四、边绘制在虚拟节点围出的通道里拟合曲线，同时避开节点盒splines、concentrate、headport/tailport、compound 配 lhead/ltaildot 默认走曲线splines=ortho 时边标签压线；splines=false 时边直接穿过节点

为什么「调不动」：约束在算法里，不在样式里

把需求翻译成约束，是用 Graphviz 的核心技能。下面这张表左边是常见诉求，中间是几乎所有人第一次都会尝试的错误做法，右边是真正起作用的手段——注意每一种都有代价，没有免费的布局控制。

你想要的无效做法有效做法代价
A 出现在 B 左边改 nodesep、加颜色分组同层内加 A -> B [style=invis]，或调整两者的书写顺序不可见边仍然参与排序与坐标计算，间距会跟着变
两个节点落在同一层给相同 group 或相同形状{ rank=same; A; B; }跨 cluster 时必须 newrank=true，而它会改变全图层级
某条边不要影响层级删掉这条边，另外手工标注constraint=false（边还在，只是不进阶段一）这条边通常会变长、更容易交叉
主干链路笔直把旁支节点删掉给主干边 weight=10 以上，让阶段一和阶段三都优先照顾它旁支被牺牲，可能歪得更明显
缩短某条特别长的边调 ranksep提高该边 weight，或降低把两端撑开的其他边的 minlen全图层数可能变化，其他区域跟着重排
图别那么宽size 缩放先 unflatten -l 3 调整宽高比再交给 dot同层的语义分组可能被打散
子图内部独立排布包一层 cluster 当容器cluster 只保证成员占连续层；真要隔离得分文件各自布局，再用 gvpack 拼拼接后跨图的边会丢，需要自己补
⚠️
阶段二决定了 DOT 文件的 diff 稳定性

层内顺序受节点与边的书写顺序影响。这意味着生成 DOT 的程序如果遍历的是哈希表，输出顺序每次不同，渲染出来的图就会无谓地大改一次。生成器必须对节点和边做确定性排序——这是把图纳入版本管理的前提，比任何样式调整都重要。

rank、cluster、constraint 的真实语义

三个最常被误解的关键字，逐个说清它们到底约束了什么：

rank 是「分层方向上的同一层」，与 rankdir 无关。rankdir=LR 只是把坐标系旋转一次，同一层从一行变成一列，语义不变。rank=min/source 把节点钉在最上层，max/sink 钉在最下层，same 则要求成员同层——但它们默认在所属 cluster 内部生效，跨 cluster 需要 newrank=true。

cluster 必须以 cluster 开头命名才会被当作簇（这是字符串前缀约定，不是关键字）。dot 处理簇的方式是先把簇整体当成一个节点参与上层排布，再递归布局内部，所以它保证的是「成员占据连续的若干层」，而不是「一个封闭容器」。外部的边完全可以横穿一个簇的矩形范围。要让边停在簇边界上，需要 compound=true 并在边上写 lhead=cluster_x 或 ltail=cluster_x。

constraint=false 是处理循环依赖最有用的一个属性。有向图里只要有环，阶段一就必须反转一部分回边，被反转的边由 DFS 顺序决定，往往不是你希望的那条，结果整张图的层级都失去意义。把已知的回边显式标成 constraint=false，等于告诉引擎「这条边不参与分层」，层级立刻恢复可读。

strict digraph deps {
    // rankdir 只影响最后的坐标系旋转，不改变「层」的语义
    rankdir=LR;
    // 打开全局排名，否则下面跨 cluster 的 rank=same 不生效
    newrank=true;
    // 阶段一的默认约束：层差至少 1，权重 1
    edge [minlen=1, weight=1];
    node [shape=box];

    subgraph cluster_edge {
        label="接入层";
        gateway; bff;
    }
    subgraph cluster_core {
        label="核心域";
        order; payment; inventory;
    }

    gateway -> bff [weight=10];       // 主干：抬权重，阶段一阶段三都优先拉直
    bff -> order [weight=10];
    order -> payment [minlen=2];      // 强制隔开两层，给边标签腾出空间
    order -> inventory;
    // 已知回边：保留语义，但排除出分层，避免整图被拉歪
    payment -> order [constraint=false, style=dashed];
    // 跨 cluster 钉同层，依赖 newrank=true
    { rank=same; payment; inventory; }
    // 只为了固定层内左右顺序，不表达任何业务含义
    payment -> inventory [style=invis, weight=100];
}

六个引擎，六种对图结构的假设

引擎不是「画风」选项，每个都对输入图做了强假设。假设不成立时，输出不是「不好看」，而是「误导」——力导向布局里两个节点靠得近，读者会本能地理解成它们关系紧密，可那只是初值和斥力的偶然结果。

引擎算法家族对图的隐含假设规模与代价假设不成立时的表现
dot分层边的方向有语义，图接近有向无环上千节点内可用，瓶颈在阶段二环多时被迫反转大量边，层级变成随机分组
neato应力优化（默认 stress majorization，距离模型取最短路）图连通，且图论距离值得映射成几何距离要算全对最短路，时间与内存随节点数平方增长，实用区间数百节点非连通图各分量互相漂移；节点重叠严重，需要额外的 overlap 处理
fdp弹簧斥力（Fruchterman-Reingold 一类），支持簇无向图，关心的是聚类结构上千节点带随机初值，同一输入多次运行结果不同，无法进版本库
sfdp多层次力导向，远场力用四叉树近似超大稀疏图，读者只看整体轮廓万级以上局部细节完全不可读，标签互相覆盖；把它当「大图解决方案」是幻觉
twopi按到 root 的广度优先距离分环存在唯一且有意义的中心中等不指定 root 时中心由算法猜，图的语义中心与几何中心不一致
circo按双连通分量排环图里真的存在环结构中等树形结构被摊成一圈，边全部横跨圆心，信息量为零

大图治理第一步：削图，而不是换引擎

「节点多到看不清」几乎从不是布局算法能解决的问题。一张两千节点的依赖图，无论用哪个引擎，人都读不出结论。可行的顺序是先降低信息量，再布局：

# 只看关心的那一块：以 payment 为种子抽出诱导子图
gvpr -i 'N[name=="payment"]' -o sub.dot graph.dot

# 其实是多张互不相干的图？按连通分量拆开，逐张渲染
ccomps -x -o part graph.dot          # 生成 part.0 part.1 ...

# 传递闭包削减：A 到 C 已经可达时删掉直连的 A 到 C
tred graph.dot > graph.tred.dot

# 想让生成的 DOT 可 diff：先规范化，再入库
nop graph.dot > graph.norm.dot

# 定位慢在哪个阶段：-v 会打印各阶段耗时
dot -v -Tsvg graph.tred.dot -o out.svg 2>&1 | tail -20

# 阶段二太慢降迭代倍率，阶段一三太慢限制单纯形迭代（用质量换时间）
dot -Gmclimit=0.3 -Gnslimit=2 -Gnslimit1=2 -Tsvg graph.tred.dot -o out.svg

-Gmclimit=0.3阶段二倍率 1.0交叉优化的迭代轮数按比例缩减，时间下降最直接交叉明显变多
-Gnslimit / -Gnslimit1阶段三 / 阶段一不限制给网络单纯形设迭代上限坐标与分层质量下降，边普遍变歪
-Gconcentrate=true阶段四（仅 dot）false合并走向相同的平行边，视觉负载骤降单条边的身份丢失，不能再追某一条依赖

-Gpack / -Gpackmode布局之后不打包多个分量紧凑排布，省画布分量之间的距离不再表达任何含义
ratio=compress 配 size输出无强行塞进固定画布字号被缩到不可读，等于没出图

把 DOT 当生成目标，不当手写语言

Graphviz 在工程里最有价值的位置是生成目标：上游工具吐 DOT，Graphviz 负责布局，产物进流水线。手写 DOT 只适合三五十个节点以内的示意图，超过这个量级，手写的维护成本和「图与现实不符」的风险都会失控。

自己写生成器时，真正会踩的是 DOT 的词法细节，而不是图算法：

import re

# 这些是 DOT 关键字，撞上就必须加引号，否则是语法错误
KEYWORDS = {"node", "edge", "graph", "digraph", "subgraph", "strict"}
BARE_ID = re.compile(r"^[A-Za-z_\x80-\xff][A-Za-z_0-9\x80-\xff]*$")

def dot_id(name):
    # 裸标识符只允许字母数字下划线；其余（含点、斜杠、冒号、中文标点）一律加引号
    if BARE_ID.match(name) and name.lower() not in KEYWORDS:
        return name
    return '"' + name.replace('\\', '\\\\').replace('"', '\\"') + '"'

def dot_label(lines):
    # \l 是左对齐换行；结尾也要带一个，否则最后一行会居中
    body = "".join(s.replace('"', '\\"') + "\\l" for s in lines)
    return '"' + body + '"'

def emit(nodes, edges):
    out = ["strict digraph g {",             # strict: 重复边自动合并
           "  rankdir=LR;",
           "  newrank=true;",
           "  node [shape=box, fontname=\"Noto Sans CJK SC\"];",
           "  edge [fontname=\"Noto Sans CJK SC\"];"]
    # 排序是为了让输出稳定可 diff，阶段二的层内顺序依赖书写顺序
    for n in sorted(nodes):
        out.append("  %s [label=%s];" % (dot_id(n), dot_label(nodes[n])))
    for a, b, back in sorted(edges):
        attrs = " [constraint=false, style=dashed]" if back else ""
        out.append("  %s -> %s%s;" % (dot_id(a), dot_id(b), attrs))
    out.append("}")
    return "\n".join(out)

输出格式、字体与中文

输出格式的选择标准不是「清不清晰」，而是「产物还要不要被再加工」。-Tdot 和 -Tjson 这两个文本目标最容易被忽略，它们让布局结果变成可编程的数据：前者带坐标可复用，后者带每个图元的绘制信息，足以自己写一个交互式渲染器。

❌
最容易踩的坑

1. 把 nodesep、ranksep 当成排版手段——它们只改留白，节点的相对位置由分层与层内排序决定，调间距永远换不来想要的拓扑。

2. 有环的依赖图不标 constraint=false——引擎会自己挑边反转，挑中的往往是主干，于是整张图的层级失去意义，而你以为是「布局不行」。

3. 以为 cluster 是隔离容器——它只保证成员占连续层，外部边照样横穿；要让边停在簇边界得开 compound=true 并写 lhead/ltail。

4. 跨 cluster 写 rank=same 却没开 newrank=true——约束被默默忽略，没有任何报错。

5. 生成 DOT 时遍历哈希表——节点书写顺序影响层内排序，于是同一份数据每次渲染都产生大面积无意义 diff。

6. 拿 sfdp 当大图解药——它只承诺画得出来，不承诺读得懂；节点多就该先 tred 削边、gvpr 抽邻域、按包折叠。

7. 用力导向引擎（fdp/sfdp/neato）出版本库里的图——带随机初值，同输入多次运行不同，评审时无法区分「改了什么」和「抖了一下」。

8. 看到力导向图里两点靠近就解读成关系紧密——那可能只是斥力平衡的偶然结果，只有 dot 的层级和 twopi 的环是有明确语义的。

9. 用 twopi 不指定 root——中心节点由算法猜，读者会把猜出来的中心当成系统核心。

10. 大图直接开 ratio=compress 配 size 硬塞——字号缩到不可读，图还在但已经没有信息传递能力。

11. DOT 生成器不给标识符加引号——带点、斜杠、冒号的包名或文件路径直接触发语法错误，撞上 node、graph 这类关键字更隐蔽。

12. 只在本机装字体就上 CI——位图输出在构建机上栅格化，中文字体缺失会让整张图的标签变成方框，而构建是「成功」的。
