Graphviz 布局引擎

🏷️ 代码生图

Graphviz 简介

Graphviz（Graph Visualization Software）是 AT&T 实验室 1991 年开发的开源图形可视化工具。它用 DOT 语言描述图结构，自动计算布局生成矢量图。跟 Mermaid、PlantUML 那些"上层语法糖"不同，Graphviz 是底层布局引擎——PlantUML、Doxygen、许多文档生成工具底层都靠它算布局。

我对 Graphviz 的定位

简单流程图我用 Mermaid，GitHub 原生渲染省事。但超过 50 个节点的复杂依赖图、网络拓扑、编译器 IR，Graphviz 的 sfdp 布局算法甩 Mermaid 几条街。它不美观但布局质量高，是给工程师看的图，不是给产品经理看的海报。

核心概念

  • DOT 语言：描述图结构的文本语言
  • 布局引擎：dot / neato / fdp / sfdp / twopi / circo 六种算法
  • 节点（Node）和边（Edge）：图的基本元素
  • 输出格式：SVG / PNG / PDF / dot / json 等

安装

# macOS
brew install graphviz

# Ubuntu / Debian
sudo apt install graphviz

# Windows
winget install Graphviz.Graphviz

# 验证
dot -V

DOT 语法快速入门

最小例子：一个有向图，三个节点两条边。digraph 是有向图，graph 是无向图：

digraph G {
    A -> B;
    B -> C;
}

渲染成 PNG：

dot -Tpng input.dot -o output.png
dot -Tsvg input.dot -o output.svg   # 矢量输出，推荐

节点和边的属性

属性是 Graphviz 的灵魂，调样式全靠它：

digraph G {
    // 全局默认样式
    node [shape=box, style=filled, color=lightblue];
    edge [color=gray50];

    // 单节点属性
    A [label="开始", shape=ellipse, fillcolor=gold];
    B [label="处理"];
    C [label="结束", shape=doublecircle];

    // 边带标签
    A -> B [label="输入", penwidth=2];
    B -> C [label="输出", style=dashed];
}
常用属性作用
shape节点形状：box/ellipse/circle/diamond/record
style填充样式：filled/dashed/dotted
fillcolor填充色
label显示文本
penwidth线宽
rankdir方向：TB（上下）/LR（左右）

布局引擎怎么选

Graphviz 最容易被忽略的就是布局引擎选择。不同算法适合不同图，选错了图一团乱：

引擎算法适合图节点规模
dot有向分层有向无环图、流程图、依赖图中小规模
neato弹簧模型无向图、关系图中小规模
fdp力导向大规模无向图较大
sfdp多尺度力导向超大规模图（万级节点）万级
twopi径向布局层级树、中心辐射中等
circo环形布局环形结构、循环图中等
我的选择经验

有向依赖图一律 dot；超大规模网络拓扑换 sfdp；想做中心辐射的径向树用 twopi。命令就是 sfdp -Tsvg input.dot -o out.svg，换个引擎名而已。

实战：依赖图示例

微服务依赖图是我最常画的场景：

digraph microservices {
    rankdir=LR;
    node [shape=box, style=filled, fillcolor=lightblue];

    api_gateway [label="API Gateway", fillcolor=gold];
    user_service [label="用户服务"];
    order_service [label="订单服务"];
    payment_service [label="支付服务"];
    db [label="数据库", shape=cylinder];

    api_gateway -> user_service;
    api_gateway -> order_service;
    order_service -> payment_service;
    user_service -> db;
    order_service -> db;
}

生产案例：编译器调用图

说个我用 Graphviz 的真事。排查一个性能问题，要知道项目里几千个函数谁调用谁。用 Clang 的静态分析工具导出 DOT 文件，sfdp 布局后发现一个函数被几十处隐式调用，缓存失效导致每次都重算。这个图要是手画，三天也画不完；Graphviz 自动布局，十分钟定位问题。这就是底层布局引擎的价值。

什么时候用 Graphviz

最佳实践

  • 输出用 SVG 矢量格式，放大不失真
  • 超大规模图用 sfdp 代替 dot
  • 用 rankdir=LR 控制横向布局
  • 节点超过 100 个，用子图（cluster）分组，图才看得清
  • DOT 文件进 Git 版本控制，产物由 CI 渲染

FAQ

Q：Graphviz 和 Mermaid 选哪个？
简单流程图用 Mermaid（GitHub 原生、语法简单）；复杂依赖图、超大规模拓扑用 Graphviz（布局算法强）。

Q：Graphviz 生成的图太乱怎么办？
换布局引擎（dot→sfdp），用子图分组，控制 rankdir，减少边的交叉。

Q：Python 怎么调 Graphviz？
pip install graphviz，它是 DOT 语言的 Python 绑定，底层还是调 graphviz 二进制。

总结

Graphviz 是底层布局引擎，用 DOT 描述图、自动算布局。它不美观但布局质量高，超大规模依赖图和拓扑是它的主场。记住按图选引擎：有向用 dot，大规模用 sfdp，径向用 twopi。下一篇看看怎么把这些工具组合起来用。
