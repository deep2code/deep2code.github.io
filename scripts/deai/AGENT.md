# 去 AI 味改写 Agent 作业说明（阶段 B）

你负责一批 HTML 文章页的**正文段落改写**：去掉 AI 腔的模板句和修辞转弯，把段落压短压直。

只改 `<p>` 里的文字。结构、标题、表格、代码、链接一律不动——那些已由脚本处理完。

规则原文见 `zh-blog-lint/去AI味改写规范.md`，本文件是执行清单。

**你的输入由 `why` 字段说明这段为什么被选中**，取值以 `plan.py` 引用的 `lint.PARA_RULES` 为准：
`预告句式` / `套话转弯` / `顺序词` / `超长段落` / `段落内 emoji`；`全文改写` 是全站普压批（阶段 B2），
这段没触门、只是超过 60 字，你的任务纯是压字数 + 顺手去掉下面编号列出的那几类句式。
两条自指规则（下面第 7、8 项）阶段 B6 起改成查整页，已不在 `PARA_RULES` 里，所以新排的队列不会再用它们
标注某一段——已落盘的 106 批里有 269 段带 `自指叙述`，那是规则还在段落口径时排的。
**判不判到你头上是一回事，写不写出来是另一回事**：`new_html` 里同样不许留自指和星星。
一段同时带两个原因时（`自指叙述+全文改写`）两件都要解决。
不在你输入里的段落不要改。

## 干活节奏（一次别吞太多）

**不要写脚本代替改写。** 压缩是逐段的语言判断，正则和模板生成出来的句子过不了字数门也过不了
人工复核（真有过一个 agent 花二十分钟在 `/tmp` 搭「改写引擎」，一份交付都没落下）。
脚本只用来切片读输入和跑自检，句子必须你自己一段一段写进 JSONL。

一批最多 45 段。**每次只处理 10–15 段**：读这些段的 `html` → 改写 → 追加写 JSONL → 再读下一组。
用 `scripts/deai/plan.py` 生成的输入里 `items` 是数组，你可以用 Python 切片按序取，不必一次读全。

## 输入 / 输出

- 输入：`_drafts/deai-in/batch-<NN>.json`（路径由调用方给出），每个 item 是一段 `<p>` 的 inner HTML，
  带 `start` / `end` / `sha1` / `cjk` / `heading` / `prev` / `next`。
- **你只写 JSONL**：`_drafts/deai-out/batch-<NN>.jsonl`，每行一个对象，只带两个字段：
  ```
  {"start": 12345, "new_html": "改写后的段落 inner HTML"}
  {"file": "a/b/index.html", "desc": "该页新的 meta description"}
  ```
  `file` / `end` / `sha1` 由 `scripts/deai/from_jsonl.py` 从输入批次回填，你不要抄，也不要自己算偏移。
  一个 `start` 一行，描述行每个文件一条。
- **必须用 `cat >> ... <<'JSONL'` 或 Python 追加的方式分多次写**，每次 10–20 条。
  不要试图在一次工具调用里输出整批；也不要只写前几条就回报完成。
- 写完跑转换 + 校验（一次跑完会同时报缺哪几条）：
  ```bash
  cd /Users/junjunyi/src-code/deep2code.github.io && python3 scripts/deai/from_jsonl.py batch-<NN>
  ```
  它退出码 0 才算交付；退出码非 0 会打印「还差 N 条，例如 file=… start=…」，补齐再跑。
- **退出码 0 之后立刻打交付标记**：`touch _drafts/deai-out/batch-<NN>.done`。
  `land.py` 只落带 `.done` 的批次。打完标就不再改 `.jsonl`——落盘是按当时那一版做的，
  之后再改的内容补不回来（apply 的 sha1 守卫挡住二次回填）。
- 只写你自己那一个 `.jsonl`，不要碰站内任何 `.html`，不要改 `_drafts/deai-in/` 下的输入文件。

## 必须改掉的（这些会被 scripts/deai/lint.py 逐页判失败）

1. **每节开头的"能解决什么"预告句**
   `搞清这一节，能解决「内存涨了十倍」……` → 删掉整句，段落直接从事实开始讲。
   如果整段只有这句，把下一段的事实提前，本段输出一个最短的直接陈述句（不能输出空）。
2. **修辞转弯**：`好消息是 / 坏消息是 / 雪上加霜的是 / 更麻烦的是 / 反直觉的结论是 /
   先纠正一个流传很广的说法 / 另一个常见误解是 / 一句话说清 / 先说结论 / 值得注意的是 /
   需要说明的是 / 换句话说 / 也就是说 / 事实上 / 本质上 / 核心在于 / 关键在于 / 这才是 / 这就是为什么`
   → 转弯删掉，结论留下。
   **路线图句同属此类**：`本篇按落地顺序讲清：A、B、C` `这篇会依次回答` → 直接把 A、B、C 当正文讲，
   别留「本篇按…讲」这层壳。这类形状多数也会被《自指叙述》判出来，两条规则命中同一段时按这条改。
3. **顺序词**：`首先……其次……最后……` → 直接按因果写，或分点。
   删序号要整组删：只删掉「第一，」会留下悬空的「第二，」。同组序号在 `prev`/`next` 里能看到，
   改某一段时确认它的邻居段；要么整组去掉序号，要么一个都不动。
   保留序号时写法要和邻居一致：别把「第一，」写成「一，」而邻居两段仍是「第二，」「第三，」。
   `一是…二是…` 同规则，且**门的中文数字检查看不见它**（正则匹配数字+量词，不匹配「一是」）。
   另一 half 在本批相邻段时，两半都要处理；只剩自己这半被改，邻居会留下没有前件的「二是」。
   拆掉并列后，段末那枚暗示「后面还有半句」的 `；` 要收成 `。`。
4. **假精确**：没有条件、没有出处的百分比（`线上 90% 的偶发故障`）改成定性说法。
   **但注意**：数字是硬校验项，`90%` 这种 token 你不能删（见下面的硬约束），
   遇到必须保留数字的假精确句，把它改写成一个明确的条件句（`三项没配对时最常见的三种现象`），
   数字仍留在原位；实在无法保留的，原样保留数字并在段末不加评论。
5. **超长段落**：每段（含拆出来的每一小段）≤65 个中文字。
   **段末标点**：每段（含每一小段）必须以 `。！？：；` 收尾，不能停在 `</code>`、`</a>`、
   引号或半句上；用 `</p>\n<p>` 拆段时，前一小段必须是一句完整的话，不许把一句话从逗号处劈开。
   原文本来就以 `、`/`，` 收尾的（站内有把一条枚举拆成两段的存量）照原样保留即可。
6. **段落里的 emoji**：`✅ ⚠️ 💡 🚀` 从句子中删掉，告警框本身不归你管。
7. **自指叙述**（`why` 里的 `自指叙述`）：主语是文章自己的句子——
   `这篇只讲 X` `本篇在路径里的位置是 Y` `这一节解释…` `这篇不讲 Redis 怎么实现，只讲一件事`。
   处理方式是把 X/Y 当正文直接讲，句子主语换成技术对象：
   `这一节解释为什么五种位置要五种编码器` → `五种位置要五种编码器，因为 HTML、JS、URL、属性、CSS
   的解析规则各自独立`。`不适用边界：本篇只讲服务端渲染` → 直接写这条边界本身
   （`服务端渲染之外的场景不适用`），别留「本篇」两层皮。
   段首带冒号的 `搞清这一节能解决的现象是：` 已由脚本删过，你遇到的是形状不规则的其余部分。
8. **自指主语**（`why` 里的 `自指主语`）：`这篇 / 本篇 / 这一篇 / 本文 / 此文 / 该篇 / 这一节 / 本节`
   出现在正文段落里就判硬项，不再等动词。这条是阶段 B5 补的：`自指叙述` 只收动词锚定的形状，
   放过了 `这篇按三段组织` `本篇是这条路径的最后一环` `本文只在需要的地方指路` `这一节直接决定你的
   API 手感` 这类，全站 240 段。改法同上——主语换成技术对象；换不动时用「这里」指代这一段在讲的
   东西（`本篇把范围收到「谁来创建」` → `这里把范围收到「谁来创建」`），别用「本文 / 本篇」兜底。
   后顾里排掉的假阳性：`脚本本文` `版本文档` `文本节点型`，这三处不是自指。
   前瞻还排掉 `本节点`（Redis 分片、K8s 节点篇里是术语）和 `本文件`（图源注释），共两处。
   口径：`C.blocks()` 只给正文 `<p>`（`SKIP_TAGS/SKIP_CLASSES` 有意跳过 table、pre、mermaid、callout、
   cluster-nav），所以 B5 之前这两条规则只查段落；阶段 B6 把它们改成查整页正文区，段落之外又清掉
   41 处（表格单元格 21、提示框标题与强调 10、表头 4、小标题 1、mermaid 标签 4、路径导航 1）。
   唯一保留的豁免是 `<pre>`：代码块受 `scripts/shrink/verify.py` 的「代码块与基线全等」保护，改不动，
   所以两条规则先 `strip_pre()` 再匹配，3 页 4 条残留登记在 `lint.PRE_EXEMPT` 里。
   `--self-test` 对这两条各植入一条表格样本（证明口径不再限于段落）、一条 `<pre>` 负例（证明豁免生效），
   并逐条核对 `PRE_EXEMPT` 的句子还在、还在 `<pre>` 里——登记失效或句子跑到正文都会让自检变红。
9. **星级评分**（阶段 B7-38 新硬项）：`⭐ ★ ☆` 落在正文区任何位置都判硬项，表格单元格也算。
   它和《段落内 emoji》不是一条：那条只看 `<p>`，而这一族的星全长在 `<td>` 里（首轮清掉 5 页 310 个）。
   这条**不进你的队列**（`plan.py` 的 `why` 只认 `PARA_RULES`），表格也不在你的射程内：
   段落里真遇到就把星删掉、把「最好 / 一般」这类词直接写进句子；表格里的评级列只报告，不动手，
   那一族由人工改并按 `scripts/deai/table-edits.json` 登记（删列会撞 `verify.py` 的表格形状门）。
   口径要记住：`✅ / ❌` 说的是「有没有这项能力」，不是打分，永远不算命中——别顺手把它换成星星。
10. **口头评级**（第十八轮新硬项）：`⭐` 换成汉字还是打分——`业界领先，架构推理能力最强` 和
    `⭐⭐⭐⭐⭐` 是同一件事。首轮清掉 22 处 / 7 页，全在表格单元格和评分雷达图旁边。
    判定按**格子形状**，不按词表：档位词（`优秀 / 良好 / 较差 / 业界领先 / 顶级 / 一流 / 极致`）
    任何列都算；量级词（`中等 / 一般 / 最佳 / 最强 / 最大`）只在列头是评论式
    （`说明 / 备注 / 特点 / 理由 / 评价 / 结论 / 优势 / 劣势 / 优点 / 缺点 / 建议`）时才算。
    所以 `写入代价 ┃ 中等`、`适合干什么 ┃ 中等复杂度的功能开发`、`延迟代价 ┃ 最高，要等串行回放`、
    转置表里的 `微调 ┃ 一般，模型仍可能幻觉` 都不命中——那是量级或某一行维度上的结论，删它等于删信息。
    和《星级评分》一样**不进你的队列**：表格不在你的射程内，遇到就报告，由人工改并按
    `scripts/deai/table-edits.json` 登记（删行删列会撞 `verify.py` 的表格形状门）。
    人工改的口径也记住：**剥档位词，不给它加 `✅` 外壳**。`Tab 补全质量 ┃ 优秀 ┃ 最佳` 改成
    `✅ 优秀 ┃ ✅ 最佳` 只是让新门闭嘴，习惯还在，下一轮就得整套豁免；那种格子按纯打分整行删，
    删前核实同一个判断在本页别处以具体写法还在（`比 Cursor 差一截`、`补全标杆`）。
11. **打分雷达图**（第十八轮新硬项）：`data-option` 里 `type: radar` 即判硬项——轴是
    `易用性 / 灵活性 / 中文能力 / 生产就绪` 这类主观维度、值是 1–10 或 0–100 自评分的图，
    和星星同族，且藏在属性里，正文规则和 `verify.py` 的数字全等一律打不到。
    `bar / line / pie` 不判：那些画的是实测数字（训练参数量占比、p99 毫秒），是数据的另一种视图。
    属性有两种写法（单引号包裸 JSON、双引号包 `&quot;` 实体），两种都要认——只按一种匹配会漏图。
    这一条同样不进队列：图由人删，删前核对下面的文字或表格已给出同一依据。
12. **问答结构化数据**（B7 第十六轮加的硬项，第十九轮补三支并把词表打通到页外面）：页外文本面是
    `<head>` 里的 `<title>` / 三条 `description` 加上 `<script type="application/ld+json">` 的 `FAQPage`。
    `page_text()` 剥掉 JSON-LD、`C.body_of()` 剥掉 `<head>`，所以这一面过去只有《问答结构化数据》
    的两支（悬空冒号、句末标点）打得到，词表类硬项一条都进不来；第十九轮清掉 17 页 51 条拷贝 + 32 条答案套话。
    两点口径：
    · **同一份词表也吃这一面**（`OUTSIDE_RULES` 走 `outside_para_text()`，命中带「页外面」前缀）：
      套话、自指、星级这些词在正文清了十八轮、在问答里留着同一句，就是本轮那 32 条化石拷贝。
      所以**改正文时别只管 `<main>`**——你在正文里删掉的 `换句话说` 之类，如果问答里也有一句，
      那一页照样红。词表只有一份，不要另写第二份。
    · 五支里前两支（悬空冒号、没有句末标点）是第十六轮按机械形状建的，本轮补后三支查**派生关系**：
      答案以悬空连接符开头（`——太小上下文不完整…` 是从 `<strong>标签</strong>——说明` 撕下来的半截）、
      问题名去掉「？」后正好等于正文某个 `<li><strong>标签</strong>：` 的标签、
      同页 ≥2 条答案逐字抄正文。这一族**不按疑问词表判真假**：`…是不是表示不缓存？` 是真问题，
      按词表判会把一大批真问题打红。「问题名＝标签」只比冒号分段后的**末段**，比首段会撞上正文里同名的主题标签。
    这一条也不进队列：JSON-LD 由调用方改，工人只被允许改 `<p>`；`verify.py` 第 14 条还会盯住
    页外面的数字与行内 `<code>`（要整页找得回来）。遇到命中就报告页面与是哪一支，由人工删拷贝或改问句；
    **不要为了消门把正文句子复制进问答**——那是本轮删掉的东西，反过来加回去等于把缺陷再生产一次。
    这一条的分支与守卫逐个变异验证，命令固定：
    ```bash
    python3 scripts/deai/lint.py --self-test        # 五支各有正例，正例声明期望命中哪一支
    python3 _drafts/mutate_round19_tmp.py           # 废一支只哑它自己的正例；废 (?!的) 门则负例必须变红
    ```
    读负例行要小心：标签里就带「应不触发」四个字，整行找「不触发」永远为真，必须看最后一个「：」之后的尾段
    ——驱动脚本第一版就这么写错，那项检查等于没做。
13. **段落之外那一面**（第二十轮把词表打通，不是新硬项）：`<td>/<th>`、`<li>`、`<h2>-<h5>`、
    `callout-title` 合计 **939,627 汉字**，而 `C.blocks()` 认定的正文 `<p>` 只有 499,591 汉字——
    第十八、十九轮把 `自指 / 星级 / 口头评级 / 雷达图` 送到了整页、把词表送到了页外，
    但 `套话转弯 / 预告句式 / 顺序词` 这三条词表规则一直只吃 `<p>`，即**只扫了全部正文文字的 34.7%**。
    现在 `NONPARA_RULES` 这三条也吃 `nonpara_para_text()`，命中带「段落外」前缀，词表仍只有一份。
    · 改表格、改小标题**不在工人射程内**（`plan.py` 只按 `PARA_RULES` 逐段派活，不碰 `check()`），
      遇到「段落外」命中就报告页面与前缀，由调用方按编辑口径改句子——
      **换写法不换意思**，别只删词：`每张表能用一句话说清它存什么事实` 里「一句话说清」是判据本身，
      要改成 `每张表存什么事实，一句说明就能讲完`，不是砍成 `每张表说得清存什么`。
    · 反过来也成立：**别把套话写进格子和标题**。门现在看得见它们了。
    · `超长段落` 与 `段落内 emoji` 不进这一面：前者是段落的形状概念（表格长句归表格），
      后者站内的 `✅/⚠️` 全在 `<td>` 里，是「有没有这项能力」不是打分（第十八轮裁决，`<pre>` 同理由被摘掉）。
    · 改标题要过 `verify.py` 第 7 条（标题文本多重集相等），逐对登记在 `KNOWN_TEXT_EDITS`，
      **登记一条改过的标题，不是给整类开豁免**；提交进 HEAD 后这条登记会判「失效」，要删。
      第二十四轮起有一种不用登记的：**装饰 emoji 不算内容**，第 7 条比对前只把**基线**标题里的
      pictographic 符号折掉（`normalize_head_deco`，判定用 `lint.is_deco_emoji` 那一份，站内只有一处定义），
      所以 `🤖 AI与大模型 → AI与大模型` 不必逐页登记；改字仍然逐对登记、仍然判红。
    这一面的四支容器与两个守卫逐个变异验证，命令固定：
    ```bash
    python3 scripts/deai/lint.py --self-test        # 四类容器各有正例，正例声明期望命中哪一类
    python3 _drafts/mutate_round20_tmp.py           # 废一支只哑它自己的正例；废守卫则对应负例必须变红
    python3 _drafts/probe_tdface_tmp.py             # 重新称这一面的面积与命中
    ```
    植入点不唯一时驱动脚本会中止（《口头评级》里也有一条同款 `<t[dh]>` 正则）——那是预期行为，
    把锚点加宽到 `FACE_RE = re.compile(` 那一段，不要改成 `replace(..., 1)` 蒙过去。
14. **标题内 emoji**（第二十四轮新硬项）：`<h1>`-`<h6>` 的文本里出现装饰性 emoji 即判硬项，跳过 `<pre>`。
    它补的是《段落内 emoji》从没覆盖的那一面：那条只扫正文 `<p>`，字符集还是八个字的死表，
    所以 18 个分类页的 `<h2 id="articles">📚 文章列表</h2>` 和 5 个分类页 h1 的前导图标活了整个 campaign。
    两条口径要记：
    · 字符集按 **Unicode 区段**收（`lint.EMOJI_RANGES`），不是列一遍本站见过的符号；
      `ARROW_RANGES`（`U+2190-U+21FF`、`U+2794-U+27AF`）**排除在外**——`Naive → Advanced`、
      `读写模式 → 缓存策略` 这类映射关系是内容，站内 9 处，收进来就是把门写成「小标题带符号就红」。
      界面装饰也不在这一面：`💡 callout-icon`、`🏷️ meta-item`、`🌙/☀` 主题开关、能力表 `✅/❌`
      都不长在标题里（实测标题面零命中），所以没有为它们开口子，也就没有「一开口子就整类豁免」。
    · 这条**不进你的队列**（不在 `PARA_RULES`），命中就在报告里写页面与标题原文。
      分类页的 `文章列表` 那一格由 `gen_categories.py` 的 `existing_heading()` 原样抄回，
      所以清完之后要重跑生成器确认幂等，而不是手改一遍就算完。
    验证固定两条命令，各钉一面：
    ```bash
    python3 scripts/deai/lint.py --self-test        # h2 正例 + 4 条边界负例（代码块/界面装饰/能力表/箭头）
    python3 _drafts/mutate_round24_tmp.py           # 累计 117 条：emoji 双向 + <pre> 承重 + 页头十面逐面变异 + 重建内容不动点 + 卡片标题两个分支
    ```

## 压缩口径

- **整批硬门：本批所有段合计 ≤ 原字数 × 0.78**（`check_out.py` 按整批总量判）。
  每条单独压到 0.82 也会被打回——一段平均要压到 76% 才有余量，先按这个尺度下刀再逐条回补。
- 每条 item 改写后中文字数 ≤ 原 `cjk` × 0.82（`cjk` ≥ 30 的条目）。
- `cjk` 在 15–29 的：至少删 3 个字，或换成更直白的短句。
- 手段按顺序用：删铺垫 → 删与 `prev`/`next` 重复的过渡 → 删举例枝节（例子里的数字与结论必须留）
  → 长句拆短 → 仍超长就用 `</p>\n<p>` 拆段（不加外层 `<p>`）。
- `prev`/`next` 只用来判断邻居的序号配对和重复，**不能把 `next` 的句子搬进本段**——那样同一条事实会在
  两页段落里出现两遍，而门只核对字数，看不出重复。
- 删掉框架句后不留光杆词当段首：`几个容易忽略的细节：` 压成 `细节：` 是错的，直接从事实起句
  （`回填要分批并控制事务：…`）。
- 平均每句 15–25 字，单句不超过 35 字。
- `——` 每页不超过 5 处：能用逗号或另起一句的就改掉。
- `「」` 只用于错误信息原文、要引用的现象、配置字面值；比喻名不用引号。

## 语气

读者是维护过生产服务的后端工程师。像同事当面讲一件事：先说结论，再说条件和代价。
不用「我们」「笔者」，不用「轻松掌握」「强大」「无缝」，不加感叹号。

## 硬约束（违反会被 check_out.py 打回）

- **数字与单位一个都不能丢、不能改、不能新增**：`30 秒`、`p99`、`2.25 版本`、`4MB`、
  `2 到 3 倍`、`① ② ③` 全部原样。禁止把阿拉伯数字写成中文数字，也禁止反向。
- **引号「」里的数量是事实，不是套话**。这类段落的骨架是
  `搞清这一节，能解决「只加了一个字段，下游调用量就翻了十倍」`，要拆掉的是
  「搞清这一节能解决」这七个字，**引号里的 `一个` `十倍` `一倍` `三个` `几天` `一次` 必须
  原词搬进改写后的句子**：`每个字段都挂 resolver，加一个字段下游调用量翻十倍`。
  只有属于骨架自身的数量（`先纠正一个流传很广的说法` 里的 `一个`）才可以删。
- **不许新增原文没有的中文数字**，包括你自己数出来的 `两个字段` `三条路` `十二个维度`——
  原文没写数量就别说数量。
- `<code>…</code>` 内容、`<strong>` 强调位置、`<a href>`、`<img>`、HTML 实体
  （`&lt; &gt; &amp; &quot;`）原样保留。拆段时行内标签各自闭合，不许跨段断开。
- 不动结构：标题、表格、`<pre>`、mermaid、列表都不在你的输入里。
- 术语沿用原文写法，不换同义词；英文术语、命令、API 名保持原样。
- 技术事实、阈值、判据、失效条件一条都不能少。宁可少压几字，不能丢信息。
- 条件词（`必须` `只有` `才` `否则` `至少` `以内`）可以换同义写法（必须→要、不能→无法），
  不能整组删掉。调用方会用 `review.py` 的 `▲` 逐条问回来，自己先按同一标准过一遍。
- **标识词不能只靠回指活着**：行内代码外的英文术语、锁模式、计划节点名（`ACCESS EXCLUSIVE`
  `Bitmap Heap Scan` `visibility map`）如果压成「这把锁」「这种方式」，只有紧邻上一段（`prev`）
  里原词还在才允许，否则原词必须留在本段。调用方用 `review.py` 的 `■` 按整页核：
  一个词从这一页彻底消失就报，删自指指针（`详见站内 DDD 那篇`）顺带带走术语是唯一的合法情形。

每个**文件**在 `descs` 里给 1 条新描述（不要去改 HTML 里的 meta 标签）：

## 队列覆盖面：加硬项之后必须重排

`_drafts/deai-in/` 里的批次是 **`plan.py` 那一刻按当时的规则表算出来的**。往 `lint.py` 新增
一条 `PARA_RULES` 硬项（`自指叙述` 就是这么加的）之后，已生成的队列并不认识它：短段（< `--min`
汉字）只有「触门」才会被排进来，于是这类段全成盲区——表现为队列跑干净了、`land.py` 每页都报
「硬项 → 0」，但全站 `lint.py` 退出码仍是 1。

收尾口径：一波跑完后必须复跑 `python3 scripts/deai/lint.py`，退出码非 0 就用同一判据把残留段排出来

```bash
python3 scripts/deai/plan.py --flagged --min 20   # 只排触门段；跑之前确认 deai-in/ 无在途批次
```

（`plan.py` 会清空并重建 `deai-in/` 与 `deai-plan.json`，落盘过的输入在 `deai-in-landed/`，
重排前先把上一份 plan 备份，别拿新队列去对旧批次号。）
残留只有个位数段、且改法是同一种句式替换时，可以不走工人：按段做一次唯一子串替换，逐段自检
「改后不触门 + `code`/`href`/数字多集合不变 + 汉字数不增」，全绿才写文件，改完复跑
`lint.py`、`check_pairs.py` 和 `python3 gen_search_index.py`。

阶段 B5 的实战记录：`自指叙述` 的盲区是 240 段（159 页，净减 593 汉字），按目录切成 5 轮
阶段 B6 的实战记录：段落之外还有 45 处自指（26 页），`C.blocks()` 一条都看不见，是拿
`lint.SELF_WORDS` 直接扫整页 HTML 得到的。这一批第一次动了 `verify.py` 保护的三类元素，5 个文件判红：
代码块注释 4 处、h2 标题 1 个、mermaid 标签 4 个。处理是分开的——代码块的不变量原样保留，4 条注释
回滚并在 lint 里跳过 `<pre>`；标题与图是渲染出来给读者看的文字，2 页 5 对以「基线片段 → 现文本片段」
登记进 `verify.KNOWN_TEXT_EDITS`，命中才放行、登记失效即判红，夹带任何别的改动也照样红（两条负例验过）。
这批登记后来随 HEAD 前进自然清空（`KNOWN_TEXT_EDITS = {}`），机制还在、表是空的——基线一旦含新文本，

阶段 B7 的实战记录：改为逐页通读，不再按词表计数开批。第一轮的收获是「看不见容器」这件事会反复出现——
`C.blocks()` 只认 `<p>`，所以 17 页里 38 个 `<blockquote>` 总结金句框整条流水线一条都没碰过
（`核心结论：`、`黄金法则：`、`一句话定位：`、`选型提示：` 这类领起式复述，内容都紧跟在同一节的图或表格之后重说一遍）。
删整块和改一句话在门上不等价：框里自带的数字和行内 `<code>` 会连带消失，`数字 token 全等`、`行内 code 全等`
两条立刻判红，所以必须逐块登记（`scripts/deai/deleted-chunks.json` + `verify.apply_known_deletions`）。
登记表第一版只存了「删前的那一串」，判红 4 页——那 4 个框的文字在 B 批被改写工人动过，阶段 A 快照里没有这个形状；
改成 `{baseline, removed}` 成对登记后，条件变成「基线里找得到前者、现文件里找不到后者」，比单串更严，
顺手还能抓住「框被恢复但登记还留着」。四种负例（照登记删 / 基线夹带改一处 `<pre>` / 登记表改坏一个字符 /
块被恢复）跑过，全部符合预期。删之前那一步不能省：逐个框读上下文、并验证框里的数字与 code 在正文别处还在，
否则删掉的就是信息而不是修辞。
登记表还有第三种失效：**基线前进后登记自己过期**。这批 44 条在金句框删除被提交进 HEAD 之后逐条复核，
44/44 报「基线里找不到这块」——基线已经不含那块，留着反而成了假豁免。表清空、内容归档在
`_drafts/deleted-chunks-expired-20261031.json`；以后每次 HEAD 前进都要重跑这个复核，别等页面进扫描范围才判红。

阶段 B7 第二轮落在 `<p>` 里面，问题就换成「哪一句是复述标题的」。`ai/coding-assistants/prompt`

这里有两件事值得记下来：

- 删整节要登记，删空转句不用。登记与否只取决于带走的东西是否落在 `verify.py` 那几条全等不变量里：
  「总结」这个标题进了 `标题文本` 多重集、FAQ 里重复的 `500 到 2000 token` 进了 `数字 token` 多重集，
  这两块进 `deleted-chunks.json`；四句空转句里没有数字、code、href、标题，直接删，门的口径不受影响。
  `_drafts/apply_b7b_tmp.py` 把这条判断写成了硬约束：改动前逐类算多重集差，差必须与所删片段自身的
  命中完全相等，且非空的差必须事先声明要登记，否则整批拒。
- 补主语不能用 `本篇` `本文` `这一篇`。`ai/langchain/index` 那句 `；只谈框架本身。` 是 B5 为了躲
  《自指主语》硬项把 `本篇` 剥掉留下的半截；改成 `这里只谈框架本身` 才既补上主语又不撞硬项。
  凡是「补回被硬项剥掉的自指」都要走这一趟：先想硬项放过哪种写法，别把删掉的红项原样贴回去。
- 一条只有读才看得出来的误判：`LangGraph 值得单独用的四个信号：` 跨两个 `<p>`、后半段以 `四条命中任意一条`
  收尾，看着像流水线拆段拆坏了。对过快照——作者原来就是这么分两段写的，`；` 结尾的链式列举是全站正文的
  既有风格（快照里 755 处）。而合并成一段会顶到 80 字上限（两段各 52、58 汉字，合并 110），要么就得删事实。
  报出来的「问题」要先用快照证伪一遍，再决定删不删。

阶段 B7 第四轮改成按专题读：`ai/langchain` 五页整页读完，每页再拿 `_drafts/read_page_tmp.py` 对现文件和
快照各打一遍然后 `diff`——压缩过头只有对着原文才看得出来，单读现文只会觉得「挺简洁」。读出来的损伤分三类，
都只能用补写而不是删除来修：

- **剥掉自指主语后剩名词短语或失去先行词**。`ai/langchain/index` 的 `这篇不复述教程，只回答三个工程问题——` 被 B5
  剥成 `三个工程问题：它把什么…` ，整段没有谓语。补主语时相邻两段不能都用 `这里`（首页那段结尾已经是
  `这里只谈框架本身`），下一段改写成 `抛开争议，真正要回答的是三个工程问题`。`intro` 的 `这个做法流传很广`
  同理：上一段在讲流式，先行词是 B5 剥掉的 `本篇最该纠正的一个流传很广的做法`，补成 `提示词硬约束这个做法`。
- **结论的根据被当成冗余压掉**。`rag` 那句 `loader 帮你调库但不保证解析对` 是「必须人工抽查」的理由，
  压掉后只剩一句命令；`agent` 的 `选择准确率明显下降，而且不是线性下降` 压成 `下降` ，「不是线性」这层
  恰好是悬崖值得单独讲的原因。这类补回去的字数是原文自己的，不是新增内容。
- **主语滑到错的物体上**。`production` 的 `不少产品把模型输出直接当 HTML 渲染，被诱导输出带脚本的链接`
  ——被诱导的是模型不是产品；同一句还丢了 `Markdown` `图片标签` 两个具体形态，它们不在 `<code>` 里，
  门的四条全等不变量一条都拦不住。
- **一句话被从中间切成两段，前段单独读成中性陈述**。`intro` 的 `有的恰好能解析。` / `变量被替换成空字符串…`
  基线是一整句（`有些恰好能通过解析，变量被替换成空字符串，prompt 静默变形`），B 批改写从逗号处劈成两个
  `<p>`，前段就不像在说坑了；并回去 53 汉字，远在 80 字上限内。同页 `答案大多在里面` 是基线
  `十次里有八九次` 被压平的，作者的频率观察被换成了一个没有根据的「大多」。

两条口径上的坑记下来免得重踩：一是保护多重集要比**本次改动的前后两版**，不能拿现文件和快照比，
已经登记的整块删除本来就带走了数字和 code，跟快照比必然误报；二是 `C.plain()` 剥标签不留空格，
`而是<code>LLM</code> 接口` 在纯文本里成了 `而是LLM 接口`，看着像缺空格的病句——`因为RAG 出问题` 同理。
这两处都在 raw HTML 里核掉了，报「读出来的问题」前先 `grep` 原文，别拿自己 dump 的产物当证据。

  只是这次作用在一句上而不是整节。
- 反过来，带数字的领句不能删。`verify.py` 的数字多重集是全等比较，windsurf 那句里的 `Pro $15/月`
  删了就只有两条路：别处再写一遍（作假），或者进 `deleted-chunks.json`（等于承认删了信息），

  并把第 3、4 条收窄到 `body_of()`、另立第 14 条「页外数字与 code 整页找得回来」——
  正文那份还在，所以既不用豁免登记也不用人肉留着。**教训：登记一条「明知该留」之前，先问这一整块该不该存在。**
- **第十九轮推翻了「JSON-LD 不是正文的逐字副本」这条结论**：那一轮抽的是「把被删正文短语回扫问答」，
  样本来自段落级改写，所以只命中一处自写的分号，`devops/gitops` 那次同步（正文 `调和与漂移` vs 问答 `调和和漂移`）
  也确实按短语 grep 整页解决。**但另有两族逐字拷贝它没扫到**：17 页的问答整块 = 正文 `<li>` 卖点列表，
  30 页 32 条答案里留着正文早已清掉的 `换句话说 / 也就是说 / 本质上`。
  判据随之换掉：不靠人工拿短语回扫，改成**同一份词表也吃这一面**（`outside_para_text()` + `OUTSIDE_RULES`），
  派生关系由《问答结构化数据》后三支盯。原那条「改正文短语时用该短语 grep 整页而不只 grep `<p>`」仍然有效，
  只是不再够用。
- **自指残留要先疑自己的 grep**：我在 JSON-LD 里扫出 11 处「全文/本节/本文」，逐条读完全是
  `全文检索`、`本节点`、`版本文件`、`文本节点`；`lint.py` 的《自指主语》真规则对这 8 句全部不报。
  裸子串扫描不能当门用，也不能当损失证据用。
- **第二十一轮：报表里的「N/N 清零」只等于「N 页被读过」，N 是几没人核对过**。`lint.py --full` 自己
  重抄了一遍遍历，用 `any(x in dp for x in WALK_SKIP_DIRS)` 判目录——子串把 `frontend/nextjs`（整组 5 页）、
  `nestjs`、`babylonjs / chartjs / threejs` 当成 `js` 目录，`vendor-lockin` 当成 `vendor` 目录剪掉了，
  9 页从没被这一面读过，报表照样打「327/327」。现在 `--full` 和 `C.all_pages()` 用同一种整段剪枝，
  口径是 337 页。**推论：报数之前先问这一页在不在扫描集里**，判据用 `--json` 出来的页名列表，不要用总数。
- **第二十一轮把「导航」划到改写队列外面**。列表区、面包屑、导航栏、categories 汇总页的篇数都由
  `gen_categories.py` 从目录派生：加一篇文章只跑脚本，不要手改 HTML 的列表区（改了下次跑脚本会被覆盖），
  也不要把它当段落损失登记——它不在 `plan.py` 的队列里。这类改动撞的是 `verify.py` 第 3、5 条
  （数字与 href 多重集），登记在 `scripts/deai/nav-edits.json`，逐页「整块旧文本 → 整块新文本」，
  块外一个字变了就判红；和 `table-edits.json` 一样，一进 HEAD 整表要清。
- **第二十一轮：派生副本撞门时先问「这一整块该不该由登记来救」**。`BreadcrumbList` 改成从可见面包屑派生之后，
  135 页的手写旧副本带着对不上的组名（「gRPC 2026」这类年份尾巴只活在那份副本里），第 14 条逐页判红。
  逐页登记整块 LD 也能绿，但那等于把这一面从此交给登记表兜。**改法是让校验按派生规则重算基线**
  （`verify.py` 的 `normalize_breadcrumb_ld`，派生函数直接 import 生成器那一份，站内只允许一处实现），
  只重算基线、不重算现文件——现文件那一段归 `gen_categories.py --dry` 的《复核》管。
  放宽拿 `_drafts/mutate_round21_tmp.py` 咬住：只改副本或只改可见那条 → 复核报不一致而 verify 不判红
  （第 14 条要的是「整页找得回来」，数字还在可见那一条里就不算丢），两处一起改又不登记 → 判红。
- **别人的提交会改变门的口径，报表数字要注明基线是哪一次提交**。本轮跑到一半有人 `git commit` 了 65 个文件，
  `verify.py --all` 的校验集从 31 页跳到 237 页，三条表格例外和一条标题例外因为「基线两边都是新文本」被判红——
  那是设计好的失效信号，核对基线之后删表就完事，不要为了让它不报去放宽载入逻辑。
  删完的代价只有一条，写在门里：拿 `_drafts/deai-snapshot/` 复查时那几页要重新登记旧文本。
- **第二十一轮：面包屑末格重名 = 抄错**。整站 335 页只有 2 个末格标签被两页共用，逐条读全是张冠李戴
  （讲自托管取舍的格子写着「代码托管平台」）。这是廉价可触发的判据，比「末格等于标题」靠谱——
  站上 298 页的末格本来就叫得比标题短。
- **第二十二轮：登记表会哑，只有在校验集里才响**。`verify.py` 的校验集原本就是「本轮有差异的文件」，
  于是登记一进 HEAD，那一页就永远不再被读——三条表格登记正是这么消失一整轮的，而且退出码照样 0。
  现在校验集 = 本轮改动 ∪ 三张登记表的页，多出来的照跑并打一行提示。**推论：任何「例外/登记」机制
  都必须自带覆盖面，不然它只是在没人注意的时候静默**。种一条两头都不在盘上的登记，当场报「基线找不到旧文本」。
- **第二十二轮：一份事实有两处拷贝时，先问哪一处该由派生得到，再问要不要登记**。
  `BreadcrumbList` 补齐 100 页一条登记都没写（比对前把基线那段按可见面包屑重算），
  同一轮改导航名的 12 处却必须逐页登记——因为 `related-card` 的锚文本是手写的，没有任何一处能派生它。
  判据是「有没有一个地方能算出这块内容」：有就改成派生，没有才登记。**登记是兜，不是豁免**，
  块外一个字变了照样判红。
  （**这一句的后半段第二十三轮作废**：侧栏「同组阅读」和上下篇标题不是「派生不出来」，
  是当时还没有派生规则。给它们定出「一个页面一个短名 = 可见面包屑末格」这条口径之后，
  三面全部改成从末格派生，911 处漂移一个字都不用手登记，见下面第二十三轮那几条。）
- **第二十二轮：mtime 不是「最后修改时间」**。`gen_feed.py` 用 `os.path.getmtime`，`git checkout`、拷贝、
  编辑器保存都会把它刷成今天，本轮碰过 111 页就等于对订阅端宣布「全站今天又更新了」。改成一次
  `git log --name-only` 扫出每页的首次/最后一次提交日。**代价要说明**：没提交的改动在这套口径下报不出来，
  所以「跑生成器」这一步排在提交之后；没提交记录的页直接报错停住，不拿今天兜过去——报错比撒利好。
- **第二十二轮：归一化没做对，命中数就是假的**。我拿「锚文本 vs 目标页末格」做全站的第二次比对，
  第一版只认 href 里显式写了 `index.html` 的，把站内最常见的 `../claude-code/` 这种目录式写法直接判成
  「对不上号，跳过」——1992 个锚点里 1599 个没进比对集，报出来的数是 44 + 7 处，真数是 608 + 83。
  这跟「裸子串扫描不能当门」是同一族：**没跳过的样本才算数**，所以任何「N 处不一致」之前要先印
  「可比对 / 总数」两个数，比值不对就是比对本身坏了。发现方式是第二次比对换了写法，两份数对不上才暴露。
- **第二十二轮：找一个族的毛病，判据要写成这一族的形状而不是第一个样本的样子**。年份尾巴我按 `(19|20)\d{2}`
  找，找到 5 处就收工；同一族的版本号尾巴（`Homebrew 6.0`、`Next.js 15`、`Gin 1.12`）一个都没扫到，
  因为那是「末格里有数字」这个更宽的判据。正确的第一问是「这一格里有多少种尾巴」，
  先称全族（335 格里 19 格带数字），再决定这一轮清哪几格。

- **第二十三轮：锚文本出现的次数不是改名的理由**。一个 hub 的「同组阅读」列表会在每个兄弟页各复制一遍，
  所以同一个错名常常 `×15`，而对的名字只写在一页的面包屑末格里。派给 agent 的定名规则里如果只写
  「统一到站内用得最多的那种叫法」，它就把 15 票投给拷贝、把 1 票投给真身，本轮 93 行里有 15 行是这种错，
  全部打回。**改名的依据只能是这一页自己的 `h1` / `title`**，锚文本次数只用来发现「有漂移」这件事本身。
- **第二十三轮：打回也要门化**。打回表（agent 说改名、我判保留）如果只凭我一句话，就等于给「把旧名塞回去」
  开了一道没有判据的后门。所以校验器加了一条：只有**现末格本身没有硬缺陷**（不带 `…`、不带年份版本号、
  括号不半截、长度合格）才允许打回；带硬缺陷的末格谁也不能判「保留」，本轮 15 条打回全部走得通这一条。
- **第二十三轮：第三面派生拷贝是面包屑里带 `href` 的上级格**。它容易被漏是因为它长得像「本页的一部分」，
  实际内容是**另一页**的末格。本轮一开始只打算管侧栏和上下篇两面，`architecture/distributed`
  那条「…CAP、Raft、2PC 与柔性事务」在 220 处上级格里漂着，一处都没被读过——它是比对时数出来的，不是想到的。
  判据是这一格有没有 `href`：有就属于被指向那一页，本页无权决定它写什么。
- **第二十三轮：登记判据要收到最窄，还要实测最窄那一条是不是多余的**。本轮 28 个改名里只有 9 页需要登记
  （末格字符串自己带走数字，第 3 条不变量必报）；第 10 页 `stateful-game-server` 的整块面包屑里也掉了
  一个 `2`，但那来自上级格——`normalize_nav_anchors()` 会按基线末格把基线那一侧重算，数字跟着走，登记它
  等于白存一份拷贝。**去掉之后单页校验仍 0 失败**，这才敢写「多余」。凡是「看起来必须登记」的条目，
  先删掉跑一次门，红了才叫必要。
- **第二十三轮：报告类门必须有退出码**。`gen_categories.py --dry` 把不一致打印出来、然后退出码 0，
  这一面在流水线里等于没有门——那 911 处漂移就是这么活了很久。现在凡是 `problems`
  非空一律 `sys.exit(1)`，而「这一组没有可列的页」那类空分类归 `skips`，只报不判红：
  那是配置口径，不是缺陷，混进 `problems` 就成了下一轮豁免整类报警的理由。
- **第二十三轮：登记表的两条失效分支各要各的正例**。`apply_known_edits` 有两条红：
  「基线已含新文本」和「基线找不到旧文本」。上一轮只种过后者，本轮正是前者才让人看见
  第二十二轮那 12 条已经全进 HEAD、整张表在哑着跑。同一个函数里的兄弟分支会互相打掩护，
  变异检查要按分支断言报出来的**那句原话**，不能只断言「红了」。
  「一进 HEAD 整表要清」是这条门的固定代价，不是缺陷。
  清空前逐条对 HEAD 复核过：第二十二轮那 11 页 / 12 条全部是「旧文不在 HEAD、新文在 HEAD」，12/12 过期，
  表清空、内容归档在 `_drafts/nav-edits-expired-20261102.json`（和金句框那批同一个口径）。

- **第二十四轮：拷贝的份数只有改完一份才知道有几份**。页头那个分类名我按 `article:section` 改成派生之后，
  顺手对了一下「meta 和 JSON-LD 都挂的 204 页里两面同名的有几页」——**56 页**。
  第七面 `articleSection`（驼峰键那份）就是这么露出来的，219 页挂着、157 页过期，比 meta 那份旧一整代。
  所以凡是把某一面改成派生，接下来一步是**按键名把同族写法全站点一遍**（冒号 / 驼峰 / `name=` / `property=`），
  不是看到一面改完就收工。
- **第二十四轮：两份手抄会分叉，问「哪一份是真的」没有答案**。meta 只漂 6 页、LD 漂 157 页，
  差别不是谁抄错了，是历史上改分类名时只同步了一半。要有的是**一个源头**（`CATEGORIES[目录]['name']`），
  两面都从它派生；写口径时明确「不存在哪一份才是真的」，否则下一轮又会挑一份当基线。
- **第二十四轮：按属性定位之前先数两种写法各有几页**。`article:section` 站内 204 页写 `property=`、
  **18 页写 `name=`**；正则锁死一种，那 18 页就**永久静默**——它不会被判「写错」，只会看起来像「这一页没这一面」。
  这类洞和「裸子串扫描不能当门」「没跳过的样本才算数」同族：放掉的那一半不会报错。
  同一族里已经称到但本轮没动的：`gen_feed.py:84` 取 `article:tag` 锁 `property=`，19 页写 `name=`，
  这 19 页进 feed 时没有 `<category>`。
- **第二十四轮：盘上永远对 ≠ 口径一致**。列表区模板的「同组阅读」取长名（`page_title()`），
  排后面的 `sync_nav_labels()` 按末格擦回来，于是**读盘的比对永远看不见**这一处口径不一致；
  代价是「重建列表区」不再是不动点。修法两步：生成处就取对（模板直接用末格），
  再加一条门《重建内容复核》——拿**正要写的那份内容**去过复核，而不是写完了再回头看盘。
- **第二十四轮：没有退出码的那句话等于没说**（第二次执行）。上一轮是 911 处漂移打印着退出 0，
  这一轮是「列表区字节数变了」打印了好几轮没人当失败。凡是报告里出现「变了 / 不一致 / 跳过」，
  第一问是它进不进 `problems`、第二问是它有没有退出码。
- **第二十四轮：缺面 ≠ 漂移，也不逐页登记**。4 页整块 Open Graph 都没有、96 页没有文章类型 JSON-LD 块，
  「补」要连带 card / image / description / `datePublished`——那是加功能，不是去重。
  所以它们进 `absent` 只报总数，而**可选元数据**（`article:section` / `articleSection`，站内各 222 / 219 页）
  连总数都不报：报出来只是把「这一页没写」登记 100 多遍，而本轮的原则就是不登记、只派生。
- **第二十四轮：`--snapshot` 口径的红不等于本轮开的洞**。同一批页拿 HEAD 当基线 313 个文件 0 失败，
  拿 `_drafts/deai-snapshot/` 复跑 80 页红，全是本轮之前的存量。这种时候**报告，不动手**：
  重做快照等于毁掉 campaign 起点的 oracle，那是比「门红着」更贵的操作。

- **第二十五轮：零漂移的那两面，写完门必须各撞一次**。描述这一族三份拷贝里，`og:description`（332 页）与
  `twitter:description`（331 页）跟 meta **一字不差**，只有 JSON-LD 那份 44 页是另一段话。正因为那两面零漂移，
  「复核报了哪一面」这件事从来没被撞过——门可能写成了只对 LD 生效。所以 D12 / D13 / D14 逐面只篡改那一份拷贝，
  断言报的面名**恰好只有它**（兄弟面不能替它背）且能字节还原。零漂移是「还没被撞过」的别名，不是「不用测」。
- **第二十五轮：把缺面按块合并，是往判据里缩**（中途称出三个块的缺面集合完全重合，就改成「一个块只报一个代表面」，
  报数当场 109 → 105，看起来像好消息）。实际是「某一面单独缺」从此永远看不见：谁删掉一个 `og:description` 标签，
  报告上什么也不发生。已回退逐面报。**唯一保留的一处合并必须实测同因**：LD `description` 与 `headline` 都由
  「这一页有没有文章类型块」决定，且称出「块在、键不在」是 0 页——报两遍只是把 96 页数两次。
  「今天几面重合」不等于「永远重合」，省下的是行数，赔掉的是覆盖面，不换。
- **第二十五轮：两种「没有」不是一种东西，各要一条用例**。「整块没做」= 只报不判红（D15b / D15c / D15d，
  guangdong 六面全报）；「块在、键不在」= **判红**（D15e，删掉那一行必须红，且变异后的块仍是合法 JSON——
  不然测的是「JSON 坏了」那条支路）。混成一种，下一轮就会拿「反正都只报」去放宽判红那一支。
- **第二十五轮：单位在写的时候就要点名，「处」不是「页」**。缺面 118 **处**、按页去重 97 页，一页最多贡献六处，
  所以 `336 − 118` 这种减法会把同一页扣六遍。同理：`gen_feed.py` 那三行打印把 `len(rss)` 标成 bytes，
  README 就记成了字符数——`feed.xml` 22,118 字符 / **29,310 字节**（CJK 比值 1.33），`sitemap.xml` 全 ASCII
  才两个数相同。**工具自报的体量先问它是 char 还是 byte，要量的话量文件**（`stat`）。
- **第二十五轮（#63）：锁死一种属性写法的另一半不会报错，它只是不出现**。第二十四轮已经称过
  `article:section` 204 : 18，本轮才去数 `article:tag`：**195 : 19**。`gen_feed.py` 的四条 meta 正则各锁一种，
  那 19 页进 feed 就**没有** `<category>`，页面本身什么问题都看不出来，全站所有门照绿。
  修法是**统一成一份读者**（`gen_categories.meta_content(html, key)`，`property=` / `name=` 都认、属性顺序不看），
  `gen_feed` / `gen_search_index` / `page_title()` 都调它——不是给每条正则各加个 `|`。
  但**校验侧（`scripts/shrink/`）不引入这份 reader**：它必须保持独立，否则就是「生成器自己判自己过」；
  独立不等于锁拼法，它那几条正则照样放开。
  属性顺序这支仍然锁死，因为称过：8802 个带 `property`/`name` 的 `<meta>` 里 `content=` 写在最前面的 **0 个**
  ——放开一个维度之前先量这一维的暴露面，量到 0 就不写，写进注释免得下一轮再猜。

- **第二十六轮：报告的第一次读数就可能是一次修复的开工单，而修复会改写读数**。那一版打印的是

- **第二十八轮：报告不是一次性的开工单，第二次读数仍要逐条看**。删完 7 页后，剩下的裸值里还有
  `categories`、`tags`、`其他` 这种一眼假的值：`categories/` 与 `tags/` 是目录页、写着目录名，

- **第二十七轮：同一条口径写在两个函数里，改一个就会忘另一个**。`heading_texts()` 第二十四轮已收到

  收尾正则会不会误配（4231 个标题开闭不配对 0 个，才敢用反引用 `</h\1>`）。
  `heading` 只进报告、不进任何门，所以改完要把「门全部重跑、红绿一位没动」也写出来。
- **第三十轮：同一件事的两份声明要互相校验，光有词表门不够**。`og:type` 与 JSON-LD 的 `@type`
  说的是同一件事，但各归各的门：`@type` 只被词表门问「是不是允许的类型，是就放行」，`og:type`
  根本不在第 14 条的射程里（那条只数字与行内 code）——两页写反成 `CollectionPage` + `article`
  谁也不报，任何页面 gate 都看不见。补门时把三种形状分开：值对不上判红、块在面不在判红
  （与「块在、`description` 键不在」同口径）、没有页面类型块的页**不进这一项**（缺声明不是漂移，
  判红等于逼人补整块结构化数据）。变异必须双向各钉一次——只钉 `BlogPosting` 那一侧，

- **跑门先分「基线漂移」和「内容回归」**。工作区可能带着别人未提交的改动（本轮：325 页只差
  `style.min.css?v=4→v=6` 一行，9 页删了「共 N 篇」的派生数字）。拿 HEAD 当基线，前者让全站
  href 多重集必红、后者被第 3 条判「数字丢失」，但都不是本轮的回归。正确做法是**不动校验口径**
  （尤其不给 `?v=` 开整类豁免），另建一份「HEAD 副本 + 同样的缓存号」当临时基线跑
  `verify --snapshot`，让本轮改动单独见红绿；其余改不掉的存量如实报出来，留给提交后基线跟上。
- **手改页面删掉的东西，模板必须同轮跟着删**。提交 `46955667` 直接改 HTML 去掉了 9 页的
  「共 N 篇」，生成器模板还在输出它；下一轮第一次跑生成器就把数字写了回去，`verify` 第 3 条
  在 8 页上报「新增 N 项」才发现。派生数字的每一次「删」，都要在生成器里找到出处一起改，
  否则页面和模板各说各的，下一轮生成器会把它恢复成「正确」状态。
- **页面里嵌的派生时间不能直接抄「最后提交日」**。写进去再提交，这一页的最后提交日就变成提交日，
  页面里还是写盘日，下一轮又判过期——改一次、红一次，永远追不上。判「这一轮工作区改过 = 今天改的」
  才能在提交当天形成不动点（干净时退回最后提交日）；`git diff HEAD` 的脏页集合要在写盘之后
  **失效重算**，否则同一次运行里的《复核》会拿写盘前的脏页表判刚写好的页。新页没有提交记录时
  记进跳过名单，不要退回今天，也不要中断整轮。
- **跨页一模一样的 `meta keywords` 是「一页写、全站抄」，不是模板**。第三十二轮称出 52 页共用
  16 个词、media 7 页共用一串，和本页内容无关。这类词表按页写（从标题与描述取），不要从
  `article:tag` 派生——那一面还留着改名前的旧分类名。新门 `check_keywords()` 只判整条列表
  完全相同，共用尾部「技术博客,踩坑」不算重复。
- **`lint` 的《页内 id 重复》只数会进 DOM 的标记**：`<pre>`、行内 `<code>`、HTML 注释里的
  `id="x"` 都不算。改重复 id 前先确认页内没有 `href="#那个id"`；没有就按标题语义改名，
  不要删锚点。
- **变异用例改了旧页，modified 面就会按定点规则变成今天**。用例若不先把两个 modified 面
  对齐今天，`verify` 会报「丢失的数字 07」、`--dry` 会多报日期面——那是第三十一轮的规则在
  正常工作，不要把这条红当成 verify 的误报去改门。
- **分类改过一次名，就要在站内把所有「名字面」扫一遍**。第三十三轮的侧栏标题就是漏掉的那一面：
  207 张卡片里 119 张写着与自己所列页面不同的名字，52 张是退役名。名字面至少五处——面包屑末格、
  导航锚文本、`article:section` / `og:site_name`、🏷️ chip、`article:tag`，还有「同组阅读 · X」的 X。
- **`同组阅读 · X` 的 X 说的是卡片列的那批页，不是本页**。全在本二级组→组主页末格，
  列到别处→本页一级分类名；取末格不取 h1（长名进不了侧栏）。这种「跟着内容走」的规则
  比逐页登记强：退役名、垃圾词、手抄变体一次全覆盖。派生面一旦成立，`verify` 第 7 条
  《标题文本》要把它和 `group-section-name` 一起两侧摘掉，正确性交给生成器的退出码，
  不要重切基线快照，也不要把 119 对现值存进登记表。
- **退役分类名不要改写成现行分类名**。`article:section` 从第二十四轮起就是现行分类名的派生拷贝，
  再往 `article:tag` 写一遍是同一件事两份；那一面本来就是关键词表，整行删掉才对。
- **统计口径不能把「没比对」算成「一致」**。「一致 207 / 有卡片 207」与「1 张比对不上手」同时成立
  就是在说谎；只数真比对过的，剩下的单独报（第二十二轮同一个坑：只报不吻合数不说可比对数）。
- **新的派生面要一起扩进《重建内容复核》**。列表区模板和排在其后的 sync 是同一面的两处口径，
  sync 会把模板写错的擦干净，盘上比对永远看不见；只有拿「正要写的那份内容」去比才露馅。
- **`FAQPage` 不是词表的盲区**：第十九轮的 `outside_para_text()` 已把问答喂进六条词表硬项。
  要测「问答是否与正文重复」，**先剥 `<script>` / `<style>` 再比**，否则每条答案都在自己那段
  JSON-LD 里和自己重合（本轮第一次数出 1805/1806「重复」就是这个错，真数是 0）。
  问答唯一没被管的是《超长段落》，那是有意的：答案本该是完整段落。
- **`sitemap` / `feed` 的 lastmod 只有提交之后重跑 `gen_feed.py` 才和页面一致**。页面里
  `article:modified_time` 在工作区脏时写今天，产物永远取 git 最后提交日；差一天就少一天抓取。

## 自检（写完输出文件后必须跑，退出码 0 才算完成）

```bash
cd /Users/junjunyi/src-code/deep2code.github.io && python3 scripts/deai/from_jsonl.py batch-<NN>
```

它会先检查条数齐不齐（缺哪几条会点名 file 和 start），再生成 batch-<NN>.json 并跑
`scripts/shrink/check_out.py`（逐段 ≤65 字、压缩达标、数字/code/链接不变、无空段、无非法 `<p>`、
每段句末有标点）。

`check_out.py` 里两类中文数字提示的处理方式不同：

- `中文数字新增`（如原文没有数量，你写成「三个阶段」）是**硬失败**，删掉你数出来的那个数。
- `[待核中文数字]`（如原文「一个」没了）是提示，逐条自己判：属于被拆掉的骨架
  （`先纠正一个流传很广的说法`、`搞清这两个维度`）可以不管；来自「」里那个实际问题的
  （`只加了一个字段，调用量翻十倍`）必须把原词补回来。
