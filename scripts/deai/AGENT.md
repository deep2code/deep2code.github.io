# 去 AI 味改写 Agent 作业说明（阶段 B）

你负责一批 HTML 文章页的**正文段落改写**：去掉 AI 腔的模板句和修辞转弯，把段落压短压直。

只改 `<p>` 里的文字。结构、标题、表格、代码、链接一律不动——那些已由脚本处理完。

规则原文见 `zh-blog-lint/去AI味改写规范.md`，本文件是执行清单。

**你的输入由 `why` 字段说明这段为什么被选中**：`预告句式` / `套话转弯` / `顺序词` /
`超长段落` / `段落内 emoji` / `自指叙述` / `自指主语` 是门判出来的；`全文改写` 是全站普压批（阶段 B2），
这段没触门、只是超过 60 字，你的任务纯是压字数 + 顺手去掉下面七类句式。
一段同时带两个原因时（`自指叙述+全文改写`）两件都要解决。
不在你输入里的段落不要改。

## 干活节奏（一次别吞太多）

**不要写脚本代替改写。** 压缩是逐段的语言判断，正则和模板生成出来的句子过不了字数门也过不了
人工复核（真有过一个 agent 花二十分钟在 `/tmp` 搭「改写引擎」，一份交付都没落下）。
脚本只用来切片读输入和跑自检，句子必须你自己一段一段写进 JSONL。

一批最多 45 段。**每次只处理 10–15 段**：读这些段的 `html` → 改写 → 追加写 JSONL → 再读下一组。
用 `scripts/deai/plan.py` 生成的输入里 `items` 是数组，你可以用 Python 切片按序取，不必一次读全。

## 输入 / 输出

- 输入：`_drafts/deai-in/batch-<NN>.json`（路径由调用方给出），每个 item 是一段 `<p>` 的 inner HTML，
  带 `start` / `end` / `sha1` / `cjk` / `heading` / `prev` / `next`。
- **你只写 JSONL**：`_drafts/deai-out/batch-<NN>.jsonl`，每行一个对象，只带两个字段：
  ```
  {"start": 12345, "new_html": "改写后的段落 inner HTML"}
  {"file": "a/b/index.html", "desc": "该页新的 meta description"}
  ```
  `file` / `end` / `sha1` 由 `scripts/deai/from_jsonl.py` 从输入批次回填，你不要抄，也不要自己算偏移。
  一个 `start` 一行，描述行每个文件一条。
- **必须用 `cat >> ... <<'JSONL'` 或 Python 追加的方式分多次写**，每次 10–20 条。
  不要试图在一次工具调用里输出整批；也不要只写前几条就回报完成。
- 写完跑转换 + 校验（一次跑完会同时报缺哪几条）：
  ```bash
  cd /Users/junjunyi/src-code/deep2code.github.io && python3 scripts/deai/from_jsonl.py batch-<NN>
  ```
  它退出码 0 才算交付；退出码非 0 会打印「还差 N 条，例如 file=… start=…」，补齐再跑。
- **退出码 0 之后立刻打交付标记**：`touch _drafts/deai-out/batch-<NN>.done`。
  `land.py` 只落带 `.done` 的批次。打完标就不再改 `.jsonl`——落盘是按当时那一版做的，
  之后再改的内容补不回来（apply 的 sha1 守卫挡住二次回填）。
- 只写你自己那一个 `.jsonl`，不要碰站内任何 `.html`，不要改 `_drafts/deai-in/` 下的输入文件。

## 必须改掉的（这些会被 scripts/deai/lint.py 逐页判失败）

1. **每节开头的"能解决什么"预告句**
   `搞清这一节，能解决「内存涨了十倍」……` → 删掉整句，段落直接从事实开始讲。
   如果整段只有这句，把下一段的事实提前，本段输出一个最短的直接陈述句（不能输出空）。
2. **修辞转弯**：`好消息是 / 坏消息是 / 雪上加霜的是 / 更麻烦的是 / 反直觉的结论是 /
   先纠正一个流传很广的说法 / 另一个常见误解是 / 一句话说清 / 先说结论 / 值得注意的是 /
   需要说明的是 / 换句话说 / 也就是说 / 事实上 / 本质上 / 核心在于 / 关键在于 / 这才是 / 这就是为什么`
   → 转弯删掉，结论留下。
   **路线图句同属此类**：`本篇按落地顺序讲清：A、B、C` `这篇会依次回答` → 直接把 A、B、C 当正文讲，
   别留「本篇按…讲」这层壳。这类形状多数也会被《自指叙述》判出来，两条规则命中同一段时按这条改。
3. **顺序词**：`首先……其次……最后……` → 直接按因果写，或分点。
   删序号要整组删：只删掉「第一，」会留下悬空的「第二，」。同组序号在 `prev`/`next` 里能看到，
   改某一段时确认它的邻居段；要么整组去掉序号，要么一个都不动。
   保留序号时写法要和邻居一致：别把「第一，」写成「一，」而邻居两段仍是「第二，」「第三，」。
   `一是…二是…` 同规则，且**门的中文数字检查看不见它**（正则匹配数字+量词，不匹配「一是」）。
   另一 half 在本批相邻段时，两半都要处理；只剩自己这半被改，邻居会留下没有前件的「二是」。
   拆掉并列后，段末那枚暗示「后面还有半句」的 `；` 要收成 `。`。
4. **假精确**：没有条件、没有出处的百分比（`线上 90% 的偶发故障`）改成定性说法。
   **但注意**：数字是硬校验项，`90%` 这种 token 你不能删（见下面的硬约束），
   遇到必须保留数字的假精确句，把它改写成一个明确的条件句（`三项没配对时最常见的三种现象`），
   数字仍留在原位；实在无法保留的，原样保留数字并在段末不加评论。
5. **超长段落**：每段（含拆出来的每一小段）≤65 个中文字。
   **段末标点**：每段（含每一小段）必须以 `。！？：；` 收尾，不能停在 `</code>`、`</a>`、
   引号或半句上；用 `</p>\n<p>` 拆段时，前一小段必须是一句完整的话，不许把一句话从逗号处劈开。
   原文本来就以 `、`/`，` 收尾的（站内有把一条枚举拆成两段的存量）照原样保留即可。
6. **段落里的 emoji**：`✅ ⚠️ 💡 🚀` 从句子中删掉，告警框本身不归你管。
7. **自指叙述**（`why` 里的 `自指叙述`）：主语是文章自己的句子——
   `这篇只讲 X` `本篇在路径里的位置是 Y` `这一节解释…` `这篇不讲 Redis 怎么实现，只讲一件事`。
   处理方式是把 X/Y 当正文直接讲，句子主语换成技术对象：
   `这一节解释为什么五种位置要五种编码器` → `五种位置要五种编码器，因为 HTML、JS、URL、属性、CSS
   的解析规则各自独立`。`不适用边界：本篇只讲服务端渲染` → 直接写这条边界本身
   （`服务端渲染之外的场景不适用`），别留「本篇」两层皮。
   段首带冒号的 `搞清这一节能解决的现象是：` 已由脚本删过，你遇到的是形状不规则的其余部分。
8. **自指主语**（`why` 里的 `自指主语`）：`这篇 / 本篇 / 这一篇 / 本文 / 此文 / 该篇 / 这一节 / 本节`
   出现在正文段落里就判硬项，不再等动词。这条是阶段 B5 补的：`自指叙述` 只收动词锚定的形状，
   放过了 `这篇按三段组织` `本篇是这条路径的最后一环` `本文只在需要的地方指路` `这一节直接决定你的
   API 手感` 这类，全站 240 段。改法同上——主语换成技术对象；换不动时用「这里」指代这一段在讲的
   东西（`本篇把范围收到「谁来创建」` → `这里把范围收到「谁来创建」`），别用「本文 / 本篇」兜底。
   后顾里排掉的假阳性：`脚本本文` `版本文档` `文本节点型`，这三处不是自指。
   前瞻还排掉 `本节点`（Redis 分片、K8s 节点篇里是术语）和 `本文件`（图源注释），共两处。
   口径：`C.blocks()` 只给正文 `<p>`（`SKIP_TAGS/SKIP_CLASSES` 有意跳过 table、pre、mermaid、callout、
   cluster-nav），所以 B5 之前这两条规则只查段落；阶段 B6 把它们改成查整页正文区，段落之外又清掉
   41 处（表格单元格 21、提示框标题与强调 10、表头 4、小标题 1、mermaid 标签 4、路径导航 1）。
   唯一保留的豁免是 `<pre>`：代码块受 `scripts/shrink/verify.py` 的「代码块与基线全等」保护，改不动，
   所以两条规则先 `strip_pre()` 再匹配，3 页 4 条残留登记在 `lint.PRE_EXEMPT` 里。
   `--self-test` 对这两条各植入一条表格样本（证明口径不再限于段落）、一条 `<pre>` 负例（证明豁免生效），
   并逐条核对 `PRE_EXEMPT` 的句子还在、还在 `<pre>` 里——登记失效或句子跑到正文都会让自检变红。

## 压缩口径

- **整批硬门：本批所有段合计 ≤ 原字数 × 0.78**（`check_out.py` 按整批总量判）。
  每条单独压到 0.82 也会被打回——一段平均要压到 76% 才有余量，先按这个尺度下刀再逐条回补。
- 每条 item 改写后中文字数 ≤ 原 `cjk` × 0.82（`cjk` ≥ 30 的条目）。
- `cjk` 在 15–29 的：至少删 3 个字，或换成更直白的短句。
- 手段按顺序用：删铺垫 → 删与 `prev`/`next` 重复的过渡 → 删举例枝节（例子里的数字与结论必须留）
  → 长句拆短 → 仍超长就用 `</p>\n<p>` 拆段（不加外层 `<p>`）。
- `prev`/`next` 只用来判断邻居的序号配对和重复，**不能把 `next` 的句子搬进本段**——那样同一条事实会在
  两页段落里出现两遍，而门只核对字数，看不出重复。
- 删掉框架句后不留光杆词当段首：`几个容易忽略的细节：` 压成 `细节：` 是错的，直接从事实起句
  （`回填要分批并控制事务：…`）。
- 平均每句 15–25 字，单句不超过 35 字。
- `——` 每页不超过 5 处：能用逗号或另起一句的就改掉。
- `「」` 只用于错误信息原文、要引用的现象、配置字面值；比喻名不用引号。

## 语气

读者是维护过生产服务的后端工程师。像同事当面讲一件事：先说结论，再说条件和代价。
不用「我们」「笔者」，不用「轻松掌握」「强大」「无缝」，不加感叹号。

## 硬约束（违反会被 check_out.py 打回）

- **数字与单位一个都不能丢、不能改、不能新增**：`30 秒`、`p99`、`2.25 版本`、`4MB`、
  `2 到 3 倍`、`① ② ③` 全部原样。禁止把阿拉伯数字写成中文数字，也禁止反向。
- **引号「」里的数量是事实，不是套话**。这类段落的骨架是
  `搞清这一节，能解决「只加了一个字段，下游调用量就翻了十倍」`，要拆掉的是
  「搞清这一节能解决」这七个字，**引号里的 `一个` `十倍` `一倍` `三个` `几天` `一次` 必须
  原词搬进改写后的句子**：`每个字段都挂 resolver，加一个字段下游调用量翻十倍`。
  只有属于骨架自身的数量（`先纠正一个流传很广的说法` 里的 `一个`）才可以删。
- **不许新增原文没有的中文数字**，包括你自己数出来的 `两个字段` `三条路` `十二个维度`——
  原文没写数量就别说数量。
- `<code>…</code>` 内容、`<strong>` 强调位置、`<a href>`、`<img>`、HTML 实体
  （`&lt; &gt; &amp; &quot;`）原样保留。拆段时行内标签各自闭合，不许跨段断开。
- 不动结构：标题、表格、`<pre>`、mermaid、列表都不在你的输入里。
- 术语沿用原文写法，不换同义词；英文术语、命令、API 名保持原样。
- 技术事实、阈值、判据、失效条件一条都不能少。宁可少压几字，不能丢信息。
- 条件词（`必须` `只有` `才` `否则` `至少` `以内`）可以换同义写法（必须→要、不能→无法），
  不能整组删掉。调用方会用 `review.py` 的 `▲` 逐条问回来，自己先按同一标准过一遍。
- **标识词不能只靠回指活着**：行内代码外的英文术语、锁模式、计划节点名（`ACCESS EXCLUSIVE`
  `Bitmap Heap Scan` `visibility map`）如果压成「这把锁」「这种方式」，只有紧邻上一段（`prev`）
  里原词还在才允许，否则原词必须留在本段。调用方用 `review.py` 的 `■` 按整页核：
  一个词从这一页彻底消失就报，删自指指针（`详见站内 DDD 那篇`）顺带带走术语是唯一的合法情形。

## 队列覆盖面：加硬项之后必须重排

`_drafts/deai-in/` 里的批次是 **`plan.py` 那一刻按当时的规则表算出来的**。往 `lint.py` 新增
一条 `PARA_RULES` 硬项（`自指叙述` 就是这么加的）之后，已生成的队列并不认识它：短段（< `--min`
汉字）只有「触门」才会被排进来，于是这类段全成盲区——表现为队列跑干净了、`land.py` 每页都报
「硬项 → 0」，但全站 `lint.py` 退出码仍是 1。

收尾口径：一波跑完后必须复跑 `python3 scripts/deai/lint.py`，退出码非 0 就用同一判据把残留段排出来

```bash
python3 scripts/deai/plan.py --flagged --min 20   # 只排触门段；跑之前确认 deai-in/ 无在途批次
```

（`plan.py` 会清空并重建 `deai-in/` 与 `deai-plan.json`，落盘过的输入在 `deai-in-landed/`，
重排前先把上一份 plan 备份，别拿新队列去对旧批次号。）
残留只有个位数段、且改法是同一种句式替换时，可以不走工人：按段做一次唯一子串替换，逐段自检
「改后不触门 + `code`/`href`/数字多集合不变 + 汉字数不增」，全绿才写文件，改完复跑
`lint.py`、`check_pairs.py` 和 `python3 gen_search_index.py`。

阶段 B5 的实战记录：`自指叙述` 的盲区是 240 段（159 页，净减 593 汉字），按目录切成 5 轮
阶段 B6 的实战记录：段落之外还有 45 处自指（26 页），`C.blocks()` 一条都看不见，是拿
`lint.SELF_WORDS` 直接扫整页 HTML 得到的。这一批第一次动了 `verify.py` 保护的三类元素，5 个文件判红：
代码块注释 4 处、h2 标题 1 个、mermaid 标签 4 个。处理是分开的——代码块的不变量原样保留，4 条注释
回滚并在 lint 里跳过 `<pre>`；标题与图是渲染出来给读者看的文字，2 页 5 对以「基线片段 → 现文本片段」
登记进 `verify.KNOWN_TEXT_EDITS`，命中才放行、登记失效即判红，夹带任何别的改动也照样红（两条负例验过）。
教训是：一条规则改成整页口径之前，先数一遍会新增多少命中，以及它们落在哪些受保护的容器里。

`_drafts/deai-b5-work-<r>.txt` + `_drafts/deai-b5-patches-<r>.json`，用 `_drafts/apply_b5_tmp.py`
直改（`--dry` 先跑一遍看拒绝清单）。定位用段 `html` 的 sha1 前 12 位而不是偏移量——同一轮里
左侧段的偏移不会漂，跨轮重跑才会，key 不受影响；回滚记录在 `_drafts/deai-b5-journal.jsonl`。
切轮时前缀要覆盖全部簇：漏掉 `programming/algorithms`、`programming/design-patterns` 就多跑了
一轮。**新硬项落地顺序：先把残留改干净，再往 `lint.py` 加规则**，反过来会让门在收尾途中变红。

## 自检（写完输出文件后必须跑，退出码 0 才算完成）

```bash
cd /Users/junjunyi/src-code/deep2code.github.io && python3 scripts/deai/from_jsonl.py batch-<NN>
```

它会先检查条数齐不齐（缺哪几条会点名 file 和 start），再生成 batch-<NN>.json 并跑
`scripts/shrink/check_out.py`（逐段 ≤65 字、压缩达标、数字/code/链接不变、无空段、无非法 `<p>`、
每段句末有标点）。

`check_out.py` 里两类中文数字提示的处理方式不同：

- `中文数字新增`（如原文没有数量，你写成「三个阶段」）是**硬失败**，删掉你数出来的那个数。
- `[待核中文数字]`（如原文「一个」没了）是提示，逐条自己判：属于被拆掉的骨架
  （`先纠正一个流传很广的说法`、`搞清这两个维度`）可以不管；来自「」里那个实际问题的
  （`只加了一个字段，调用量翻十倍`）必须把原词补回来。

注意：本批改写还没落盘到 HTML，所以全站 `scripts/deai/lint.py` 现在仍会报这些页——那是存量，
不是你的漏改。你要保证的是 `from_jsonl.py` 退出码 0，且每个 `new_html` 里不再出现上面
「必须改掉的」六类句式。落盘后由调用方复跑 lint。
