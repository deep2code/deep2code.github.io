1. SQL 基础回顾

SQL (Structured Query Language) 是关系型数据库的标准查询语言。MySQL 并没有完全实现 ANSI SQL 标准，有自己的扩展和简化。

基本规则

  • 大小写不敏感，但约定：关键字、函数名用大写；表名、列名、参数用小写
  • 分号 ; 是语句结束符
  • 一行可以写多条语句，一条语句也可以跨多行
  • 默认 autocommit，除非显式关闭

SQL 标准及进化

SQL 作为关系型数据库的标准语言，经历了多个版本的演进：

MySQL 扩展：MySQL 在标准 SQL 基础上增加了许多特有功能：

  • REPLACE：插入或更新
  • INSERT ... ON DUPLICATE KEY UPDATE：冲突更新
  • INSERT IGNORE：忽略重复
  • GROUP_CONCAT：字符串聚合
  • EXPLAIN FORMAT=JSON：详细执行计划
  • SHOW 系列：查看状态信息

4. 基本操作

-- 查看数据库
SHOW DATABASES;
USE database_name;
SHOW TABLES;

-- 创建数据库
CREATE DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 创建表
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    age INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_name (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 插入数据
INSERT INTO users (name, email, age) VALUES 
    ('Alice', 'alice@example.com', 25),
    ('Bob', 'bob@example.com', 30);

-- 查询数据
SELECT * FROM users;
SELECT id, name, email FROM users WHERE age > 20 ORDER BY created_at DESC LIMIT 10;

-- 更新数据
UPDATE users SET age = 26 WHERE id = 1;

-- 删除数据
DELETE FROM users WHERE id = 1;

-- 聚合查询
SELECT 
    COUNT(*) as total,
    AVG(age) as avg_age,
    MAX(age) as max_age,
    MIN(age) as min_age
FROM users;

-- 分组查询
SELECT age, COUNT(*) as cnt FROM users GROUP BY age HAVING cnt > 1;

-- 关联查询
SELECT u.name, o.order_id, o.total
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.status = 'completed';

6. InnoDB 存储引擎

  • 事务支持：ACID 完整支持
  • 行级锁：支持高并发
  • MVCC：多版本并发控制
  • 外键约束：完整参照完整性
  • 崩溃恢复：自动恢复
-- 查看存储引擎
SHOW ENGINES;

-- 查看表引擎
SHOW TABLE STATUS LIKE 'users';

-- 设置存储引擎
CREATE TABLE t1 (id INT) ENGINE=InnoDB;
ALTER TABLE t1 ENGINE=InnoDB;

-- InnoDB 关键参数
-- my.cnf
[mysqld]
innodb_buffer_pool_size = 4G      # 缓冲池大小，通常为可用内存 70%
innodb_log_file_size = 1G         # Redo 日志大小
innodb_flush_log_at_trx_commit = 1  # 0/1/2，1 最安全
innodb_flush_method = O_DIRECT    # 跳过 OS 缓存
innodb_file_per_table = 1         # 每个表独立表空间

数据文件存储与结构

InnoDB 将数据持久化到磁盘文件，理解文件结构对性能调优和故障恢复至关重要。

文件目录结构

mysql_data_dir/
├── ibdata1              # 系统表空间（数据字典、undo log、change buffer）
├── ib_logfile0          # Redo Log 日志文件 1（循环写入）
├── ib_logfile1          # Redo Log 日志文件 2
├── undo_001             # Undo Log 表空间 1（MySQL 8.0 独立）
├── undo_002             # Undo Log 表空间 2
├── ibtmp1               # 临时表空间（排序、临时表）
├── mysql/               # 系统数据库（用户、权限等）
├── your_db/             # 业务数据库目录
│   ├── users.ibd        # 独立表空间文件（innodb_file_per_table=1）
│   └── orders.ibd
├── binlog.000001        # 二进制日志（主从复制、时间点恢复）
├── binlog.index         # binlog 索引文件
├── slow.log             # 慢查询日志
└── error.log            # 错误日志

页（Page）结构 — InnoDB 最小 I/O 单元

InnoDB 默认页大小 16KB，所有数据和索引都按页组织。

┌─────────────────────────────────────────┐
│  File Header (38 bytes)                 │  页类型、校验和、LSN
├─────────────────────────────────────────┤
│  Page Header (56 bytes)                 │  页状态、槽位数、记录数
├─────────────────────────────────────────┤
│  Infimum Record (虚拟最小记录)           │
├─────────────────────────────────────────┤
│  User Records (用户记录)                 │  ← 行数据按主键排序存储
│  ...                                     │
├─────────────────────────────────────────┤
│  Supremum Record (虚拟最大记录)          │
├─────────────────────────────────────────┤
│  Free Space (空闲空间)                    │
├─────────────────────────────────────────┤
│  Page Directory (页目录，槽位数组)        │  ← 二分查找加速
├─────────────────────────────────────────┤
│  File Trailer (8 bytes)                  │  校验和、LSN（检测损坏）
└─────────────────────────────────────────┘

B+ 树索引结构

InnoDB 使用 B+ 树作为索引结构，聚簇索引的叶子节点存储完整行数据。

                    [根节点: 页号]
                   /       |        \
              [内部节点] [内部节点] [内部节点]   ← 只存主键+页号
             /     \     /     \
        [叶子页] [叶子页] [叶子页] [叶子页]      ← 存完整行数据
        ←──── 双向链表连接 ────→               ← 范围扫描高效
  • 聚簇索引：叶子节点 = 完整行数据，按主键排序，一张表只有一个
  • 二级索引：叶子节点 = 索引列值 + 主键值，回表查询聚簇索引
  • 区（Extent）：64 个连续页 = 1MB，减少随机 I/O
  • 段（Segment）：多个区组成，分为数据段、索引段、回滚段

行格式（Row Format）

MySQL 8.0 默认使用 Dynamic 行格式，支持变长字段高效存储。

变长字段长度列表 | NULL 标志位 | 记录头信息(5字节) | 列1数据 | 列2数据 | ...
                                                                 │
                                              超过 768 字节的大字段
                                              只存 20 字节指针 + 外部页

Redo Log 与 Undo Log

  • Redo Log：物理日志，记录"页做了什么修改"，循环写入，用于崩溃恢复（WAL 预写日志）
  • Undo Log：逻辑日志，记录"修改前的数据"，用于事务回滚和 MVCC 一致性读
  • Binlog：逻辑日志，记录完整 SQL 语句，用于主从复制和时间点恢复

7. 索引（核心重点）

-- 创建索引
CREATE INDEX idx_name ON users(name);
CREATE UNIQUE INDEX idx_email ON users(email);
CREATE FULLTEXT INDEX idx_content ON articles(content);

-- 复合索引（最左前缀原则）
CREATE INDEX idx_age_name ON users(age, name);
-- 相当于 age, age+name, age+name+email

-- 查看索引
SHOW INDEX FROM users;
SHOW CREATE TABLE users;

-- 删除索引
DROP INDEX idx_name ON users;

-- 索引使用分析
EXPLAIN SELECT * FROM users WHERE name = 'Alice';
EXPLAIN ANALYZE SELECT * FROM users WHERE age > 25;

-- 强制使用索引
SELECT * FROM users FORCE INDEX (idx_name) WHERE name = 'Alice';

索引设计原则

  • 主键：自增 INT/BIGINT 或 UUID（考虑性能用自增）
  • WHERE 条件：高频条件字段建索引
  • 复合索引：遵循最左前缀原则
  • 避免过多：索引不是越多越好（写入开销）
  • 覆盖索引：优先覆盖查询字段

8. 事务

-- 开启事务
START TRANSACTION;

-- 或者
BEGIN;

-- 操作的么
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;

-- 提交
COMMIT;

-- 或者回滚
ROLLBACK;

-- 设置保存点
SAVEPOINT sp1;

-- 回滚到保存点
ROLLBACK TO SAVEPOINT sp1;

-- 事务特性（ACID）
-- Atomicity（原子性）：要么全部成功，要么全部失败
-- Consistency（一致性）：事务前后数据库状态一致
-- Isolation（隔离性）：并发事务相互隔离
-- Durability（持久性）：事务提交后数据持久保存

隔离级别

隔离级别脏读不可重复读幻读MySQL 默认
READ UNCOMMITTED✅ 可能✅ 可能✅ 可能-
READ COMMITTED❌ 不可能✅ 可能✅ 可能Oracle
REPEATABLE READ❌ 不可能❌ 不可能✅ 可能*MySQL
SERIALIZABLE❌ 不可能❌ 不可能❌ 不可能-
 
-- 查看隔离级别
SELECT @@transaction_isolation;

-- 设置隔离级别（会话级）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 设置隔离级别（全局级）
SET GLOBAL TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 2026 推荐：OLTP 场景用 READ COMMITTED，RR 容易产生间隙锁争用

10. 性能优化

-- 开启慢查询日志
SHOW VARIABLES LIKE 'slow_query_log';
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;
SET GLOBAL slow_query_log_file = '/var/log/mysql/slow.log';

-- 查看慢查询
SELECT * FROM mysql.slow_log ORDER BY start_time DESC LIMIT 10;

-- EXPLAIN 分析
EXPLAIN SELECT u.name, o.total 
FROM users u 
LEFT JOIN orders o ON u.id = o.user_id 
WHERE u.age > 25;

-- EXPLAIN ANALYZE（MySQL 8.0+）
EXPLAIN ANALYZE SELECT * FROM users WHERE age > 25;

-- 查看执行计划类型
-- type: const > eq_ref > ref > range > index > ALL
-- 最好达到 ref 或 range 级别

-- 优化 LIMIT 分页
-- 慢：SELECT * FROM users LIMIT 1000000, 10
-- 快：SELECT * FROM users WHERE id > 1000000 ORDER BY id LIMIT 10

-- 避免 SELECT *
SELECT id, name FROM users WHERE age > 25;

-- 使用 EXISTS 代替 IN
SELECT * FROM users u WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);

-- 批量插入优化
INSERT INTO users (name, age) VALUES 
    ('A', 20), ('B', 25), ('C', 30);
-- 每次 1000 条比每次 1 条快 10 倍+

11. 主从复制

-- 主库配置
[mysqld]
server-id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
binlog_row_image = FULL
sync_binlog = 1

-- 创建复制用户
CREATE USER 'repl'@'%' IDENTIFIED BY 'repl_password';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';

-- 查看主库状态
SHOW MASTER STATUS;
-- 记录 File: mysql-bin.000001, Position: 12345

-- 从库配置
[mysqld]
server-id = 2
relay_log = /var/log/mysql/mysql-relay-bin
read_only = 1
super_read_only = 1

-- 启动复制
CHANGE MASTER TO
    MASTER_HOST='master_host',
    MASTER_USER='repl',
    MASTER_PASSWORD='repl_password',
    MASTER_LOG_FILE='mysql-bin.000001',
    MASTER_LOG_POS=12345;

START SLAVE;

-- 查看复制状态
SHOW SLAVE STATUS\G
-- 关键: Slave_IO_Running, Slave_SQL_Running

17. MySQL 向量支持（9.0+）

-- MySQL 9.0+ 向量支持（实验性）
-- 创建向量表
CREATE TABLE documents (
    id INT AUTO_INCREMENT PRIMARY KEY,
    content TEXT,
    embedding VECTOR(768),  -- 768 维向量
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 创建向量索引（MySQL 9.0+）
CREATE VECTOR INDEX idx_embedding 
ON documents(embedding) 
USING IVFFLAT 
WITH (lists = 100);

-- 相似度搜索
SELECT id, content, 
    vector_distance(embedding, '[0.1, 0.2, ...]') AS distance
FROM documents
ORDER BY distance
LIMIT 5;

-- 兼容方案：使用 JSON 存储
CREATE TABLE documents_json (
    id INT AUTO_INCREMENT PRIMARY KEY,
    content TEXT,
    embedding JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 手动计算余弦相似度
SELECT 
    id,
    content,
    (SELECT SUM(a.val * b.val) 
     FROM JSON_EACH(embedding) a 
     JOIN JSON_EACH('[0.1, 0.2, ...]') b 
     ON JSON_EXTRACT(a.key, '$') = JSON_EXTRACT(b.key, '$')
    ) AS similarity
FROM documents_json
ORDER BY similarity DESC
LIMIT 5;

🏢 企业实践

18. OLTP 场景最佳实践

  • 主键设计：自增 BIGINT，性能最优
  • 索引策略：WHERE 条件字段加索引，复合索引最左前缀
  • 避免：SELECT *、函数计算、隐式转换
  • 写入：批量 INSERT，1000 条/批
  • 事务：小事务，减少锁持有时间

20. 分库分表

InnoDB 存储引擎架构深度解析

InnoDB 是 MySQL 默认的事务型存储引擎，其架构设计围绕事务安全、并发性能、崩溃恢复三大目标。理解 InnoDB 的内存结构和磁盘文件，是优化 MySQL 性能的基础。

内存结构

InnoDB 的内存分为三大区域：

  • Buffer Pool（缓冲池）：最大的内存区域，默认占物理内存的 50-75%。缓存数据页和索引页，采用 LRU 算法（改进的 Midpoint Insertion Strategy，防止全表扫描污染缓存）。包含数据页、索引页、Insert Buffer、自适应哈希索引、锁信息、数据字典等
  • Change Buffer（写缓冲）：二级索引的插入/更新缓冲。当修改的二级索引页不在 Buffer Pool 中时，先记录到 Change Buffer，避免随机 IO，后续合并到磁盘。适用于写多读少的场景
  • Log Buffer（日志缓冲）：Redo Log 的内存缓冲，默认 16MB。事务提交时根据 innodb_flush_log_at_trx_commit 策略刷入磁盘（0=每秒刷、1=每次提交刷、2=每次提交写OS缓存）

Adaptive Hash Index（自适应哈希索引）：InnoDB 自动监控索引页的访问模式，对热点索引页建立哈希索引，将 B+树的 O(log n) 查找降为 O(1)。由 innodb_adaptive_hash_index 控制，默认开启。

磁盘文件结构

  • 表空间（Tablespace）：InnoDB 8.0 默认使用独立表空间（innodb_file_per_table=1），每张表一个 .ibd 文件。系统表空间 ibdata1 存储数据字典、Undo Log（8.0 前）、Change Buffer 等
  • Redo Log（重做日志）：循环写入的物理日志，记录页的物理修改。用于崩溃恢复（Crash Recovery），保证已提交事务不丢失。默认两个 48MB 文件（ib_logfile0/1），循环覆盖
  • Undo Log（回滚日志）：逻辑日志，记录数据修改前的状态。用于事务回滚和 MVCC。8.0 后独立表空间存储，支持自动截断
  • Doublewrite Buffer（双写缓冲）：防止部分写（Partial Write）导致页损坏。数据页先写入 Doublewrite Buffer（连续写），再写入实际位置（随机写）。崩溃时可从 Doublewrite 恢复完整页

MVCC 与索引底层原理

MVCC 实现原理

多版本并发控制（MVCC）是 InnoDB 实现隔离级别的核心机制，通过保存数据的多个版本来实现读写不阻塞。

关键组件：

  • 隐藏列：每行数据包含 DB_TRX_ID（最后修改该行的事务ID）、DB_ROLL_PTR（指向 Undo Log 的回滚指针）、DB_ROW_ID（无主键时的隐藏行ID）
  • Undo Log 链：每次修改都会在 Undo Log 中记录旧版本，通过 DB_ROLL_PTR 形成版本链。Purge 线程定期清理不再需要的旧版本
  • Read View（一致性视图）：事务开始时生成的快照，包含当前活跃事务列表。判断某行版本是否可见的规则：trx_id < min_id（已提交，可见）、trx_id > max_id（未来事务，不可见）、在活跃列表中（未提交，不可见）

隔离级别与 MVCC 的关系：

  • READ COMMITTED：每条 SELECT 都生成新的 Read View，能看到其他事务已提交的修改
  • REPEATABLE READ：事务中第一条 SELECT 生成 Read View，后续复用，保证可重复读。这是 MySQL 默认隔离级别
  • SERIALIZABLE：所有 SELECT 都加共享锁，退化为锁机制并发控制

B+树索引底层

InnoDB 使用 B+树作为索引结构，与 B 树的关键区别：非叶子节点只存键，数据只在叶子节点；叶子节点通过双向链表连接。

  • 聚簇索引（Clustered Index）：主键索引，叶子节点存储完整行数据。表数据就是聚簇索引的一部分。如果没有定义主键，InnoDB 选择第一个唯一非空索引，或自动生成 6 字节隐藏主键
  • 二级索引（Secondary Index）：叶子节点存储主键值。查询时需要回表（先用二级索引找到主键，再用聚簇索引找行数据）。覆盖索引（Covering Index）可以避免回表
  • 索引下推（ICP）：MySQL 5.6 引入，将 WHERE 条件中索引包含的列下推到存储引擎层过滤，减少回表次数。由 optimizer_switch='index_condition_pushdown=on' 控制
  • 页分裂与合并：B+树页（默认 16KB）满时分裂，删除后合并。随机插入会导致频繁页分裂和碎片，自增主键是最佳实践

锁机制与并发控制

行锁与间隙锁

InnoDB 的锁分为多个层次：

  • 共享锁（S Lock）：读锁，允许多个事务同时持有，阻止写。SELECT ... LOCK IN SHARE MODE
  • 排他锁（X Lock）：写锁，只允许一个事务持有，阻止其他读写。INSERT/UPDATE/DELETE 自动加
  • 意向锁（Intention Lock）：表级锁，表明事务即将在表中的某些行加锁。IS/IX 锁之间兼容，提高加锁效率（不需要逐行检查）
  • 记录锁（Record Lock）：锁定索引记录。例如 WHERE id=10 FOR UPDATE
  • 间隙锁（Gap Lock）：锁定索引记录之间的间隙，防止其他事务在间隙中插入新记录。只在 REPEATABLE READ 隔离级别下使用，用于防止幻读
  • Next-Key Lock：记录锁 + 间隙锁，锁定记录本身及其前面的间隙。InnoDB 默认的行锁算法，左开右闭区间

死锁检测：InnoDB 使用等待图（Wait-for Graph）检测死锁，当检测到循环等待时，回滚代价最小的事务（undo 量最少的）。可以通过 SHOW ENGINE INNODB STATUS 查看最近的死锁信息。

8大常见陷阱与最佳实践

  1. 索引失效场景：对索引列使用函数/运算（WHERE YEAR(create_time)=2026）、隐式类型转换（字符串列用数字查询）、LIKE 左模糊（%abc）、OR 连接非索引列、不符合最左前缀原则。用 EXPLAIN 检查 type 列（ALL 是全表扫描，ref/range 是索引）
  2. 大事务导致 Undo 膨胀：长事务持有 Undo Log 不释放，导致 Undo 表空间膨胀，影响性能。避免在事务中等待用户输入、批量操作分批提交、监控 information_schema.INNODB_TRX 中的长事务
  3. Redo Log 太小导致性能抖动：Redo Log 写满时触发 Checkpoint，强制刷脏页，导致性能尖刺。建议设置 innodb_log_file_size 为 1-2GB（8.0 最大 128GB），innodb_log_files_in_group=2-4
  4. Buffer Pool 命中率低：全表扫描、大结果集查询会污染 Buffer Pool。用 SHOW STATUS LIKE 'Innodb_buffer_pool_read%' 计算命中率（应 > 99%）。大表查询考虑 SQL_BUFFER_RESULT 或分批处理
  5. 间隙锁导致的死锁：REPEATABLE READ 下，唯一索引的等值查询会退化为记录锁，但范围查询和非唯一索引会加 Next-Key Lock。高并发插入场景可能因间隙锁冲突导致死锁。考虑降低隔离级别为 READ COMMITTED（间隙锁关闭）
  6. 慢查询未及时发现：开启 slow_query_log=1，设置 long_query_time=1（秒），用 pt-query-digest 分析慢查询日志。注意 log_queries_not_using_indexes 会记录所有未用索引的查询，可能产生大量日志
  7. 连接数耗尽：max_connections 默认 151，高并发时可能耗尽。应用层使用连接池（HikariCP、go-sql-driver 的 SetMaxOpenConns），监控 Threads_connected 和 Aborted_connects。不要盲目调大 max_connections，每个连接占用内存（约 2-3MB）
  8. 主从延迟：大事务、DDL 操作、网络延迟、从库性能不足都会导致主从延迟。监控 Seconds_Behind_Master（不准确，仅参考），使用 pt-heartbeat 精确测量。8.0 支持并行复制（slave_parallel_workers），基于 WriteSet 的并行复制可显著提升吞吐量
