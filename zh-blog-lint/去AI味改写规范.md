# 去 AI 味改写规范

适用于站内全部文章正文（`<main>` 里的段落、列表、导读框、小标题）。代码块、表格里的数据、链接、`id` 属性、图片、mermaid 图不在这次改写范围内。

改写前先跑 `python3 scripts/deai/lint.py <文件或目录前缀>` 看命中，改完再跑一次，命中必须归零。

## 一、要删掉的东西

### 1. 每节开头的"能解决什么"预告句

```
搞清这一节，能解决「流式接口为什么重试不生效」「双向流为什么莫名死锁」。
```
删。第一句直接说这一节讲的东西本身。

### 2. "这篇怎么读"导读框

整块删除，不做压缩、不保留一句概括。文章开头只留一段说明这篇覆盖什么、和站内哪几篇分工。

### 3. 小标题的三段式编号前缀

`① 用法 · 出问题时的动手顺序` → `出问题时的动手顺序`
`② 原理 · 单线程模型与事件循环` → `单线程模型与事件循环`
`③ 场景 · 什么时候不该用 Redis` → `什么时候不该用 Redis`

### 4. 修辞转弯

这些词后面跟的都是废话，把转弯删掉、把结论留下：

> 好消息是 / 坏消息是 / 雪上加霜的是 / 更麻烦的是 / 反直觉的结论是 / 先纠正一个流传很广的说法 / 另一个常见误解是 / 核心矛盾一句话说清 / 真正决定选型的是 / 这才是 / 这就是 / 本质上 / 换句话说 / 值得注意的是 / 综上所述 / 首先·其次·最后

```
好消息是 gRPC 自带背压：窗口耗尽时 Send 会阻塞。
→ gRPC 自带背压：窗口耗尽时 Send 阻塞，生产者被拖慢。
```

### 5. 假精确数字

没有测量条件、没有出处的百分比一律删掉或改成定性描述。

```
线上 90% 的偶发 UNAVAILABLE 就不会出现。
→ 常见的偶发 UNAVAILABLE 多数来自这三项没配对。
```
有出处的保留：官方默认值、协议常量、自己压测过的数据（写明版本和条件）。

## 二、要压缩的东西

- **一段只说一件事**。段落超过 3 句就拆，或删掉重复的那部分。正文单个 `<p>` 超过 150 汉字即不合格。
- **同一事实只讲一遍**。导读框、正文、末尾 FAQ 三处重复同一个结论，只留正文那处。
- **从句改短句**。"X 不是 A，而是 B"这种句式一篇里最多留 2 处，其余直接说 B。
- **破折号 `——` 只做一件事**：引出补充说明。能用逗号或另起一句的就改掉。每页 `——` 不超过 5 处。
- **`「」` 只用于**：错误信息原文、要引用的现象、配置项的字面值。给概念起的比喻名不用引号。每页 `「` 不超过 15 处。
- **绝对表述**：`必须 / 一定 / 永远 / 所有 / 从不` 换成"默认""通常""实测下来"，除非讲协议强制项。
- **装饰符号**：段落里的 `✅ ⚠️ 💡` 只保留在告警框上，正文句子不用 emoji。

## 三、不能动的东西

1. 技术事实、阈值、版本号、默认值、命令、参数名——一个都不能少，也不能改口径。
2. `<table>` 的行和单元格内容（表格已经是压缩后的形态，只允许改表头措辞）。
3. `<code>`、`<pre>`、`<div class="mermaid">` 整块原样保留。
4. `id` 属性、`href`、`src`、`<script type="application/ld+json">` 之外的 meta 标签。FAQPage 里的 JSON-LD 与正文同步删改：正文删掉的问答，JSON-LD 里也要删；改写的，两边措辞一致。
5. 文章结构层级：`<h2>` 的数量和内容保持，只去掉标题里的编号前缀。
6. 站内交叉引用链接不能断。

## 四、改完的样子

```html
<!-- 改前 -->
<h2 id="flowctrl">② 原理 · 流控：吞吐上限是窗口除以 RTT</h2>
<p>反直觉的结论是：显式设置 WithInitialWindowSize 会关闭动态调窗，把窗口钉死在你给的值上——不少「照帖子调优反而变慢」就是手动设成 1MB 后比自动调窗还小。HTTP/2 有两级流控窗口：连接级和流级。协议默认值都是 65535 字节，连接级窗口只能靠 WINDOW_UPDATE 放大，SETTINGS 里的 INITIAL_WINDOW_SIZE 只作用于流。单条流的稳态吞吐上限就是一道除法：窗口 / RTT。64KB 窗口配 100ms 的跨区 RTT，约 640KB/s——无论带宽多富余。</p>

<!-- 改后 -->
<h2 id="flowctrl">流控：吞吐上限是窗口除以 RTT</h2>
<p>HTTP/2 有两级流控窗口：连接级和流级。默认值都是 65535 字节，连接级只能靠 WINDOW_UPDATE 放大，INITIAL_WINDOW_SIZE 只作用于流。</p>
<p>单条流的稳态吞吐上限是 窗口 / RTT。64KB 窗口配 100ms 跨区 RTT，约 640KB/s，和带宽富余多少无关。</p>
<p>grpc-go 默认不固定窗口，用 PING 估 BDP 动态放大到 4MB 量级。手动设 WithInitialWindowSize 会关掉动态调窗，把窗口钉死在给定的值上。设成 1MB 反而比默认慢，就是踩了这个。</p>
```

事实一条没少，字数少三成，没有转弯词。

## 五、验收

```bash
python3 scripts/deai/lint.py                 # 全站汇总：硬项清零页数
python3 scripts/deai/lint.py database/redis  # 单页或目录前缀
python3 scripts/deai/lint.py --self-test     # 植入已知违规，确认每条规则都能触发
```

判定口径：硬项（导读框、编号标题、预告句式、套话转弯、顺序词、超长段落、段落内 emoji）
命中数为 0；且 `python3 scripts/shrink/verify.py --snapshot _drafts/deai-snapshot --all` 通过
（`<pre>`/mermaid/表格/链接/内联 code/数字 token 与基线全等）。

阶段 A（删导读框、去标题编号）由 `python3 scripts/deai/strip_boilerplate.py --check-only --files <页>` 复核。
